# 常驻指令文件内容规则

## 1. 内容规则
- 开头写明对象、范围与完成定义；完成定义回答“何种状态构成完成”。
- 每条规则给出可观察的判定条件：阈值、命令、字段或可复核的动作，不用“合理”“合适”作判据。
- 不写模型能自己知道的通用要求；只写与通用做法不同、模型推导不出的内容。

## 2. 禁止项与强调

- 每条禁止项给出替代行为或理由；红线可以保持禁止，但必须说明理由。
- 平实祈使句为默认语气；整句强调只用于红线，普通要求不用“绝不”等绝对措辞。
- 不以编号声明优先级；需要顺序的显式声明“靠前的规则优先”，不靠编号暗示。
- 不留无条件的相互矛盾要求；两条规则冲突时写明适用条件或删除其一。

## 3. 语境与层级

- 上下文只放模型从代码推导不出的信息：构建命令、测试运行方式、仓库约定、必需的架构决策与环境变量。
- 长文档改为链接，不粘贴；一行承载一条要求，不写压缩段落。
- 不写未确认的工具、命令或配置键；未确认的先提问或省略。
- 声明指令层级时与宿主规则的效力顺序一致；层级定义与注入防线依 `prompt-engineering` 的规则。
- 信息不足、含糊与超范围的请求各有一个动作；至少包含“无法处理”分支。
- 按目标模型调整语气与详略的规则依 `prompt-engineering`；本文件只写任务自身的要求。
