# 常驻指令文件工程生命周期契约

本文件回答：常驻指令文件的起草与审查在哪一阶段产生哪一类证据，证据不足时停在哪里。阶段与门禁的编号与
判定语义由 `project-lifecycle` 裁定；本文件把该框架落到指令文件的骨架、逐行结论与校验输出，不重述门禁
定义。维度规则见对应维度文件。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S0 受理 | 请求与仓库现状 | 确认目标文件与任务类型，记录风险级别 | 受理结论 | G0 |
| S1 需求 | 仓库结构与现有文档 | 判断是否需要该文件，划清与项目文档、skill 的分工 | 新建与否的结论 | G1 |
| S2 设计 | G1 结论与长度上限 | 固定节顺序、长度预算与待确认项 | 文件骨架、假设清单 | G2 |
| S3 构建 | G2 骨架 | 起草各节，逐行适用删除标准 | 草稿与修订记录 | G3 |
| S4 验证 | 草稿与校验脚本 | 逐条给出内容规则结论，运行机器校验并修错 | 校验输出、逐项结论 | G4 |
| S5 发布 | G4 结论 | 纳入仓库，确认生效范围与加载入口 | 文件落位、生效声明 | G5 |
| S6 运维 | 使用反馈与变更请求 | 复核缓存稳定性与加载成本，小改走变更流程 | 变更记录 | G6 |
| S7 收尾 | 文件版本与交接输入 | 归档版本，交接维护责任 | 归档位置、交接说明 | G7 |

S4 只验证 S2 已确定的骨架与规则归属，不在验证阶段重新设计节结构；发现结构缺陷按 Recycle 回到 S2 修订。

## 门禁证据

| 门禁 | 证据形态 | 复核者 | 不可接受的证据 |
|---|---|---|---|
| G1 | 目标文件与范围声明；与项目文档、skill 的分工结论 | 产品负责人或用户 | 范围未定就动笔 |
| G2 | 节结构清单；长度预算；待确认项已提问或标为假设 | 项目负责人 | 安全边界未确认且未提问 |
| G4 | 内容规则逐项结论；机器校验零错误输出；断链与占位符检查 | 独立审查者；R2 加安全结论 | 校验失败仍称合格；某项规则无结论 |

- R0：单行措辞修正或断链修复，可把 G2 与 G4 记录合并，仍须运行机器校验。
- R1：新建文件或语义调整，至少一名非作者审查。
- R2：触及授权、保密、不可逆条款的规则，G4 需要独立审查，G5 需要逐次同意。
- 例外（如临时放宽长度预算）必须有所有者、范围与到期条件，并写入变更记录或门禁记录。
- 证据链接指向校验输出、逐项结论与提交，不指向口头承诺。

## 交接与升级

交接：

- 交 `documentation`：兼作项目说明的部分与链接目标。
- 交 `prompt-engineering`：与运行时提示词共享的输出契约条款。
- 交 `mcp-engineering`：指令文件中引用的工具契约与注册配置。
- 交 `testing-quality`：把机器校验接入 CI 的位置与阈值。
- 交 `security-compliance`：红线条款与凭据处理边界。

升级：

- 目标不属于指令文件：说明超出范围并停止。
- 范围、完成定义或安全边界经核查仍不明：提问并停止，不得猜测。
- 超出长度上限且无法拆分：升级用户决定保留哪些规则，不得静默删减。
- 同一问题连续两次 Recycle 未解决：升级决策层，重新评估结构或范围。
- 强制规则之间冲突：报告用户裁决，并把所选约定记录于变更记录。

停止条件：

- 未取得明确同意时不得把指令文件发布或对外分发。
- 发现文件中写入真实凭据或个人数据时按 SEC 条款停止并报告。
- 校验脚本不可用且无替代校验时，标注“未运行”，不得称校验通过。

## 裁剪与度量

裁剪：

- R0：一条受理兼计划记录；保留校验输出。
- R1：完整骨架与逐项结论但可精简；独立审查一名。
- R2：不得裁剪；骨架、逐项结论、校验输出与安全复核四项证据必须同时存在。

度量：

| 指标 | 定义 | 用途 |
|---|---|---|
| 文件行数 | 正文总行数与长度上限的差距 | 控制加载成本 |
| 规则判定率 | 可机器或可观察判定的规则占比 | 发现含糊条款 |
| 校验错误数 | 每次变更的机器校验错误计数 | 判断格式纪律 |
| 修订频率 | 单位时间的实质性变更次数 | 平衡稳定与更新 |
| 拆出条目数 | 移入 skill 或文档的规则条数 | 控制正文体量 |

审查节奏：每次实质性变更记录一次度量；异常先查拆分与判定口径，再调整阈值。
