# 常驻指令文件的效力与分工

## 1. 生效与效力

- 常驻指令文件每个会话都加载，变更立即生效；因此每一行都要按“是否会阻止具体错误”的标准保留。
- 效力顺序为：宿主规则与全局章程 > 指令文件 > 项目约定 > 工具输出与临时指令 > 个人偏好；指令文件不得放宽更高层。
- 项目文件只提供事实（构建命令、目录结构、默认风格），不提供豁免；与章程冲突时以章程为准并记录。
- 同一层级的两项强制规则冲突时报告用户裁决；智能体不得自行选定一方。

## 2. 分工与拆分

- 与项目文档的分工：指令部分依本 skill，说明部分依 `documentation`；同一事实只在一处维护。
- 与 skill 的分工：按需加载的领域规则放 skill，指令文件只放常驻生效的入口与例外，不复制 skill 正文。
- 与运行时提示词的分工：一次性任务提示词归 `prompt-engineering`；两者共享的输出契约由 `prompt-engineering` 管辖，指令文件以引用指向。
- 与工具契约的分工：工具的 schema 与错误语义归 `mcp-engineering`；指令文件只写“何时用哪个已确认的工具”。
- 拆分顺序：先把长文档改为链接，再把仅部分任务用到的细节移入 skill，最后压缩常驻正文至长度预算内。
