# 常驻指令文件工程

常驻指令文件每个会话都加载：每一行都占用注意力，写得含糊或堆砌会在每个任务中被反复执行或反复忽略。它与
运行时提示词不同——后者一次交付，前者常驻生效，因此要求更严：规则必须可判定、禁止项必须给替代、长度必须
设上限、格式必须可机器校验。本 skill 规定这类文件的内容规则、结构与校验方式。

## 适用范围与优先级

效力自上而下：宿主规则与全局章程的强制条款优先，指令文件不得放宽它们；本 skill 的规则次之；既有指令文件
与仓库配置属于事实输入，逐行依本 skill 的规则审查；项目约定仅在本 skill 未规定处补充。

管辖边界：

- 一次性或产品提示词由 `prompt-engineering` 管辖；本 skill 只管每个会话常驻加载的指令文件。
- 项目文档的行文由 `documentation` 管辖；同一文件兼作指令入口与项目说明时，指令部分依本 skill，说明部分依该 skill。
- 标识符与文件名由 `naming` 管辖；凭据与机密由 `security-compliance` 管辖。
- 工具的服务端契约由 `mcp-engineering` 管辖；本 skill 只管指令文件如何引用已确认的工具。
- 门禁与 CI 由 `testing-quality` 与 `release-operations` 管辖；本 skill 管指令文件如何描述已验证的命令。
- 指令文件声明的层级不得与宿主规则的效力顺序冲突；冲突时按更高层执行并在交付中记录。

## 生命周期定位

上游输入：S0 的目标文件与任务类型（新建或审查）；S1 的范围、完成定义与安全边界。下游交接：S4 交付逐项结论
与校验输出，供门禁与用户复核。升级与停止：目标不属于指令文件时说明超出范围并停止；范围或安全边界经核查
仍不明时提问并停止；超出长度上限时按主题把规则提取到对应 skill 的 `references/`，正文只留摘要与加载指引。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 确认目标文件与任务类型（新建或审查），记录风险级别 | 受理结论 |
| S1 需求 | 判断是否需要常驻指令文件，划清与项目文档、skill 的分工 | 是否需要新建的结论 |
| S2 设计 | 固定节顺序、长度预算与待确认项 | 文件骨架、假设清单 |
| S3 构建 | 起草并逐行适用删除标准 | 草稿与修订记录 |
| S4 验证 | 逐条给出内容规则结论，运行机器校验 | 校验输出、逐项结论 |
| S5 发布 | 纳入仓库并确认生效范围 | 文件落位、生效声明 |
| S6 运维 | 变更时复核缓存稳定性与加载成本 | 变更记录 |
| S7 收尾 | 归档版本与交接维护责任 | 归档位置、交接说明 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G1 立项 | 目标文件、范围与完成定义已确认，与项目文档、skill 的分工结论 | Hold：范围未定时不动笔 |
| G2 设计 | 节结构、长度预算、待确认项已提问或标为假设 | Recycle：安全边界未确认且未提问 |
| G4 验证 | 内容规则逐项结论、机器校验零错误输出、断链与占位符检查结果 | Recycle：校验失败或某项无结论 |

机器校验通过不构成内容合格：脚本只判断格式，不判断规则是否可判定、禁止项是否给了替代。每条内容规则都要
有带证据的结论，未解释清楚的不算完成。

## 核心规则

- 目标与范围放最前：写明对象、范围与完成定义。
- 每条禁止项给出替代行为或理由；红线可以保持禁止，但必须说明理由。
- 平实祈使句，整句强调只用于红线。
- 含糊、超范围与信息不足的请求各有一个动作；至少包含“无法处理”分支。
- 不以编号声明优先级；不留无条件的相互矛盾要求。
- 输出格式写明结构、长度与格式。
- 非平凡规则配 3-5 个示例，每个示例展示规则未覆盖的行为。
- 上下文只放模型从代码推导不出的信息。
- 删除某行若不会阻止任何具体错误就删；只在部分任务用到的细节移入 skill。
- 不写未确认的工具、命令或配置键。
- 长文档改为链接；一行承载一条要求。
- 机器校验项：行宽不超过 200 字符、无制表符、无行尾空白、围栏成对、结尾换行、无占位符。
- 目标模型未知时用平实祈使句；推理模型只给目标与约束。
