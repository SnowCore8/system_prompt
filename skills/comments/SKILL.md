# 注释

注释以三种方式失效：复述代码已经说明的内容；随代码演进变得过时；用含糊的概括掩盖意图。只有记录读者无法从代码恢复的信息（契约、理由、隐患或计划）时，注释才值得维护成本。本 skill 规定注释的决策流程与每种注释的规则集，既服务于写注释的作者，也服务于评判注释的审查者。

## 适用范围与优先级

效力按下列层级判定，高层覆盖低层，低层只在高层未规定时补充。

1. 平台、法律与宿主约束：Javadoc、rustdoc、TSDoc 与 godoc 的注释位置要求不是可选项。
2. 本 skill 的规则：注释内容、位置、标记、弃用声明与工具指令以本文件与 `references/` 为准。
3. 项目约定与事实：现有代码、文档工具配置、注释 linter 与仓库声明的自然语言是输入；项目约定只在本 skill 未规定处补充，不得覆盖本 skill。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 本 skill 管辖嵌入源码的注释与由文档注释生成的 API 文档；独立文档、ADR 与变更日志归 `documentation`，注释长成文档时移动并链接，不复制。
- 弃用时机、移除窗口与公告位置归 `release-operations`；本 skill 只规定弃用标记的语法与替代项写法。
- 格式化、行宽与注释 linter 的配置归 `code-style`；机密扫描与泄露响应归 `security-compliance`；审查深度与合并门禁归 `vcs-collaboration`。
- 生成代码与第三方引入代码保留生成标记与上游注释，重新生成或重新引入，不手工编辑。
- 每个仓库只声明一种自然语言用于注释；标识符、API 术语与引用的上游文本保持原样。
- 代码是事实来源：与当前代码矛盾的注释是缺陷，在同一次变更中修复或删除；无注释胜于错误注释。

## 生命周期定位

上游输入：S2 设计中的公开契约、文档生成器、注释 linter 与仓库声明的语言。下游交接：S3 构建中的增量实现、S4 验证中的文档构建与 doctest、S5 发布中的弃用声明与发布说明衔接。

升级与停止：注释中出现凭据或个人数据时立即停止、保留证据并报告，按 `security-compliance` 的泄露响应处理；公开符号的契约变更退回 G2 重新确认；调查结束前不清理。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 确定公开契约的文档注释要求、自然语言、标记与工具指令策略 | 注释策略、文档工具配置、语言声明 |
| S3 构建 | 按类型写注释，契约随签名同步；标记带负责人与触发条件 | diff 中的注释、标记清单、弃用声明 |
| S4 验证 | 核对注释与代码一致，运行文档构建、doctest 与注释 lint | 构建输出、doctest 结果、过时注释清单 |
| S5 发布 | 核对弃用声明、生成标记与发布说明的衔接 | 弃用与移除窗口记录、发布说明 |

## 门禁与证据

证据必须可复核：构建命令与输出、diff 行号、issue 链接；口头说明与计划不构成证据。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 注释策略、文档工具配置、仓库语言声明、公开契约清单 | 策略缺失时 Hold，补齐后再过门 |
| G3 构建 | 注释 diff、标记的负责人与触发条件、弃用声明与替代项 | Recycle 到 S3；裸标记与被注释掉的代码阻断合并 |
| G4 验证 | 文档构建与 doctest 输出、注释 lint 结果、过时注释清单 | 修复后重验；行为变更未同步注释时 Recycle |
| G5 发布 | 弃用与移除窗口记录、生成标记完整、发布说明衔接 | Hold 发布，补齐替代指引后再过门 |

| 编号 | 维度名 | 首条规则 | 详情 |
|---|---|---|---|

| 2 | 标记 | TODO、FIXME 与 HACK 带负责人与移除触发条件，NOTE 与 WARNING 写明条件、后果与动作。 | `references/markers.md` 第 1 节 |

| 4 | 文件头与单位注释 | 说明单元的用途与不变量，不写作者横幅与变更记录。 | `references/file-headers.md` 第 1 节 |
