# MCP 服务器与工具工程

MCP 服务器把能力暴露给智能体，是新的边界：工具名称与描述决定智能体何时调用，参数 schema 决定调用能否成功，
错误语义决定失败后智能体做什么。服务器失效的常见原因不是实现错误，而是契约含糊：描述里没有触发条件、schema
与实现不一致、失败被伪装成成功、注册配置把机密写进共享文件。本 skill 规定从传输、契约到测试与版本的规则。

## 适用范围与优先级

效力自上而下：平台的协议规范与宿主规则的强制条款优先；本 skill 的规则次之；既有服务器、注册配置与调用方
提示词属于事实输入，依本 skill 的规则处理；个人偏好不得覆盖。

管辖边界：

- 调用方如何在提示词中描述工具、何时调用、失败怎么办，由 `prompt-engineering` 管辖；本 skill 管服务端契约本身。
- 面向人的 API 契约、分页与幂等由 `api-data` 管辖；本 skill 只管面向智能体的工具接口。
- 工具名与参数名的选择规则由本 skill 规定；一般标识符格式争议依 `naming`。
- 凭据存储、轮换与供应链由 `security-compliance` 管辖；本 skill 管注册配置里的机密边界与工具权限。
- 版本、制品与上线节奏由 `release-operations` 管辖；本 skill 交付弃用计划与兼容性结论。

## 生命周期定位

上游输入：S1 的服务对象与工具边界；S2 的传输选择、工具契约与错误目录。下游交接：S3 的可运行服务器与 schema
一致性证据；S4 的契约测试与注入样本结论；S5 的注册配置与版本记录。升级与停止：平台能力不支持所选特性时回到
S2 换方案；工具职责重叠时先合并再实现；注册配置无法安全落位时停止发布。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定涉及服务器、工具、注册还是调用方，记录风险级别 | 受理结论 |
| S1 需求 | 确认服务对象与工具边界，比较自建与复用 | 工具清单、复用结论 |
| S2 设计 | 定传输、工具契约、错误目录与安全边界 | 契约 schema、注册方案 |
| S3 构建 | 实现服务器与工具，schema 与实现保持同源 | 可运行服务器、一致 diff |
| S4 验证 | 契约测试、注入样本、手动测试与权限复核 | 测试输出、审查结论 |
| S5 发布 | 版本与变更记录、注册配置、回滚与公告 | 版本记录、注册结果 |
| S6 运维 | 监控调用失败率，处理弃用与兼容 | 指标、弃用记录 |
| S7 收尾 | 下线公告、配置清理与归档 | 下线记录、归档位置 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 工具清单与契约 schema、传输与注册方案、错误目录、安全边界 | Recycle：契约缺触发条件或错误路径 |
| G3 构建 | 服务器可运行、schema 与实现一致、失败路径已处理 | Recycle：手工改写生成物或伪造成功 |
| G4 验证 | 契约测试输出、注入样本结果、手动测试记录、权限与机密复核 | Hold：错误路径未测或机密复核未做 |
| G5 发布 | 版本与变更记录、注册配置、回滚方式、下线与弃用公告 | 停止发布：无回滚或未公告 |

契约变更按破坏性判定：新增可选参数是兼容变更；删参数、改必填或收窄枚举是破坏性变更，必须先走弃用窗口。

## 核心规则

- 一次只绑定一种传输：stdio 归单个客户端进程，HTTP 用会话头关联请求。
- 工具名以点或下划线分组承载命名空间；描述写明何时调用与何时不调用；参数用 JSON Schema 声明类型、必填、默认与枚举。
- 失败返回结构化错误（代码、信息、数据），不伪造成功，不泄露堆栈与内部路径。
- 注册即授权：配置最小权限，机密不写入共享文件，工具结果视为不可信数据。
- 契约测试覆盖 schema 与错误路径；破坏性变更走版本与弃用窗口。
- 部分完成必须报告哪些完成、哪些未完成，不得用成功结果掩盖失败。
