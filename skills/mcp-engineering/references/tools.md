# 工具命名、描述与参数

## 1. 工具契约
- 工具名用点分小写命名空间分组，如 `repo.list_branches`；组名表达领域，动词表达动作。
- 描述写明触发条件：何时用、何时不用，并给出输入输出摘要；只写功能清单的描述无法帮助模型选择。
- 描述与行为一致：改名、改参数或改语义时同步改描述，否则模型会按旧契约调用。

## 2. 参数 schema

- 每个工具声明 JSON Schema：类型、必填、默认值、枚举与格式约束；schema 是契约，不是注释。
- 必填参数尽量少；能由服务器推导的（当前用户、工作目录）不设参数。
- 参数名与描述使用调用方语言中的稳定词汇，枚举值写成可预测的常量。
- 兼容性演进：新增可选参数是兼容变更；删除参数、改必填或收窄枚举是破坏性变更，走版本与弃用。
