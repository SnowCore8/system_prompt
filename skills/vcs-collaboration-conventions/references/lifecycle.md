# 版本控制与协作规范生命周期契约

本文件把分支、审查与所有权接入 Stage-Gate 生命周期：计划阶段定模型与保护，构建阶段定 PR 与合并，验证
阶段定批准与增量复审，发布阶段定标签与热修复路径。维度规则见 `dimensions.md`，工作表见 `playbooks.md`；
本文件只写阶段职责、门禁证据、交接升级与裁剪度量。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 立项结论、发布节奏、团队规模 | 读取平台设置，选择分支模型，定义分支类别、合并方式、审查级别、保护集合与所有权边界 | 分支策略、规则集配置、CODEOWNERS 草案 | G2 |
| S3 构建 | G2 的分支策略与任务拆分 | 从登记基线开分支，控制体量与提交单位，准备 PR，按风险分派审查，按依赖顺序合并 | PR 描述、审查结论、合并提交、删除的分支 | G3 |
| S4 验证 | 待合并的增量与审查记录 | 核对批准有效性、必需校验在合并结果上通过、阻塞线程已解决、生成路径按输入审查 | 批准记录、校验输出、过期批准处理记录 | G4 |
| S5 发布 | 已合并的发布内容 | 保护发布分支与发布标签，确认热修复经审查并向前移植，向发布门禁移交合并证据 | 标签规则、热修复 PR、合并与移植记录 | G5 |

阶段细则：

- **S2 审查级别。** 轻量：文档、注释、仅测试、格式化与补丁级依赖更新，一名审查者；标准：普通功能、缺陷
  修复与次版本依赖更新，一名归属所有者；高风险：认证、支付、权限、加密、数据迁移、公共接口、依赖主版本
  与 CI/发布工具，两名审查者且包含领域或安全审查者。
- **S2 体量预算。** 单个可审查变更约 400 行改动、十个文件；400 至 800 行的例外须在设计说明中写明拆分
  理由并增加第二名审查者；超过 800 行拆成堆叠。机械重命名、格式扫描、锁文件与生成文件从行为变更中拆出。
- **S2 保护集合。** 默认分支、每个受支持发布分支与发布标签纳入保护；按分支类别启用校验：主干要求全集，
  发布分支增加打包与发布校验，维护分支至少要求构建、测试与发布所有者批准。
- **S2 规则集细节。** 要求 PR 与批准（标准 1 名、高风险 2 名）、过期批准失效、最近一次推送须经他人批准、
  代码所有者审查、对话解决、必需状态检查并绑定 `merge_group`、线性历史、签名提交（组织要求时）、阻止
  强制推送与删除、发布分支要求受保护环境部署、代码扫描结果。标签规则阻止移动或删除 `v*` 等发布标签；
  推送规则限制路径、扩展名与文件大小。必需校验名称必须与工作流 job 名称一致，重命名 job 会使规则静默失效。
- **S3 分支与提交。** 分支名、提交类型与范围遵循 `naming-conventions`；一个提交一个逻辑变更，提交可构建
  并通过所在领域校验，合并前压缩 fixup；变基个人分支须带租约，冲突在作者分支解决并重跑受影响校验。
- **S3 PR 与状态。** 描述按顺序回答解决何种问题、如何解决、验证了什么、可能出现何种错误；草稿不进审查
  队列；就绪意味着描述完整、自审完成、必需校验通过。审查期间以小 fixup 推送，不重写已进入审查的分支。
- **S3 堆叠与合并。** 堆叠自底部合入，父变更合入后子分支变基并重跑校验；合并方式按分支类别选择；合并后
  删除主题分支；发布分支禁止在合并提交中解决冲突。
- **S4 审查行为。** 首次响应目标为一个工作日，小增量当日复审，停滞一日后改派；评论前缀 `must:` 阻塞、
  `should:` 请求修复或解释、`nit:` 局部偏好、`q:` 需要回答；未标记按 `should:` 处理；解决线程前须有回复
  或关联修复，作者不得自行解决未处理的反对意见。
- **S4 证据复核。** 批准只对当前 diff 有效；实质性推送后须重新取得；基线移动后变基且冲突解决未改代码的，
  可保留批准但须重跑校验；不可达的审查者由归属团队回退审查者接替，等待不构成审查状态。
- **S4 生成与第三方路径。** 审查生成器输入、重新生成命令与版本标记，比对重新生成结果；第三方引入目录核对
  固定版本、许可证与补丁列表；手工修改生成产物一律视为未审查。
- **S5 标签与热修复。** 已发布标签不可变，仅发布自动化或发布所有者可创建标签；门禁失败的标签在发布前按
  发布流程删除，已公开标签不删除、不移动；热修复自发布标签切出，经审查后打新补丁标签并向前移植到主干。
- **S5 签名。** GPG、SSH 与 S/MIME 签名均可被平台验证，推送前确认 `Good signature`；网页与部分 API 提交
  由平台代签，只证明经由平台产生；密钥丢失时轮换并重新登记，不关闭验证以恢复推送。
- **S5 fork 信任。** fork 的 `pull_request` 构建仅获只读令牌且无仓库机密；禁止在 `pull_request_target` 或
  `workflow_run` 中检出并执行不可信代码；工作流、复合 action 与 CODEOWNERS 由平台团队审查，发布与部署
  机密仅在受保护环境批准后可用。

## 门禁证据

- **G2**：模型选择与理由、分支类别与生命周期上限、每类合并方式、审查级别表、保护清单、所有权映射、下一次
  复审触发条件。模型与发布路径冲突时 Recycle。
- **G3**：PR 标题与描述、关联 issue、体量与堆叠顺序、自审清单、必需校验在合并结果上的输出、草稿转就绪的
  时间点。校验仅在作者副本通过时不得合入。
- **G4**：归属团队批准、批准未因推送过期、阻塞线程已解决、生成路径按输入审查、必需校验覆盖合并组合。
  任一缺失即 Hold，重新审查增量。
- **G5**：发布分支与标签已受规则集保护、热修复经审查并向前移植、发布提交与标签指向一致、绕过记录已复审。
- 绕过记录字段：操作者、原因、被绕过的规则、请求链接、合并后审查人与完成日期；缺任一项按事故处理。
- 批准角色：R1 由项目负责人批准并至少一名独立审查者；R2 增加架构或安全审查；智能体不得代替人工批准，
  也不得把用户沉默视为批准。

## 交接与升级

- 上游：`project-lifecycle-governance` 给出阶段与风险级别；`testing-and-quality-conventions` 给出必需校验
  集合；`repository-governance-conventions` 给出角色、治理决策与 CODEOWNERS 批准要求；
  `security-compliance-conventions` 给出访问控制、签名与凭据策略；`naming-conventions` 给出分支、提交与
  标签命名。
- 下游：`release-operations-conventions` 消费合并与标签证据；`worktree-collaboration-conventions` 按分支
  类别为每个工作树分配分支；`documentation-conventions` 承接贡献者指南与模板行文。
- 升级触发：需要重写受保护分支、需要删除或移动已发布标签、保护被绕过、批准过期仍有争议、所有权冲突、
  审查者不可达、单人仓库缺少补偿控制。上述情形停下并请求用户或治理负责人裁决。
- 强制规则冲突时报告用户；平台设置无法读取时记录缺口并以仓库内策略文件为准，请有权限者核对后再宣布合规。
- 停止条件：分支模型与发布路径不一致、保护机制无法启用且无补偿检查、必需校验无法在合并结果上运行时保持
  Hold，不进入合并。

## 裁剪与度量

- R0 允许主干直接提交或以自查加必需 CI 替代批准，仍须在变更记录中留下验证证据；R1 使用标准审查与保护；
  R2 增加第二名审查者、独立批准与完整绕过记录。
- 单人仓库、trunk-based 与无 PR：批准数设为零并以自审记录与必需 CI 替代，自审写明检查项与结论；CODEOWNERS
  仅通配条目时记录单点与补偿控制，不假装存在第二所有者。
- 不可裁剪：默认分支与发布标签保护、必需校验、阻塞线程解决、过期批准失效、所有权覆盖、绕过记录。
- 度量：PR 体量中位数、前置时间、首次审查响应时长、过期批准数、绕过次数、孤儿路径数、合并队列失败率、
  逃逸缺陷数。
- 度量口径：前置时间从首次提交计至合并；响应时长按工作日计算；体量按改动行数而非提交数统计；口径变更与
  上一次数据同时展示。
- 度量审查按月或按发布进行；异常先查分支模型、审查负载与所有权覆盖，不以收紧数字替代修复根因，也不用于
  个人排名。
