# 架构与设计清单

在新增模块、划分边界与审查设计时，把本文件与 `SKILL.md` 一起使用。每份清单在其标题所指的时刻适用：边界清单用于
新增模块之前，依赖清单用于审查依赖图时，ADR 模板用于记录决策时。不适用的条目要给出简短理由，而不是打勾；未勾选的
条目是未决风险，不是形式。

## 架构审查清单

对照模块清单与依赖图运行这份清单，而不是凭「本应如此」的记忆。

- [ ] 依赖图是有向无环图，依赖只从外层指向内层。
- [ ] 每个模块能用一个变更理由描述，且只用一个。
- [ ] 模块内聚：内部元素因同一个理由一起变化。
- [ ] 模块间低耦合：改动一个模块的内部实现，不会迫使另一个模块改动。
- [ ] 公共接口最小化，内部类型、实体与存储细节不越过边界。
- [ ] 接口按调用方隔离，没有上帝接口。
- [ ] 抽象在内层，实现在外层，内层不依赖外层的具体实现。
- [ ] 数据流显式（参数与返回值），控制流显式（调用与编排可见）。
- [ ] 跨模块数据传递通过契约，而不是内部结构或存储行。
- [ ] 外部依赖（网络、时钟、文件、随机、第三方 SDK）都在接缝后面。
- [ ] 接缝与注入点显式、少而清晰，可替换依赖可测试。
- [ ] 新建或推翻的架构决策有 ADR。
- [ ] 没有为假设的通用性引入抽象（YAGNI），没有过度设计。
- [ ] 新接口的契约内容已交由 `api-and-data-conventions` 审查。
- [ ] 与相邻 skill 的边界清楚：契约、风格、重构手法、测试策略各有归属。

## 边界决策表

实现之前，为每一行记录一个决策。默认值持续有效，直到已测量的需求将其推翻；同一项目对同一行使用相同的选择。

| 决策 | 默认 | 选择其他方案的情形 | 义务 |
|---|---|---|---|
| 模块粒度 | 一个模块一个变更理由 | 一个理由横跨多个模块时合并为组件 | 模块清单记录每个模块的理由 |
| 分层数量 | 按变化速率分层，够用即可 | 系统有明显不同的稳定性与变化速率 | 每层依赖方向向内、无环 |
| 接口粒度 | 按调用方拆小接口 | 单一调用方使用全部方法时合并 | 每个接口只承载真实使用的方法 |
| 抽象时机 | 出现第二个真实场景才抽象 | 已有两处重复实现且会继续分化 | 抽象由第二个场景回填形状 |
| 接缝位置 | 外部依赖与易变实现之后 | 需要隔离测试或替换的任意依赖之后 | 接缝显式、少而清晰 |
| 数据流 | 参数与返回值显式传递 | 跨进程或异步需要消息 | 契约由 `api-and-data-conventions` 定义 |
| 决策记录 | 新建或推翻架构决策就写 ADR | 纯风格或日常功能不写 | ADR 含背景、决定、后果、替代方案 |

- 把每个决策记录在 ADR 或模块文档中；只活在审查者脑子里的决策会在下一次变更时被重新争论。
- 测量结果变化时重新审视决策，并说明会重新打开它的条件，而不是让问题悬着。
- 一致性胜过局部优化：与系统其他部分依赖方向不同的模块，是整个系统的新决策，不是一个模块的捷径。

## ADR 模板

新建 `docs/adr/` 下的 ADR 时按此骨架填写（目录与文件名约定归 `documentation-conventions`）。复制后删掉不适用的段落，
不保留空占位。

```markdown
# ADR-NNNN：<一句话决定>

- 状态：<提议 / 已接受 / 已取代（由 ADR-MMMM 取代）>
- 日期：<YYYY-MM-DD>

## 背景

<要解决什么问题，有哪些约束；一句话说清为什么现在必须做这个决定>

## 决定

<选择了什么，用可判定的话说清；不要写「更合理」「更优雅」这类无法核对的形容词>

## 后果

<带来的收益与代价；哪些路径因此变贵，哪些替代路径因此关闭>

## 替代方案

<被否掉的选项，以及否掉它的可核对理由>
```

- 状态只写当前为真的一条，不追加历史；决策变了就写一篇新 ADR，标注它取代哪一篇。
- 「决定」写可判定的事实（依赖方向、模块边界、接缝位置），不写形容词；审查者要能据此核对代码。
- 一篇 ADR 一条决策；塞进多条无关决策的 ADR，读者无法判断哪条已过时。

## 依赖图审查清单

对照依赖图本身（或依赖校验器的输出）运行，而不是凭模块清单的记忆。

- [ ] 每个依赖箭头都有明确方向，且从外层指向内层。
- [ ] 图中无环；校验器能确认 DAG，违反在合并前被捕获。
- [ ] 内层不依赖外层实现，抽象与实现方向正确。
- [ ] 每个抽象至少有一个真实实现，且实现数量与抽象价值相称。
- [ ] 没有被所有调用方都绕过、形同虚设的抽象。
- [ ] 新增依赖经过评估：是契约依赖（允许）还是内部结构依赖（越界）。
- [ ] 依赖方向与分层约定一致，任何例外都有 ADR 记录理由。
