# 架构与设计清单

在新增模块、划分边界与审查设计时，本文件应当与 `SKILL.md` 配合使用。每份清单在其标题所指的时刻适用：边界清
单用于新增模块之前，依赖清单用于审查依赖图时，ADR 模板用于记录决策时。不适用的条目应当给出简短理由，不得以
打勾代替；未勾选的条目属于未决风险，而非形式。
正文「审查清单」为设计期的权威；本文件仅载明各时刻的工作表与正文未展开的条件。

## 架构审查清单

对照模块清单与依赖图运行本清单，不得凭「本应如此」的记忆运行。

- [ ] 每个模块能够以一个变更理由描述，且仅有一个。
- [ ] 模块内聚：内部元素因同一理由一起变化。
- [ ] 模块间低耦合：变更一个模块的内部实现，不会迫使另一模块改动。
- [ ] 公共接口已经最小化，内部类型、实体与存储细节未越过边界。
- [ ] 抽象置于内层，实现置于外层，内层不依赖外层的具体实现。
- [ ] 数据流显式（参数与返回值），控制流显式（调用与编排可见）。
- [ ] 跨模块数据传递通过契约，而非内部结构或存储行。
- [ ] 外部依赖（网络、时钟、文件、随机、第三方 SDK）均置于接缝之后。
- [ ] 接缝与注入点显式、少而清晰，可替换的依赖可测试。
- [ ] 未为假设的通用性引入抽象（YAGNI），不存在过度设计。
- [ ] 与相邻 skill 的边界清晰：契约、风格、重构手法与测试策略各有管辖者。

## 边界决策表

实现之前，应当为每一行记录一项决策。默认值持续有效，直至已测量的需求将其推翻；同一项目对同一行应当使用相同
的选择。

| 决策 | 默认 | 选择其他方案的情形 | 义务 |
|---|---|---|---|
| 模块粒度 | 一个模块一个变更理由 | 一个理由横跨多个模块时合并为组件 | 模块清单记录每个模块的理由 |
| 分层数量 | 按变化速率分层，够用即可 | 系统有明显不同的稳定性与变化速率 | 每层依赖方向向内、无环 |
| 接口粒度 | 按调用方拆小接口 | 单一调用方使用全部方法时合并 | 每个接口仅承载真实使用的方法 |
| 抽象时机 | 出现第二个真实场景才抽象 | 已有两处重复实现且会继续分化 | 抽象由第二个场景回填形状 |
| 接缝位置 | 外部依赖与易变实现之后 | 需要隔离测试或替换的任意依赖之后 | 接缝显式、少而清晰 |
| 数据流 | 以参数与返回值显式传递 | 跨进程或异步需要消息 | 契约由 `api-and-data-conventions` 定义 |
| 决策记录 | 新建或推翻架构决策即写 ADR | 纯风格或日常功能不写 | ADR 含背景、决定、后果、替代方案 |

- 代理应当将每项决策记录于 ADR 或模块文档；仅存于审查者记忆的决策将在下一次变更时被重新争论。
- 测量结果变化的，代理应当重新审视决策，并说明会重新开启该决策的条件，不得使问题悬置。
- 一致性优于局部优化：与系统其他部分依赖方向不同的模块，属于整个系统的新决策，而非一个模块的捷径。

## ADR 模板

新建 `docs/adr/` 下的 ADR 时，应当按此骨架填写（目录与文件名约定由 `documentation-conventions` 管辖）。复
制后应当删除不适用的段落，不得保留空占位。

```markdown
# ADR-NNNN：<一句话决定>

- 状态：<提议 / 已接受 / 已取代（由 ADR-MMMM 取代）>
- 日期：<YYYY-MM-DD>

## 背景

<要解决什么问题，有哪些约束；一句话说清为什么现在必须做这个决定>

## 决定

<选择了什么，用可判定的话说清；不要写「更合理」「更优雅」这类无法核对的形容词>

## 后果

<带来的收益与代价；哪些路径因此变贵，哪些替代路径因此关闭>

## 替代方案

<被否掉的选项，以及否掉它的可核对理由>
```

- 状态仅应书写当前为真的一项，不得追加历史；决策变更的，应当编写新 ADR，并标注其取代的 ADR。
- 「决定」应当书写可判定的事实（依赖方向、模块边界、接缝位置），不得书写形容词；审查者应当能够据此核对代
  码。
- 一篇 ADR 一条决策；塞入多条无关决策的 ADR，将使读者无法判断其中哪一条已经过时。

## 依赖图审查清单

对照依赖图本身（或依赖校验器的输出）运行本清单，不得凭模块清单的记忆运行。

- [ ] 每个依赖箭头均有明确方向，且由外层指向内层。
- [ ] 图中无环；校验器能够确认 DAG，违反在合并前被捕获。
- [ ] 内层不依赖外层实现，抽象与实现的方向正确。
- [ ] 每个抽象至少有一个真实实现，且实现数量与抽象价值相称。
- [ ] 不存在被所有调用方绕过、形同虚设的抽象。
- [ ] 新增依赖已经评估：属于契约依赖（允许）或内部结构依赖（越界）。
- [ ] 依赖方向与分层约定一致，任何例外均有 ADR 记录理由。
