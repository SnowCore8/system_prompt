# 框架选择与变更（CH-5、CH-6）

CH-5、CH-6 沿用原用户全局约束的编号。

## CH-5 框架选择

新建模块或功能前，应当先确定框架，包括模块边界、分层、数据流、接口、错误与状态约定；命名规则、命名表与重命名
由 `naming-conventions` 裁定，本文件只确认其存在与维护责任。应当沿用现有框架；偏离的，应当说明原因与影响。缺乏
框架的，后续每次修改都将牵动整体。

## CH-6 框架变更的程序

变更框架的，应当先修改文档，列出受影响文件与迁移步骤；命名方案变更由 `naming-conventions` 裁定并遵循其重命名
流程。否则代码与文档将分叉。
