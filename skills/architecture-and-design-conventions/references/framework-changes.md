# 框架变更与命名（CH-5、CH-6）

CH-5、CH-6 沿用原用户全局约束的编号。

## CH-5 框架与命名

新建模块或功能前，应当先确定框架与命名，包括模块边界、分层、数据流、接口、错误与状态约定，以及目录、文件、
类、函数、变量、配置键与字段的统一命名表。应当沿用现有框架；偏离的，应当说明原因与影响。缺乏框架的，后续
每次修改都将牵动整体。

## CH-6 框架变更的程序

变更框架或命名方案的，应当先修改文档，列出受影响文件与迁移步骤。命名规则示例：布尔名称以 `is`、`has`、
`can`、`should`、`needs` 开头；数量名称携带单位，例如 `timeout_ms`。否则代码与文档将分叉。
