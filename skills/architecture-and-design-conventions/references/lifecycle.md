# 架构与设计规范生命周期契约

本文件说明本 skill 在阶段与门禁中的位置：架构结论何时必须成立、以什么证据成立、不成立时退回哪里。
阶段编号、门禁语义与决策权限由 `project-lifecycle-governance` 裁定；本文件只把该框架落到模块、依赖边、接缝与 ADR 上。
未列出的阶段不产出本 skill 的证据；被要求在那些阶段出结论时，回到 S2 重新裁定边界，而不是在收尾阶段改设计。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S1 探索 | 问题陈述、结果指标、平台与技术约束 | 列出至少两个架构方向与不做事，说明各自成本、风险与退出方式 | 选项比较与推荐 | G1 |
| S2 计划 | 范围与验收标准、安全威胁模型、性能目标 | 划定模块与组件边界，确定分层、依赖方向、数据流与接缝；裁定是否新建 ADR | 边界决策、依赖图源文件、ADR、接缝设计 | G2 |
| S3 构建 | 已通过 G2 的设计 | 新代码置于正确层；发现偏差时更新 ADR 与依赖图，不静默偏离 | 依赖图 diff、更新的 ADR、评审结论 | G3 |
| S4 验证 | 增量与依赖校验器 | 复核 DAG、抽象与实现方向、接缝可替换、ADR 与实现一致 | 校验输出与审查结论 | G4 |

S3 与 S4 不重新裁定边界：构建阶段只回写偏差，验证阶段只核对证据；需要改边界时按 Recycle 回到 S2。

## 门禁证据

| 门禁 | 证据形态 | 复核者 | 不可接受的证据 |
|---|---|---|---|
| G1 | 架构选项比较、主要风险与退出方式、约束来源 | 产品负责人；R2 加架构负责人 | 只有一个方向，没有不做事选项 |
| G2 | 模块清单与变更理由、依赖图源文件、接缝与注入点说明、ADR | 架构负责人与非作者审查者 | 截图、白板照片、口头约定 |
| G3 | 依赖校验器输出、ADR 更新 diff、偏差处理记录 | 提交者自检；R1 起加独立审查 | 以“先合并再修”推迟依赖修复 |
| G4 | DAG 校验、层依赖检查、接缝测试、ADR 与代码一致性核对 | 独立审查者；R2 加安全或合规结论 | 只凭模块清单记忆判断 |

G1 的架构证据可以是一段文字；G2 起必须有依赖图源文件与 ADR，文字描述不能替代校验器输出。

- R0：单模块内新增函数或类，可把 G2 与 G4 记录合并，只须说明所属模块与依赖方向。
- R1：边界、分层或框架变更需要独立审查；依赖图以源文件附在拉取请求中。
- R2：框架替换、跨团队边界重划或影响生产拓扑的变更，G2 需要架构与安全评审，迁移与回退方案随计划一并提交。
- 依赖校验器的输出随增量提交，基线取目标分支；并行变更因此不能互相掩盖新增的环。
- 例外（存量反向依赖、暂缓的框架替换）必须有所有者、范围与到期条件，记录于 ADR 或结构决策。
- 记录字段与存放位置以 `project-lifecycle-governance` 的模板为准，便于未参与者复核。

## 交接与升级

交接：

- 交 `project-structure-conventions`：模块清单、依赖方向与公开面，由该 skill 落到目录、导入规则与构建图门禁。
- 交 `api-and-data-conventions`：接口位置与边界，由该 skill 定义资源、错误与版本化。
- 交 `refactoring-conventions`：目标结构、接缝位置与收紧顺序，由该 skill 决定安全手法与提交粒度。
- 交 `testing-and-quality-conventions`：接缝的可替换点与需要注入的外部依赖。
- 交 `documentation-conventions`：ADR 的目录、模板与索引方式。
- 交 `vcs-collaboration-conventions`：边界审查所需的 code owner 映射。

升级：

- 新增依赖出现环或反向边：不得以 ADR 豁免，Recycle 到 S2 重划边界，或在本增量内抽取接缝。
- 框架变更缺少文档修改与迁移步骤：停在上一步，按 `framework-changes.md` 补齐后再进入 G2。
- ADR 停留在提议状态而代码已实施：视为决策分叉，Recycle 到 S2，使两者一致。
- 强制规则冲突：报告用户裁决；非强制约定冲突可记录所选约定于 ADR。
- 同一问题连续两次 Recycle 未解决：升级决策层，重新评估边界、分层或目标。
- 阶段回退保留失败记录：被否决的边界方案与依赖图留在 ADR 中，作为后续决策的输入。

停止条件：

- 依赖图无法校验且无法在本增量内建立校验点时，停止扩大改动，先补校验。
- 变更将影响生产拓扑或共享平台而未取得对应授权时，停止实施并说明所需批准。
- 发现设计文档与实现存在事实冲突且无法判断何者为真时，先查证再修改，不以猜测补齐。
- 紧急止损按 AU-5 优先：先恢复可用路径或回退框架切换，再补 ADR 与门禁记录，不改写已发生的时间线。

## 裁剪与度量

裁剪：

- R0：一段文字说明模块、依赖方向与理由；不新建 ADR。
- R1：一页设计记录加依赖图 diff；边界或框架变更必须写 ADR。
- R2：不得裁剪；设计评审、依赖图、回退方案与独立结论同时存在。

度量：

| 指标 | 定义 | 用途 |
|---|---|---|
| 循环依赖数 | 校验器报告的环数量与存量趋势 | 判断边界是否在退化 |
| 反向边数 | 内层指向外层的依赖条数 | 识别分层被绕过的位置 |
| ADR 覆盖率 | 有 ADR 的架构决策数与已发生决策数之比 | 发现只存在于讨论中的决定 |
| 变更波及模块数 | 单次需求实际改动的模块数量 | 衡量边界是否降低耦合 |
| 接缝测试占比 | 通过注入点替换外部依赖的用例比例 | 衡量可测试性设计是否落地 |
| 未使用抽象数 | 只有一个实现且无替换需求的接口与开关数量 | 发现过度设计残留 |

审查节奏：每个迭代末对照依赖校验输出；每个季度复核 ADR 覆盖与未使用抽象，异常先查根因再调整目标。
