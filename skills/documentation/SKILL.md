# 文档

文档缺陷多来自缺失与脱节，而非文笔：页面从未编写，代码变更后事实过时，同一答案散落多处，读者找不到页面也无人负责。
本 skill 把文档视为产品的组成部分，规定每类页面怎么写、事实放在哪里、如何随变更同步与验证。

## 适用范围与优先级

效力依下列层级判断，高层覆盖低层，低层仅在高层未规定时补充：

1. 强制约束。法律披露模板、文档站生成器约束与公司强制政策不可选。
2. 本 skill 的规则。页面结构、事实归属、同步与校验以本文件与 `references/` 为准。
3. 项目事实。既有目录、模板与工具链先阅读后裁定；它们在本 skill 未规定处补充。
4. 个人偏好，不得覆盖以上三层。

边界：

- 源码注释与 docstring 归 `comments`；由注释生成的参考页，结构依本 skill，文笔依该 skill。
- API 契约内容归 `api-data`；参考页是其生成投影，结构依本 skill，字段与错误定义不复制。
- 披露与隐私政策的内容归 `security-compliance`；本 skill 只规定页面结构与行文。
- 变更日志与运行手册中必须记录的发布事实由 `release-operations` 规定；本 skill 规定其结构与编写节奏。
- 哪些文件必须存在、置于何处由 `project-structure` 管辖；本 skill 规定其内容。
- 同一层级强制规则冲突时报告用户裁决，不得自行选定。

## 生命周期定位

上游：S1 的问题与读者决定文档服务谁；S2 的范围与设计决策决定需要哪些页面。下游：S3 的增量与文档 diff 同批落地；
S4 的一致性结论进入验证证据；S5 的变更日志供发布使用；S7 的归档与交接记录进入收尾报告。停止条件：事实缺少权威来源时
停止编写，先确定归属；批量删除或归档依 AUT-1 与 IRR-1 取得同意。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定涉及哪些页面与事实，确认变更范围与停止条件 | 受影响页面清单 |
| S1 需求 | 把问题、用户与约束写成章程或简报，划定文档集范围 | 读者定义、文档缺口清单 |
| S2 设计 | 为 ADR 与设计文档提供模板与必需章节，规划文档任务 | ADR 骨架、文档任务清单 |
| S3 构建 | 随增量更新页面，维持单一权威归属与当前事实 | 与代码同批的文档 diff |
| S4 验证 | 核对文档与实现一致，运行构建、链接与示例校验 | 构建输出、链接校验结果 |
| S5 发布 | 交付变更日志与发布说明的结构与动作 | 分组条目、升级动作 |
| S6 运维 | 维护运行手册与故障排查页，事故后补复盘 | 运行手册更新、复盘记录 |
| S7 收尾 | 写收尾报告，归档过时页面并留重定向 | 收尾报告、归档状态 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G1 立项 | 读者与问题已写明，文档缺口与负责人已列出 | Hold：读者未定时不写页面 |
| G4 验证 | 文档构建、链接与示例校验输出；每项用户可见行为变化均有对应文档 diff | Recycle：缺文档 diff 视为验证未完成 |
| G5 发布 | 变更日志按版本分组；发布说明含升级动作与迁移指南链接 | Hold：缺升级动作的发布说明不得发布 |
| G7 收尾 | 收尾报告、过时页面归档状态与重定向记录 | Hold：未归档即关闭的按遗留缺陷继续整改 |

证据缺失按缺陷处理；是否阻塞合并由 `testing-quality` 裁定。构建失败、死链与示例不可运行不得以"稍后修复"结案。

## 核心规则

- 为一位读者、一个问题编写；面向所有人的页面服务不了任何人。
- 结果、决定或下一步放在开头数行，背景放其后。
- 每项事实只有一个权威归属，其余位置链接而非复制。
- 文档与行为在同一次变更中更新；过时文档比缺失文档更危险。
- 示例给出完整命令与真实输出，注明版本；编造输出会掩盖不兼容。
- 指南与参考只写当前事实；日期、原因与取舍放 ADR 或变更日志。
- 优先归档过时页面：重定向或留墓碑页，核查入站引用后再删除。
- 先写受支持的路径，再写替代方案；选项菜单让读者替文档做决定。
