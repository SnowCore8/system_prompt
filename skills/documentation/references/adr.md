# 文档：ADR 与设计文档

ADR 记录"为什么这样决定"，设计文档记录"准备怎么做"。前者不可变，后者在实现前演进；两者分开，读者不会把提议当成既定事实。

## 1. ADR 与设计文档
- ADR 的编写时机、内容要素、状态流转与不可改规则归 `architecture-design`；本 skill 只规定两类页面的模板与章节。
- 设计文档含问题、目标与非目标、提案、备选方案、风险、上线方式与未决问题；提案必须可验证。
- 两类页面分开存放并以链接互引，不得把提议写成已决定的事实。

## 2. 设计文档的生命周期

- 实现与设计分叉的处置（回写 ADR 或回退实现）归 `architecture-design`；本 skill 负责同步标记设计文档的当前状态。
- 设计文档在实现完成后标记过期或归档，避免读者误读为当前设计。

## 3. 归属

- 决策原因放 ADR，当前行为放参考页，两者链接；同一原因不写第二份副本。
