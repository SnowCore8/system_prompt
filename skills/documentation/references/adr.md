# 文档：ADR 与设计文档

ADR 记录"为什么这样决定"，设计文档记录"准备怎么做"。前者不可变，后者在实现前演进；两者分开，读者不会把提议当成既定事实。

## 1. ADR 与设计文档
- 每份 ADR 只记录一个决策，编号连续，字段为状态、背景、决定、后果与备选方案。
- 状态只用一套值（如 Proposed、Accepted、Superseded）；已接受的 ADR 决定正文不得改写，推翻须写新 ADR 并链接旧编号。
- 背景写决策所解决的问题，不写团队行程；后果写明谁受何影响，包括负面后果。

## 2. 设计文档的结构

- 设计文档含问题、目标与非目标、提案、备选方案、风险、上线方式与未决问题；提案必须可验证。
- 实现与设计分叉时先更新设计文档或写 ADR 说明偏差，不得静默偏离。
- 设计文档在实现完成后标记过期或归档，避免读者误读为当前设计。

## 3. 归属

- 决策原因放 ADR，当前行为放参考页，两者链接；同一原因不写第二份副本。
