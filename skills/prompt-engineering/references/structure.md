# 目标、类型与结构

## 1. 目标与结构
- 第一段回答模型要完成什么任务、成功的判定标准是什么；出现“等等”“合理”“合适”的继续拆分。
- 判定标准可观察：写“不超过 120 字”“仅输出 JSON”，不写“简洁”“专业”。
- 一个提示词只承担一类职责；承担多类职责的拆成系统提示与任务指令。

## 2. 类型与职责

- 系统提示回答任务与边界；任务指令回答本次做什么；few-shot 提供参照示例；输出契约规定结果形式。
- 工具调用指令回答何时调用何工具；检索指令回答如何使用检索内容；分类审查提示回答如何判定标签；评测提示供评测者评分。
- 完整提示词须选一类，片段可以组合；混装是规则互相污染的主要来源。

## 3. 结构与分层

- 骨架五段：目标、输入、约束、输出、失败处理；示例与解释按需补充。
- 输入写明来源与可信级别；不可信内容用明确分隔符包住并声明数据区指令不执行。
- 需要机读结果时优先平台的结构化输出或 function calling，配一份 JSON Schema；文字写“仅输出 JSON”是兜底。
- 系统提示与共享前缀保持稳定以利用缓存；每次请求变化的动态输入放在末尾。
- 记录 temperature、top_p 与选择依据；确定性解析用 0 或平台最低值，创意生成的取值写入记录并说明依据。
- 按目标模型调整语气与详略：推理模型给目标与约束、少给分步，不写“think step by step”；指令遵循模型给可观察的步骤与顺序。
