# 测试与质量规范生命周期契约

本文件把测试与质量规范接入 S0–S6 与 G0–G6：界定各阶段的输入、活动、输出与门禁，规定证据包与复核方式，给出
交接对象与升级条件，并说明按风险与环境差异的裁剪方式与度量口径。规则细节见 `dimensions.md`，命令、阈值与
豁免模板见 `gates.md`。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S0 受理 | 变更请求与风险级别 | 判断该变更的测试预算、门禁强度与是否需要安全或合规校验 | 测试范围结论 | G0 |
| S1 探索 | 验收标准与结果指标 | 确认每条验收标准都能映射到可判定测试，识别不可测项 | 可测性结论与缺口清单 | G1 |
| S2 计划 | 可测性结论、现有 CI 配置与基线 | 选定层级、定义门禁与阈值、指定负责人、写明豁免策略与 DoR 测试条件 | 测试策略与门禁清单 | G2 |
| S3 构建 | 测试策略与增量 | 随变更提交测试，维护确定性，运行增量校验与 DoD 检查 | 增量测试、失败输出、DoD 结果 | G3 |
| S4 验证 | 完成的可运行增量 | 运行全量套件、静态分析与依赖校验，整理证据与不稳定清单 | 验证证据包 | G4 |
| S5 发布 | 验证证据与发布候选 | 复核门禁未被下调，执行部署后冒烟，确认制品与报告可追溯 | 门禁快照与冒烟结果 | G5 |
| S6 收尾 | 逃逸缺陷与门禁运行数据 | 分析逃逸原因，回写测试、门禁与基线 | 逃逸分析与改进项 | G6 |

S1 的可测性结论只在验收标准无法判定时单独产出；验收标准已可测的，直接进入 S2 的门禁设计。

## 门禁证据

| 门禁 | 证据包 | 复核人 | 失效条件 |
|---|---|---|---|
| G0 | 风险级别、测试范围结论与需附加的安全校验清单 | 任务负责人 | 风险级别缺失，或测试范围与影响面不符 |
| G2 | 层级矩阵、门禁命令/触发器/阈值/负责人、豁免策略、DoR 测试条件 | 项目负责人与审查者 | 阈值或负责人缺失，策略覆盖不到验收标准 |
| G3 | 随变更提交的测试、失败输出、DoD 检查、未关闭风险 | 增量审查者 | 行为变更无对应测试，或测试无法失败 |
| G4 | 全量输出与退出码、覆盖率报告、SARIF、静态校验基线、不稳定测试清单、未运行项 | 独立审查者与产品负责人 | 证据来自旧提交，或删改测试、下调阈值后通过 |
| G5 | 冒烟结果、必需门禁快照、制品与报告的追溯链接、有效豁免 | 发布负责人与运营 | 冒烟未执行，或本版本放宽门禁且无豁免记录 |
| G6 | 逃逸分析、门禁改进项、基线变化与负责人 | 项目负责人 | 同类逃逸无新增测试或门禁，或改进项无负责人 |

证据组织：

- 每条证据写明命令、工具版本、退出码与执行时间，并关联到具体提交；报告上传为制品，保留期覆盖一个发布周期。
- 覆盖率报告必须同时给出产生它的命令与工具版本；只有百分比而无命令的记录不可复现。
- 未运行项、被跳过项与隔离项分别列出，写明原因与负责人；不得用“全绿”掩盖缺失的层级。
- 首次失败结果保留可见；重试仅用于已证实的基础设施错误，重试后的绿色不得覆盖首次失败。
- 豁免记录包含门禁、范围、批准人、理由、到期日与跟踪标识；到期未关闭的豁免按缺陷处理。

## 交接与升级

上游交接：

- 从 `project-lifecycle-governance` 接收 G0 风险级别、G1 验收标准与 G2 计划要求；门禁集合必须覆盖这些验收项。
- 从 `architecture-and-design-conventions`、`api-and-data-conventions` 接收接缝与契约变更，据此确定契约测试与
  集成测试的范围。
- 从 `security-compliance-conventions` 接收严重程度与修复期限；本 skill 只决定扫描在何处运行、阈值与失败报告。

下游交接：

- 门禁命令、触发器与必需状态校验交给 `release-operations-conventions` 与 `vcs-collaboration-conventions`
  实现为流水线与规则集；本 skill 不接管流水线执行。
- 不稳定测试的根因调查交给 `debugging-conventions`；本 skill 负责隔离、负责人与期限，不负责定位根因。
- 逃逸缺陷与门禁运行数据交给 S6 复盘，并回写测试策略、层级矩阵与基线。

升级条件：

- 阈值或门禁范围需要变更：作为受审变更提交，写明理由、负责人与关联 issue；在导致失败的同一变更中不得下调。
- 验收标准无法由任何层级判定：Recycle 到 S1/S2，与产品负责人重写验收标准，不得以“人工验证过”替代。
- 平台能力不足（如私有仓库缺少必需扫描）：记录补偿控制与负责人，按 G2 决策；不得据此整体豁免门禁。
- 出现删除、跳过或放松测试的压力：按 HO-5 拒绝，并报告替代方案（修复、豁免或缩小发布范围）。
- 疑似机密进入测试数据或日志：按 SP-6 停止、保留证据并报告，不得清理后再排查。

## 裁剪与度量

| 级别 | 测试与门禁的裁剪 | 不可裁剪项 |
|---|---|---|
| R0 | 仅运行与改动相关的用例并自检，记录可合并 | 真实命令与退出码，失败路径验证 |
| R1 | 完整门禁与独立审查，精简工件 | 必需状态校验、变更覆盖率、静态校验基线 |
| R2 | 全量套件、安全与性能校验、发布前冒烟与独立结论 | G4 与 G5 不得合并，豁免记录与未运行项披露 |

环境差异：

- 单人仓库允许自审，但门禁不得因单人维护而整体豁免；单条豁免的批准安排与补偿控制见 `gates.md` 的豁免模板，
  由维护者具名记录，不由智能体自批。
- 无部署仓库跳过部署后冒烟与性能层级；CLI 或库仍应在其文档化命令上执行命令冒烟，其余层级照常运行。
- 遗留项目采用分阶段变更：以经审查的计数为现有违规建立基线，新规则先作用于每个变更文件，基线随修复缩小并
  最终删除；一次性将全部门禁设为阻塞会在短期内被全部关闭。

度量口径：

| 指标 | 定义 | 用途 |
|---|---|---|
| 变更覆盖率 | 变更行中被执行的比例 | 判断新增逻辑是否被验证 |
| 逃逸缺陷 | 发布后才发现且本应被门禁捕获的缺陷数 | 评估层级与门禁的覆盖 |
| 不稳定比率 | 同提交重复运行结果不一致的测试占比 | 评估套件可信度 |
| 门禁时长 | 必需校验在 PR 上的总耗时 | 评估反馈速度与分片需求 |
| 豁免到期关闭率 | 到期前关闭或续期有据的豁免占比 | 评估例外治理 |
| 首次失败保留率 | 重试后仍保留首次失败记录的运行占比 | 评估证据诚实度 |

指标按迭代或按月复核；异常先查测试数据、环境漂移与工具版本，再判断是否存在真实质量下降。缩小统计范围、
重定义缺陷或隐藏失败均属失真。指标用于改进，不用于个人排名；R0 任务只在出现返工时记录指标。
