# 智能体团队的工作树协作

多个智能体同时改一个工作副本时，最先失效的通常不是代码，而是边界：两个写者覆盖同一文件、测试共用数据库、
删除别人的未提交改动、集成时才发现基线已经漂移。Git worktree 提供独立工作目录与同一对象库，但不自动
提供所有权、依赖顺序、环境隔离或清理纪律。本 skill 把智能体团队分为 **领导者智能体** 与 **协作者智能体**；
领导者统一管理工作树的创建、分配、集成、恢复与清理，协作者只在分配给自己的工作树内写入。分支模型与审查
流程仍由 `vcs-collaboration-conventions` 裁定。

## 适用范围与优先级

效力依下列层级判断：高层覆盖低层，低层仅在高层未规定时补充。

1. 强制性的平台、法律、宿主与全局用户约束。文件系统权限、托管平台限制与宿主沙箱规则不可选。
2. 本 skill 的规则。工作树分配、单写者、环境隔离、交付、集成、恢复与清理，以本文件与 `references/` 为准。
3. 既有项目事实与约定。智能体应当先阅读任务板、分支模型、工作树根目录、测试命令、服务端口与清理策略；
   这些是事实输入，按本 skill 的规则处理。
4. 个人偏好，不得覆盖上述三层。

分工边界如下：

- 分支模型、PR/MR、审查、保护分支与合并方式由 `vcs-collaboration-conventions` 裁定；本 skill 只决定
  工作树的分配、隔离、交付与生命周期，不另立分支策略。
- 项目目录、包/工作区边界与依赖图由 `project-structure-conventions` 裁定；工作树只是该结构的临时副本，
  不得借隔离之名改变模块边界。
- 测试层级、门禁阈值与本地/CI 对齐由 `testing-and-quality-conventions` 裁定；本 skill 只规定每个工作树
  必须隔离哪些运行资源、以及在什么基线上验证集成结果。
- 发布、部署与回滚由 `release-operations-conventions` 裁定；工作树位于集成之前，不得从工作树直接发布。
- 机密、个人信息、许可证与依赖漏洞由 `security-compliance-conventions` 裁定；本 skill 只规定不得把
  机密复制进工作树、以及不可信智能体的最小权限边界。
- 分支名、工作树名与提交消息的格式由 `naming-conventions` 裁定；本 skill 只要求名称唯一、可归属、可检索。

同一强制规则冲突的，智能体应当报告用户裁决，不得自行选定；非强制项目约定冲突的，应当说明冲突与所选约定，
并记录于任务板或集成记录。

## 全局用户约束映射

本 skill 不复制全局约束，以下条款按其原文适用：

- 工作树的创建、读取、编辑、测试与任务临时文件清理属于 AU-1 任务级预授权；新增依赖、非保护分支推送
  等按计划级处理；推送共享/保护分支、强制推送、变更远端历史、删除远端分支、批量删除用户/未跟踪文件、
  清理未跟踪内容、变更 CI 或共享配置，必须逐次取得明确同意。
- 删除、覆盖或 `worktree remove --force` 涉及未提交改动/未跟踪文件时，适用 IR-3 与 IR-1：先说明将丢失
  的内容并取得明确同意；情况不明时，不得使用 `-f`、`--force` 或 `-y`。
- 任务产生的临时文件按 IR-6 清理；不得清理他人工作树、主工作树或用户文件。
- 不重写已推送历史，不使用 `--hard` 重做提交；仅可 amend 最近未推送的提交（IR-7/IR-8）。
- 不复制或提交 `.env`、私钥、令牌或含凭据连接串（SP-3/SP-5）。
- 变更范围、测试证据与完成声明遵循 AU-4、CH-2、HO-2 与 HO-6；团队委派仍受 ME-2、ME-3、ME-4 约束。

## 团队角色

团队只分为两类角色，不另设集成者、清理者或独立的工作树管理员。

- **领导者智能体（Leader）**：每个团队一个；负责规划、任务分配、全部工作树的创建与移除、基线更新、
  集成、冲突处理、最终验证、权限与清理。
- **协作者智能体**：只在自己被分配的工作树中写入；负责提交、测试与交付报告。需要新工作树、基线更新、
  跨范围修改、移交或清理时，向领导者提出请求。下文“写者”均指承担写入任务的协作者智能体。
- 人类协作者按同一分工参与；协作者不得自行晋升为领导者，也不得绕过领导者管理 Git worktree。

## 核心规则

- **一个可写工作树只有一个写者。** 领导者智能体、协作者智能体、人类协作者或 CI 进程不得同时修改同一工作树。只读观察者
  可以共享；需要并行写入的，必须由领导者智能体拆到不同工作树，并各自登记所有权。
- **领导者智能体统一管理全部工作树。** 工作树的创建、登记、分配、基线更新、移交、集成、清理与强制移除只能
  由领导者智能体执行；协作者智能体只能修改分配给自己的工作树并在其中提交。
- **按独立交付物拆分，而不是按智能体数量拆分。** 任务之间没有共享可变文件、没有先后依赖的，才建立独立
  工作树；共享文件、契约、迁移或顺序依赖的，放在同一工作树串行完成。一个协作者智能体可以负责多个顺序任务，但
  不得同时写两个工作树。
- **领导者智能体先登记再创建。** 任务板是工作树所有权的权威来源；领导者智能体至少记录任务 ID、写者、分支、基线 SHA、
  工作树路径、写入范围、依赖任务与状态。没有领导者智能体登记的工作树视为未授权，不得开始写入。
- **领导者智能体从已提交的集成基线创建。** 工作树必须从登记过的提交创建，不得从脏工作副本复制；基线变化时由
 领导者智能体更新并记录新 SHA。写者不得自行改变基线，也不得绕过领导者智能体重新创建工作树。
- **领导者智能体拥有并管理集成工作树。** 写者只提交自己的分支；领导者智能体负责合入、变基、冲突解决、集成验证与合并
  队列。写者不得直接把工作树推到受保护分支或共享分支，也不得自行删除、移动或重建集成工作树。
- **工作树路径必须独立、可回收、无嵌套。** 路径放在仓库外或仓库内已忽略的专用根下；不得把工作树建在
  另一个工作树内，不得以软链接代替工作树，不得复用已合并或已放弃的路径。
- **环境按工作树隔离。** 依赖、构建目录、缓存、临时目录、数据库/schema、服务实例与端口必须按工作树分配；
  无法隔离的资源必须加锁串行，不得让两个写者共享可变的构建输出或数据库。
- **机密不复制，权限最小化。** 工作树通过环境变量或宿主密钥注入读取机密，不得把 `.env`、私钥、令牌、
  生产数据库转储复制进工作树；不可信智能体的工作树不得获得超出任务的写权限或网络权限。
- **脏工作树优先保全。** 任何删除、重置、`clean`、`worktree remove --force` 之前，必须先盘点未提交改动、
  未跟踪文件与正在运行的进程；能够归档就先归档，不得以“清理”为名丢失他人的工作。
- **先集成分支，再验证结果。** 合并顺序服从依赖 DAG；集成后必须在集成结果上运行与风险相称的测试、lint、
  类型检查与冒烟测试，不得只依赖写者工作树内的通过结果。
- **清理由领导者智能体执行，且不是完成的同义词。** 只有工作树干净、提交已合入或已归档、无进程占用、且所有权
  明确时，领导者智能体才能移除；移除后由领导者智能体清理分支、锁与临时端口，并记录结果。

## 工作树决策

| 场景 | 选择 | 原因 |
|---|---|---|
| 两个任务改不同模块，且无共享契约 | 每个任务一个工作树，并行 | 隔离写入，减少相互覆盖 |
| 两个任务改同一文件或同一 schema | 同一工作树串行，或拆成有依赖的任务 | 并行只会制造冲突与半成品 |
| 只读调查、代码搜索、方案比较 | 不建工作树，使用临时副本或只读检出 | 避免为无写入任务占用路径与依赖 |
| 一个协作者智能体承接多个顺序任务 | 复用同一工作树，按任务切换基线 | 减少环境重建；仍保持单写者 |
| 多个独立交付物需要统一验收 |领导者智能体分配独立工作树 + 专用集成工作树 | 写者不污染集成基线 |
| 需要修改共享配置文件 | 指定单一工作树与单一所有者，其他写者走依赖 | 共享文件没有并行安全边界 |
| 工作树落后于集成基线 | 由领导者智能体更新或重建 | 避免在未知基线上交付 |
| 工作树已合并、已放弃或协作者智能体失联 |领导者智能体先隔离、保全、审查，再回收 | 不能假设不再需要未提交内容 |
| 协作者智能体想自行创建工作树 | 拒绝，由领导者智能体登记并分配 | 防止路径、基线与所有权失控 |

## 生命周期

1. **规划。** 领导者智能体列出任务、依赖 DAG、写入范围与可并行边界；识别共享文件、迁移、生成物与外部资源。
2. **分配。** 领导者智能体在任务板登记写者、基线、分支、路径与依赖，并在存在集成工作时指定集成工作树；确认没有第二个写者。
3. **创建。** 领导者智能体从登记的提交创建工作树与分支；配置独立环境、端口、临时目录与依赖；运行基线冒烟。
4. **执行。** 写者只修改其写入范围；小步提交；不得清理或重置不属于自己的文件；需要跨范围修改时先向领导者智能体申请。
5. **交付。** 写者提交说明基线与验证证据；把提交 SHA、diff 范围、测试命令与已知风险交给领导者智能体。
6. **集成。** 领导者智能体按 DAG 合入或变基；领导者智能体处理或指定冲突处理；在集成结果上重新验证；更新任务状态。
7. **清理。** 领导者智能体确认干净、已合并或已归档、无进程占用后移除工作树与分支；回收端口、锁与临时资源。
8. **审计。** 领导者智能体抽查工作树、分支、任务板与集成记录是否一致；保留必要的决策与失败证据。

## 反模式

| 反模式 | 为什么失败 | 修复 |
|---|---|---|
| 两个智能体共用一个可写工作树 | 互相覆盖、无法归属、冲突不可复现 | 拆成独立工作树，或串行并登记单写者 |
| 一个协作者智能体同时开多个工作树写代码 | 注意力与验证分裂，提交归属混乱 | 同一时间只保留一个活跃写入任务 |
| 从脏工作副本创建工作树 | 基线不可复现，审查无法判断真实差异 | 先提交或归档，再从登记的 SHA 创建 |
| 共用构建目录或数据库 | 测试互相污染，失败无法归因 | 每树独立目录、schema、端口与实例 |
| 写者直接推共享分支 | 绕过集成与保护，冲突留给他人 | 写者只交付分支，领导者智能体合入 |
| 用 `worktree remove --force` 清理 | 不可逆丢失未提交改动与未跟踪文件 | 先盘点、归档、确认，再普通移除 |
| 工作树嵌套在另一个工作树中 | Git 路径、忽略规则与清理范围混乱 | 使用仓库外的平级根目录 |
| 复制 `.env` 或私钥到工作树 | 机密扩散到更多磁盘与日志 | 用环境注入；不落盘复制 |
| 只看写者工作树的测试 | 合并后的真实组合从未被验证 | 在集成结果上重跑门禁 |
| 协作者智能体自行创建或删除工作树 | 绕过领导者智能体，路径、基线与所有权失控 | 仅领导者智能体执行；协作者提出请求 |
| 已失联写者的工作树直接删除 | 可能含唯一未提交成果 | 先隔离、通知、保留，再走回收决定 |

## 审查清单

- [ ] 每个工作树有唯一写者、任务 ID、基线与写入范围，且由领导者智能体登记。
- [ ] 工作树的创建、分配、基线更新与移除均由领导者智能体执行。
- [ ] 并行任务之间没有共享可变文件或未解决的依赖。
- [ ] 工作树从已提交基线创建，路径平级、唯一、未嵌套。
- [ ] 依赖、构建、缓存、端口、数据库与临时目录已按树隔离。
- [ ] 机密未复制进工作树；不可信智能体权限最小。
- [ ] 写者只提交自己的范围，未直接推共享分支。
- [ ] 集成顺序符合依赖 DAG，冲突有明确处理者。
- [ ] 集成结果上重新跑过测试、lint、类型检查与必要的冒烟。
- [ ] 脏工作树、未跟踪文件与进程在清理前已盘点。
- [ ] 移除前确认干净、已合并或已归档，未使用未经同意的强制删除。
- [ ] 分支、锁、端口与临时资源已回收，任务板状态已更新。
- [ ] Windows 路径长度、大小写、CRLF 与文件锁已验证（若支持 Windows）。
- [ ] Linux/macOS 的权限、软链接与大小写敏感行为已验证（若支持）。
- [ ] 失败、回退与未能清理的工作树已记录，保留可恢复证据。
