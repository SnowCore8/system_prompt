# 工作树协作操作手册

本文件提供可执行的分配、创建、集成、恢复与清理步骤。所有工作树管理命令仅由领导者智能体执行；写者只修改
分配给自己的工作树并提交。命令中的变量必须先替换并确认；删除、`--force`、重置或共享分支推送依全局用户约束
取得授权。维度细则见 `dimensions.md`。

## 1. 分配工作表

在任务板或集成记录中为每个工作树填写：

| 字段 | 必需内容 | 示例 |
|---|---|---|
| `task_id` | 任务板唯一 ID | `api-retry-17` |
| `owner` | 协作者智能体（唯一写者） | `agent-3` / `alice` |
| `lead` | 领导者智能体 | `lead` |
| `base_sha` | 创建时的提交 | `a927645` |
| `branch` | 工作分支 | `feat/api-retry` |
| `worktree` | 绝对或仓库相对路径 | `../wt/api-retry` |
| `write_scope` | 目录/文件/契约 | `src/http/**`, `openapi.yaml` |
| `depends_on` | 前置任务 ID | `api-contract-12` |
| `status` | 创建/写入/交付/集成/清理 | `writing` |

领导者智能体分配前检查：同一路径没有第二个写者；共享文件已被识别；依赖任务的状态允许开始；写者知道基线与验证命令。

## 2. 创建工作树

### Git 工作树

只有领导者智能体执行：

```bash
base_sha=$(git rev-parse HEAD)
git worktree list --porcelain
git worktree add -b "$branch" "$worktree_path" "$base_sha"
```

创建后立即：

1. 领导者智能体记录 `base_sha`、实际路径、分支、写者与所有者。
2. 检查 `.git` 文件、忽略规则、子模块、LFS 与 hooks 是否可用。
3. 安装该树依赖，配置独立构建目录、端口、数据库/schema 与临时目录。
4. 运行最小构建与冒烟；失败先修环境，不进入功能开发。

### 路径与平台

- 工作树根放在仓库外的平级目录，或仓库内被忽略的专用根；不要嵌套在另一个工作树里。
- Windows 使用短根路径，避免保留字符与深层中文目录；验证大小写与路径长度。
- 不用软链接、junction 或复制目录替代工作树；Git 元数据必须真实。
- 共享只读缓存可以复用；共享可写构建目录、数据库与设备必须禁止或显式加锁。

## 3. 集成队列

### 入队前

- 写者提交完成，工作树状态干净，提交 SHA 已记录。
- 交付说明包含基线、写入范围、测试命令/结果、已知失败与风险，并发送给领导者智能体。
- 依赖任务已合入，或本任务已声明可独立验证。

### 集成步骤

1. 领导者智能体在集成工作树更新到当前集成基线，确认工作树干净。
2. 领导者智能体按依赖 DAG 取出一个交付，合入或变基；记录使用的提交。
3. 解决冲突时先理解双方语义；不明确时退回写者，不猜。
4. 在集成结果上运行受影响测试、lint、类型检查与冒烟。
5. 领导者智能体通过后记录集成 SHA 与证据，更新任务板，再处理下一个交付。
6. 队列空后领导者智能体检查工作树、分支与任务板是否一致。

### 集成检查

- [ ] 合入顺序符合依赖关系。
- [ ] 每个交付都能追溯到写者、基线与提交。
- [ ] 验证在集成结果上执行，而不是只在写者工作树。
- [ ] 冲突解决后重新运行受影响门禁。
- [ ] 创建工作树、基线更新、合入与移除均由领导者智能体执行。
- [ ] 共享分支没有被写者直接推送。
- [ ] 集成失败已退回或标记阻塞，未静默丢弃。

## 4. 脏与残留工作树恢复

### 只读盘点

```bash
git -C "$worktree_path" status --short
git -C "$worktree_path" diff
git -C "$worktree_path" diff --cached
git -C "$worktree_path" ls-files --others --exclude-standard
git -C "$worktree_path" log --oneline "$base_sha"..HEAD
```

同时确认是否有进程占用该目录、端口、数据库或锁文件。只读盘点不需要授权；删除、重置或强制移除需要。

### 保全

1. 能提交的，提交到临时分支或原分支。
2. 不能提交的，生成 patch 或归档目录副本，记录位置与校验和。
3. 未跟踪文件逐项确认；不得把机密复制进归档。
4. 协作者智能体失联时领导者智能体通知其所有者，保留路径与分支，由领导者智能体决定是否回收。

### 清理

```bash
git -C "$worktree_path" status --short
git worktree remove "$worktree_path"
git worktree prune
git branch -d "$branch"
```

只有领导者智能体确认干净、已合入或已归档、无进程占用后才执行。`--force` 不是默认步骤；使用前必须有明确同意与可恢复副本。

## 5. Windows/Linux 检查

### Windows

- [ ] 工作树根路径短，无保留字符，未超过构建工具路径限制。
- [ ] 大小写不敏感不会造成两个工作树或两个文件同名冲突。
- [ ] CRLF/自动换行与可执行位差异已由 `.gitattributes`/CI 覆盖。
- [ ] 编辑器、索引器、杀毒软件或测试进程未锁定工作树。
- [ ] 未用 junction/软链接替代工作树；Git 元数据真实。

### Linux/macOS

- [ ] 权限位、umask 与属主符合预期；其他用户不能写工作树。
- [ ] 软链接未逃逸出工作树；构建/测试不跟随到主工作树。
- [ ] 大小写敏感与路径分隔符差异已考虑。
- [ ] 容器/命名空间中的路径映射与 Git 看到的一致。
- [ ] 临时目录、端口与进程清理只作用于本树。

## 6. 审计与收尾

- 领导者智能体抽查 `git worktree list --porcelain`：路径存在、分支对应、无孤立/嵌套项。
- 领导者智能体抽查任务板：每个工作树有写者、领导者智能体授权、基线、依赖与状态；已完成任务已清理或归档。
- 抽查分支：已合并分支已删除；未合并分支仍有对应工作树或明确保留原因。
- 抽查资源：端口、数据库、锁、临时目录与后台进程已释放。
- 抽查证据：失败、回退、失联与强制清理都有记录，未覆盖他人工作。
- 发现清理失败或残留时，记录路径、原因、责任人与下次处理时间，不静默忽略。
