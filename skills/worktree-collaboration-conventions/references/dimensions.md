# 工作树协作维度

本文件展开 `SKILL.md` 的六个维度。每个维度按“默认值、检查点、失效模式”组织；阈值仅在项目事实没有更严格
规定时生效。

## 1. 分配与所有权

**默认值**

- 可写工作树按**独立交付物**分配，不按代理数量分配。一个写者同一时间只持有一个活跃写入工作树。
- 任务板记录 `task_id`、`owner`、`base_sha`、`branch`、`worktree`、`write_scope`、`depends_on`、
  `integrator` 与 `status`；字段缺失的工作树不得开始写入。
- 只读调查、审查与日志收集可以共享检出；不得把“只读”权限借给需要写入的代理。
- 所有权转移必须先更新任务板，再由新写者确认基线、脏状态与未完成提交；不得口头转移。

### 检查点

| 检查 | 合格条件 | 不合格示例 |
|---|---|---|
| 写者唯一 | 同一路径同一时刻只有一个写者 | 两个子代理同时改同一分支 |
| 范围明确 | 写入范围列出目录/文件/契约 | “负责后端”没有文件边界 |
| 依赖有序 | `depends_on` 指向已完成或可并行的任务 | 契约变更与调用方同时开工 |
| 基线可追溯 | 记录完整或至少 12 位 SHA | “从当前主分支”无具体提交 |

**失效模式**

- 任务板只记录代理名，不记录路径与基线；恢复时无法判断哪个工作树属于哪个任务。
- 一个代理为了“效率”同时开两个工作树，提交、测试与上下文互相污染。
- 写者失联后，其他代理直接接管目录；新写者不知道已有未提交内容，覆盖唯一成果。
- 只读任务被要求“顺手改一下”，实际变成第二写者；应新建任务与工作树，或由原写者执行。

## 2. 创建与布局

**默认值**

- 使用 `git worktree add -b <branch> <path> <base>` 从已提交 SHA 创建；先确认基线与分支尚不存在。
- 工作树根放在仓库外的平级目录，或仓库内已忽略的专用根；不得放在另一个工作树内部。
- 路径按任务与写者命名，保证唯一；分支名与路径名遵循 `naming-conventions`。
- 不用软链接、junction 或复制目录代替工作树；Git 元数据与忽略规则必须真实生效。
- 需要子模块、LFS、稀疏检出或 Git hooks 的，在工作树创建后显式初始化并验证，不假设主工作树的配置自动可用。
- Windows 路径遵守长度与大小写限制；工作树根尽量短，避免中文路径与深层嵌套。

### 创建核对

1. 先 `git status` 与 `git rev-parse HEAD` 确认源基线。
2. 用 `git worktree list --porcelain` 确认路径与分支不冲突。
3. 创建工作树后，检查 `.git` 文件指向、忽略规则、子模块与 LFS 状态。
4. 运行最小构建/测试，确认环境能在该路径工作。
5. 把实际路径与 HEAD 写回任务板；不要只记录创建命令。

**失效模式**

- 从脏工作副本复制文件，导致基线不可复现；后续 diff 混入未提交内容。
- 工作树嵌套导致清理范围重叠；删除外层时破坏内层。
- 在 Windows 上路径过长或大小写冲突，构建工具写入失败；应在创建前验证路径。
- 未初始化子模块/LFS，测试在缺失文件上通过或失败原因不可归因。
- 复用已合并工作树的路径与分支，残留状态被误认为新基线。

## 3. 环境与测试隔离

**默认值**

- 每个工作树独立安装依赖、构建输出、缓存与临时目录；共享只读包缓存时，必须保证不会被写者修改。
- 数据库使用独立 schema/实例/文件；迁移在每个工作树自己的库上运行；不得让两个写者共享可变数据库。
- 服务实例、端口、Unix socket、命名管道与锁文件按工作树分配；并行测试使用端口池或动态端口。
- 机密通过宿主环境或密钥注入，不复制 `.env`、私钥、令牌或生产转储；日志不得打印机密。
- 需要共享外部资源（设备、模拟器、浏览器、消息队列）的，显式加锁并串行；锁的持有者与超时写入任务板。
- 测试失败先归因于工作树环境还是代码；不得用清理全局缓存掩盖隔离缺陷。

### 资源矩阵

| 资源 | 隔离方式 | 共享前提 |
|---|---|---|
| 依赖目录 | 每树独立安装或只读缓存 | 缓存不可写、版本锁定 |
| 构建输出 | 每树独立目录 | 不共享可变输出 |
| 数据库 | 独立文件/schema/实例 | 只读快照，且写者不写 |
| 端口 | 动态分配或端口池 | 显式锁与释放 |
| 临时目录 | 每树独立子目录 | 不发生跨树清理 |
| 浏览器/设备 | 串行租用 | 有超时、心跳与回收 |

**失效模式**

- 两个工作树共用构建目录，A 的产物被 B 覆盖，测试结果不可复现。
- 共用数据库导致迁移互锁；失败的工作树留下半迁移状态。
- 所有代理用同一端口，启动失败被误判为代码失败。
- 为“方便”复制生产 `.env`，机密扩散到临时目录、日志与提交。
- 共享缓存可写，缓存污染跨任务传播；应改为只读或按树隔离。

## 4. 交付与集成

**默认值**

- 写者交付的是提交 SHA 与证据，不是“当前目录能跑”；交付记录包含基线、diff 范围、测试命令、已知失败与风险。
- 集成顺序服从依赖 DAG；先集成被依赖的变更，再集成消费者；无法确定顺序的，先拆小或加适配层。
- 合并/变基/挑选策略由 `vcs-collaboration-conventions` 裁定；本维度只要求集成在专用工作树或合并队列中完成。
- 集成者负责冲突解决与最终验证；冲突解决后重新运行受影响门禁，不得沿用写者工作树的旧结果。
- 写者不得直接把共享分支推到受保护分支，也不得在集成者不知情时改变基线。
- 集成结果通过后，更新任务板、记录集成 SHA 与验证证据，再进入清理。

### 集成队列

1. 收集交付记录，确认写者、基线、范围与依赖。
2. 按 DAG 排序；同层任务可并行验证，但合并到集成基线时串行。
3. 在集成工作树更新到当前基线，合入/变基一个变更。
4. 运行受影响测试与冒烟；失败退回写者或调整顺序。
5. 提交集成结果，记录 SHA；重复直到队列清空。

**失效模式**

- 写者只贴“测试通过”，没有命令与基线；集成者无法复现。
- 按提交时间而不是依赖顺序合并，消费者先于契约合入。
- 冲突由最后提交者随意解决，未理解双方语义；应在集成结果上重跑测试。
- 写者绕过集成直接推共享分支，保护规则与审查失效。
- 集成后不清理旧工作树，后续任务误用过期基线。

## 5. 恢复与清理

**默认值**

- 清理前先盘点：`git status`、未跟踪文件、stash、进行中的进程、未推送提交与分支合并状态。
- 有未提交内容时，优先提交到临时分支、生成 patch 或归档到任务记录；不得直接 `reset --hard`、`clean -fd` 或强制移除。
- 写者失联时先隔离工作树并通知；保留路径、分支与证据，等待有权限者决定回收。
- 工作树干净且提交已合入/已归档后，使用普通 `git worktree remove`；不使用 `--force`，除非用户明确同意且已保全。
- 移除后执行 `git worktree prune`，删除已合并分支、释放端口/锁，并更新任务板。
- 清理失败或存在残留时记录原因、路径与下次处理人，不得静默忽略。

### 脏状态处置表

| 状态 | 处置 | 禁止 |
|---|---|---|
| 已提交且已合入 | 普通移除 | 直接删除分支前的验证 |
| 已提交未合入 | 保留分支并通知集成者 | 强制移除 |
| 未提交改动 | 提交/补丁/归档 | reset、clean、覆盖 |
| 写者失联 | 隔离、保留、上报 | 未审查即回收 |
| 仅有构建产物 | 确认忽略规则后清理 | 删除未跟踪源码 |

**失效模式**

- 用 `--force` 清理“看起来没用”的工作树，丢失唯一未提交成果。
- 只删目录不 `prune`，Git 元数据残留；后续创建同名路径失败。
- 删除分支前未确认已合入，丢失提交引用。
- 清理时误删共享缓存或端口锁，影响其他工作树。
- 写者失联后直接重新分配目录，新写者覆盖旧内容。

## 6. 平台与安全

### Windows

- 路径长度、保留字符、大小写不敏感与反斜杠转义必须在创建前验证；工作树根尽量短。
- 文件锁与杀毒/索引进程可能阻止删除；移除前关闭编辑器、终端与测试进程。
- CRLF/自动换行与可执行位行为不同；以仓库 `.gitattributes` 与 CI 为准，不依赖本地默认。
- 避免 junction/软链接；Git 对工作树路径与 `.git` 文件的处理必须按原生方式验证。

### Linux 与 macOS

- 权限位、umask、软链接与大小写敏感差异必须在工作树内验证；不得假设主工作树的属主与权限自动一致。
- 容器/命名空间中的路径映射要确认 Git 看到的是同一路径；`/tmp` 清理不得跨工作树。
- 并行进程的文件锁、PID、端口与临时目录必须按工作树隔离；信号与超时清理要覆盖子进程。

### 安全边界

- 不可信代理只获得任务需要的写路径；不得读取主工作树的机密、生产凭据或共享用户目录。
- 工作树路径不得位于敏感目录、系统目录或可被其他用户预测/写入的位置。
- 日志、补丁与任务板不记录令牌、私钥、个人信息或完整生产数据。
- 外包/外部代理的工作树在回收前执行 diff、产物与残留检查；不要把其分支直接视为可信。

**失效模式**

- Windows 路径过长或大小写冲突，构建写到错误位置。
- Linux 下软链接逃逸工作树，写者修改了主工作树文件。
- 共享用户缓存中的凭据被不可信代理读取。
- 日志记录完整环境变量，泄露令牌。
- 回收外部代理工作树前未审查，带入未经批准的内容。
