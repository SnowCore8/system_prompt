# 版本控制与并行协作

协作失效比算法缺陷更容易造成代码丢失：请求不断膨胀使任何审查者都无法一次审完，历史里留下无人能解释的合并，
某一目录在作者离职后失去归属，两个智能体同时写一个工作副本互相覆盖。这些失效在规则阶段都容易预防。本 skill
规定从分支模型到合并路径的决策流程，把分支、审查、保护、所有权与工作树并行统一为一条可复核的协作链，并把
合并与审查证据接入各阶段门禁。

## 适用范围与优先级

效力自上而下：平台与组织的强制策略、宿主规则与全局章程优先；本 skill 的规则次之；既有分支模型、贡献者指南
与 CODEOWNERS 属于事实输入，依本 skill 的规则处理，项目约定仅在本 skill 未规定处补充；个人偏好不得覆盖。

管辖边界：

- 分支、提交与标签的命名格式归 `naming`；本 skill 管围绕这些名称的流程、合并方式与保护。
- 发布时机、版本号与 CI/CD 归 `release-operations`；本 skill 管变更到达主分支的路径与发布标签的不可变性。
- 门禁本身与阈值归 `testing-quality`；本 skill 管受保护分支上必须执行哪些校验、何时可以合并。
- 访问控制策略细节与凭据归 `security-compliance`；本 skill 管分支保护与所有权机制及其绕过记录。
- 目录与包边界归 `project-structure`；工作树只是该结构的临时副本，不借隔离之名改变模块边界。
- 授权分级依 AUT-1：非保护分支的普通推送属计划级确认；推送保护或共享分支、删除远端分支、重写已发布历史均须逐次明确同意。公开历史只可追加，改写按 IRR-7 处理。
- 仅存在于审查者记忆中的规则不构成规则；分支模型、审查级别与所有权应写入贡献者指南并与平台设置一致。

## 生命周期定位

上游输入：S1 的团队规模与发布路径结论、S2 的范围、审查者与合并方式；本 skill 在 S3 执行分支、PR、审查、合并
与工作树集成，在 S4 提供独立审查与批准证据，在 S5 核对发布分支与发布标签的保护，在 S6 维护分支卫生，在 S7
清理遗留工作树并复盘协作事故。缺少审查、必需校验或所有权证据时停在对应门禁；分支模型与发布路径不符时回到
S2 重新选择；需要重写受保护分支、移动发布标签或绕过保护时升级用户裁决。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定任务涉及的分支、PR、保护或工作树对象，记录风险级别 | 受理结论与影响面初判 |
| S1 需求 | 确认团队规模、发布路径与并行任务边界 | 分支模型取舍、并行任务清单 |
| S2 设计 | 选定分支模型、合并方式、审查级别、保护集合与所有权映射，登记工作树分配 | 分支策略、规则集配置、CODEOWNERS 草案、任务板 |
| S3 构建 | 控制分支体量与寿命，准备 PR，分派审查，工作树从基线创建并按依赖集成 | PR 记录、审查结论、合并提交、集成记录 |
| S4 验证 | 保证批准有效、必需校验在合并结果上通过、阻塞评论已解决 | 批准记录、校验输出、集成验证结果 |
| S5 发布 | 保护发布分支与发布标签，热修复经审查并向前移植 | 标签规则、热修复 PR、合并证据 |
| S6 运维 | 维护分支卫生与保护漂移，处置协作事故 | 绕过记录、漂移修复记录 |
| S7 收尾 | 清理已合并分支与遗留工作树，复盘协作失效 | 清理记录、复盘结论 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 分支模型与每类合并方式、审查级别表、保护清单、所有权映射、工作树任务板与并行边界 | Recycle 到 S2，补齐模型与分配 |
| G3 构建 | 体量合规的 PR 与自审、必需校验在合并结果上通过、工作树基线 SHA 与按依赖的集成记录 | 退回修改或 Recycle 到 S3 |
| G4 验证 | 归属团队批准、阻塞评论已解决、批准未因推送过期、集成结果上的验证输出 | Hold，重新审查增量 |
| G5 发布 | 发布分支保护、标签不可变规则、热修复已向前移植 | 停止打标签与发布 |

模型或保护与发布路径冲突时 Recycle 到 S2；证据缺失时 Hold；保护无法启用且无补偿检查时 No-Go。绕过保护必须
记录操作者、原因、被绕过的规则与合并后审查；无记录的绕过按事故处理。

## 核心规则

- 每个分支类别只使用一个模型与一种合并方式；混用会使 blame、bisect 与 revert 不可靠。
- 主分支始终保持可发布：每个提交都能构建、通过必需门禁并可部署。
- 分支生命短、体量小：三个工作日内集成，可审查 diff 约 400 行以内；超出的拆分或置于开关之后。
- 审查深度取决于风险：认证、支付、权限、数据迁移与公共接口走高风险路径并配置第二名审查者。
- 门禁在合并结果上运行，不在作者副本上运行；合并队列或预合并任务针对合并基线验证。
- 每条审查评论标注阻塞、非阻塞、Nit 或疑问，作者以回复或修复解决每个阻塞项。
- 默认保护、绕过即事故：受保护分支要求审查与必需校验，禁止强制推送与删除。
- CODEOWNERS 为每条可合并路径指定真实所有者，回退所有者是平台或维护者团队。
- 智能体团队只有领导者与协作者两类角色：领导者统一管理全部工作树的创建、分配、集成、恢复与清理，协作者只在自己的工作树内写入。
- 一个可写工作树只有一个写者；工作树从已提交基线创建，环境按树隔离；删除或强制移除前先盘点未提交改动。
- 已合并的主题分支删除，已发布的发布标签不可移动或重建。
