# PR 与代码审查

## 1. PR 与审查
- 一个请求承载一个逻辑变更：重命名、格式化等机械性改动与行为变更分开提交，使每部分都能独立审查与回退。
- 标题说明结果，描述说明问题、做法、风险与验证证据，并链接关联条目与推迟的后续工作。
- 校验未通过、自审未完成时保持草稿状态；草稿不进入合并审查。
- 必需校验全部在合并结果上通过、自审完成并填写模板后，才标记为就绪。
- 生成文件与第三方引入文件的审查规则依 `code-review`（审查生成器输入与重新生成命令）；PR 记录重新生成的证据。

## 2. 代码审查

- 审查深度与风险分级、评论规范、作者与审查者职责由 `code-review` 管辖；本 skill 只规定审查接入 PR 与合并路径的机制。
- 审查在 PR 审阅线程上记录并绑定提交；批准方与必需校验按分支保护规则接入合并条件。
- 单人仓库或无第二人的，必需批准设为 0，以自审记录与必需 CI 替代，并把该缺口记录于治理文件。
