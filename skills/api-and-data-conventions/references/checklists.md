# 接口与数据清单

在审查、发布与清理期间，本文件应当与 `SKILL.md` 配合使用。每份清单在其标题所指的时刻适用：设计清单用于契约
变更获批之前，操作手册用于迁移运行期间，保留工作表用于数据集创建时，而非有人要求删除时。不适用的条目应当给
出简短理由，不得以打勾代替；未勾选的条目属于未决风险，而非形式。
正文“审查清单”为设计期的权威；本文件载明各时刻的工作表与正文未展开的条件；本文件的设计清单为正文之外的补充条件，冲突时以正文为准。

## API 设计审查清单

对照契约 diff 本身运行本清单，不得凭服务本应做什么的记忆运行。

- [ ] 操作、请求、响应、错误与事件均在 IDL 中定义，并且实现在 CI 校验中与 IDL 一致。
- [ ] 列出每个消费方：读取旧形态的移动客户端、合作伙伴集成、内部服务、仪表盘、报表、导出与分析任务。
- [ ] 变更被声明为增量式或破坏性，并附支撑该声明的版本或兼容性策略。
- [ ] 破坏性变更具有版本边界、替代方案、废弃窗口，以及能够证明何时可以安全移除的用量测量。
- [ ] 字段存在性与可空性明确：可选意味着缺失有效，null 属于有文档的状态，而非意外。
- [ ] 枚举说明如何处理未知值，并预期客户端能够容忍后来新增的值。
- [ ] 每个错误均使用稳定错误码、正确的状态码族、安全的消息与结构化对象的 details 列表。
- [ ] 校验 details 为结构化对象的列表，逐项指出字段路径与违反的规则，而非数据库列或内部异常消息。
- [ ] 集合端点强制最大页大小、带唯一决胜键的确定性排序；同一 API 默认一种分页风格，offset 例外已在契约
  中记录，且同一操作未混用两种风格。
- [ ] 过滤与排序位于允许列表中且经过校验；热过滤与排序字段的索引需求已按 `performance-conventions` 评估，
  并在契约中记录索引或接受的成本。
- [ ] 可重试写入接受幂等键，且重放与键复用行为由测试覆盖。
- [ ] 速率限制与配额有文档，返回限制头与带 `Retry-After` 的 429，并按租户与按主体设定预算。
- [ ] 授权为对象级，租户、所有者与主体 ID 来自已验证的令牌，而非请求 payload。
- [ ] 403 与 404 的存在性策略在各资源间一致，并针对无访问权限的调用方测试。
- [ ] 长操作返回 202 与状态资源、终态，以及有文档的重试或取消路径。
- [ ] 事件与 webhook 携带类型、schema 版本、事件 ID、时间戳与签名，且消费方对重放安全。
- [ ] 同步路径能够装入调用方超时时间，或契约说明超时与异步替代方案。
- [ ] 版本化决定有记录，且仅为已经证明属于破坏性的变更创建新版本。
- [ ] 支持窗口与停用日期记录于契约中，而非仅在计划文档中。
- [ ] API 参考、示例、变更日志与错误码目录在同一次变更中更新。
- [ ] 契约测试以前一客户端版本针对新 schema 运行，并在双跑期间运行两个当前版本。
- [ ] 部署失败时具有回滚或前向修复路径，并考虑缓存了旧 schema 或响应的客户端。

## 错误模型

每个错误均使用同一信封。HTTP 状态码承载大类，错误码承载确切原因，客户端应当依错误码而非消息文本选择行为。

| 错误码族 | HTTP 状态 | 可重试 | 示例 |
|---|---|---|---|
| 校验 | 400 | 否 | `validation.invalid_field`：字段缺失、格式错误或超出范围。 |
| 认证 | 401 | 否 | `auth.unauthenticated`：凭据缺失、过期或无效。 |
| 授权 | 403 | 否 | `auth.forbidden`：调用方已知但缺少权限。 |
| 未找到或已隐藏 | 404 | 否 | `resource.not_found`：资源不存在或对该调用方隐藏。 |
| 冲突 | 409 | 否 | `conflict.version_mismatch`：资源自调用方读取以来已变化。 |
| 语义 | 422 | 否 | `order.not_cancellable`：请求格式正确，但状态不允许该操作。 |
| 速率限制 | 429 | 是，按 `Retry-After`，且仅限安全或幂等操作 | `rate_limit.exceeded`：预算或配额耗尽。 |
| 依赖 | 502 或 503 | 是，带退避，且仅限安全或幂等操作 | `dependency.unavailable`：上游依赖失败。 |
| 内部 | 500 | 是，仅在带幂等键时 | `internal.unexpected`：未处理的失败；仅包含请求 ID。 |

- `code` 稳定、唯一、有文档，不得因不同原因复用；新增属于兼容变更，客户端须容忍未知 code；重命名或删除属于破坏性变更。
- `message` 可安全展示给用户或运维者，不得被解析，并可在契约边界之外本地化；错误消息不得包含机密、令牌、
  堆栈跟踪或个人数据。
- `details` 属于结构化对象的列表，包含字段路径、规则标识符，以及仅在回显安全时方包含的被拒绝值；不得将
  details 压平进消息。
- 每个错误响应均在响应体与响应头中携带请求标识符，使支持人员能够将报告与日志关联，而无需再向调用方索取信
  息。
- 可重试的族包含 `Retry-After` 或重试提示，且仅安全或幂等操作可重试；500 仅在带幂等键时可重试。
- 应用、网关与校验层返回同一信封；带 500 的空响应体属于契约违规。

## 分页、幂等与版本化决策

实现之前，代理应当在契约中为每一行记录一项决策。默认值持续有效，直至已测量的需求将其推翻；同一 API 中的每
个端点对同一行应当使用相同的选择。

| 决策 | 默认 | 选择其他方案的情形 | 契约义务 |
|---|---|---|---|
| 分页风格 | 游标 | 小型稳定集合需 offset 页码跳转，且已在契约中记录为例外 | 下一个游标、稳定排序、最大页大小、例外记录 |
| 页大小 | 固定默认值与硬上限 | 报表或导出流程需要更大页 | 默认值、最大值与超限错误 |
| 总数 | 省略 | 用户界面需要精确计数并接受其成本 | 准确性保证与最大延迟 |
| 过滤语法 | 重复查询参数 | 深层复合查询是真实产品需求 | 允许字段、操作符、值格式、未知参数策略 |
| 排序 | 有文档的默认值加唯一决胜键 | 调用方需要不同顺序 | 允许字段、方向、稳定性保证 |
| 幂等窗口 | 客户端可重试写入 24 小时 | 批处理任务或合作伙伴需要更长重放窗口 | TTL、键作用域、指纹不匹配行为 |
| 版本化 | 在一个主版本内增量演进 | 为外部调用方批准破坏性变更 | 主版本边界、支持窗口、迁移指南 |
| 废弃窗口 | 以 `release-operations-conventions` 的通知窗口为准，项目可延长 | 安全或法律修复需要立即移除，且例外已记录 | 停用日期、替代方案、头、用量阈值 |
| 同步与异步 | 工作能够装入请求预算时用同步 | 工作超出超时或必须在连接丢失后继续 | 202 形状、状态、轮询或 webhook |
| 速率限制作用域 | 按租户与按主体 | 某个工作流需要自己的预算 | 限制、头、429 响应体、`Retry-After` |

- 代理应当将每项决策记录于契约或其 ADR；仅存于审查者记忆的决策将在下一次变更时被重新争论。
- 测量结果变化的，代理应当重新审视决策，并说明会重新开启该决策的条件，不得使问题悬置。
- 一致性优于局部优化：与同类端点分页方式不同的端点，属于整个 API 的新决策，而非一条路由的捷径。

## Expand-Contract 迁移操作手册

本操作手册适用于旧代码能够观察到的任何 schema 变更。代理不得将各阶段压缩为一次部署，即使表当前很小；
该纪律是为表变大的那一日准备的计划。

| 阶段 | 动作 | 回滚 | 验证 |
|---|---|---|---|
| 准备 | 统计受影响行数，估算时长与锁，确认备份与时间点恢复，选择低峰时段，取得批准。 | 暂无；在第一次写入前中止。 | 计数与估算符合计划；负责人与窗口已商定。 |
| 扩展 | 新增可空列或表，或并发构建索引；此时没有任何内容读写它。 | 删除新对象；它未被使用。 | 旧代码与旧查询不受影响。 |
| 双写 | 部署同时写入两种形式并读取旧形式的代码。 | 重新部署前一发布。 | 新行填充两种形式；错误率与延迟不变。 |
| 回填 | 运行带限流与保存游标的分批幂等回填。 | 停止任务；旧形式仍服务读取。 | 行覆盖完整、不匹配计数为零、复制延迟恢复。 |
| 验证 | 对账不匹配，按类型校验约束：CHECK 与外键 `VALIDATE CONSTRAINT`，NOT NULL 在回填后设置，UNIQUE 并发建索引后添加。 | 删除约束；保留可空列。 | 零违规行；约束有效；旧代码仍可用。 |
| 切换读取 | 部署读取新形式并继续双写的代码。 | 重新部署读取旧形式的代码。 | 一致性检查、错误率与延迟在范围内。 |
| 收缩 | 停止写入旧形式，然后在废弃窗口之后删除旧对象。 | 仅可自备份恢复；本阶段需要审批门禁。 | 无引用残留；行数与文档已更新。 |

### 预检

- 统计受影响行数并记录；没有数字即开始的迁移无法验证。
- 在生产规模数据上估算时长与锁，并说明锁阻塞哪些写入。
- 确认存在备份或时间点恢复点，并且恢复经过测试，而不仅仅是配置了。
- 在安排迁移之前选定窗口、时区、负责人与值班联系人。
- 定义停止条件：中止运行所依据的错误、延迟或锁等待阈值。

### 回滚

- 截至并包括读取切换的各阶段均可通过重新部署前一代码回滚；在废弃窗口关闭之前保留旧列与旧读取路径。
- 收缩阶段不可逆：删除之前需要经过验证的备份或时间点恢复点以及审批门禁。
- 应当优先前向修复而非反向迁移，因 down 脚本很少针对真实数据演练。
- 应当停止回填而非逆转它；幂等批次可以自其游标继续。
- 在生产运行之前，应当在 staging 克隆上演练回滚。
- 新代码写入数据之后，仅当两种形式保持一致时，回滚代码方为安全。

### 验证

- 比较各阶段前后的行数与校验和，而非仅在结束时比较。
- 通过旧路径与新路径读取相同的行，并对样本与已知边界情况比较结果。
- 为每个新约束运行违规行查询；约束有效并不证明数据正确。
- 在运行结束后检查复制延迟、锁等待、错误率与延迟，而非仅在运行期间检查。
- 重新运行热查询的查询计划；新索引或新列可能朝任一方向改变计划。

## 销毁性变更审批清单

销毁性变更将删除、截断、重命名、收窄或覆盖在线数据。执行之前应当以书面形式确认每一项；口头批准不覆盖后来
更大范围的同类变更。

- [ ] 变更已经具名：哪个对象、在哪个环境，以及究竟什么会消失。
- [ ] 数据丢失已经量化：行数、大小，以及无法自其他来源重建的值。
- [ ] 存在备份或时间点恢复点，且最近测试过自其恢复。
- [ ] 消费方清单完整：没有在线服务、报表、导出或分析任务仍在读取该对象。
- [ ] 有权者批准的是该确切操作，而非泛泛的清理工作。
- [ ] 废弃窗口已过，或安全/法律需求证明跳过它是合理的。
- [ ] 执行窗口、时区与值班负责人已经商定，且团队已经收到通知。
- [ ] 试运行报告了受影响行数，且数字符合预期。
- [ ] 脚本或迁移是幂等的，或由失败时关闭的前置条件保护。
- [ ] 停止条件明确：哪种错误、延迟或时长会中止运行。
- [ ] 变更后验证查询已经提前写好，并在变更后立即运行。
- [ ] 代码与 schema 的回滚可行且经过测试，或以书面形式接受损失不可逆。
- [ ] 派生副本已经处理：搜索、缓存、数据仓库、导出与日志。
- [ ] 备份及其到期时间已经考虑，并正确说明删除窗口。
- [ ] 操作者、时间、计数与结果记录于权威记录系统中。
- [ ] 被删除对象的定义与计数记录于获批请求中，供未来重建尝试使用。

## 数据保留工作表

每个数据集创建时，代理应当填写一行，并每年审查该表。类别与期限来自安全数据清单；本工作表记录其执行位置以及
删除的发生方式。保留期自触发条件开始，而非自建表开始；空单元格属于未决风险。

| 数据类别 | 位置 | 保留期 | 删除机制 | 负责人 |
|---|---|---|---|---|
| 公开 | CMS 与 CDN 中已发布的内容 | 取消发布后加 30 天 | 删除该行并清除缓存 | 内容团队 |
| 内部 | 主数据库中的服务配置与遥测 | 滚动 13 个月 | 定时删除分区 | 服务负责人 |
| 机密 | 主数据库与数据仓库中的合同与账单记录 | 合同结束后 7 年 | 按合同 ID 运行清理任务 | 财务系统 |
| 受限 | 主数据库、搜索索引与缓存中的客户资料 | 账户关闭后加 30 天 | 擦除任务扇出到所有存储 | 身份团队 |
| 受限 | 对象存储中的支持附件 | 工单关闭后加 90 天 | 删除对象并检查回执 | 支持系统 |

- 类别与期限应当自清单复制；不得臆造任一项，亦不得默认永久保留。
- 触发条件应当指明启动计时的那个事件，例如账户关闭或最后活动日期。
- 删除机制应当指明移除数据的任务、API 或策略，而非移除它的意图。
- 负责人应当是审查期间能够为该行负责的团队或角色；共同负责人等同于没有负责人。
- 安全或法务角色设定的法律保全暂停该行的计划；应当记录其范围、授权与审查日期，并仅在该角色的指示下解除。
- 每一行均应当测试一次：对样本运行删除机制，并验证副本已自存储中消失。

### 副本与存储映射

删除仅在到达每个副本之后才到达该行。规范的副本与存储映射载于 `dimensions.md` 第 3 节；代理应当以该映射取得
按存储的列表，并记录上述数据集级行。

## 测试数据规则

Fixture 隔离、确定性种子数据与凭据作用域由 `testing-and-quality-conventions` 管辖。本清单仅覆盖测试数据
不得包含或变成的内容，以及其退役方式。

- 代理应当为测试生成合成数据，不得将生产转储恢复到开发、测试或 staging 存储。
- 生产数据必须为调试离开生产时，应当不可逆地脱敏，限制提取范围，并在调查结束后删除。
- 测试 schema 应当通过自空库运行迁移历史构建，并测试自上一发布升级；ORM 生成的 schema 将掩盖迁移缺陷。
- Fixture 不得包含真实邮箱地址、电话号码、机密或内部地址；`example.test.invalid` 等保留名称使规则保持可
  见。
- 非生产存储获得较短保留期与定时重置，使陈旧个人数据无法累积。
- 快照与 golden 文件应当在提交前审查个人数据，因其亦属于副本。
- 删除与保留任务应当如其他代码一般测试：任务应当清理的每个存储均具有一个 fixture 与一条断言。
