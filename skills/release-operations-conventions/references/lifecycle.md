# 发布与运维规范生命周期契约

本文件把发布与运维接入 Stage-Gate 生命周期：计划阶段固定版本、批准、回滚与观察方式，发布阶段按摘要晋级
并观察，收尾阶段完成复盘与恢复验证。规则细节见 `dimensions.md`，操作步骤见 `playbooks.md`；本文件只写
阶段职责、门禁证据、交接升级与裁剪度量。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 立项结论、架构与 API 决策、测试策略 | 确定版本来源与递增规则、发布类型与批准人、冻结日历、部署与回滚方案、观察指标、支持窗口 | 发布策略、发布计划、回滚方案、变更台账 | G2 |
| S5 发布 | G4 验证结论、已批准发布提交 | 在批准提交上打标签，自标签构建一次并过门禁，按摘要经环境晋级，执行观察与必要回滚 | 制品摘要、CI/CD 记录、部署与回滚记录、观察快照 | G5 |
| S6 收尾 | 发布或事故结束 | 对照 SLO 与收益，完成事故复盘与行动项，演练恢复，更新运行手册与开关清单 | 复盘记录、行动项、恢复演练结果 | G6 |

阶段细则：

- **S2 版本与节奏。** 一个制品只保留一个版本来源，版本在发布提交上设定并嵌入制品；发布列车按公布日历
  发车，错过截止点的功能等待下一班。兼容性承诺写明受支持版本、修复窗口、最短弃用通知期与升级路径，
  无法兑现时在发布前书面修订。
- **S2 变更台账。** 每个条目记录变更类别（破坏性、行为改变、内部）、所需通知窗口、公告日期、弃用页面与
  回滚标准；类别的判定依据是兼容性影响，不是作者信心。捆绑多个类别会扩大回滚范围，应尽量拆开。
- **S2 观察设计。** 部署前写明成功指标、错误率、延迟、业务信号与阈值，以及每项转为回滚的条件；对用户
  可见征兆或 SLO 燃烧率告警，每条告警带严重级别、所有者与运行手册。
- **S2 恢复目标。** 按数据类别给出 RPO 与 RTO，确定备份频率、保留、异地不可变副本与恢复演练频率；保留
  窗口短于发现窗口的备份视为缺陷。
- **S5 标签与构建。** 标签创建在已批准的发布提交上，自该标签在干净检出中构建并运行门禁；仅当门禁通过且
  制品与标签匹配后才发布。门禁未通过而标签仍未公开时，可在同一发布任务内删除该标签并留痕；已公开标签不删除，
  已发布制品必须能追溯到通过门禁的标签。
- **S5 晋级。** 同一摘要经开发、staging 与生产；环境定义保存在版本控制中并审查差异；晋级生产需要针对
  特定摘要的书面批准，手工配置修改不得绕过该批准。staging 使用匿名化的同形数据，拓扑与依赖尽量一致。
- **S5 部署策略。** 具备 N-1 兼容性的无状态服务用滚动部署；需要快速切换与回滚且容量翻倍的用蓝绿；
  具备成功指标与足够流量的用金丝雀。部署前写好比例、时长、成功指标与中止标准，回滚重新部署已保留摘要。
- **S5 数据迁移。** 按扩展、迁移、收缩推进，使上一应用版本在上线期间能够针对新 schema 运行；与代码同批
  删除或重命名列的迁移消除回滚选项，须按不可逆变更批准。
- **S5 工作流实现。** 构建与发布作业在标签或 `release: published` 事件上运行；由工作流以 `GITHUB_TOKEN`
  创建的 Release 不再触发 `release` 事件，发布与部署放在同一工作流，或以 `workflow_dispatch` 与独立发布
  身份触发。构建作业上传制品，部署作业按名称与摘要下载，不得在部署作业中重建。
- **S5 最小权限。** 顶层权限只读；发布制品申请 `contents: write`，生成证明申请 `attestations: write`，
  上传 SARIF 申请 `security-events: write`，云访问申请 `id-token: write` 并换取短期凭据，不使用长期
  云密钥。部署作业以 `concurrency` 串行化同一环境，失败保留首次运行记录。
- **S5 证明与回滚。** 生成构建来源证明与 SBOM 并随 Release 上传，发布前以 `gh attestation verify` 验证
  自身制品，失败即停止；回滚通过 `workflow_dispatch` 输入上一版本摘要重新部署，不重建、不移动标签。
- **S6 复盘。** 每个 SEV1、SEV2、数据丢失与安全事故在五个工作日内完成复盘，覆盖影响、时间线、发现过程、
  促成原因、有效做法与行动项；行动项带负责人、截止日期、跟踪条目与验证步骤，未验证不视为完成。
- **S6 收尾。** 更新发布说明、变更日志、运行手册与开关清单；删除已达移除版本的开关与旧路径；把未关闭
  风险、支持窗口与值班安排交接给运营。

## 门禁证据

- **G2**：版本来源与递增规则、发布类型与批准人、冻结日历、回滚方案与数据影响、观察指标与阈值、支持窗口、
  变更台账。缺少回滚方案或观察设计时 Recycle 至设计，不得进入构建收尾。
- **G5**：已批准发布提交与附注标签、制品摘要与构建记录、针对制品的测试与安全结论、staging 晋级记录、
  回滚演练、受保护环境批准、观察仪表盘与告警就绪。任何一项缺失即 Hold。
- **G6**：对照基线的结果与 SLO 数据、事故复盘与行动项状态、恢复演练实测 RPO 与 RTO、运行手册与开关
  清单更新、遗留风险与支持安排。未关闭项须有负责人与到期日。
- 批准角色：R0 由执行者自检并记录；R1 由发布所有者与项目负责人批准；R2 增加发起人、运营与安全批准。
  智能体不得代替人工批准，也不得把用户沉默视为发布授权。
- 证据时效：发布后配置漂移、标签被移动、制品被替换或环境被手工修改时，原有 G5 证据失效，须重新取得。

## 交接与升级

- 上游：`testing-and-quality-conventions` 提供 G4 的测试与质量结论；`api-and-data-conventions` 提供兼容性
  与迁移方案；`architecture-and-design-conventions` 提供部署与容量假设；`security-compliance-conventions`
  提供凭据、披露时间表与保留要求。
- 下游：`documentation-conventions` 承接发布说明、变更日志与运行手册；`vcs-collaboration-conventions`
  承接标签保护与合并路径；`repository-governance-conventions` 承接制品元数据、SBOM 随包与不可变设置；
  支持与运营团队承接值班、状态页与升级路径。
- 升级触发：缺少回滚路径、回滚会逆转已完成迁移、发布类型与批准不匹配、生产指标越界、凭据疑似泄露、
  披露时间冲突。上述情形停下并请求用户或安全负责人裁决，不以“先上线再观察”推进。
- 回滚授权：回滚部署按值班权限执行并记录；涉及数据逆转或恢复的回滚须事故指挥官与数据所有者批准；生产
  部署、回滚与迁移仍须用户逐次明确同意。
- 停止条件：G4 证据缺失、环境不可读、观察信号未就绪、冻结窗口未公布时保持 Hold；紧急止损按 AU-5 先执行
  最小动作并立即报告。

## 裁剪与度量

- R0 轻量变更合并 G4 与 G5 记录，仍须验证与观察；R1 使用标准发布清单并保留回滚演练；R2 独立批准、
  完整回滚证据与安全结论，G4 与 G5 不得合并。
- 无部署仓库与单人维护：库、规范与 CLI 项目可以跳过 `dimensions.md` 第 3 节的环境晋级段、第 5 节的值班
  轮值与呼叫、第 6 节的备份与恢复演练，以及 `playbooks.md` 中“事故严重级别与呼叫矩阵”的呼叫与轮值条款
  和“备份与恢复演练检查清单”。豁免不外扩：版本号、一次构建、制品与回滚仍适用；严重级别分诊、事故指挥官、
  沟通与复盘仍适用；维度第 1 节的发布记录仍适用。单人维护时批准人与执行人可以为同一人，但须在发布记录
  中具名。
- 不可裁剪：制品摘要与保留、回滚方案或已接受风险、观察指标与阈值、事故复盘、恢复能力证明（豁免项除外）、
  逐次授权。
- 度量：变更前置时间、变更失败率、平均恢复时间、回滚比例、逃逸缺陷、SLO 燃烧率、复盘行动项关闭率、
  恢复演练实测 RPO 与 RTO。
- 度量口径：变更失败率按“导致回滚、热修复或事故的发布”除以总发布计算；恢复时间从告警确认计至用户
  影响结束；口径变更与上一次数据同时展示，避免趋势失真。
- 度量审查按月或按发布进行，异常先查数据定义、发布类型与流程根因，不调整 SLO 或隐藏失败；度量用于改进
  系统，不用于个人排名。
