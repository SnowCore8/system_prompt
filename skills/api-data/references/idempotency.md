# 幂等与重试

## 1. 幂等与重试

重试不是可选项：网关、客户端库与用户都会重试。被重试的写入必须要么幂等，要么以键去重。

- 每个可能被重试的写入具有幂等契约：键的作用域、存储的响应、TTL 与重放行为明确规定并测试。
- 客户端可能重试的 POST 或动作端点接受作用于主体的 `Idempotency-Key`；相同键与相同请求体重放存储的
  响应，相同键配不同请求体属于冲突。
- PUT 与 DELETE 按定义幂等。
- 重试仅适用于安全操作或幂等操作，采用指数退避加抖动，并设定最大次数与总超时：429 按 `Retry-After`
  重试；500 仅在带幂等键时可重试；502 与 503 限安全或幂等操作；4xx（除 408 与 429）不重试。
- 以响应头公布速率限制；配额不得作为正确性机制，应改用幂等、预留或队列。

## 2. 判定与边界

- 键的作用域限定至端点与主体，在处理程序运行之前拒绝被复用的键，TTL 记录于契约而非代码。
- 不得假定客户端不实施重试；即使客户端代码不重试，网关与用户也会重试。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 带存储响应的 `Idempotency-Key` | 文档写“客户端不应重试” | 网关与用户仍会重试，写入重复 |
| 指数退避加抖动并尊重 `Retry-After` | 对每个失败立即重试且不限次数 | 重试放大中断，服务恢复后被打垮 |
| 以幂等或队列控制重复 | 把速率限制当并发控制 | 合法重试失败，正确性靠运气 |
