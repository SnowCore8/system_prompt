# 分页与集合

## 1. 分页与集合

集合是 API 中最常见的形状，也是行为破坏最不易察觉之处：页在数据移动时跳过或重复行，默认值在未公告时
改变。

- 集合有界、确定性有序且可重复：强制最大页大小，默认排序记录在契约中并以唯一键打破平局。
- 同一 API 默认一种分页风格：大型或变化的集合用游标分页；仅小型稳定集合需 offset 的，在契约中记录为
  例外，同一操作不得混用两种风格。
- 返回下一个游标或链接；总数设为可选，因其代价高昂；完整导出作为独立任务处理，不得作为一页。
- 过滤字段、操作符与值格式加入允许列表，对未知过滤条件应用有文档的策略。
- 在同一版本内，默认页大小与默认排序保持固定；即使 schema 未变，变更任一项也属于行为破坏。

## 2. 判定与边界

- 判据：页既不跳过也不重复——游标加唯一决胜键。
- 热过滤与排序字段的索引需求由 `performance` 裁定，并在契约中记录索引或接受的成本。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 游标加唯一决胜键 | 活跃表上用 `OFFSET 20000 LIMIT 20` | 插入或删除行时页漂移 |
| 默认页大小与排序写入契约 | 默认值静默变更 | 客户端对顺序与页内容的断言被破坏 |
| 过滤允许列表加未知项策略 | 任意过滤透传存储层 | 索引失配与注入风险 |
