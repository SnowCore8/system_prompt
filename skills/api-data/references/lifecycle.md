# API 与数据生命周期契约

本文件回答一个问题：契约与数据工作在哪一阶段产生哪一类证据，证据不足时停在哪里。阶段与门禁的编号、
判定语义与决策权限由 `project-lifecycle` 裁定；本文件把该框架落到端点、事件、表与删除路径，不重述门禁
定义。维度规则见对应维度文件。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 设计 | 范围与验收标准、数据清单、性能目标 | 定义 IDL、错误模型、分页与幂等契约、授权边界；设计扩展、回填、收缩阶段 | 契约 diff、迁移与回滚方案、锁估算、保留与删除路径 | G2 |
| S3 构建 | 已通过 G2 的计划 | 按阶段落地实现；生成物由 IDL 产出；编写契约测试与可重启的回填脚本 | 可运行增量、生成物差异为零、契约测试 | G3 |
| S4 验证 | 增量与测试环境 | 以前一客户端版本验证兼容性；测量锁与复制延迟；逐存储验证删除传播 | 兼容性与数据验证结论 | G4 |
| S5 发布 | G4 结论、逐次明确同意 | 复核批准与恢复点；把迁移作为独立步骤执行并观察指标 | 执行记录、变更后验证查询 | G5 |
| S6 运维 | 回填与清理任务、契约事故 | 监控任务进度与复制延迟，处置契约与数据事故 | 任务运行记录、事故结论 | G6 |
| S7 收尾 | 保留工作表与退役计划 | 执行数据退役与归档，核对保留期、删除路径与备份到期 | 退役记录、保留核对结果 | G7 |

S4 只验证 S2 已确定的行为，不在验证阶段重新设计契约；发现设计缺陷时按 Recycle 回到 S2 修订方案。

## 门禁证据

| 门禁 | 证据形态 | 复核者 | 不可接受的证据 |
|---|---|---|---|
| G2 | 契约 diff 与消费方清单；两步增量或版本边界声明；迁移与回滚方案；生产规模锁估算；保留与删除路径 | 接口所有者与数据所有者 | 只有设计描述，没有 diff 或清单 |
| G3 | IDL 与实现一致的 CI 输出；重生成后差异为零；契约测试；回填脚本的幂等与游标 | 提交者自检；R1 起加独立审查 | 手工修补生成物；以“表很小”跳过阶段 |
| G4 | 前一客户端版本的契约测试与双跑结果；锁与复制延迟数据；约束验证查询；删除传播的逐存储回执 | 独立审查者；R2 加安全与合规结论 | 未运行的测试；假定客户端兼容 |
| G5 | 迁移独立执行记录；已验证的恢复点；试运行计数；变更后查询；销毁性变更的逐次同意 | 运营与发布批准人 | 以部署步骤代替迁移；口头批准 |

- R0：单服务内新增可选字段或修正错误文案，可把 G2 与 G4 记录合并为一条，仍须运行契约测试与生成物校验。
- R1：契约 diff 与迁移方案须有一名非作者审查；双跑至少覆盖上一个发布版本。
- R2：删除、截断、收窄类型、跨团队契约或涉及个人数据的变更，G4 需要独立的数据与安全结论，G5 需要逐次
  同意与回滚演练记录。
- 例外（如 offset 分页、临时放宽的保留期）必须有所有者、范围与到期条件，并写入契约或门禁记录。
- 证据链接指向具体文件、提交或查询结果，不指向聊天记录或口头承诺。

## 交接与升级

交接：

- 交 `testing-quality`：契约 diff 基线、契约测试用例与兼容矩阵，作为 CI 门禁运行。
- 交 `release-operations`：迁移阶段清单、部署顺序、停止条件与回滚触发阈值。
- 交 `documentation`：参考页、迁移指南与错误码目录的更新点。
- 交 `code-style`：生成目录的格式化与 lint 排除项。
- 交 `performance`：索引与查询的取舍结论。
- 交 `security-compliance`：字段类别映射、删除传播的存储清单与备份到期日。

升级：

- 消费方清单无法补全，或某客户端无法测试：升级为未验证兼容性风险，由用户决定是否接受。
- 销毁性变更缺少恢复点、批准或试运行计数：停在上一步，不得进入 G5。
- 版本策略与已对外承诺的支持窗口冲突：Recycle 到 S1 重新比较选项。
- 强制规则之间冲突：报告用户裁决，并把所选约定记录于契约或 ADR。
- 同一问题连续两次 Recycle 未解决：升级决策层，重新评估范围、版本边界或目标。

停止条件：

- 未取得逐次明确同意时不得执行生产迁移、回填或数据库写入。
- 发现疑似凭据或个人数据泄露时按 SEC 条款停止并保留证据，不继续清理。
- 生产规模锁估算显示将阻塞写入且无法拆分时，停止实施并回报。
- 紧急止损按 AUT 的紧急例外优先：先停止写入或回到读取切换前的版本，再补 G4/G5 记录与复盘。

## 裁剪与度量

裁剪：

- R0：一条受理兼计划记录，一句验收；保留契约测试输出与生成物校验。
- R1：完整清单但可精简；双跑只要求上一个发布版本；独立审查一名。
- R2：不得裁剪；契约、迁移、保留、批准与回滚演练四项证据必须同时存在。

度量：

| 指标 | 定义 | 用途 |
|---|---|---|
| 破坏性变更占比 | 每个发布周期内破坏性契约变更数与总变更数之比 | 判断版本策略是否失控 |
| 已测客户端版本数 | 每次发布实际运行的客户端版本数量 | 发现只验证一个版本的盲区 |
| 迁移中止次数 | 触发停止条件或回滚的迁移执行次数 | 校准锁估算与分批参数 |
| 回填重跑率 | 因失败或中断而重跑的回填批次比例 | 检验幂等与游标设计 |
| 删除传播覆盖率 | 已验证完成删除的存储数与该数据集副本总数之比 | 判断擦除是否真正完成 |
| 支持窗口偏差 | 已过停用日期仍存活的版本数 | 发现废弃承诺未兑现 |

审查节奏：每季度复核一次度量与保留工作表；异常先查数据定义与流程根因，再调整阈值。
