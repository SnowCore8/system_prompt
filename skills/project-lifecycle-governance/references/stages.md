# 阶段活动与裁剪

本文件按 S0–S6 展开每个阶段的入口、活动、输出、门禁证据与裁剪方式。阶段编号与 `SKILL.md` 一致；门禁
判据的详细矩阵在 `gates.md`，迭代与度量在 `agile.md`。

## S0 受理与分类

入口：任何新请求、变更请求、事故或组合提案。

活动：

- 复述请求的对象、动作与预期结果，确认没有对象缺失或歧义。请求分类依 `rules/global-user-constraints.md`
  表 1 与 IN 系列条款执行。
- 确认授权级别：任务级预授权、计划级确认或逐次明确同意。涉及生产、共享资源、不可逆操作或受保护文件时，
  不得以“先做再说”推进。
- 记录风险级别 R0/R1/R2 与判断依据；范围、影响或授权变化时重新分级。
- 写明停止条件：出现什么证据、错误、成本或风险时必须停下并报告。
- 指定负责人、利益相关者与沟通路径；多智能体任务指定领导者与协作者。

输出：受理记录，至少包含请求摘要、分类、授权、风险级别、停止条件、负责人与下一个门禁。

门禁证据：请求原文或等价复述、授权依据、风险分级理由、受保护对象清单、停止条件。

裁剪：R0 可将受理与计划合并为一条记录；R1 保留完整受理记录；R2 必须独立记录并明确人工批准人。

## S1 探索与立项

入口：G0 已 Go 或 Conditional Go，条件已关闭。

活动：

- 描述问题与受影响用户，区分“用户说想要什么”与“用户需要完成什么”。
- 收集约束：法规、平台、预算、时间、技术、依赖、安全与隐私。
- 列出至少两个可选方案（含“不做事”），说明成本、风险、收益与退出方式。
- 定义结果指标与收益基线；指标必须可测量，不能只写“更好用”。
- 形成建议：继续、缩小范围、延期或停止；需要立项的，写章程或探索简报。
- 对 R2 或涉及个人数据、凭据、生产变更的提案，完成初步威胁模型与合规判断。

输出：章程或探索简报，包含问题、用户、结果指标、约束、选项、建议、收益基线与主要风险。

门禁证据：用户或数据来源、问题陈述、选项比较、收益基线、初步风险与安全判断。

裁剪：R0 用一段话说明问题、结果与不做的后果；R1 用一页简报；R2 使用完整章程并附利益相关者确认。

## S2 计划与设计

入口：G1 已 Go，立项结论与收益基线已确认。

活动：

- 固定范围与不做事项，写明验收标准与验收人。
- 完成设计与架构决策：模块边界、依赖方向、接口与数据、目录与包、命名与风格、配置与错误处理。
- 制定测试策略与质量门禁：测试层级、覆盖率或等价阈值、静态分析、CI 校验、DoD。
- 制定交付计划：任务拆分、依赖、估算、里程碑、迭代目标、WIP 上限与资源。
- 制定发布与回滚计划：版本、变更记录、部署路径、回滚触发条件、可观测性与通告。
- 建立风险登记：概率、影响、触发信号、缓解措施、负责人与复审时间。
- 对 R2 完成安全、隐私、许可证、数据迁移与容量评估；需要时进行设计评审。
- 检查 Definition of Ready；未满足的条目不得进入构建。

输出：计划或待办、设计决策记录、测试策略、发布与回滚方案、风险登记、验收标准。

门禁证据：范围与验收标准、设计与 ADR、测试与门禁方案、风险登记、资源与时间承诺、回滚方案。

裁剪：R0 可将计划压缩为任务清单与验收句；R1 使用精简模板；R2 必须保留完整设计、风险与回滚证据。

## S3 构建与迭代

入口：G2 已 Go，Definition of Ready 满足。

活动：

- 按迭代目标交付小增量；每个增量可构建、可测试、可审查。
- 控制 WIP；多智能体任务按工作树或模块隔离，单写者原则与集成顺序见
  `worktree-collaboration-conventions`。
- 遵守代码、命名、注释、架构、接口、并发与性能规范；发现设计偏差时更新 ADR，不得静默偏离。
- 每次提交附带相关测试；调试遵循先复现、再定位、后修复、必验证。
- 持续更新文档、运行手册与变更记录；不把文档留到发布前补写。
- 每个迭代结束进行评审：演示增量、收集反馈、调整待办；必要时回顾流程。

输出：可运行增量、测试、文档、评审记录、更新的设计与风险登记。

门禁证据：增量与提交记录、测试结果、审查结论、DoD 检查、未关闭风险与处理计划。

裁剪：R0 一次交付即可；R1 至少一次迭代评审；R2 每个迭代保留评审与集成记录，关键接口变更须重新过
G2 的设计评审。

## S4 验证与验收

入口：G3 已 Go，增量达到可验证状态。

活动：

- 执行测试策略：单元、集成、端到端、回归、兼容性与必要的人工验收。
- 执行安全与合规检查：依赖漏洞、机密扫描、许可证、隐私影响、威胁模型复核。
- 执行性能与并发验证：目标、基准、剖析、负载与故障注入；无目标不优化。
- 检查文档、运行手册、变更记录与迁移指南是否与实现一致。
- 独立审查：R1 至少一名非作者审查；R2 需要架构、安全或合规的独立结论。
- 对照验收标准逐项给出通过、失败或有条件通过；失败项必须修复或明确接受并记录。

输出：验证报告、审查结论、缺陷清单、验收结论、发布准备度评估。

门禁证据：测试输出与覆盖率、缺陷趋势、安全与许可证结论、性能数据、验收签字或明确批准。

裁剪：R0 以自动化测试与自检为主；R1 增加独立审查；R2 不得省略安全、回滚演练与验收人确认。

## S5 发布与上线

入口：G4 已 Go，发布准备度满足。

活动：

- 确认版本、变更记录、发布说明、迁移与弃用通告。
- 确认部署路径、环境、权限、回滚触发条件与回滚演练结果。
- 确认可观测性：日志、指标、追踪、告警、值班与升级路径。
- 按 `release-operations-conventions` 执行构建、签名、晋级与部署；生产变更按 AU-1 第 3 级取得逐次同意。
- 发布后验证关键指标与用户路径；异常时按预案回滚或止损。

输出：发布记录、部署与回滚证据、可观测性截图或链接、通告与支持安排。

门禁证据：版本与制品哈希、CI/CD 记录、回滚演练、监控与告警配置、批准记录。

裁剪：R0 可合并发布与验证记录；R1 使用标准发布清单；R2 必须独立批准并保留完整发布与回滚证据。

## S6 运营、收尾与复盘

入口：G5 已 Go，发布完成或项目进入运营。

活动：

- 监控结果指标与服务质量；处理事故、缺陷与用户反馈。
- 对照 G1 的收益基线评估收益实现、成本、进度与范围偏差。
- 记录决策、变更、风险与事故的最终状态；关闭或转移未完成事项。
- 进行复盘：什么有效、什么无效、意外是什么、下一次改变什么；行动项有负责人与到期日。
- 归档工件、清理临时资源、移交运行责任；仓库停止时按 `repository-governance-conventions` 归档。
- 对 R2 或重大事故，完成事后审查并更新威胁模型、运行手册与测试。

输出：收尾报告、收益对照、复盘记录、行动项、归档与交接记录。

门禁证据：结果指标、偏差分析、复盘行动项、归档状态、交接确认。

裁剪：R0 用简短复盘记录；R1 使用标准收尾报告；R2 需要独立事后审查与收益评估。

## 阶段回退

- 任何门禁都可以 Recycle 到指定阶段；回退必须写明返工项、重新评审的门禁与影响范围。
- 回退不得删除已产生的证据；失败记录与负面结果属于后续决策的输入。
- 同一问题连续两次回退仍未解决时，升级到更高决策层，重新评估方案、范围或目标，不得无限循环。
- 紧急事件按 AU-5 先止损，再补记录；补记录必须区分当时已知事实与事后补充信息。
