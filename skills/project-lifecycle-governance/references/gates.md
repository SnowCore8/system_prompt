# 门禁判据与决策权限

门禁是阶段之间的承诺点。每个门禁只做一件事：判断现有证据是否足以承担下一阶段的风险。证据不足时，
正确的决定是 Hold 或 Recycle，而不是用计划、口头保证或“应该没问题”补位。

## 门禁矩阵

| 门禁 | 要回答的问题 | 最低证据 | R0 决定 | R1 决定 | R2 决定 | 不通过时 |
|---|---|---|---|---|---|---|
| G0 受理 | 请求、授权与风险是否清楚？ | 请求复述、授权依据、风险级别、停止条件 | 执行者 | 项目负责人 | 项目负责人 + 发起人 | 澄清、Hold 或 No-Go |
| G1 立项 | 问题是否真实，是否值得做？ | 用户与问题、结果指标、收益基线、选项比较 | 执行者 | 产品负责人 | 发起人或组合委员会 | 缩小、延期或 No-Go |
| G2 计划 | 范围、设计、验收与回滚是否成立？ | 范围与验收、设计/ADR、测试策略、风险登记、回滚方案 | 执行者 | 项目负责人 + 审查者 | 项目负责人 + 架构/安全 + 发起人 | Recycle 到 S1 或 S2 |
| G3 构建 | 增量是否可验证？ | 可运行增量、测试、评审、DoD 检查 | 执行者 | 项目负责人 + 审查者 | 项目负责人 + 质量/安全 | Recycle 到 S2 或 S3 |
| G4 验证 | 是否满足验收与质量要求？ | 测试输出、缺陷趋势、安全/性能结论、验收结论 | 执行者 | 独立审查者 + 产品负责人 | 独立审查 + 安全/合规 + 产品负责人 | 修复、Recycle 或 No-Go |
| G5 发布 | 能否安全上线并回滚？ | 版本与制品、CI/CD 记录、回滚演练、可观测性、批准 | 执行者 | 项目负责人 + 运营 | 发起人 + 运营 + 安全（如需） | Hold、回滚或取消发布 |
| G6 收尾 | 是否产生价值，是否留下可复用证据？ | 收益对照、偏差、复盘行动、归档与交接 | 执行者 | 项目负责人 | 发起人或组合委员会 | 补充证据或转入运营改进 |

表中“决定”是批准角色，不是会议规模。R0 可以由执行者自检，但不得自批 R2；R1 的独立审查者不得是增量
作者；R2 的安全与合规结论不得由交付团队自行出具。

## 决定语义

- **Go**：证据满足当前门禁，进入下一阶段。Go 不构成对后续不可逆操作的授权；AU-1 第 3 级行为仍需逐次同意。
- **Conditional Go**：主体工作可继续，但附有条件。条件必须可验证、有负责人与到期日，并写明关闭证据。
  条件不得是当前门禁本应完成的证据；例如不得以“发布前补做安全审查”通过 G4。
- **Hold**：证据缺失或外部依赖未就绪。Hold 期间不得推进受影响的工作，但可以并行处理不受影响的任务。
- **Recycle**：退回指定阶段返工。记录必须写明返工项、重新评审的门禁与影响范围；不得只写“再改改”。
- **No-Go**：停止、关闭或转向。记录理由、已产生成本、剩余资产与归档方式；不得把 No-Go 伪装成延期。
- **Defer**：仅用于组合层，把提案放回队列。项目层不得用 Defer 替代 Hold、Recycle 或 No-Go。

## 证据标准

可接受的证据：

- 测试命令与真实输出、退出码、覆盖率或等价质量数据。
- 审查记录、签字、批准邮件或平台审批记录。
- 压测、故障注入、回滚演练与恢复验证记录。
- 安全扫描、依赖审计、许可证与 SBOM 结论。
- 监控截图、指标查询链接、发布与部署记录。
- 收益基线、结果指标与对照数据。

不可接受的证据：

- 计划中的工作、未运行的测试、他人的口头保证。
- “通常会通过”“应该没问题”“和上次一样”。
- 只有文档描述、没有执行记录的验证。
- 由执行者自行出具并自行批准的 R2 安全结论。

## 决策权限与升级

- R0：执行者自检并记录；涉及安全、凭据、生产或不可逆时立即升级为 R1/R2。
- R1：项目负责人批准；G2/G3/G4 至少一名独立审查者；跨模块或依赖变更增加对应模块负责人。
- R2：发起人或组合委员会批准；G2 增加架构与安全评审；G4 增加独立验证；G5 增加运营与安全批准。
- 权限冲突时按 `rules/global-user-constraints.md` 的效力顺序处理；安全、授权与不可逆约束优先于进度。
- 连续两次 Recycle 或同一风险超过复审日期未处理时，升级到更高决策层；升级记录写明未解决项与可选方案。
- 智能体不得代替人工批准 R2 门禁，也不得把用户的沉默视为批准。

## 紧急路径

- 服务中断、数据损坏、漏洞正在被利用或凭据确认泄露时，按 AU-5 先实施最小止损，再报告。
- 止损后补 G0/G4/G5 记录，写明当时已知事实、采取的动作、影响范围与后续验证；不得改写时间线。
- 紧急发布不豁免 G4；无法完整验证时，记录未验证部分、风险接受人与回滚条件。
- 事故复盘按 S6 执行；复盘行动项进入待办并指定负责人与到期日。

## 门禁记录字段

每次门禁至少记录：

| 字段 | 内容 |
|---|---|
| 门禁 | G0–G6 与阶段名 |
| 日期与负责人 | 决策时间、批准人与记录人 |
| 风险级别 | R0/R1/R2 与依据 |
| 证据 | 链接、命令输出、审查记录或指标 |
| 决定 | Go/Conditional Go/Hold/Recycle/No-Go/Defer |
| 条件 | 条件、负责人、到期日、关闭证据 |
| 下一门禁 | 下一阶段、预计时间与前置条件 |

记录存放位置由项目约定；本仓库的模板见 `templates.md`。记录应当可被未参与会议的人复核。
