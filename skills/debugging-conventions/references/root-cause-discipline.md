# 根因治理与方案验证（CH-4、ME-12）

CH-4 沿用原用户全局约束的编号；ME-12 的常驻条款与本文冲突时，以 `rules/global-user-constraints.md` 为准。

## CH-4 根因治理

补丁无法修复根因的，应当重构，不得逐层叠加补丁。同一问题的第二个补丁仍然失败的，应当停止，先查明根因；根因
属于结构性的，应当重构。重构超出授权的，应当说明根因、范围与替代方案，再请求确认。补丁将掩盖根因，使后续改动
成本持续上升。

## ME-12 方案验证

新方案失败时，至少实现并运行 3 个实现版本；每个版本记录改动、命令、输出与失败点，先定位实际根因。
3 个实现版本均无效且根因有证据，才可判定方案不可行。未定位根因时，只能报告不确定，不得编造不可行断言。

ME-12 不改变 CH-4 与 `dimensions.md` 中“第二个补丁失败即停止打补丁”的规则：3 个版本应当针对不同根因
假设或不同实现路径，不得把 3 个版本做成 3 次叠补丁，无论补丁是否相同。
