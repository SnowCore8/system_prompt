# 代码风格

风格问题是复合问题：格式噪声会淹没审查中的行为变更，布局漂移会把每次修改都变成多处编辑，未锁定的依赖与未校验的配置会在本地与生产之间制造差异，被吞掉的错误与无语境的日志会把事故拖成猜测。本 skill 把机器能裁决的事项交给配置，把人的注意力留给机器无法裁决的决定。

## 适用范围与优先级

效力按下列层级判定，高层覆盖低层，低层只在高层未规定时补充。

1. 平台、语言与宿主约束：语法要求、编译器开关与全局治理章程中关于机密、不可逆与诚实的规定，不存在豁免。
2. 本 skill 的规则：格式化、布局、依赖、配置、错误与日志的规则以本文件与 `references/` 为准；已配置的 formatter、linter 与 `.editorconfig` 属于项目事实，按规则使用。
3. 项目约定与事实：现有配置、构建脚本与有文档的风格指南是输入；项目约定只在本 skill 未规定处补充，不得覆盖本 skill。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 本 skill 管辖模块内的文件与资源放置、格式化、依赖版本、配置、错误与日志；目录与包边界归 `project-structure`，模块边界与依赖方向归 `architecture-design`。
- 标识符命名归 `naming`；注释内容归 `comments`；格式化工具决定注释缩进，注释是否应当存在由 `comments` 裁定。
- 测试策略与门禁阈值归 `testing-quality`；发布、告警与可观测性字段 schema 归 `release-operations`；漏洞、许可证与供应链证据归 `security-compliance`。
- 生成代码与第三方引入代码不按本 skill 的编辑要求处理：保留标记、排除于 formatter 与 linter 之外，以重新生成或重新引入替代手工编辑。
- 机器能裁决的规则必须落在配置或 CI 里；只存在于指南中的风格规则会在一个季度内失效。强制规则冲突时报告用户裁决；非强制项目约定冲突时说明冲突并记录选择。

## 生命周期定位

上游输入：S1 需求中记录的现状与约束；S2 设计中 `architecture-design` 的模块边界与 `security-compliance` 的准入判据。
下游交接：格式与 lint 命令交 `testing-quality` 接入 CI；日志字段与告警交 `release-operations`；配置键参考页交 `documentation`；生成目录排除项交 `project-structure`。

升级与停止：工具版本未锁定、风格变更与行为变更混在同一 diff、依赖准入缺少健康度与许可证证据、机密出现在配置或日志中时停止并回报；强制规则冲突时报告用户裁决，不自行选择。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 选定 formatter、linter 与行宽唯一取值，确定依赖锁定与准入标准、配置优先级与校验点、生成目录排除项 | 工具与规则配置、依赖准入结论、配置 schema、CI 命令 |
| S3 构建 | 以最小配置或代码变更落地规则；机械变更与行为变更分开提交；同步文档 | 配置文件 diff、仅重格式化的独立提交、manifest 与锁文件变更 |
| S4 验证 | 在干净检出上运行格式校验、lint、构建与相关测试，确认无手工折行与生成物改动 | 校验命令输出与退出码、diff 核对结论 |

## 门禁与证据

证据必须可复核：命令、退出码与 diff 行号；计划与口头保证不构成证据。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | formatter 与 linter 选型、行宽与导入分组的唯一取值、依赖锁定与准入标准、配置优先级与校验方案 | Hold：工具或规则未定；Recycle 到 S2 补齐方案 |
| G3 构建 | 配置 diff 与仅含 formatter 命令的机械变更、锁文件与 manifest 同步、生成物由重新生成而非编辑 | Recycle 到 S3：风格与行为混在同一 diff，或规则只写在指南未落在配置 |
| G4 验证 | 干净检出上的格式校验与 lint、构建与相关测试输出、退出码；diff 无构建产物与机密 | Hold：仅本地通过且 CI 未跑；No-Go：机密进入代码、配置或日志 |

## 维度索引

每个维度的完整规则、默认值与边界见对应文件；详情列的节号即该文件中的章节编号。

| 编号 | 维度名 | 首条规则 | 详情 |
|---|---|---|---|
| 1 | 格式化与行宽 | 每类文件只配置一个 formatter，行宽只有一个取值，机器能裁决的内容一律交给配置。 | `references/format.md` 第 1 节 |
| 2 | 模块内文件与资源布局 | 每个文件只有一个内聚的变更理由，资源按一种布局放置。 | `references/layout.md` 第 1 节 |
| 3 | 生成代码与第三方引入代码 | 生成输出与第三方引入代码通过修改其来源而变化，不得手工编辑。 | `references/generated.md` 第 1 节 |
| 4 | 依赖版本管理 | 仅声明直接依赖，应用锁定精确版本，库声明范围，提交一个锁文件。 | `references/deps.md` 第 1 节 |
| 5 | 配置处理 | 固定一套有文档的优先级顺序，启动时按 schema 校验一次，失败即拒绝启动。 | `references/config.md` 第 1 节 |
| 6 | 错误处理 | 仅捕获能够处理的错误，补充上下文并保留原因，或让它继续传播。 | `references/errors.md` 第 1 节 |
| 7 | 日志策略 | 在决定结果的边界记录一次结构化日志，用说明何人应当行动的级别。 | `references/logging.md` 第 1 节 |

## 参考资料

- `references/lifecycle.md`：本 skill 在 S2–S4 的职责、G2–G4 的证据形态、与其他 skill 的交接、裁剪与度量。

- `references/deps.md`、`references/config.md`：依赖与配置维度的完整规则；增删依赖或搭建配置层级前阅读。
- `references/errors.md`、`references/logging.md`：错误与日志维度的完整规则；审查 catch 语句或日志行前阅读。
