# 日志策略

## 1. 日志策略

日志是生产故障的唯一见证：级别错置或无字段的日志行，会把事故变成猜测。

- 在决定结果的边界记录一次事件，较低层返回错误不重复记录；重复日志行放大日志量并模糊首次出现。
- 用说明何人应当行动的级别：ERROR 表示必须有人行动，WARN 表示已处理的降级，INFO 表示生命周期与业务事件，DEBUG 在生产中保持关闭。
- 级别属于结果而非异常类型：同一超时被重试时是 WARN，耗尽重试结束请求时是 ERROR。
- 结构化日志带稳定字段：`timestamp`、`level`、`event`、`service`、`trace_id`、`error_code`；可变数据放字段，不放事件字符串。
- 不记录机密、令牌、Authorization 头、完整请求或响应体、未脱敏的个人数据；记录标识符或脱敏值。
- 调用方取消与截止是预期情况，不记 ERROR；库代码返回错误，由调用方决定记录什么。
