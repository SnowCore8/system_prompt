# 格式化与行宽

## 1. 格式化与行宽

本文件是维度 1 的完整规则：默认值、边界情况与实施纪律。已配置的 formatter 与 `.editorconfig` 属于项目事实，按本文件处理。

- 每类文件只配置一个 formatter，配置保存在仓库中，工具版本在 pre-commit 与 CI 中锁定；两个 formatter 重写同一文件会产生无休止的变更循环。
- 行宽只设置一次，从 formatter 配置或项目审查规则读取：Black 与 Ruff format 为 88，Prettier 为 80，rustfmt 为 100；
  项目配置为实际取值，不得按文件或按作者设置。
- 字符串字面量、URL、哈希与数据表不得拆分，拆分即改变含义；formatter 无法拆分的行保持长行并记录该例外，不得为整个项目放宽行宽。
- 引号、分号、缩进与尾随逗号在配置中决定，不在代码中决定；对取值有异议的，按项目级配置变更处理，不在单个文件内联覆盖。
- import 按标准库、第三方、项目三组排列，组内排序，组间空行，禁止通配符导入。
- 块结构保持扁平：每行一条语句，花括号可选的语言亦写花括号，以提前返回代替 return 之后的 else；
  嵌套超过三层时提取为函数，提取手法见 `refactoring`。
- 空白交给 formatter，不手工折行、对齐或缩进；手工编辑会被下一次运行撤销，其间只产生审查噪声。
- 提交 `.editorconfig` 设置 UTF-8、LF 换行与文件末尾换行；编辑器按自身设置重排文件是混合 diff 最常见的来源。
- 强制手段落在 CI 校验模式与本地写入模式，两者使用同一已锁定命令。

### 实施纪律

- 风格变更就是代码变更：以一次范围明确的变更落地，不混入行为变更；混在一起的先拆成两次提交。
- 重新格式化只限于本次变更涉及的文件，不格式化无关文件。
- formatter 版本升级会重排无关文件，作为独立变更落地，并与功能变更分开审查。
- 生成目录、第三方引入目录与构建输出目录在 formatter 与 linter 配置中排除，排除项写入可审查的配置文件。
- 配置 diff 决定后续上百个格式化 diff，按设计文档的标准审查配置变化。
- 纯格式化提交的描述只写 formatter 命令，不写其他内容。

| 正例 | 反例 | 原因 |
|---|---|---|
| `ruff format` 挂在 pre-commit | 审查时口头要求按 Black 风格 | 机器裁决空白，人审查逻辑 |
| `line-length = 100` 写入配置 | 按 120 手工折行 | 手工折行会被 formatter 重新合并 |
| import 分三组并排序 | `from x import *` | 名称来源可见，依赖变化即破坏 |
| 提交 `.editorconfig` | 一台机器 LF、另一台 CRLF | 换行不再污染每个 diff |
