# 配置处理

## 1. 配置处理

配置是每一环境中运行的代码，与代码一样接受审查、版本管理与回滚。

- 固定一套有文档的优先级顺序：命令行标志、环境变量、本地配置文件、共享配置文件、编译期默认值；启动时按该顺序加载并合并一次。
- 只保留一个模块读取所有来源，功能代码不另造第二套阶梯；模块接收类型化配置对象，不接收字典，不直接读环境。
- 按 schema 在启动时校验合并结果一次：必填键存在、类型与范围正确、URL 可解析、互斥选项被拒绝；指出失败的键并以非零状态退出。
- 必填键不提供回退，可选键提供带单位与范围的有文档默认值；移除调用点中的隐藏回退，如 `timeout or 30`。
- 按数据而非分支分离环境：以显式环境变量选择 `config/prod.yaml` 等文件，缺失文件即错误；业务逻辑中不写 `if env == "prod"`。
- 每个行为只保留一个键；两个键控制同一行为或某个布尔值变成永久路径的，退役不再控制行为的键。
- 配置变更无法单独回滚时属于部署风险：新值验证通过前保留旧值，验证后于后续变更移除。

### 环境分离与机密

- 机密按名称引用，运行时从机密存储解析；不写入代码、配置文件、日志或错误消息。
- 本地 `.env` 只承载开发用非机密值并列入忽略；生产值经流水线注入。
- 测试套件构建显式配置 fixture，不读取开发者的 shell 环境，使测试不依赖未导出的变量。
- 机密处理与轮换的完整策略由 `security-compliance` 裁定；本文件只要求配置路径上不出现机密值。
