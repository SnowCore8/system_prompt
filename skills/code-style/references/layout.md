# 模块内文件与资源布局

## 1. 模块内文件与资源布局

项目级目录、包与工作区边界由 `project-structure` 裁定；本文件只规定模块内部的文件与资源放置。

- 每个文件只有一个内聚的变更理由；应用代码默认 300 行触发警告、500 行拆分，文件长出第二项职责时即使未达行数亦应拆分。
- 文件与资源按职责而非层次放置；目录与文件的命名形式（集合复数、单个功能单数、避免 `utils/` 等无主目录）由 `naming` 裁定。
- 单文件中的常量、类型与辅助函数就近放置于使用处；被多个文件共用时提升到模块内公共文件，不新增全局杂物堆。
- 文件移动属于结构变更，与逻辑编辑分开实施；移动目标与引用更新按 `refactoring` 的安全手法执行。
- 静态资源按类型分目录放置；资源名、倍率与禁用内容由 `naming` 裁定。
- 测试 fixture、快照与基准文件归入模块内测试数据目录，目录名称由 `naming` 裁定。
- 迁移文件的命名与排序规则由 `naming` 裁定；生成数据与压缩资源属于构建输入，不参与手工排版。
