# 模块内文件与资源布局

## 1. 模块内文件与资源布局

项目级目录、包与工作区边界由 `project-structure` 裁定；本文件只规定模块内部的文件与资源放置。

- 每个文件只有一个内聚的变更理由；应用代码建议 300 行警告、500 行拆分，文件长出第二项职责时即使未达行数亦应拆分。
- 文件按职责而非层次命名与放置；目录中集合用复数、单个功能用单数；避免 `utils/`、`helpers/`、`common/` 这类无主目录。
- 单文件中的常量、类型与辅助函数就近放置于使用处；被多个文件共用时提升到模块内公共文件，不新增全局杂物堆。
- 文件移动属于结构变更，与逻辑编辑分开实施；移动目标与引用更新按 `refactoring` 的安全手法执行。
- 静态资源按类型分目录放置，资源名用 kebab-case，相关时带倍率或尺寸；不编码营销活动或人名。
- 测试 fixture 放 `fixtures/` 或 `testdata/`，快照放 `__snapshots__/`，基准文件放 `golden/`。
- 迁移文件带时间戳并保持有序；生成数据与压缩资源属于构建输入，不参与手工排版。
