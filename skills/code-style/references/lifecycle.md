# code-style 生命周期契约

本文件是 `code-style` 的阶段契约：阶段职责、门禁证据、交接与升级、裁剪与度量。阶段与门禁编号由 `project-lifecycle` 裁定，本文件只写本 skill 在各阶段的输入、活动、输出与证据形态。

## 阶段职责

| 阶段 | 输入 | 活动 | 产出与证据 |
|---|---|---|---|
| S0 受理 | 风格、依赖或配置类请求 | 复述对象与范围，判断改动是否可逆、是否触及共享配置或 CI 脚本 | 受理记录、风险级别 R0/R1/R2 |
| S1 需求 | 现状事实：现有 formatter、linter、manifest、锁文件、配置加载器与 CI 命令 | 记录不一致的样式、未锁定的工具与未校验的配置，列出待决项 | 风格现状清单、约束清单 |
| S2 设计 | 现状清单、`architecture-design` 的边界与 `security-compliance` 的判据 | 选定工具与唯一取值，确定依赖策略与配置优先级 | 配置方案、准入结论、配置 schema |
| S3 构建 | G2 通过的方案 | 落地最小配置变更或代码变更；机械变更与行为变更分提交；同步文档 | 配置 diff、独立格式化提交、锁文件变更 |
| S4 验证 | 增量与测试策略 | 在干净检出上运行格式校验、lint、构建与相关测试，核对 diff | 命令输出与退出码、diff 核对结论 |
| S5 发布 | 验证证据 | 确认发布制品中无构建产物、缓存与未审查的依赖 | 制品清单、冻结模式安装记录 |
| S6 运维 | 运行日志与配置事实 | 依据级别与内容策略判断日志与配置缺陷，归入修复待办 | 故障中的日志证据、配置漂移记录 |
| S7 收尾 | 全程记录 | 复盘风格与依赖规则是否被 CI 强制，遗留项移交 | 复盘记录、遗留项清单 |

## 门禁证据

G0：请求复述、授权依据、风险级别与停止条件；触及共享 CI 配置或生产配置时按 R2 处理。
G1：风格现状清单与约束清单；未列入清单的现状不得当作已确认事实。
G2：工具选型与行宽等唯一取值、依赖准入结论、配置优先级与校验方案、排除目录；缺唯一取值或准入证据时 Hold。
G3：配置 diff、仅含 formatter 命令的机械变更提交、锁文件与 manifest 同步、重新生成的输出；风格与行为混在一个 diff 时 Recycle。
G4：干净检出上的格式校验、lint、构建与相关测试的输出与退出码；CI 未跑或 diff 中出现构建产物与机密时不得通过。
G5：制品清单与冻结模式安装记录；无法从锁文件复现安装时 Hold。
G6/G7：故障日志证据与复盘记录；只作记录，不作为发布前门禁的替代。

## 交接与升级

上游交接：`architecture-design` 提供模块边界与依赖方向；`security-compliance` 提供漏洞、许可证与供应链判据；`testing-quality` 提供 CI 中的门禁位置。
下游交接：格式与 lint 命令交 `testing-quality`；日志字段 schema 与告警规则交 `release-operations`；配置键参考页交 `documentation`；生成目录排除项交 `project-structure`。

升级条件：工具版本未锁定、风格与行为混在同一 diff、依赖准入缺健康度或许可证证据、机密出现在配置或日志中时停止并回报；强制规则冲突时报告用户裁决。停止条件：无授权不得改动共享 CI 或部署脚本；无证据不得宣称验证通过。

## 裁剪与度量

裁剪：R0 只保留受理、一次验证与交付记录；R1 使用精简计划与 G4 非作者审查；R2 需独立审查与回滚演练，不得自批。风格、依赖与配置的证据不因裁剪而省略。

度量：格式化告警数、lint 违规数、未锁定工具数、配置漂移次数按基线比较趋势；指标恶化时先查根因，不调整阈值。度量不替代门禁判断。
