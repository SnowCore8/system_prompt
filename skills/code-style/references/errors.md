# 错误处理

## 1. 错误处理

错误是生产故障的见证：原因丢失、错误分类错置或吞掉错误的 catch，会把事故变成猜测。

- 一个模块只选一种错误风格：异常用于意外且不可恢复的情况，错误值或结果值用于预期的领域结果；
  不在一个 API 中混用，并在公开接口面声明所选风格。
- 按来源分类：领域错误是预期的业务失败，由调用方处理；系统错误是意外的运行失败，由响应者处理；分类写在模块公开接口面。
- 不吞掉错误：仅为处理、补充上下文或转换结果而 catch；空 catch、每层记录再重抛、把一切失败映射为一个通用错误都会破坏证据链。
- 补充上下文并保留原因：`raise InvoiceSyncError(...) from exc`、`fmt.Errorf("sync: %w", err)`；以不丢堆栈的方式包装。
- 在 API 边缘把内部错误映射为公开错误码，不向客户端泄露堆栈、SQL、内部主机名或异常类名；错误码目录由 `api-data` 的契约裁定。
- 返回可操作的错误消息：说明什么失败了、下一步能做什么、关联 ID；启动失败时点名阻塞的键或依赖。
