# 命名

名称是代码库中阅读次数最多的接口。好名称说明事物是什么、做什么、贴合语言并在各层之间稳定；坏名称迫使每个读者钻进实现才能理解意图。本 skill 规定命名的决策流程与各类命名产物的规则集，既服务于写名称的作者，也服务于审查名称的评审者。

## 适用范围与优先级

效力按下列层级判定，高层覆盖低层，低层只在高层未规定时补充。

1. 平台、语言与宿主约束：Go 的导出标识符、C# 的接口约定与 PEP 8 属于语言要求，不存在豁免。
2. 本 skill 的规则：名称的术语、大小写、语法形式、禁用同义词与命名表以本文件与 `references/` 为准。
3. 项目约定与事实：现有代码、命名表、lint 配置与语言版本是输入；项目约定只在本 skill 未规定处补充，不得覆盖本 skill。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 本 skill 裁定名称本身；提交流程与分支模型归 `vcs-collaboration`，API 版本化与 schema 演进归 `api-data`，格式化与行宽归 `code-style`，测试命名之外的测试策略归 `testing-quality`。
- 生成代码、第三方引入代码与外部协议字段保留原名，在边界处隔离并把映射记入命名表。
- 重命名属于一次变更，不是顺手清理：先读全部引用，在授权范围内更新测试、文档与 fixture；公开名称视为 API。
- 同一概念只允许一个名称，同一名称不得指两件事；新增术语在第二处使用前登记进命名表。

## 生命周期定位

上游输入：S2 设计中的接口契约、数据模型、目录与包边界、发布与分支方案，它们决定需要哪些名称与跨层映射。下游交接：S3 构建中的实现与审查、S4 验证中的命名 lint 与一致性核对、S5 发布中的标签与发布说明。

升级与停止：公开名称重命名、跨仓库共享标识符、需要版本化或弃用的名称变更，退回 G2 重新确认并取得授权；命名表与既有契约冲突且授权范围内无法裁决时，停止并报告冲突双方。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 把接口、数据、配置、目录与发布产物名称纳入设计，确定禁用同义词与命名 lint 规则 | 命名表、跨层名称清单、lint 规则 |
| S3 构建 | 按各维度规则命名新增标识符；重命名按引用清单与回滚点执行 | diff 中的名称、命名表更新、引用清单 |
| S4 验证 | 核对跨层一致性与命名 lint 结果，检查公开名称的别名或弃用路径 | lint 输出、跨层映射、别名或弃用证据 |
| S5 发布 | 核对发布标签、发布说明与变更记录中的名称与命名表一致 | 标签与说明的一致性检查 |

## 门禁与证据

证据必须可复核：lint 命令与输出、diff 行号、命名表条目；计划与口头承诺不构成证据。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 命名表、跨层名称清单、命名 lint 规则、重命名影响与回滚说明 | 缺命名表或公开名称未定时 Hold |
| G3 构建 | 命名 lint 输出、diff 与大小写矩阵一致、重命名引用清单 | Recycle 到 S3；公开名称无别名或弃用路径时按 No-Go 阻断 |
| G4 验证 | 跨层一致性核对、lint 通过记录、别名与弃用证据 | 修复后重验；无法兼容的公开改名按 No-Go |
| G5 发布 | 发布标签、发布说明与命名表一致 | Hold 发布，修正名称后再过门 |

## 维度索引

每个维度的完整规则、默认值与示例见对应文件；详情列的节号即该文件中的章节编号。

| 编号 | 维度名 | 首条规则 | 详情 |
|---|---|---|---|
| 1 | 文件与目录 | 名称小写、不含空格，按主要导出或职责命名，测试文件与被测单元同名。 | `references/files.md` 第 1 节 |
| 2 | 包与命名空间 | 采用反向域名或简短小写名称，按领域而非层次命名，公开接口保持稳定。 | `references/packages.md` 第 1 节 |
| 3 | 类型与接口 | 类型用单数名词短语，接口体现能力或角色，C# 之外不使用 I 前缀。 | `references/types.md` 第 1 节 |
| 4 | 函数与方法 | 动作用动词短语，谓词用布尔形容词，一个名称对应一个动作。 | `references/functions.md` 第 1 节 |
| 5 | 变量、参数与常量 | 按作用域控制长度，不编码类型，常量用 UPPER_SNAKE 并带单位。 | `references/variables.md` 第 1 节 |
| 6 | API 与序列化 | 资源用复数，路径用 kebab-case，每个 schema 只选一种 JSON 键大小写。 | `references/api.md` 第 1 节 |
| 7 | 数据库与配置 | 表用复数 snake_case，列用单数，索引带前缀，环境变量用带应用前缀的 UPPER_SNAKE。 | `references/database-config.md` 第 1 节 |
| 8 | 测试与提交 | 测试名写行为加条件，提交用 `type(scope): summary` 并说明原因。 | `references/tests-commits.md` 第 1 节 |
| 9 | 分支、标签与资产 | 分支用 `type/slug`，发布标签用带 v 前缀的 SemVer，资产文件用 kebab-case。 | `references/branches-tags-assets.md` 第 1 节 |
