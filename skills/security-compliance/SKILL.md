# 安全与合规

安全与合规失效具有不对称性：凭据进入提交历史、copyleft 库随制品分发、个人数据流向未批准的处理者，都无法事后修复，因为泄露已经发生。
本 skill 规定威胁建模、机密管理、供应链、许可证、隐私与披露的规则及每项规则所需的证据；法律条文与合同问题移交法务，本 skill 不构成法律意见。

## 适用范围与优先级

效力依下列层级判断，高层覆盖低层，低层仅在高层未规定时补充：

1. 强制约束。法律、法规、合同、许可证条款与宿主指令不可选；本 skill 的任何默认值不得放松它们。
2. 本 skill 的规则。控制措施、修复期限、例外与披露承诺以本文件与 `references/` 为准。
3. 项目事实。`SECURITY.md`、`LICENSE`、数据清单、已接受风险登记册与既有扫描配置先阅读后裁定；它们在本 skill 未规定处补充。
4. 个人偏好，不得覆盖以上三层。

边界：

- 智能体何时必须取得授权、何时先止损，由全局用户约束的 AUT 与 SEC 条款裁定；本 skill 只规定项目策略：
  什么数据可以收集、存储与披露，以及每项由谁批准。
- 机密扫描的门禁位置与阈值归 `testing-quality`；本 skill 管辖严重程度、修复期限与例外批准。制品签名与发布流程归 `release-operations`。
- `SECURITY.md` 的存在与位置归 `project-structure`；本 skill 管辖其内容与响应承诺。
- 同一层级强制规则冲突时报告用户裁决，不得自行选定。

## 生命周期定位

上游：G0 的数据类别与授权，G1 的需求与约束，`architecture-design` 的边界与数据流。下游：威胁模型与许可证分类进入 G2；
扫描结论与 SBOM 进入 G4；签名与披露状态进入 G5；事故复盘进入 S7 并回写运行手册与测试。停止条件：确认泄露先按 AUT-5 止损、
按 SEC-6 保留证据并报告；许可证未识别的依赖禁止引入；必需审查未完成不得合并。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 列出资产、数据类别与信任边界，确认风险级别与受保护对象 | 分级结论、受保护对象清单 |
| S1 需求 | 初步判断是否涉及个人数据、凭据、第三方代码或生产 | 初步威胁与合规约束清单 |
| S2 设计 | 完成威胁模型、许可证分类、依赖策略与 PII 清单 | 威胁模型、许可证分类、审查分派 |
| S3 构建 | 落实默认拒绝、边界校验、凭据注入，运行机密与依赖扫描 | 控制措施、扫描结果、安全债务条目 |
| S4 验证 | 评定发现项、确定修复期限、处理例外并生成 SBOM | 扫描与审计结论、例外记录 |
| S5 发布 | 复核 SBOM、声明、签名与披露状态 | 发布证据包、残余风险 |
| S6 运维 | 分诊新告警、安排补丁、监控凭据轮换与例外到期 | 告警处置记录、补丁记录 |
| S7 收尾 | 复盘事故与泄露，更新威胁模型与运行手册，关闭或续期例外 | 事后审查、改进项与负责人 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G0 受理 | 数据分类、资产与信任边界清单、风险级别与授权依据 | Hold：分类缺失时不得处理生产数据或凭据 |
| G2 计划 | 威胁模型或一行"未跨越边界"、许可证分类、依赖审查记录、PII 清单 | Recycle 到 S2：信任边界无模型；No-Go：许可证禁止项无替代 |
| G4 验证 | 扫描结果与严重程度、修复期限、VEX 或例外记录、SBOM 与许可证报告 | Hold：扫描未运行或结果过期；Recycle：高危未修复且无接受记录 |
| G5 发布 | 重新生成的 SBOM 与声明、签名或来源证明、披露与公告状态 | Hold：制品缺 SBOM 或签名；No-Go：确认泄露未轮换 |
| G7 收尾 | 例外关闭或续期记录、控制改进项与负责人、威胁模型更新 | Hold：过期例外未处置；继续整改 |

证据必须对应具体提交与制品；依赖树变化后旧扫描结果失效。例外含负责人、到期日与补偿控制，口头接受不构成证据。

## 核心规则

- 每个信任边界一份轻量威胁模型，不跨越边界的功能记录一行说明。
- 默认拒绝：新权限、新字段、新开关默认关闭，新端点默认要求认证。
- 机密值只经运行时注入，不得进入仓库、日志或构建产物；命中后先轮换再清理。
- 依赖视为待分发的代码：审查维护状况、漏洞与许可证，锁文件固定版本。
- 每次发布依制品依赖图生成 SBOM 与声明文件并随制品分发。
- 个人数据收集前分级并登记用途、保留期限与接收方。
- 披露遵守承诺的时间线，公告与修复同时发布，不得静默修复。
