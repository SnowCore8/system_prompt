# 安全与合规：威胁模型

威胁模型回答“谁可能伤害什么、如何伤害、现有控制是否足够”。它的价值在于限定投入：
高风险边界深挖，不跨越边界的改动一行带过，避免安全审查流于形式。

## 1. 威胁模型
- 功能跨越信任边界、新增接口或权限、引入新数据类别或第三方代码时，均须更新威胁模型。
- 触发条件依实际变更判定：接受不可信输入、跨服务调用、授予访问权限、存储新类别数据均属跨越边界。
- 完全不跨越边界的功能，在变更记录中写一行“未跨越边界”，不必展开模型。

## 2. 模型内容

一页模型至少覆盖六项：资产及其价值、入口点、信任边界、滥用场景、现有控制、残余风险与负责人。

- 资产用具体名称，不用类别代称；入口点列出方法、路径或事件，不写"所有接口"。
- 滥用场景按"攻击者能力 + 资产"逐一列举，每条对应一项控制或一项残余风险。
- 残余风险必须写明负责人与缓解计划；无负责人即视为未处理。

## 3. 投入与更新

- 投入随风险调整：涉及资金、生产数据或外部用户的功能深挖，内部只读工具一行带过；不得反向。
- 入口点、数据类别或信任边界变化时更新模型；旧模型不能作为当前设计的证据。
- 事故复盘发现的缺口回写模型，并给出负责人与到期日。
