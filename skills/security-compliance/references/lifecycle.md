# 安全与合规生命周期契约

本文件规定本 skill 在 S0–S7 中的职责、门禁证据、交接与升级、裁剪与度量。控制措施细节见六个维度文件；
阶段与门禁编号由生命周期治理模型裁定，本 skill 主责 S2 的安全计划、S4 的安全结论与 S5 的发布前复核。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 |
|---|---|---|---|
| S0 受理 | 请求、涉及的系统与数据 | 列出资产、数据分类与信任边界，确认风险级别与授权 | 分级结论、受保护对象清单 |
| S1 需求 | 分级结论与方案选项 | 判断是否涉及个人数据、凭据、第三方代码或生产变更 | 初步威胁说明、合规约束清单 |
| S2 设计 | 初步威胁与设计输入 | 完成威胁模型、许可证分类、依赖策略、PII 清单与审查分派 | 威胁模型、许可证分类、清单条目 |
| S3 构建 | 威胁模型与控制要求 | 落实默认拒绝、边界校验、凭据注入，运行机密与依赖扫描 | 控制措施说明、扫描结果 |
| S4 验证 | 增量与扫描结果 | 评定发现项、确定修复期限、处理例外并生成 SBOM | 安全与合规结论、例外记录 |
| S5 发布 | 验证结论与发布候选 | 复核 SBOM、声明、签名与披露状态 | 发布证据包、残余风险 |
| S6 运维 | 运行中的告警与依赖更新 | 分诊新告警、安排补丁、监控凭据轮换与例外到期 | 告警处置记录、补丁记录 |
| S7 收尾 | 事故、泄露与发布后反馈 | 复盘根因、更新威胁模型与运行手册、关闭或续期例外 | 事后审查、控制改进项 |

S3 与 S4 的边界是扫描与评定的分界：扫描随提交持续运行，结论必须在 G4 前出具，
依赖树变化后重新生成。

## 门禁证据

| 门禁 | 证据包 | 失效条件 |
|---|---|---|
| G0 | 数据分类、资产与信任边界清单、风险级别、授权依据 | 分类缺失，或处理生产数据无授权 |
| G2 | 威胁模型或“未跨越边界”说明、许可证分类、依赖审查记录、PII 清单 | 信任边界无模型，或审查未分派 |
| G4 | 扫描结果与严重程度、修复期限、例外记录、SBOM 与许可证报告 | 扫描未运行、结果过期，或高危无接受记录 |
| G5 | 重新生成的 SBOM 与声明、签名或来源证明、披露状态 | 制品缺 SBOM、签名不可验证，或公告与版本不符 |
| G7 | 例外关闭或续期记录、改进项与负责人、更新的威胁模型 | 过期例外未处置，或改进项无人负责 |

证据组织：扫描输出与 SBOM 附在发布记录并关联具体制品与提交；例外写明缺口、补偿措施、负责人与到期日；
威胁模型随设计变更更新；公开前的漏洞材料只经私有渠道流转。

## 交接与升级

- 从 `project-lifecycle` 接收 G0 风险级别与受保护对象；涉及生产、凭据、个人数据的
  自动升至 R2 流程。
- 从 `architecture-design` 接收边界与数据流，用于更新威胁模型；从 `api-data` 接收数据模型与删除路径，用于核对 PII 清单。
- 扫描门禁的位置与阈值交给 `testing-quality`；发布流水线与制品晋级交给 `release-operations`，SBOM、签名与声明的验证结论由本 skill 出具；事故响应与值守交给 `release-operations`，退役与归档交给 `maintenance-retirement`，复盘结论回写本 skill 的威胁模型。
- 升级：确认泄露或漏洞被利用时按 AUT-5 先止损、按 SEC-6 保留证据并报告；未知许可证停止引入依赖；新处理者或跨境传输转隐私审查；无法取得 CVE 编号时记录申请状态，不得虚构。
- 停止：必需审查未完成、许可证未识别或泄露调查未结束时停止受影响步骤，报告证据与受阻项。

## 裁剪与度量

| 级别 | 裁剪 | 不可裁剪项 |
|---|---|---|
| R0 | 未跨越边界的功能一行说明，扫描沿用既有配置 | 机密扫描与许可证检查 |
| R1 | 一页威胁模型、许可证分类与依赖审查记录 | 必需审查、例外记录与修复期限 |
| R2 | 完整威胁模型、独立安全结论、SBOM 与签名、披露计划 | 独立结论不得自出，G4 与 G5 不得合并 |

度量：以未修复高危数、例外逾期数、凭据轮换逾期数与披露时限达标率为准；数值上升时先查分类与责任人，不得放宽期限。
单人维护的披露时限标注为尽力而为，不对外承诺 SLA。
