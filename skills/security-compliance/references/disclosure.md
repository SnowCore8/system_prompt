# 安全与合规：协同披露

披露流程决定修复与公告谁先到达用户：先修复后公告，用户有时间打补丁；先公开后修复，
漏洞被利用的窗口无限延长。流程写进 `SECURITY.md`，时限写进承诺。

## 1. 渠道与范围

- 公开报告渠道：私有漏洞报告、安全公告与联系邮箱写入 `SECURITY.md`；报告范围写明适用与不适用的对象。
- 渠道必须有人监控，报告到达记录时间戳；漏洞细节在公告前不得进入公开议题。
- 报告者署名随其同意写入公告；不署名的保持匿名。

## 2. 时间线

- 自报告到达起 2 个工作日内确认收到；5 个工作日内完成初步分诊并评定严重程度。
- 严重问题自分诊起 7 个自然日内发布修复；修复与公告同日发布，公告含受影响版本、修复版本与升级动作。
- 单人维护时上述时限标注为尽力而为；有 CNA 时申请 CVE 编号，无法取得时记录申请状态与联系对象，不得虚构编号。

## 3. 协调与收尾

- 与报告者协调发布日期；禁发期内不向第三方泄露细节；多项目受影响时协调统一发布。
- 发布后核对公告、变更日志与 `SECURITY.md` 与实际状态一致；复盘写入 S7 并回写威胁模型与测试。
