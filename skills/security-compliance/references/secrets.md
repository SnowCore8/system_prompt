# 安全与合规：机密存储与轮换

机密指密码、私钥、机密 API key、会话令牌与含凭据的连接串。机密管理的目标不是“找得到即可用”，而是泄露后可快速吊销且影响面受限。

## 1. 机密存储与轮换
- 仓库中只提交对机密的引用：环境变量注入、机密管理器或平台机密存储；真实值不得进入提交、日志、构建产物或错误报告。
- `.env.example` 只含变量名与不可用的假值；真实 `.env` 类文件必须被忽略并受扫描保护。
- 运行时凭据按环境隔离：CI 机密打码显示，不提供给不受信任的 fork 构建。

## 2. 范围与轮换

- 每个服务、任务与环境各签发一个凭据，限制至其所需资源与操作；共享管理员凭据属于永久性发现项。
- 每个凭据登记范围、负责人、轮换间隔与下次轮换日期；到期未轮换按发现项处理。
- 轮换前先验证新值可用并完成发布，再吊销旧值；轮换顺序写进运行手册。

## 3. 扫描与泄露处置

- 机密扫描覆盖提交、拉取请求、历史与构建日志；命中在推送前阻断，绕过需具名批准与到期日。
- 已暴露的值先吊销或轮换，再清理可见副本并调查使用痕迹；历史中的值即使已删除仍按已暴露处理。
- 怀疑泄露时停止操作、保留证据并报告，调查结束前不清理痕迹。
