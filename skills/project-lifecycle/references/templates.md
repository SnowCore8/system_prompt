# 模板与记录

## 1. 模板与记录
模板只规定最小字段，不规定篇幅。R0 可以只保留一段记录；R1 使用完整字段但可精简；R2 必须保留证据链接与
批准记录。所有字段均为必填，除非标注“可选”。

- 模板是证据载体，不是官僚检查表；没有决策价值的字段可以合并，但不得删除授权、风险、验收、回滚与收益
  字段。
- 记录应当在门禁发生时完成；事后补记必须标注补记时间与当时已知事实。
- 记录中的敏感信息按 SEC 处理，不得把凭据、个人信息或内部地址写入可广泛分发的模板。
- 模板版本由项目维护；修改模板后，下一次门禁使用新版本，已完成的记录保持原样。

## 2. 受理记录

| 字段 | 填写要求 |
|---|---|
| 请求 | 一句话复述对象、动作与预期结果 |
| 分类 | 提问、动作请求、陈述、歧义、混合、对象不明等 |
| 授权 | 任务级、计划级或逐次明确同意；写明依据 |
| 风险级别 | R0/R1/R2 与判断依据 |
| 影响面 | 文件、系统、数据、用户、生产与共享资源 |
| 停止条件 | 出现何种错误、成本、风险或证据时停止 |
| 负责人 | 决策人、执行人与沟通路径 |
| 下一门禁 | G0–G7 中的下一个门禁与时间 |

## 3. 需求说明

| 字段 | 填写要求 |
|---|---|
| 需求 | 当前状态、受影响用户与不做的后果 |
| 结果 | 可测量的结果指标与收益基线 |
| 范围 | 包含与不包含的事项 |
| 约束 | 法规、平台、预算、时间、技术、安全与隐私 |
| 选项 | 至少两个方案，含“不做事”，比较成本、风险与收益 |
| 优先级 | 排序依据与相对其他待办的位置 |
| 建议 | 继续、缩小、延期或停止，并说明理由 |
| 风险 | 主要风险、触发信号与缓解措施 |
| 决策 | 批准人、日期与条件 |

## 4. 计划与 ADR

| 字段 | 填写要求 |
|---|---|
| 目标 | 本阶段或本迭代要交付的结果 |
| 验收 | 可判定的验收标准与验收人 |
| 设计 | 模块、接口、数据、目录、依赖与关键决策 |
| 任务 | 拆分到可估算、可验收的条目 |
| 依赖 | 内部与外部依赖、提供者与可用时间 |
| 风险 | 概率、影响、缓解、负责人与复审时间 |
| 测试 | 层级、环境、数据、覆盖目标与失败处理 |
| 发布 | 版本、变更记录、部署、回滚与可观测性 |
| DoR | 每条是否满足 Definition of Ready |

ADR 的字段与状态取值由 `architecture-design` 管辖，见其 `references/adr.md`。

## 5. 测试策略

| 字段 | 填写要求 |
|---|---|
| 层级 | 单元、集成、端到端、回归与人工验收的范围 |
| 环境 | 所需环境、数据与隔离方式 |
| 门禁 | 进入 CI、合并与发布必须通过的校验与阈值 |
| 覆盖 | 覆盖目标、豁免清单与未验证项 |
| 数据 | 测试数据来源、虚假值与敏感数据处理 |
| 失败处理 | 失败时的定位、修复、回归与重跑规则 |

## 6. 发布与回滚计划

| 字段 | 填写要求 |
|---|---|
| 版本 | 版本号、制品与哈希 |
| 部署 | 环境、路径、批次、观察窗口与权限 |
| 回滚 | 触发条件、步骤、时间与演练记录 |
| 观测 | 日志、指标、追踪、告警与健康检查 |
| 通告 | 用户、依赖方与内部通告的内容与时间 |
| 值守 | 发布期间的值班人与升级路径 |

## 7. 运维手册

| 字段 | 填写要求 |
|---|---|
| 启动与停止 | 顺序、依赖、健康检查与优雅关闭 |
| 备份与恢复 | 备份范围、频率、保留期与恢复步骤 |
| 扩容与限流 | 扩容触发条件、操作步骤与限流策略 |
| 故障处置 | 常见故障、现象、排查步骤与止损动作 |
| 告警 | 告警清单、阈值、责任人与升级路径 |

## 8. 门禁记录

| 字段 | 填写要求 |
|---|---|
| 门禁 | G0–G7 与阶段名 |
| 时间与地点 | 日期、时区、会议或异步记录链接 |
| 参与人 | 批准人、执行人、审查者与记录人 |
| 风险级别 | R0/R1/R2 与依据 |
| 证据 | 每项证据的链接、命令输出或指标 |
| 决定 | Go、Conditional Go、Hold、Recycle、No-Go 或 Defer |
| 条件 | 条件、负责人、到期日与关闭证据 |
| 未解决项 | 风险、缺陷、依赖与升级路径 |
| 下一门禁 | 阶段、时间与前置条件 |

示例：

| 字段 | 内容 |
|---|---|
| 门禁 | G4 验证门 |
| 证据 | 单元与集成测试通过；依赖审计无高危；独立审查通过 |
| 决定 | Conditional Go |
| 条件 | 性能回归基线在发布前补齐；负责人为性能负责人；到期日为下一工作日 |
| 下一门禁 | G5 发布门，条件关闭后召开 |

## 9. 验证证据包

| 字段 | 填写要求 |
|---|---|
| 范围 | 验证覆盖的变更、版本与提交 |
| 命令与环境 | 测试命令、环境版本与数据说明 |
| 输出 | 真实输出、退出码与覆盖数据 |
| 缺口 | 未运行、未覆盖项与原因 |
| 结论 | 通过、失败或有条件通过；验收人结论 |
| 审查 | 审查者、意见与处理方式 |

## 10. 收尾报告

| 字段 | 填写要求 |
|---|---|
| 结果 | 对照 G1 基线的收益、采用率与用户结果 |
| 偏差 | 范围、时间、成本、质量与风险的偏差及原因 |
| 质量 | 缺陷、事故、变更失败率与遗留问题 |
| 教训 | 什么有效、什么无效、意外与下一次改变 |
| 行动 | 行动项、负责人、到期日与验证方式 |
| 资产 | 代码、文档、数据、环境与访问权限的归档或移交 |
| 关闭 | 未完成事项的转移、接受或取消决定 |

## 11. 事故复盘

| 字段 | 填写要求 |
|---|---|
| 时间线 | 发现、响应、止损、恢复与通告的时间点 |
| 影响 | 用户、数据、收入与信誉的影响范围 |
| 根因 | 直接原因、系统性原因与未起作用的控制 |
| 发现 | 监控缺口、流程缺口与文档缺口 |
| 行动 | 行动项、负责人、到期日与验证方式 |

事故复盘关注事实与系统性改进，不追究个人；复盘结论更新运行手册、测试与告警。

## 12. 登记表

变更请求：基线、变更内容与原因、影响、选项（含“不变更”）、回滚方式、决定（批准人、条件、到期日与
重新评审的门禁）。范围、验收、日期或风险变化时重新过门，不得在构建或发布中静默改变目标。

风险登记：风险、概率与影响、触发信号、缓解、负责人、复审日期与门禁。超过复审日期未处理的，升级并进入
门禁记录。

依赖登记：依赖类别（技术、数据、团队、供应商或合规）、提供者与消费者、窗口、验证方式、失败回退、升级
路径。依赖未经提供者确认时，不得把相关门禁判为 Go。

例外记录：被偏离的规则、范围与期限、理由与影响、补偿控制、批准人与复核人。到期未复核的例外自动失效；
智能体不得自批例外，也不得把例外写成项目约定。
