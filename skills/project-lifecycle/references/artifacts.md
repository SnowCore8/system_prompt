# 工件通用规则

## 1. 工件通用规则

工件是阶段决定的可复核载体：每个工件有唯一权威归属与负责人，证据必须能让未参与者独立复核。模板字段
见 `templates.md`。

- 每项事实只保留一个权威归属；其他工件链接至该归属，不复制内容。
- 工件必须标注负责人、状态与日期；计划中的内容不得写成已实现事实。
- 占位符、TODO 与虚假值必须显式标记、纳入跟踪并在交付中说明；生产路径不得使用未披露的占位内容。
- 工件厚度随风险级别裁剪，但授权、风险、验收、回滚与收益字段不得删除。
- 记录中的敏感信息按 SEC 处理，不得写入凭据、个人信息或内部地址。

## 2. 工件清单与归属

| 工件 | 最小内容 | 负责人 | 门禁 |
|---|---|---|---|
| 受理记录 | 请求、分类、授权、风险级别、停止条件 | 项目负责人 | G0 |
| 需求说明 | 需求与用户、结果指标、约束、选项、优先级、收益基线 | 产品负责人 | G1 |
| 计划与待办 | 范围、验收、任务、依赖、风险、测试、发布与回滚 | 项目负责人 | G2 |
| 架构与 ADR | 背景、决定、替代方案、后果、状态 | 架构负责人 | G2/G3 |
| 测试与质量策略 | 层级、环境、数据、门禁、覆盖率基线、未验证项 | 质量负责人 | G2/G4 |
| 发布与回滚计划 | 版本、制品、部署、权限、验证、回滚、通告、值守 | 运营负责人 | G5 |
| 运维与运行手册 | 监控告警、值守升级、备份恢复、容量、故障处置 | 运营负责人 | G6 |
| 门禁记录 | 门禁、日期、风险、证据、决定、条件、下一门禁 | 项目负责人 | G0–G7 |
| 验证证据包 | 测试输出、审查结论、性能与安全证据、验收结论 | 质量与安全 | G4/G5 |
| 收尾与收益报告 | 收益、偏差、成本、教训、行动项、退役归档与交接 | 项目负责人 | G7 |
| 事故复盘 | 时间线、影响、根因、发现、行动项 | 运营负责人 | 事故后 |

生命周期记录组还包括决策日志、证据索引与变更日志：决策日志按时间记录每个门禁与变更决定；证据索引把
门禁记录链接到测试输出、审查结论与指标；变更日志记录基线与范围的变化。三者的保留与销毁由
`security-compliance` 与 `project-structure` 裁定。

## 3. 证据包与追溯

- 验证证据包至少包含命令、环境、版本、输出、覆盖缺口与审查结论。
- 门禁记录必须能追溯到测试输出、审查结论、指标或批准；无法追溯的证据视为不存在。
- 证据按强度分级：实际运行输出与独立审查最强，可复现的静态检查次之，设计说明与计划最弱。
- 未运行的验证标注“未运行”，不得以计划中的验证冒充已完成。
