# 生命周期治理自身契约

本 skill 不交付业务增量，它交付的是可复核的阶段决定。本文件说明它在 S0–S7 与 G0–G7 中必须留下什么，
以及何时把决定交给专业 skill、人工批准者或组合委员会。逐阶段的完整活动在 `stages.md`，门禁判据在
`gates.md`。

## 阶段职责

| 阶段 | 输入 | 本 skill 的活动 | 输出 |
|---|---|---|---|
| S0 受理 | 请求、上下文、已有授权 | 分类、复述、分级、固定停止条件与负责人 | 受理记录、风险依据 |
| S1 需求 | 受理记录、用户与业务事实 | 组织需求澄清、结果指标、选项与收益基线 | 需求说明、G1 建议 |
| S2 设计 | 需求说明、设计与依赖事实 | 固定范围与验收，组织任务拆分、设计与回滚方案 | 计划基线、风险与依赖登记 |
| S3 构建 | 计划基线、迭代目标 | 检查 DoR/DoD、WIP 与交接 | 迭代记录、增量证据 |
| S4 验证 | 增量、测试策略、验收标准 | 组织测试、安全、性能与独立审查 | 验证证据包、验收结论 |
| S5 发布 | 验证证据、发布与回滚方案 | 组织发布准备、生产授权、观测与通告 | 发布记录、G5 决定 |
| S6 运维 | 发布记录、运行指标、告警 | 组织监控、事故响应与恢复演练 | 运维记录、事故复盘 |
| S7 收尾 | 运维记录、指标、事故与变更 | 收益对照、复盘、退役归档、交接与退出 | 收尾报告、行动项 |

## 门禁证据

| 门禁 | 本 skill 的检查点 | 不合格时 |
|---|---|---|
| G0 | 授权、对象、风险级别、停止条件与负责人是否齐全 | 澄清或 Hold |
| G1 | 需求与用户、结果指标、收益基线与选项比较是否成立 | Recycle 或 No-Go |
| G2 | 范围、验收、设计、测试、依赖与回滚方案是否可执行 | Hold 或 Recycle |
| G3 | DoR/DoD、WIP、增量与交接记录是否完整 | Recycle 到 S3 |
| G4 | 证据是否可追溯、独立审查是否完成、未验证项是否披露 | Recycle 或 Hold |
| G5 | 回滚演练、生产授权、观测与通告是否就绪 | Hold |
| G6 | 监控告警、恢复演练、事故记录与值守路径是否可用 | Recycle 到 S6 |
| G7 | 收益对照、行动项、退役归档与交接是否完成 | 补充证据或继续整改 |

门禁证据必须来自实际执行，计划、口头保证与“应该没问题”不构成证据。本 skill 只判断证据是否足以支撑
决定，不代替专业 skill 出具技术结论，也不代替人工批准 R2。

## 交接与升级

- 向产品负责人交接：需求、结果指标、收益基线与验收建议。
- 向架构、安全、测试、发布等专业 skill 交接：阶段、风险级别、所需证据与停止条件。
- 向运营交接：发布记录、回滚触发条件、观测项、未关闭风险与值守安排。
- 向组合委员会交接：收益、成本、容量、依赖与退出建议。
- 升级触发：风险上升、关键依赖未确认、同一问题连续两次 Recycle、证据冲突、角色缺位或出现安全与不可逆
  风险。

## 裁剪与度量

R0 可合并记录与门禁，但保留授权、验证与交付三项事实；R1 使用精简工件与独立审查；R2 保留完整章程、
设计、验证、回滚演练与人工批准。裁剪只减少工件与会议，不减少证据、审查、安全控制与授权。

治理度量关注：门禁条件关闭率、证据完整率、风险老化天数、决策等待时间、收益实现率与依赖确认率。度量
用于判断治理是否有效，不用于排名；指标恶化时先查流程与证据质量，不得直接调整目标。
