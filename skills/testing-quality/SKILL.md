# 测试与质量门禁

质量门禁以四种方式失效：测试不断言任何内容，只证明进程能启动；门禁在截止压力下被豁免，直至无人记得绿色
的含义；本地与 CI 各自维护一份命令，一台机器通过无法说明另一台；不稳定测试被无限重试，直至红色套件成为
常态。本 skill 规定测试层级的选择流程、门禁与覆盖率基线的定义方式、静态分析的严重级别与升级路径、本地与
CI 的对齐规则，以及不稳定测试的隔离与修复流程，并把证据接入 S4 验证门禁。

## 适用范围与优先级

效力按下列层级判断，高层覆盖低层：

1. 平台、法律与宿主的强制约束，包括托管平台预设的必需校验与监管校验。
2. 本 skill 的规则与默认值，见本文件与 `references/`。
3. 项目既有配置与约定。自定阈值前先读 CI 配置、测试运行器设置、覆盖率配置与 bootstrap 脚本；这些属于
   事实输入，依本 skill 的规则处理。
4. 个人偏好，不得覆盖以上三层。

边界与例外：

- 格式化与 linter 的风格规则归代码风格 skill；本 skill 只规定哪些静态校验成为门禁及其严重级别。
- CI/CD 流水线、环境晋级与可观测性归 `release-operations`；本 skill 规定必须存在哪些门禁与阈值，不规定
  流水线实现。
- 依赖漏洞的严重程度与修复期限归安全合规 skill；本 skill 规定漏洞扫描的运行位置与阻塞阈值。
- 契约设计归 API 契约 skill；本 skill 规定契约变更所需的契约测试。
- 生成代码、第三方引入代码、迁移脚本与入口粘合代码不受覆盖率门禁约束，排除项须记录路径、原因、负责人
  与到期时间。
- 阶段判定与门禁决定归 `project-lifecycle`；本 skill 提供测试与门禁证据，不自行作出 Go/No-Go
  决定。
- 单人仓库、无部署仓库与遗留项目的裁剪见 `references/lifecycle.md` 的“裁剪与度量”；裁剪只减工件，不减验证。

## 生命周期定位

上游输入：G0 记录的风险级别、G1 的验收标准与结果指标，以及既有 CI 配置、覆盖率基线与不稳定测试清单。
下游交接：测试策略与阈值进入 G2；增量测试与 DoD 检查进入 G3；全量验证证据进入 G4；门禁快照与冒烟结果
进入 G5；逃逸缺陷分析进入 S6。
升级与停止：无阈值或无负责人的校验不得作为门禁；豁免必须依程序取得非作者的具名批准并记录到期日；出现
泄露嫌疑时按 SEC 条款停止并报告；不得删除、跳过或弱化测试以换取绿色（HON）。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 依风险级别确定本次变更的测试预算与门禁强度 | 风险级别与测试范围结论 |
| S1 需求 | 确认验收标准可转化为可判定的测试 | 可测性结论、验收标准与测试的映射 |
| S2 设计 | 选定测试层级，定义每道门禁的命令、触发器、阈值与负责人 | 测试策略、门禁清单、DoR 测试条件 |
| S3 构建 | 随变更提交测试，保持确定性，执行增量验证 | 增量测试与失败输出、DoD 检查 |
| S4 验证 | 运行全量套件与静态校验，整理可复核的验证证据 | 测试输出、覆盖率报告、静态扫描结果、不稳定测试清单 |
| S5 发布 | 复核门禁未被下调，执行部署后冒烟 | 门禁快照、冒烟结果、未运行项清单 |
| S6 运维 | 分析逃逸缺陷，回写测试与门禁 | 逃逸分析、门禁改进项与负责人 |
| S7 收尾 | 复盘测试策略与门禁的成效，形成改进项 | 复盘记录、改进项 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 层级选择表、每道门禁的命令/触发器/阈值/负责人、豁免策略 | Hold：阈值或负责人缺失；Recycle 到 S2：策略覆盖不到验收标准 |
| G3 构建 | 随变更提交的测试、失败输出、DoD 检查结果 | Recycle 到 S3：行为变更无对应测试，或测试无法失败 |
| G4 验证 | 全量测试输出与退出码、覆盖率报告、静态扫描基线、不稳定测试清单 | Hold：证据不完整或来自旧提交；Recycle：弱化测试或下调阈值；No-Go：必需校验持续失败且无有效豁免 |
| G5 发布 | 部署后冒烟结果、门禁快照、制品与报告的可追溯性 | Hold：冒烟未执行，或门禁被放宽且无豁免记录 |

证据必须绑定到具体提交。以本地通过代替 CI 输出、以重试掩盖首次失败、以旧版本的覆盖率报告充数，均不构成
证据。R0 任务可以合并 G3 与 G4 记录，但必须保留真实命令与输出。
