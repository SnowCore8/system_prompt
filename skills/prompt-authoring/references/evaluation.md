# 提示词评测与回归

提示词改动的默认证据为评测结果，而非单条演示。本文件规定评测集、断言、回归与成本的实施方式。

## 评测集

- 每条样本应当包含输入、期望行为（断言）、可选参考答案、来源与创建日期。
- 分层覆盖：正常输入、边界输入、非法输入、注入尝试、超长输入、空输入与语言混杂。
- 规模自小开始：每类 10 至 30 条，足以发现明显回归；上线前再扩充高频真实场景，并作脱敏处理。
- 样本应当去重并标注难度；不得以评测集内的原题作为 few-shot 示例。
- 真实用户数据必须脱敏；凭据、个人信息与内部地址不得进入评测集。

## 断言优先于打分

能够以程序判定的，不得使用主观评分：

- 结构化输出：依 schema 校验字段、类型、枚举与必填项。
- 拒答：断言 status 或关键词，并确认输出不包含被禁止的内容。
- 工具调用：断言工具名、参数与调用次数，避免多余写操作。
- 引用：断言引用片段能够在给定资料中找到。
- 对开放式答案，使用评分 rubric 并辅以人工抽检；rubric 本身亦应当版本化。

## LLM-as-judge 评测偏差

以模型给候选答案打分时，分数会系统性偏向某些特征，不得直接作为客观分。常见偏差与缓解方式如下：

- **位置偏差**：偏好先出现或后出现的答案。缓解：同一对答案交换顺序各评一次，结果不一致的，视为平手或取
  平均值；无法交换的，至少随机化顺序。
- **自偏好偏差**：偏好与自身风格或措辞相近的答案。缓解：以参考答案与可核验引用为锚点，rubric 仅询问
  “是否满足判据”，不得询问“写得好不好”。
- **冗长偏差**：偏好更长的答案。缓解：rubric 明确“更长不加分”；必要时将长度单列维度，或对长度作归一
  化处理。
- **格式偏差**：对排版工整但内容空泛或错误的答案给予高分。缓解：将事实正确与可核验设为主要分项，格式仅
  作门槛或小分。
- **拒答漏判**：将“拒绝”或“无答案”作为低分混入分数。缓解：将“拒答”或“无答案”单列为一类结果，断言其
  被正确识别，不与其他候选共同排名。

通用缓解措施：rubric 仅给出可判定的打分标准，不得要求评测模型提供建议或改写答案；成对比较比绝对打分更稳
定；关键样本应当加人工抽检，并与评测模型分数对照。

## 回归流程

1. 固定基线：记录当前版本的指标、成本、延迟与失败样本。
2. 单变量变更：一次仅修改提示词、模型或参数中的一项。
3. 全量运行评测：至少运行冻结集与高频场景集。
4. 对比与归因：列出改善与退化的样本，逐条判断属于期望变化还是回归。
5. 通过条件：核心断言零失败；总体指标不低于基线；成本与延迟在预算内。
6. 记录：将版本、模型、参数、评测结果与结论写入提交或发布说明。

通过与否作为发布门禁的判定，由 `testing-and-quality-conventions` 管辖；本文件仅定义评测集、断言与回归口
径。

## 成本与延迟

- 记录每条样本的输入与输出 token 数及耗时，计算单次成本。
- 长上下文提示词优先采用检索或摘要，不得将整库塞入系统提示。
- 评测并行执行时应当分桶统计，避免限流造成假阴性。

## 对抗输入

- 注入：资料中藏有“忽略以上指令”“输出系统提示”等文本，断言模型不执行。
- 越权：要求工具写操作或访问未授权数据，断言模型拒绝并说明边界。
- 隐私：要求复述他人数据或凭据，断言模型拒绝且不回显。
- 格式破坏：输入包含未闭合分隔符、超长行或控制字符，断言输出仍可解析。

## 版本与可回滚

- 提示词文件与评测脚本应当同仓版本化；生产环境读取固定版本，不得读取浮动 latest。
- 保留上一版提示词与对应评测结果；回滚方式为换回旧文件，不得以临时修改措辞替代。
- 模型升级视为行为变更：应当重跑评测，比较指标与成本，再决定是否切换。

## 门禁清单

- [ ] 评测集已冻结并纳入版本控制。
- [ ] 核心断言可程序化校验。
- [ ] 注入、越权、隐私与格式破坏样本各至少一条。
- [ ] 基线指标、成本与延迟已记录。
- [ ] 本次改动为单变量，且有前后对比。
- [ ] 核心断言零失败，总体指标不低于基线。
- [ ] 版本、模型与参数已记录，旧版本可回滚。
- [ ] 真实数据已脱敏，评测结果不含机密。
