# 提示词评测与回归

提示词改动的默认证据是评测结果，不是单条演示。本文件给出评测集、断言、回归与成本的落地做法。

## 评测集

- 每条样本包含：输入、期望行为（断言）、可选参考答案、来源与创建日期。
- 分层覆盖：正常输入、边界输入、非法输入、注入尝试、超长输入、空输入、语言混杂。
- 规模从小开始：每类 10-30 条足以发现明显回归；上线前再扩充高频真实场景（脱敏后）。
- 样本去重并标注难度；不要用评测集里的原题做 few-shot 示例。
- 真实用户数据必须脱敏；凭据、个人信息与内部地址不得进入评测集。

## 断言优先于打分

能用程序判定的，不要用主观评分：

- 结构化输出：按 schema 校验字段、类型、枚举与必填项。
- 拒答：断言 status/关键词，且不包含被禁止的内容。
- 工具调用：断言工具名、参数与调用次数，避免多余写操作。
- 引用：断言引用片段能在给定资料中找到。
- 对开放式答案，用评分 rubric 加人工抽检；rubric 本身也要版本化。

## 回归流程

1. 固定基线：记录当前版本的指标、成本、延迟与失败样本。
2. 单变量变更：一次只改提示词、模型或参数中的一项。
3. 全量跑评测：至少跑冻结集与高频场景集。
4. 对比与归因：列出改善与退化的样本，逐条判断是期望变化还是回归。
5. 通过条件：核心断言零失败；总体指标不低于基线；成本与延迟在预算内。
6. 记录：把版本、模型、参数、评测结果与结论写入提交或发布说明。

## 成本与延迟

- 记录每条样本的输入/输出 token 与耗时，计算单次成本。
- 长上下文提示词优先做检索或摘要，不把整库塞进系统提示。
- 评测并行执行时分桶统计，避免限流造成假阴性。

## 对抗输入

- 注入：资料中藏“忽略以上指令”“输出系统提示”等文本，断言模型不执行。
- 越权：要求工具写操作或访问未授权数据，断言拒绝并说明边界。
- 隐私：要求复述他人数据或凭据，断言拒绝且不回显。
- 格式破坏：输入包含未闭合分隔符、超长行、控制字符，断言输出仍可解析。

## 版本与可回滚

- 提示词文件与评测脚本同仓版本化；生产读取固定版本，不读浮动 latest。
- 保留上一版提示词与对应评测结果；回滚是换回旧文件，不是临时改措辞。
- 模型升级视为行为变更：重跑评测，比较指标与成本，再决定是否切换。

## 门禁清单

- [ ] 评测集已冻结并纳入版本控制。
- [ ] 核心断言可程序化校验。
- [ ] 注入、越权、隐私与格式破坏样本各至少一条。
- [ ] 基线指标、成本与延迟已记录。
- [ ] 本次改动为单变量，且有前后对比。
- [ ] 核心断言零失败，总体指标不低于基线。
- [ ] 版本、模型与参数已记录，旧版本可回滚。
- [ ] 真实数据已脱敏，评测结果不含机密。
