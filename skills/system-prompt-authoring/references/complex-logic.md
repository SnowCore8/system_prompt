# 复杂逻辑：判定表与状态表

规则涉及多个条件组合或状态迁移的，不得将其放入一张大图。表格为事实来源，图仅作概览。

## 何时使用

| 情形 | 采用 |
|---|---|
| 多个条件选出一个动作 | 判定表 |
| 任务随事件在状态间迁移 | 状态表 |
| 既有状态又有条件分支 | 状态表；条件列引用判定表 |
| 计算、循环或数据结构 | 伪代码，或带表驱动测试的纯函数 |

## 判定表

### 判定表模板

| 顺序 | 条件 A | 条件 B | 条件 C | 动作 |
|---|---|---|---|---|
| 1 | 否 | * | * | 仅报告 |
| 2 | 是 | 是 | 无 | 拒绝 |
| 3 | 是 | 是 | 有方案 | 执行 |
| 4 | 是 | 否 | * | 执行 |

- 顺序：自上而下，首个匹配者生效；采用“最后匹配者生效”的，应当明确写出。
- `*` 表示任意值，`-` 表示不适用；两个符号均应当定义。
- 动作：每行仅给出一个可观察的结果。
- 默认：说明无行匹配时所适用的分支。

### 判定表示例：授权

| 顺序 | 显式同意 | 生产环境 | 回滚方案 | 动作 |
|---|---|---|---|---|
| 1 | 否 | * | * | 仅报告；不执行 |
| 2 | 是 | 是 | 无 | 拒绝；先要求给出回滚方案 |
| 3 | 是 | 是 | 有方案 | 执行；保留回滚路径 |
| 4 | 是 | 否 | * | 执行 |

“显式同意”指对该操作直接、明确的批准；含糊的“先这样吧”不构成同意。无行匹配的，默认拒绝并报告。

## 状态表

### 状态表模板

| 当前状态 | 事件 | 条件 | 下一状态 | 动作 |
|---|---|---|---|---|
| 等待授权 | 用户同意 | 非生产环境 | 执行中 | 开始改动 |
| 等待授权 | 用户拒绝 | - | 已拒绝 | 停止；不得绕过该限制实施行为 |

- 每个状态与事件的组合均必须显式定义，或适用默认行。
- 标出终态；禁止自终态静默返回执行中。
- 条件列可以引用判定表的结论，不得重复展开。

### 状态表示例：清点 → 计划 → 评估 → 实施 → 验证 → 提交 → 交付 → 完成

| 当前状态 | 事件 | 条件 | 下一状态 | 动作 |
|---|---|---|---|---|
| 清点 | 任务已接受 | 范围与授权明确 | 计划 | 记录范围、当前状态、依赖与约束 |
| 清点 | 任务已接受 | 范围或授权不明确 | 阻塞 | 请求澄清或报告；不得进入计划 |
| 计划 | 清点完成 | 可拆分，或步骤超过四步 | 评估 | 定义步骤、负责人与验收；委派或创建待办清单 |
| 计划 | 清点完成 | 单条线性路径 | 评估 | 定义一次一步的计划；不得委派 |
| 评估 | 计划已批准 | 风险可接受且可回滚 | 实施 | 按选定方案、回滚路径与平台工具开始改动 |
| 评估 | 计划已批准 | 高风险或无回滚 | 阻塞 | 请求确认或提出替代方案 |
| 阻塞 | 用户澄清或授权 | 范围与授权明确 | 计划 | 记录澄清或授权结果，重新进入计划 |
| 阻塞 | 风险已接受 | 范围与授权明确，仅风险待接受 | 实施 | 执行已批准的改动；范围和授权不明确的，不得实施 |
| 实施 | 改动完成 | 改动未超出范围 | 验证 | 确认 diff 并冻结改动 |
| 实施 | 改动进行中 | 根因是结构性的 | 实施 | 重构；不得继续叠加补丁 |
| 实施 | 发现阻塞 | - | 阻塞 | 报告阻塞点与已完成的部分 |
| 验证 | 实施完成 | 相关测试与全量测试通过 | 提交 | 收集证据与真实输出 |
| 验证 | 实施完成 | 测试失败或未运行 | 实施 | 修复；不得提交；未运行的，标注“未运行” |
| 提交 | 验证通过 | diff 干净，不含机密或构建产物 | 交付 | 审查 diff，拆分提交并撰写提交信息 |
| 提交 | 验证通过 | 发现机密、构建产物或范围蔓延 | 实施 | 移除或修复问题；不得提交 |
| 交付 | 交付已发出 | - | 完成 | 报告交付；关闭任务 |
| 交付 | 收到反馈 | - | 清点 | 依反馈开始新一轮 |

小任务可以将清点、计划、评估合并为一次；禁止跳过验证、提交或交付的检查。任何未列出的组合均停留在当前状态
并报告；不得猜测。

## 便于模型理解的写法

- 条件列使用布尔值或枚举，不得写入长句。
- 动作列仅放置一个结果；禁止写入“视情况处理”。
- 表格应当放置于规则附近；不得仅放置于附录。
- 表格之后应当补充 3-5 个边界用例：默认、异常、冲突与信息不足。
- 需要配图的，图仅作概览；图与表冲突的，以表为准。
- 表格开始重复或嵌套超过两层时的处理见 [SKILL.md](../SKILL.md) 的“复杂逻辑”一节。

## 维护与验收

- 应当先修改表，再修改图；禁止未同步表格即手工修改图。
- 规则变化时，应当同步更新边界用例。
- 逻辑复杂至表格无法承载的，应当编写带表驱动测试的纯函数；不得使提示词承载算法。
- 图仅作概览；事实来源始终为表格或代码。
