# 发布与运维

一次未受控的部署会损害从未接触该变更的用户，一次未被发现的事故会持续到客户上报，一次未经验证的恢复会把
可恢复的中断变成永久数据丢失。发布与运维的失效几乎都是流程缺口：本 skill 规定版本与兼容性承诺、单一制品
的构建与晋级、发布与回滚的成文路径、以遥测证明发布成功、事故指挥与复盘，以及恢复可行性的证明，并把证据
接入 G5 发布与 G6 运维门禁。

## 适用范围与优先级

效力按下列层级判断，高层覆盖低层：

1. 法律、合同与平台的强制要求以及宿主与全局用户约束，包括数据处置义务与支持窗口承诺。
2. 本 skill 的规则与默认值，见本文件与 `references/`。
3. 项目已写入文档的发布策略与运行事实：版本来源、CI 配置、环境定义、告警规则、运行手册与最近的事故记录。
4. 个人偏好与工具链便利性，不得覆盖以上三层。

边界与例外：

- 发布标签的命名归 `naming`；标签的创建时点、指向与保护由本 skill 决定。
- 变更日志、发布说明、运行手册与事故复盘文档的格式归 `documentation`；本 skill 规定必须记录的内容与更新时点。
- 分支、PR 与审查归 `code-review` 与 `vcs-collaboration`；已审查变更如何形成发布由本 skill 决定。
- 门禁阈值与不稳定测试归 `testing-quality`；流水线阶段、环境晋级与上线控制由本 skill 决定。
- 产品版本与 API 版本：API 版本与契约归 `api-data`；产品版本、兼容性承诺与发布节奏由本 skill 决定。
- 凭据、机密存储与披露归 `security-compliance`；部署权限与回滚决策权由本 skill 决定，并消费安全流程签发的凭据。
- 平台托管的保留、复制与备份调度归平台所有者；引用平台合同取值，不得把平台默认抄入项目。
- 发布默认不可逆：每项不可逆操作须有经过演练的回滚路径或备份恢复路径（IRR）；没有回滚路径的发布不得
  通过 G5。
- 本 skill 的批准均为项目角色批准，不替代用户对部署、回滚与迁移的明确同意（AUT）。

## 生命周期定位

上游输入：G4 的验证结论与已批准的变更。本 skill 在 S2 固定发布与回滚计划，在 S5 执行发布与观察，在 S6
值守与响应，在 S7 复盘与归档。
下游交接：发布记录与运行手册交给运维与文档角色；事故复盘与行动项进入 S7。
升级与停止：回滚方案缺失时 Recycle 到 S2；缺少 G4 证据的发布停在 G5，不得上线；发布后指标越界时按预案
回滚并复盘；授权、披露或回滚冲突升级用户与安全负责人。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 固定版本策略、发布类型、批准人、回滚方案与观察指标 | 发布计划、回滚方案、观察指标与阈值 |
| S4 验证 | 汇总门禁结果，确认制品可复现且可追溯 | 门禁快照、制品摘要与校验和 |
| S5 发布 | 构建一次并晋级制品，受控部署，观察成功指标 | CI/CD 记录、回滚演练、观察快照 |
| S6 运维 | 值守告警、响应事故、维护运行手册、演练恢复 | 事故记录、恢复演练结果、运行手册更新 |
| S7 收尾 | 按严重级别复盘事故，跟踪行动项并归档 | 事故复盘、行动项、未关闭风险 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 版本与兼容性结论、发布类型与批准人、回滚方案与数据影响、观察指标与阈值 | Recycle 到 S2，补齐方案 |
| G5 发布 | 制品摘要与构建记录、必需门禁结果、回滚演练、可观测性就绪、逐次授权 | Hold，不得部署 |
| G6 运维 | 监控与告警在岗、恢复演练通过、事故记录完整 | Recycle 到 S6，不得无人值守 |
| G7 收尾 | 事故复盘与行动项、SLO 对照、运行手册更新 | Hold：补充证据后关闭 |

G2 证据不足时 Recycle 到 S2；G5 缺证据、回滚不可执行或授权未取得时 Hold；目标不成立或风险不可接受时
No-Go。回滚后重新发布须重新取得 G5 证据。决定语义与批准角色归 `project-lifecycle`。
