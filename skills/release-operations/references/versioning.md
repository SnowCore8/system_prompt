# 版本策略与发布类型

## 1. 版本策略与发布类型

- 递增规则：补丁修复行为且不改契约；次版本增加能力且保持兼容；主版本变更契约；预发布使用后缀并标记
  `pre-release`。
- 发布类型决定三件事：批准人、上线方式、回滚方式。按兼容性影响选择类型，不得按请求紧急程度选择。
- 兼容性承诺：写明哪些版本继续获得修复、弃用路径保留期限与升级所需操作；一次发布作出的承诺对之后的每个
  发布构成约束。
- 弃用公告放在用户可见旧路径之处：运行时告警、页面提示与变更日志并用，写明移除版本与日期。
- 功能开关是临时机制：每个开关写明所有者、默认值、移除触发条件与清理版本。
- 支持窗口与发布节奏写入发布策略；同一版本号不得有第二个含义。默认值可被项目发布策略收紧，不得放宽
  批准列或回滚列。
