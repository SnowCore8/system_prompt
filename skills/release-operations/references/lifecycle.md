# 生命周期契约：发布与运维

本文件是发布与运维在各阶段的输入、活动、输出与证据契约。阶段与门禁的判定语义归
`project-lifecycle`；本文件只规定本 skill 负责提供的证据与交接。

## 阶段职责

S2 设计：输入为 G1 的兼容性目标与发布节奏。活动：确定版本递增规则与支持窗口；按影响选择发布类型与
批准人；写明回滚方案、数据影响、观察指标与阈值；公布冻结窗口。输出：发布计划与回滚方案，进入 G2。

S4 验证：输入为 G4 证据。活动：汇总必需门禁结果，核对制品摘要、构建记录与校验和，确认制品可复现且
可追溯。输出：门禁快照与制品摘要。

S5 发布：输入为已批准的制品。活动：构建一次并晋级；按部署策略上线；在观察期内持续读取成功指标；越界时
按预案回滚或止损。输出：CI/CD 记录、回滚演练记录、观察快照，进入 G5。

S6 运维：输入为上线后的服务。活动：值守告警、按严重级别响应事故、维护运行手册与仪表盘、执行恢复演练。
输出：事故记录与恢复演练结果，进入 G6。

S7 收尾：输入为运维期记录。活动：按严重级别复盘事故，跟踪行动项，对照 SLO，归档发布与事故记录。输出：
事故复盘与未关闭风险，进入 G7。

## 门禁证据

G2：版本与兼容性结论、发布类型与批准人、回滚方案与数据影响、观察指标与阈值；缺失时 Recycle 到 S2。

G5：制品摘要与构建记录、必需门禁结果、回滚演练、可观测性就绪与逐次授权；缺失时 Hold，不得部署。

G6：监控与告警在岗、恢复演练通过、事故记录完整；缺失时 Recycle 到 S6，不得无人值守。

G7：事故复盘与行动项、SLO 对照、运行手册更新；缺失时补充证据后关闭。

## 交接与升级

- 发布计划交给运营角色进入 G5；部署与回滚按运行手册执行，手册与实际步骤不一致时以演练结果修正手册。
- 生产变更须取得逐次明确同意（AUT）；紧急止损按应急条款先行，事后补记录并复盘。
- 发布后指标越界时按预案回滚并复盘；回滚决策权与批准链写入发布计划。
- 授权、披露或回滚冲突升级用户与安全负责人；同一冲突不得由执行者自行裁断。

## 裁剪与度量

裁剪：

- R0：合并发布与收尾记录，回滚路径仍须写明；单文件改动无需独立批准。
- R1：标准发布计划与发布记录。
- R2：完整发布计划、回滚演练、独立批准，G4 与 G5 不得合并。
- 无部署仓库：制品与发布说明仍按版本管理，部署与回滚章节以分发方式替代；单人值守的以轮值升级路径替代。

度量：

- 变更失败率、平均恢复时间（MTTR）、部署频率与前置时间；SLO 达成与错误预算消耗；告警噪声率与误报率；
  恢复演练通过率与实测 RPO/RTO 对照。
- 指标恶化时先查根因，不得直接调整目标或改变口径。
