# 并发测试

## 1. 并发测试

并发缺陷具有概率性：同一交错本次通过、下次崩溃。普通测试不探索交错，无法证明并发正确。本节规定使竞争
在测试阶段暴露的手段及其边界。

- 涉及共享状态的测试，在提供运行期竞态检测器的语言中必须启用检测器：Go 用 `go test -race`，C/C++ 用
  ThreadSanitizer，Rust 用 `loom` 或 Miri。
- 未内置检测器的语言，以压力测试、静态工具与审查替代，并记录覆盖缺口；检测器未运行的，不得声称不存在
  数据竞争。
- 压力测试提高交错覆盖：同一操作并发运行大量迭代，采用不同线程数与随机调度；随机失败必须打印种子与
  输入。
- 确定性靠注入而非偶然：向关键点注入延迟、栅栏与屏障，或记录并重放调度，使失败可以复现。
- 以模型检查补足：Loom、TLA+ 等工具显式枚举交错，可在小范围内证明所有交错无竞争；适用于锁顺序与协议
  等有限状态问题。
- 失败的并发测试属于缺陷而非噪声：生产竞态导致的不稳定测试按缺陷修复，不得重试或跳过。

## 2. 判定与边界

- 检测器只覆盖已执行的交错；通过不等于正确，仅是对该段执行历史的证明。
- 检测器通过不构成充分证明；说明未覆盖的交错，并用压力测试与模型检查扩大覆盖。
- 以“测试通过”作为并发正确的证明不可接受；以 sleep 稳定时序同样无效。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| CI 中运行 `go test -race` | 并发测试仅运行普通模式 | 竞争不会被检测 |
| 以压力测试提高交错覆盖 | 并发路径仅运行一次 | 概率性竞争未被检出 |
| 注入延迟使失败可以复现 | 以 sleep 稳定时序 | 时序仍不确定 |
| 记录种子与输入 | 随机失败未打印种子 | 无法复现 |
