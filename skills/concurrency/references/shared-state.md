# 共享状态与数据竞争

## 1. 共享状态与数据竞争

数据竞争的定义可以判定：两个或更多执行流并发访问同一内存位置，其中至少一个为写入，且未以同步建立
先发生关系，即构成数据竞争。本节规定竞争的三种根源——原子性、可见性与锁粒度——的处理方式。

- 以同步建立先发生关系，不得以 sleep 或侥幸替代。任何读改写（如 `count++`、先检查后行动）必须采用
  原子操作或持锁；读写两侧持有同一把锁。
- 锁定的对象是不变量而非字段：一把锁保护一组必须同时成立的字段，任何只读写其中一部分的路径都持有
  同一把锁。
- 可见性靠锁、原子操作或内存屏障建立，不靠时间流逝。Java 的 `volatile` 只保证可见性与有序性；C/C++
  的 `volatile` 不提供线程间同步语义。
- 复杂不变量优先以消息传递或不可变值消解，不以增加锁的数量处理。
- 仅锁定写侧而未锁定读侧的，读到的仍是写入一半的中间状态。

## 2. 判定与边界

- 判定数据竞争只需三个条件：多执行流访问同一位置、至少一个写入、无先发生关系；三者同时成立即构成
  竞争。
- 原子性只保护单个操作；两个以上字段共同构成不变量的，分别用原子类型保护仍可被并发打破。
- 竞争的后果为内存模型允许的任意值：崩溃、中间状态或仅在特定调度下复现的错误结果。
- 竞争并非唯一要修的问题：加锁后的顺序依赖、优先级反转与锁序不一致不表现为数据竞争，归
  `references/deadlock.md` 管辖。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 读与写持有同一把锁 | 仅锁定写侧，读侧不加锁 | 读侧看到写入一半的中间状态 |
| 一把锁保护整个不变量 | 每个字段各设一个原子类型 | 复合不变量仍可被并发打破 |
| 以锁或原子操作建立先发生关系 | 以 sleep 等待另一线程的写入 | 可见性不因时间流逝而获得保证 |
| 依数据划分锁 | 依方法划分锁 | 语义一致的字段被不同的锁分别保护 |
