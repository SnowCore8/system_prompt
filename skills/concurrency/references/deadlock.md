# 死锁与活锁

## 1. 死锁与活锁

死锁指四个条件同时成立：互斥、持有并等待、不可抢占、循环等待；破坏任意一项即可消除。活锁是另一情形：
执行流仍在活动，在让渡与重试之间往返，但无任何执行流前进。两者都表现为停滞，但排查与修复方法不同。

- 统一锁顺序为首选：为全局锁集合确定一个偏序，任何执行流按同一顺序申请；两段代码以相反顺序申请同一组锁，构成循环等待，与其他死锁条件并存时即形成死锁。
- 自第二把锁起采用 try-lock 加超时，不得无限等待；无法取得的，释放已持有的锁并重试，或超时上报。
- 锁数、超时上限与重试上限记录于并发文档；否则只是把死锁转化为无限重试。
- 持锁期间不得申请顺序未知的其他锁、不得回调、不得实施 I/O；锁嵌套把顺序交给外部代码。
- 减少锁的数量与粒度：单一大锁不产生死锁但消除并发；依不变量拆锁时同时规定全局顺序。
- 活锁以让渡与重试上限修复：随机退避、不对称延迟或最终失败上报，保证至少一方前进。

## 2. 判定与边界

- 排查先绘制资源等待图：执行流为节点，边表示“持有 X 并等待 Y”；存在环即为死锁，环上任一边都是破环点。
- 破环方法：统一顺序（消除循环等待）、try-lock 加超时（打破持有并等待）、减少锁数量（合并不变量）、把
  回调与 I/O 移出临界区（消除锁嵌套）。
- 检测器不覆盖死锁的，以带超时的看门狗在停滞时打印每个执行流的锁状态。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 全局一致的锁顺序 | 两处代码以相反顺序加锁 | 相反顺序构成循环等待 |
| try-lock 加超时 | 无限等待第二把锁 | 死锁转化为永久停滞 |
| 持锁期间不回调、不嵌套 | 持锁调用外部代码 | 锁顺序交由外部代码决定 |
| 以资源等待图查找环 | 逐线程翻栈帧推测死锁 | 找不到环就无法确定破环点 |
