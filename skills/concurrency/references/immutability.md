# 不可变性与消息传递

## 1. 不可变性与消息传递

最可靠的并发正确性是没有共享可变状态。本节的默认顺序为：先不可变，再消息传递，最后加锁。

- 不可变值不产生数据竞争：一经创建即不改变，任何执行流并发读取都安全；采用不可变数据结构、冻结可变
  对象或返回防御性拷贝。
- 消息传递使数据只有一个所有者：数据在创建者处可变，经通道/队列把所有权移交给接收者，任何时刻仅一个
  执行流可以访问。
- 传递后创建者不得再读取；以类型系统或约定强制所有权转移。
- 通道/队列本身需要同步，但传递的是所有权而非共享；发送与接收之间是同步边界。
- 不可变为默认，加锁为例外：写不出“为何必须共享可变状态”的理由时，先以不可变或消息传递改写。
- 大对象拷贝有成本，但换取零竞争；热路径上共享不可变部分，仅拷贝可变部分。

## 2. 判定与边界

- 判定顺序：能改不可变值的改不可变值；否则看能否移交所有权；最后才加锁共享。
- 冻结与拷贝的取舍依成本与竞争权衡；为节省拷贝而整体共享，是为较小收益引入较大风险。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 返回不可变值或防御性拷贝 | 直接暴露内部可变对象 | 调用方与内部共享，绕过同步 |
| 以通道传递所有权 | 传递引用后双方继续使用 | 所有权不清晰，仍属共享 |
| 冻结可变对象以消除竞争 | 处处加锁保护同一份数据 | 锁越多，推理越难 |
| 共享不可变部分，拷贝可变部分 | 为节省拷贝而整体共享 | 为较小收益引入较大风险 |
