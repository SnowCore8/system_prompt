# 并发与并行正确性

并发程序有四类可预见的失效：共享可变状态未经同步就被并发读写，形成时有时无的数据竞争；锁的申请顺序
不一致，两个执行流互相等待形成死锁；以大量复制代替共享，把锁竞争伪装成性能问题；测试只证明“本次未
崩溃”，而竞态的暴露依赖具体交错。本 skill 规定以“是否可以不共享”为起点的决策顺序、同步原语的选择依据、
死锁与活锁的排查方法，以及让并发缺陷在验证阶段暴露的手段。

## 适用范围与优先级

效力层级自上而下，高层覆盖低层：

1. 语言内存模型、运行时调度器与 CPU 缓存一致性等强制约束。
2. 本 skill 的规则：共享状态、同步原语、死锁与并发模型、并发测试。
3. 项目并发约定与事实：既有锁、通道、线程池与并发文档是输入，仅在本 skill 未规定处补充。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 本 skill 管并发正确性；锁竞争造成的吞吐与延迟问题归 `performance` 定位与优化。
- 通用测试策略与门禁阈值归 `testing-quality`；本 skill 只要求并发特有的检测器、压力测试与交错覆盖。
- 跨服务重试、幂等键与退避归 `api-data`；本 skill 只处理进程内的共享与同步。
- 锁、通道与任务的名称归 `naming`，不变式的注释写法归 `comments`；本 skill 规定应记录哪些内容。
- 不共享的数据、单执行流数据与不可变数据不适用同步规则，但仍应写明为何可以不共享。
- 同一层级的强制规则冲突时报告用户裁决，并把所选约定记入并发设计说明。

## 生命周期定位

上游输入：S2 的并发模型、共享状态清单与锁顺序设计——哪些数据共享、用何种原语、等待如何超时、如何测试。
下游交接：S3 的实现与审查、S4 的检测器与压测证据、S6 的事故止损与复现、S7 的复盘与回归。升级与停止：
新增跨进程共享、变更全局锁序或引入新执行模型时退回 G2 重新评审；无法取得竞态证据时报告覆盖缺口，不得
声称正确；事故期间按 AUT-5 先止损，再补门禁记录。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定变更是否触碰共享状态，记录风险级别与停止条件 | 受理结论与共享状态范围 |
| S1 需求 | 确认引入并发是否有可判定的收益目标，列出不并发化的后果 | 收益目标与选项比较 |
| S2 设计 | 选定并发模型，列出共享状态清单、原语、锁全序与超时，设计并发测试 | 并发设计说明、锁顺序表、测试方案 |
| S3 构建 | 按原语决策实现同步，临界区不含回调与 I/O，记录锁与不变式 | 代码与注释、检测器局部结果 |
| S4 验证 | 运行竞态检测器与压力测试，绘制资源等待图排查死锁 | 检测器与压测输出、覆盖缺口说明 |
| S5 发布 | 复核并发相关告警、超时配置与回滚触发条件 | 发布前复核记录 |
| S6 运维 | 竞态与死锁事故的止损、复现与监控接入 | 事故记录与复现条件 |
| S7 收尾 | 复盘竞态事故，补回归用例并更新并发文档 | 根因结论、行动项与回归用例 |

## 门禁与证据

证据必须可复核：检测器命令与退出码、压测参数与随机种子、资源等待图；单次通过不等于正确，竞态的暴露依赖交错。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 共享状态清单、并发模型与原语选择理由、锁全序与超时、并发测试方案 | Hold：模型或锁序未定；Recycle 到 S2 补齐设计 |
| G3 构建 | 每项共享状态读写两侧的同步覆盖与代码位置、临界区清单、检测器局部结果 | Recycle 到 S3：无同步的共享写入阻断合并 |
| G4 验证 | 检测器与压力测试输出、死锁排查记录、未覆盖交错与替代验证说明 | Recycle 到 S3：证据缺失；以单次通过冒充证明的报告越线并 Recycle |
| G7 收尾 | 事故根因、复现用例、并发文档与检测器接入的更新记录 | Hold：复盘证据不全不得关闭 |

## 维度索引

每个维度的完整规则、判定与正反例见对应文件；维度编号即该文件的节号。

| 编号 | 维度名 | 首条规则 | 详情 |
|---|---|---|---|
| 1 | 共享状态与数据竞争 | 共享可变状态必须具有显式同步，读写两侧持有同一把锁并锁定整个不变量。 | `references/shared-state.md` 第 1 节 |
| 2 | 同步原语选择 | 按保护对象、读写比例与等待方式选择原语，单标量用原子操作，多字段不变量用锁。 | `references/sync-primitives.md` 第 1 节 |
| 3 | 死锁与活锁 | 锁按全局偏序申请，持锁期间不回调，自第二把锁起用 try-lock 加超时。 | `references/deadlock.md` 第 1 节 |
| 4 | 异步与并发模型 | 线程、协程、事件循环与线程池各管一类任务，事件循环内不得阻塞。 | `references/models.md` 第 1 节 |
| 5 | 并发测试 | 提供运行期检测器的语言必须启用检测器，其余以压测与静态分析替代并记录缺口。 | `references/concurrency-testing.md` 第 1 节 |
| 6 | 不可变性与消息传递 | 可变状态默认不共享，先改不可变值，再以消息传递移交所有权，最后才加锁。 | `references/immutability.md` 第 1 节 |
