# 项目结构：公开入口与内部可见性

公开面是包对外的承诺：导出的每项都要长期维护，未导出的都可以自由重构。公开面越小，跨团队变更越少。

## 1. 公开入口与内部可见性
- 每个包声明入口或导出清单，只暴露稳定 API；内部类型、实体与存储细节不得越过边界。
- 入口文件只做装配：解析参数、加载配置、构建依赖并调用应用；业务规则不进入口。
- 不得用全量 barrel 文件重导出内部结构；内部子路径以命名或构建规则阻断。

## 2. 共享代码

- 共享包仅承载稳定契约与通用机制，具有所有者；不把多个模块的编排堆进共享目录。
- 被两个模块使用的代码按 `architecture-design` 的裁定明确依赖方向，而不是各自复制或塞入共享层。

## 3. 版本与契约

- 公开 API 的变更按破坏性分级并走发布流程；内部重构不改变公开面，不需要对外通告。
- 公开入口与文档、示例保持一致；文档引用未导出的符号即视为边界泄漏。
