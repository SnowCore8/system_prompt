# 项目结构：结构门禁与变更

边界只有可执行才存在：目录约定无门禁支撑，一季度内即被绕过。门禁失败必须指出违反的边；结构调整按小步移动，与行为变更分开。

## 1. 结构门禁与变更
- 每个包或模块至少一道门禁：导入检查、构建图校验或包导出校验；路径别名纳入同一门禁。
- 门禁在合并前运行并失败即阻断；例外写明所有者、范围与到期条件，到期自动失效。
- 门禁阈值与 CI 接入位置归 `testing-quality`；本 skill 定义违规边的判定。

## 2. 结构调整

- 一次变更只移动或重划一类边界；移动文件同步更新导入、测试与文档，保持构建通过。
- 大规模移动按小步进行，每步独立可回滚；与行为修改分开提交。
- 结构决策写入 ADR 或包说明，改变边界时同步所有者映射与依赖它的工作流。

## 3. 平台投影

- CODEOWNERS 与工作流路径过滤是结构的投影，不是边界本身；不得以路径过滤替代导入检查。
- 新增或移动包时在同一次变更中更新所有者映射；投影与目录脱节的按缺陷处理。
