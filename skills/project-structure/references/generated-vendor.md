# 项目结构：生成与第三方目录

生成代码与第三方引入代码的共同点：真源在别处。手工编辑产物，下次生成或升级即丢失；混入业务模块，边界与所有权随之消失。

## 1. 生成与第三方目录
- 每个生成目录写明生成命令、来源与所有者；产物只读，修改生成器或源注释后重新生成。
- 生成目录排除于格式化、lint 与手工审查之外，但纳入构建与门禁；生成产物不得提交进仓库的可编辑区域。
- 生成命令纳入构建或脚本，保证任何人可复现同一产物。

## 2. 第三方引入代码

- vendor 或等价目录保留上游来源、版本与补丁记录；不得改写为自有代码。
- 就地修改的补丁有记录并在升级时重新评估；问题报告上游，或维护独立 fork 的补丁文件。
- 第三方代码排除于项目格式化与风格规则之外，保留原注释与许可证头。

## 3. 平台与工具目录

- `.github/actions` 的本地 action、`tools` 下的辅助脚本按可复用单元放置，写明所有者。
- 平台生成与下载的缓存目录加入忽略规则，不进入源码树与发布制品。
