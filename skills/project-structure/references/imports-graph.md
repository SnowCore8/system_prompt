# 项目结构：物理导入与构建图

逻辑边界只有落到物理依赖上才可检查。构建图以模块与包为节点，描绘导入、路径别名与包依赖；违规边在合并前被门禁阻断，而不是事后发现。

## 1. 依赖图

- 以模块与包为节点绘制物理导入与构建依赖，标记循环、反向依赖、跨层边与深层导入。
- 运行依赖与开发依赖分开记录；循环与反向边的架构判定归 `architecture-design`，本 skill 阻断已判定的违规边。
- 依赖声明与导入一致：应用与包只依赖 manifest 声明的包，开发、peer 与可选依赖按用途声明。

## 2. 别名与深层导入

- 路径别名与导入规则纳入同一门禁；别名不得隐藏对内部子路径的深层导入。
- 跨包相对路径禁止；跨模块共享状态经显式契约传递，不以全局变量或共享可变文件绕过。

## 3. 门禁输出

- 门禁失败信息指出违反的边、涉及的文件与修复方式；无法指出位置的检查不构成门禁。
- 存量违规以接缝逐步收紧：新代码不得新增违规边，存量边登记并限期消除。
