# 项目结构

项目结构是依赖关系的物理形态：目录放错，模块边界随之消失；包边界不清，循环依赖穿过工作区；公开面不受控，
内部改动变成跨团队变更。本 skill 把已裁定的逻辑边界落到目录、包与导入规则，并用门禁保证边界可检查；逻辑边界的裁定归 `architecture-design`。

## 适用范围与优先级

效力依下列层级判断，高层覆盖低层，低层仅在高层未规定时补充：

1. 强制约束。包管理器、构建工具、语言模块系统与托管平台的限制不可选。
2. 本 skill 的规则。目录、包与工作区、依赖图、公开面、生成与第三方目录、结构门禁以本文件与 `references/` 为准。
3. 项目事实。目录树、manifest、工作区配置、构建图与 CODEOWNERS 先阅读后裁定；它们在本 skill 未规定处补充。
4. 个人偏好，不得覆盖以上三层。

边界：

- 逻辑边界、分层与依赖方向的裁定归 `architecture-design`；本 skill 只做物理落点并阻断已判定的违规边，未裁定的先回该 skill。
- 模块内部的文件与资源布局、格式化与依赖版本归 `code-style`；目录与包的名称归 `naming`。
- 结构门禁接入 CI 的位置与阈值归 `testing-quality`；仓库停止的物理归档由本 skill 规定，退役的通告与处置顺序归 `maintenance-retirement`。
- 强制规则冲突时报告用户裁决，不得自行选定。

## 生命周期定位

上游：`architecture-design` 的边界与依赖方向、G1 的需求与约束、既有 manifest 与构建图。下游：导入规则与构建图检查
交 `testing-quality` 接入 CI；生成目录的格式化排除交 `code-style`；目录所有者映射随目录变更同步。停止条件：边界未裁定、
结构调整无法独立回滚、或门禁缺失导致边界无法检查时停止，报 Recycle 到 S2。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 选择项目形态，把已裁定边界映射到目录、包与工作区，定义公开面与门禁 | 目录映射表、包清单、门禁方案 |
| S3 构建 | 按映射落地新增或移动目录，同步导入、测试与文档 | 结构调整 diff、构建输出 |
| S4 验证 | 复跑导入检查与构建图门禁，确认无深层导入与未声明依赖 | 导入检查输出、所有者映射核对 |
| S5 发布 | 核对打包入口与制品清单，确认发布含所需目录 | 包导出与制品清单 |
| S7 收尾 | 归档仓库或退役目录，清点目录与依赖 | 归档记录、目录清点 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 计划 | 项目形态选择理由、目录到模块与所有者的映射、公开面设计、门禁方案 | Hold：边界未经架构裁定；Recycle 到 S2 补齐映射 |
| G3 构建 | 结构调整 diff、构建与导入检查输出、包 manifest 与所有者同步记录 | Recycle 到 S2/S3：跨包相对路径或未声明依赖仍在 |
| G4 验证 | 导入检查、构建图与包导出校验通过；例外有所有者与到期条件 | Hold：门禁只在本地运行；Recycle 到 S3：边界只存在于命名 |

## 核心规则

- 每个代码顶层目录对应一个模块或包，具有单一职责与所有者。
- 包与工作区边界显式：每包有 manifest、公开入口与版本策略，根只做编排。
- 公开面最小化：内部子路径不得被外部导入，不得用全量 barrel 重导出内部。
- 生成与第三方目录只读、可重生成，排除于手工编辑与格式化之外。
- 边界必须可执行：导入检查、构建图或 CI 门禁强制边界，失败信息指出违反的边。
- 结构调整与行为变更分开：一次变更只移动一类边界，同步更新导入、测试与文档。
- 结构决策写入 ADR 或包说明；改变边界时同步所有者映射与相关工作流。
