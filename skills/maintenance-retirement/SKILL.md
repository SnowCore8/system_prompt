# 维护、退役与复盘

多数系统在发布之后才暴露出真正的成本：受支持版本无人维护、技术债无声增长、退役的服务仍消耗资源、交接后
无人知道如何运行。本 skill 规定补丁与小版本的交付规则、技术债的登记与偿还、退役与归档的完整路径、交接的
必备内容，以及复盘与收益对照的产出要求，覆盖 S6 运维与 S7 收尾。

## 适用范围与优先级

效力按下列层级判断，高层覆盖低层：

1. 法律、合同与平台的强制要求（数据保留义务、支持窗口承诺）以及宿主与全局用户约束。
2. 本 skill 的规则与默认值，见本文件与 `references/`。
3. 项目既有约定：维护策略、支持窗口、债务台账与运行手册属于事实输入。
4. 个人偏好与工具习惯，不得覆盖以上三层。

边界与例外：

- 发布与回滚执行、事故响应归 `release-operations`；本 skill 管辖发布之后的维护与收尾。
- 测试与门禁阈值归 `testing-quality`；补丁与小版本沿用正式发布的质量要求。
- 归档的平台设置与仓库转移机制归 `project-structure`；本 skill 规定退役时的处置顺序与证据。
- 阶段与门禁判定归 `project-lifecycle`；本 skill 提供 S6/S7 的证据。
- 交接不得移交机密明文；凭据轮换与机密处置归 `security-compliance`。
- 退役与交接涉及删除与权限变更时须逐次明确同意（AUT）；不可逆处置须先备份并验证恢复（IRR）。

## 生命周期定位

上游输入：G5 发布记录、支持承诺与运行手册。本 skill 在 S2 固定支持窗口与退役条件，在 S6 交付补丁与治理
技术债，在 S7 执行退役、归档、交接与复盘。
下游交接：退役记录与归档位置交给运维角色；复盘行动项进入后续待办。
升级与停止：支持承诺无法兑现时升级产品负责人；退役条件触发而无人授权时 Hold；交接未确认不得关闭 G7。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 在设计时固定支持窗口、维护路径与退役条件 | 支持承诺、退役条件清单 |
| S6 运维 | 交付补丁与小版本，登记并偿还技术债 | 补丁记录、债务台账、维护窗口记录 |
| S7 收尾 | 执行退役与归档，完成交接与复盘 | 退役记录、归档确认、交接清单、复盘报告 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 支持窗口与升级路径、退役条件与数据处置方案 | Recycle 到 S2，补齐维护与退役设计 |
| G6 运维 | 补丁测试与向前移植证据、债务台账与偿还记录 | Hold：补丁未验证；Recycle 到 S6：债务增长无登记 |
| G7 收尾 | 退役通告与数据处置、归档可恢复、交接确认、复盘行动项 | Hold：交接未确认或行动项无负责人 |
