# 性能清单

在建立基准、定目标与审查优化时，本文件应当与 `SKILL.md` 配合使用。每份清单在其标题所指的时刻适用：基准清单
用于优化之前，审查清单用于改动获批之前，目标工作表用于设定阈值时。不适用的条目应当给出简短理由，不得以打勾
代替；未勾选的条目属于未决风险，而非形式。
正文“审查清单”为设计期的权威；本文件仅载明各时刻的工作表与正文未展开的条件。

## 性能审查清单

对照基准与剖析结果运行本清单，不得凭“本应更快”的记忆运行。

- [ ] 基准脚本、输入集与结果随代码提交，可复现。
- [ ] 存在明确的延迟/吞吐/内存目标与测量口径（分位、单位、稳态或突发）。
- [ ] 优化前后使用同一套基准对比，环境、输入与口径一致。
- [ ] 结果报告波动（多次运行的中位数或最小值），而非单次值。
- [ ] 一次仅变更一处，收益可归因，改动可单独回滚。
- [ ] 改动对应剖析结果中的真实热点，而非猜测。
- [ ] 无显著收益的改动已经回滚，未予保留。
- [ ] 未优化已经达标的路径，不存在过早优化。
- [ ] 缓存具有失效与一致性策略，命中率具有测量支持。
- [ ] 索引按查询增设，写入成本已经权衡，schema 约束由 `api-and-data-conventions` 管辖。

## 基准方法论

基准的价值来自可复现，而非运行速度。可信的基准应当满足下列各项。

- **同一脚本。** 基准代码应当与测试代码分离，并固定于仓库中；变更基准脚本等同于更换尺子，前后数字不可比。
- **同一输入。** 输入集应当固定且代表真实负载形状；变更输入后对比所得的数字无效。合成输入应当贴近真实数据
  分布，不得采用均匀随机。
- **同一环境。** 前后两次运行应当在同一机器、同一负载、同一配置下进行；其他进程争抢 CPU 时测得的结果不可
  信。
- **同一口径。** 指标定义应当一致：采用 p50 或 p99，峰值常驻或总分配；口径一经变更，结论即作废。
- **足够样本。** 应当多次运行并报告分布（最小值、中位数与波动），不得采用单次值；单次值淹没于噪声。
- **热身与稳定。** 应当跳过首次运行的 JIT 编译、缓存填充与冷启动，待系统稳定后取样；仅当冷启动本身属于指标
  时，方单独测量。
- **结果留档。** 应当将基线、优化后的数字与变更一并记录，供审查与回滚；未留档的优化无法复盘。

## 目标/预算工作表

每个性能目标创建时，应当填写一行，并随需求变化重新审查。阈值来自项目承诺或 SLO，不得由本 skill 臆造；空单
元格属于未决风险。

| 目标 | 路径或场景 | 阈值 | 口径 | 当前值 | 状态 |
|---|---|---|---|---|---|
| 登录延迟 | 登录接口 | p95 ≤ 200ms | 稳态、生产负载 | 待测 | 未达标 |
| 报表吞吐 | 导出任务 | ≥ 1000 行/秒 | 突发、峰值 | 待测 | 未达标 |
| 内存 | 常驻服务 | 峰值 ≤ 512MB | 峰值常驻 | 待测 | 未达标 |

- 阈值与口径应当自项目承诺或 SLO 复制，不得凭空发明；无项目目标的，应当停止并请求目标；“更快”“不应过
  慢”不构成目标。
- 路径或场景应当指明该目标所约束的对象，避免一项目标被泛化至全部路径。
- 当前值应当以基准或生产观测填充（生产观测由 `release-operations-conventions` 管辖）；未测量的，应当书写
  “待测”，不得填写假设。
- 状态仅在“未达标 / 已达标”之间切换；仅未达标的路径进入优化。

## 优化决策表

实现之前，应当为每一行记录一项决策。默认值持续有效，直至已测量的需求将其推翻。

| 决策 | 默认 | 选择其他方案的情形 | 义务 |
|---|---|---|---|
| 是否优化 | 仅未达成目标时优化 | 目标未达标且有热点证据 | 记录对应目标与热点 |
| 优化顺序 | 先复杂度，后常数 | 数据量恒定，复杂度不再是瓶颈 | 先更换算法，再处理常数 |
| 变更粒度 | 一次一处 | 一处依赖另一处方能生效时打包 | 每次变更可归因、可回滚 |
| 缓存引入 | 命中率测量后决定 | 命中率高且不一致可以接受 | 失效与一致性策略 |
| 索引新增 | 按查询增设并权衡写入 | 查询已经确认属于热点且有收益 | 记录对应查询与写入成本 |
| 结果判定 | 前后同一基准对比 | 环境、输入或口径不一致时不判定收益，结论记为未验证并复测 | 报告波动与样本量 |

- 代理应当将每项决策记录于基准或性能文档；仅存于优化者记忆的决策将在下一次优化时被重新争论。
- 测量结果变化的，代理应当重新审视决策，并说明会重新开启该决策的条件，不得使问题悬置。
- 一致性优于局部优化：同一路径反复变更口径，将使全部历史结论作废。

## 优化记录模板

每次优化应当填写一行，随变更提交；缺行等同于未优化。复制后应当删除不适用的字段，不得保留空占位。

```markdown
## 优化记录

- 目标：<对应哪条未达标的目标>
- 热点：<剖析结果指向的路径或函数>
- 变更：<一次只改的一处，一句话说清>
- 基线：<优化前同基准的数字，含口径与样本>
- 结果：<优化后同基准的数字，含口径与样本>
- 判定：<有收益 / 无显著差异，回滚或保留>
```

- “变更”应当书写可判定的一处改动，不得书写“做了一些优化”。
- “基线”与“结果”必须来自同一套基准；数字应当具有口径（分位、单位）与样本量。
- “判定”仅应书写有收益或无显著差异；无显著差异的改动应当回滚，不得保留。
