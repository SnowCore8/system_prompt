# 性能清单

在建立基准、定目标与审查优化时，把本文件与 `SKILL.md` 一起使用。每份清单在其标题所指的时刻适用：基准清单用于优化
之前，审查清单用于改动获批之前，目标工作表用于设定阈值时。不适用的条目要给出简短理由，而不是打勾；未勾选的条目是
未决风险，不是形式。
正文「审查清单」是设计期权威；本文件只放各时刻的工作表与正文未展开的条件。

## 性能审查清单

对照基准与剖析结果运行这份清单，而不是凭「本应更快」的记忆。

- [ ] 基准脚本、输入集与结果随代码提交，可复现。
- [ ] 有明确的延迟/吞吐/内存目标与测量口径（分位、单位、稳态或突发）。
- [ ] 优化前后用同一套基准对比，环境、输入与口径一致。
- [ ] 结果报告波动（多次运行的中位数或最小值），而不是单次值。
- [ ] 一次只改一处，收益可归因，改动可单独回滚。
- [ ] 改动对应剖析结果里的真实热点，不是猜测。
- [ ] 无显著收益的改动已回滚，而非留下。
- [ ] 缓存有失效与一致性策略，命中率有测量支持。
- [ ] 索引按查询加，写入成本已权衡，schema 约束归 `api-and-data-conventions`。

## 基准方法论

基准的价值来自可复现，而不是跑得快。一次可信的基准满足下面每一条。

- **同一脚本。** 基准代码与测试代码分离，固定在仓库中；改动基准脚本等于换尺子，前后数字不可比。
- **同一输入。** 输入集固定且代表真实负载形状；换输入后对比的数字无效。合成输入要贴近真实数据分布，而不是均匀随机。
- **同一环境。** 前后两次运行在同一机器、同一负载、同一配置下进行；在其他进程争抢 CPU 时测得的结果不可信。
- **同一口径。** 指标定义一致：是 p50 还是 p99，是峰值常驻还是总分配；口径一变，结论作废。
- **足够样本。** 多次运行并报告分布（最小值/中位数/波动），而不是单次值；单次值淹没在噪声里。
- **热身与稳定。** 跳过首次运行的 JIT 编译、缓存填充与冷启动，等系统稳定后再取样；冷启动本身是一个指标时才单独测。
- **结果留档。** 把基线、优化后的数字与变更一起记录，供审查与回滚；没有留档的优化无法复盘。

## 目标/预算工作表

每个性能目标创建时填一行，并随需求变化重审。阈值来自项目承诺或 SLO，而非本 skill 臆造；空单元格是未决风险。

| 目标 | 路径或场景 | 阈值 | 口径 | 当前值 | 状态 |
|---|---|---|---|---|---|
| 登录延迟 | 登录接口 | p95 ≤ 200ms | 稳态、生产负载 | 待测 | 未达标 |
| 报表吞吐 | 导出任务 | ≥ 1000 行/秒 | 突发、峰值 | 待测 | 未达标 |
| 内存 | 常驻服务 | 峰值 ≤ 512MB | 峰值常驻 | 待测 | 未达标 |

- 阈值与口径从项目承诺或 SLO 复制，绝不凭空发明；「更快」「别太慢」不是目标。
- 路径或场景指明这条目标约束谁，避免一条目标被泛化到所有路径。
- 当前值用基准或生产观测填充（生产观测归 `release-operations-conventions`），未测就写「待测」，不填假设。
- 状态只在「未达标 / 已达标」之间切换；只有未达标的路径才进入优化。

## 优化决策表

实现之前，为每一行记录一个决策。默认值持续有效，直到已测量的需求将其推翻。

| 决策 | 默认 | 选择其他方案的情形 | 义务 |
|---|---|---|---|
| 是否优化 | 只有未达标才优化 | 目标未达标且有热点证据 | 记录对应目标与热点 |
| 优化顺序 | 先复杂度，再常数 | 数据量恒定，复杂度不再是瓶颈 | 先换算法，再抠常数 |
| 变更粒度 | 一次一处 | 一处依赖另一处才能生效时打包 | 每次变更可归因、可回滚 |
| 缓存引入 | 命中率测量后决定 | 命中率高且不一致可接受 | 失效与一致性策略 |
| 索引新增 | 按查询加且权衡写入 | 查询已确认热且有收益 | 记录对应查询与写入成本 |
| 结果判定 | 前后同一基准对比 | 环境无法完全一致时注明偏差 | 报告波动与样本量 |

- 把每个决策记录在基准或性能文档中；只活在优化者脑子里的决策会在下一次优化时被重新争论。
- 测量结果变化时重新审视决策，并说明会重新打开它的条件，而不是让问题悬着。
- 一致性胜过局部优化：同一路径反复改口径，会让所有历史结论作废。

## 优化记录模板

每次优化一行，随变更提交；缺行等于没优化。复制后删掉不适用的字段，不保留空占位。

```markdown
## 优化记录

- 目标：<对应哪条未达标的目标>
- 热点：<剖析结果指向的路径或函数>
- 变更：<一次只改的一处，一句话说清>
- 基线：<优化前同基准的数字，含口径与样本>
- 结果：<优化后同基准的数字，含口径与样本>
- 判定：<有收益 / 无显著差异，回滚或保留>
```

- 「变更」写可判定的一处改动，不写「做了一些优化」。
- 「基线」与「结果」必须来自同一套基准；数字要有口径（分位、单位）与样本量。
- 「判定」只写有收益或无显著差异；无显著差异的改动回滚，不保留。
