# 优化纪律

## 1. 优化纪律

优化的价值来自可归因、可复现与可回滚；缺乏纪律的优化，等于变更一批效用不明的代码。

- 一次仅变更一处：每次变更只改一个变量并立即重测；一处依赖另一处方能生效的，作为一组落地但记录依赖，
  保持可归因、可回滚。
- 变更后重新测量：以同一套基准重测并记录；未重测即声称有收益属于编造。
- 保留基准作为对照：优化前保存基线结果，优化后与基线对比。
- 无效的优化回滚：测量显示无显著收益的改动回滚，不得保留。
- 优化以证据归因：改动必须对应剖析结果中的热点；无剖析支持的重写属于重写，不属于优化。

## 2. 判定与边界

- 一次变更仅涉及一个逻辑点，其余内容不变，判为合规。
- 前后数字均留档，供审查与回滚。
- 回滚属于重构或修复，依行为变化由 `refactoring` 或测试门禁管辖。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 变更连接池大小，重测并记录前后 p95 | 一次变更序列化、连接池与索引三处 | 前者可归因，后者收益来源不明 |
| 测量无收益即回滚改动 | 无效改动以“未造成损害”为由保留 | 前者保持整洁，后者误导后续判断 |
| 优化对应剖析中的热点 | 未剖析即重写“可能慢”的模块 | 前者有证据，后者属于猜测 |
