# 缓存与索引取舍

## 1. 缓存与索引取舍

缓存与索引用空间换时间，均带来一致性与维护成本；两者属于取舍，而非免费加速。

- 引入缓存前先定失效与一致性策略：何时失效、由谁失效、不一致窗口多大、是否可以接受；无失效策略的缓存
  是数据错误源。
- 无法命中的缓存不得设置：先测量命中率与收益再决定；命中率低、失效频繁或键空间过大的缓存成本大于收益。
- 索引按查询增设并权衡写入成本：每个索引对应一条真实查询；外键、热过滤与连接建索引，复合列先等值后
  范围。
- 缓存与索引不改变正确性：清空缓存、删除索引后系统仍应正确，仅变慢；把正确性建立在缓存存在之上的系统，
  一经失效即出错。

## 2. 判定与边界

- 判据：任何缓存都能说明失效触发条件与不一致上限；任何索引都对应真实查询并已权衡写入放大。
- 索引的 schema 约束、迁移与锁影响归 `api-data`；本 skill 只判定是否值得增设。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 缓存有 TTL 并按事件失效 | 先增设缓存，失效以后再说 | 后者使缓存成为数据错误源 |
| 按查询增设索引并权衡写入 | 为每列建索引以防万一 | 后者写入放大，收益未获证明 |
| 命中率测量后再决定缓存 | 默认缓存总比不缓存快 | 低命中缓存的成本大于收益 |
