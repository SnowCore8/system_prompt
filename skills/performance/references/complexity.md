# 复杂度分析

## 1. 复杂度分析

复杂度回答“数据量增长时会如何”，而非“当前有多慢”。复杂度决定伸缩性，剖析决定热点；两者分工，不得
相互替代。

- 以大 O 判断伸缩性：时间与空间复杂度描述算法随输入规模增长的行为；O(1)、O(log n)、O(n)、O(n log n)、
  O(n²) 的差别属于数量级。
- 复杂度差距属于设计问题，先于局部优化处理：O(n²) 算法微调常数因子无法挽救数据量增长后的崩坏；先换算法
  或数据结构，再谈常数优化。
- 剖析定位当前热点，复杂度判断未来伸缩：复杂度低未必当前不慢，当前不慢未必数据量翻倍后不崩坏。
- 常数优化仅在热点上实施：复杂度足够低后，常数优化只对剖析确认的热点有意义。

## 2. 判定与边界

- 判据：能说明算法在最坏情况与常见情况下的时间与空间大 O。
- 数据量将增长时优先处理复杂度而非常数；数据量恒定时不强求更低复杂度。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| O(n²) 嵌套循环改为哈希或排序 | 在 O(n²) 上微调循环展开 | 后者无法挽救数据量增长后的崩坏 |
| 数据量将增长，先更换算法 | 数据量恒定，仍强求 O(log n) | 后者为不存在的伸缩付出成本 |
| 热点以剖析定位，伸缩以大 O 判断 | 仅以大 O 决定修改哪一行 | 大 O 不指示当前热点所在 |
