# 常见瓶颈

## 1. 常见瓶颈

热点通常归属于少数几类模式。先行归类再对症处理；归类错误，优化方向也将错误。

- N+1 查询：循环内逐条查询，把一次可查的数据拆成多次往返；修复为批量查询、联表或预取，把往返次数降到
  常数次。
- 多余的 IO：重复读取相同数据、读取量远大于所需、热路径上同步网络或磁盘访问；修复为去重、按需取数、
  异步化或缓存。
- 锁竞争：多个线程争抢同一把锁，把可并行的路径串行化；性能问题由本 skill 定位与优化，语义正确性归
  `concurrency`。
- 内存分配：热路径频繁分配触发 GC 压力；修复为复用缓冲、减少临时对象或改用栈上结构。
- 算法复杂度：以复杂度分析判断伸缩性；O(n²) 会在数据量增长的某一规模突然崩坏；修复为更换算法或数据结构。

## 2. 判定与边界

- 归类判据：循环体内存在查询调用且次数随数据量增长是 N+1；同一数据短时间多次读取是多余 IO；CPU 不高但
  吞吐不足且等待长是锁竞争；剖析显示分配集中于热路径是分配问题。
- 本维度不变更并发结构；需要改锁粒度或模型时移交 `concurrency`。

## 3. 正反例

| 瓶颈 | 症状 | 典型修复 |
|---|---|---|
| N+1 查询 | 延迟随记录数线性增长 | 批量查询、联表、预取 |
| 多余的 IO | 同一数据重复读取 | 去重、按需取数、缓存 |
| 锁竞争 | CPU 不高但吞吐不足 | 定位争用点并优化 |
| 内存分配 | GC 停顿频繁 | 复用缓冲、减少临时对象 |
| 算法复杂度 | 数据量增长时延迟陡增 | 更换算法或数据结构 |
