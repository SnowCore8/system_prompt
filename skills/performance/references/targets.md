# 性能目标与预算

## 1. 性能目标与预算

目标属于停止条件：无阈值，即无从判断何时优化、何时停止、何时构成过度优化。

- 先定目标或暂定目标再优化：阈值与口径（如 p95 延迟 ≤ 100ms、每秒 ≥ 1000 请求）来自项目承诺或 SLO；
  无目标的先建基准并提出标注假设的暂定目标。
- 目标与预算写明口径：明确 p50/p95/p99、平均值或峰值、稳态或突发；同一指标的不同口径不可比；内存预算
  写明峰值常驻或总分配。
- 预算约束资源，不束缚正确性：正确性问题的修复优先于性能。
- 默认优化对象限于未达标的路径：已达标路径的例外仅限用户明确要求，或改动用于降低风险与维护性。

## 2. 判定与边界

- 暂定目标须标注假设，不构成项目承诺；仅当目标会改变范围、预算或验收标准且无法从上下文推定时，才请求
  确认。
- “更快”“不应过慢”不构成目标；无法测量的阈值不构成预算。
- 例外实施须保留基准、无收益预期说明与回滚方式。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 写明“p95 登录延迟 ≤ 200ms”后再优化 | 以“让登录更快一点”为起点改代码 | 前者有停止条件，后者不知何时停止 |
| 仅优化超标十倍的报表查询 | 无要求时反复优化已达标的首页 | 前者对应未达标目标，后者没有回报 |
| 内存预算写为“峰值常驻 ≤ 512MB” | 仅写“内存不应过高” | 前者可测，后者不可判定 |
