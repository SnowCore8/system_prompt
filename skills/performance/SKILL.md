# 性能

性能工作最严重的失败不是没做优化，而是未测量就优化、没有目标就优化，或优化已经达标的路径。无基准的优化
无法证明收益；无目标的优化没有停止条件；一次变更多处的优化无法归因。本 skill 规定先测量、再定目标、后
优化的程序，常见瓶颈的识别方式，以及使优化可判定、可回滚、可复现的规则。

## 适用范围与优先级

效力层级自上而下，高层覆盖低层：

1. 编译器优化行为、运行时调度、存储引擎与网络的物理上限等强制约束。
2. 本 skill 的规则与默认值：目标口径、测量方法与优化纪律。
3. 项目性能目标、SLO、基准脚本与既有剖析结果属于事实输入，依本 skill 的规则处理；项目约定仅在本 skill
   未规定处补充。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 并发正确性（锁语义、数据竞争、死锁）归 `concurrency`；锁竞争造成的吞吐与延迟问题由本 skill 定位与优化。
- 基准接入 CI 的机制、阈值与告警策略归 `testing-quality`；本 skill 管基准与剖析的方法论。
- 生产遥测与告警归 `release-operations`；本 skill 管开发期的基准与剖析，两者结论不得相互替代。
- 索引的 schema 约束、迁移与锁影响归 `api-data`；本 skill 只判定是否值得为某查询增设索引。
- 阶段与门禁判定归 `project-lifecycle`；本 skill 提供性能证据，不自行决定 Go/No-Go。
- 强制规则冲突时报告用户裁决；非强制的项目约定冲突说明所选约定并记录于性能目标或基准文档。

## 生命周期定位

上游输入：S1 的结果指标与收益基线、已有 SLO、剖析结果与基准脚本。下游交接：目标与预算进入 G2；基准与
剖析方法进入 S3；前后对比数据作为 G4 证据；发布前快照与回滚阈值交给 G5；容量与告警关注点交给 S6；收益
对照与残留瓶颈交给 S7。升级与停止：无可复现基准时停止优化并先建基线；目标缺失且影响范围、预算或验收
标准时请求用户确认；测量显示无显著收益时回滚改动，不得保留。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定诉求是否属于性能问题，记录风险级别与停止条件 | 受理结论与分流说明 |
| S1 需求 | 建立现状基线，写明指标口径与不优化的后果 | 基线数字与目标候选 |
| S2 设计 | 固定性能目标、预算、测量环境、基准脚本位置与停止条件 | 目标与预算表、基准计划 |
| S3 构建 | 运行基线、剖析定位热点、按单点变更实施并逐次复测 | 剖析输出、单点变更记录、逐次复测数据 |
| S4 验证 | 以同一套基准取得前后对比，判定收益与回归 | 前后对比表、噪声说明、回归结论 |
| S5 发布 | 复核关键路径指标、发布前后比对与回滚阈值 | 发布前基线快照、回滚触发条件 |
| S6 运维 | 观察容量与性能告警，处置性能事故 | 容量记录、事故处置结论 |
| S7 收尾 | 对照目标评估收益，登记残留瓶颈与后续项 | 收益对照、残留瓶颈清单 |

## 门禁与证据

优化前的基线、优化后的复测与前后对比必须使用同一脚本、同一输入与同一环境；任一条件变化，数字即不可比。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G1 立项 | 现状基线、指标口径与不优化的后果 | Recycle 到 S1：问题与指标不可测；无法测量的缩小范围或 No-Go |
| G2 设计 | 目标与预算、基准脚本与输入集位置、测量环境、停止条件 | Recycle 到 S2：目标缺口径或基准不可复现 |
| G4 验证 | 前后对比数据、样本量与波动、剖析热点与改动的对应关系 | Hold：环境或口径变化使数字不可比；Recycle：改动不对应热点 |
| G5 发布 | 关键路径发布前快照、回归比对结论、回滚阈值与触发条件 | Hold：关键路径无基线或回归超阈值且无接受记录 |
| G7 收尾 | 目标达成情况、无效优化回滚记录、残留瓶颈与负责人 | Hold：复盘数据不全不得关闭 |
