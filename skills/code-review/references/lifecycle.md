# 生命周期契约：代码审查

本文件是代码审查在各阶段的输入、活动、输出与证据契约。阶段与门禁的判定语义归
`project-lifecycle`；本文件只规定本 skill 负责提供的证据与交接。

## 阶段职责

S2 设计：输入为风险级别与范围。活动：把变更分为轻量、标准或高风险；确定审查深度、审查者构成（含领域或
安全审查者）与周转预期；写入审查级别表。输出：审查级别表与分派规则。

S3 构建：输入为审查级别表。活动：作者准备体量合规的请求（标题、描述、关联 issue、验证证据、自审结果），
按风险请求对应审查者；审查者按深度审阅并给出带严重级别的评论。输出：请求记录、审查评论与自审结果。

S4 验证：输入为审查记录。活动：确认批准有效、阻塞线程已解决、R1/R2 独立审查结论齐备；核对必需校验在
合并结果上通过。输出：批准记录与独立审查证据，进入 G4。

S5 发布：输入为发布路径。活动：审查热修复与向前移植，核对发布分支与标签路径上的审查记录。输出：热修复
审查记录。

## 门禁证据

G3：体量合规的请求、描述与自审、必需校验在合并结果上通过；缺失时退回修改，不得合入。

G4：归属审查者的批准、阻塞评论已解决；R1 至少一名非作者审查，R2 两名独立审查且执行者不自批；缺失时
Hold，重新审查增量。

## 交接与升级

- 审查结论交给合并门禁；分歧决定记录进入请求或 ADR，交给归属团队决策负责人。
- 审查者不可达时改派回退审查者；等待不构成审查状态。
- 阻塞线程未解决时不得合并；发现测试被弱化或证据造假时报告并按 HON 条款处理。
- 生成产物与机器产出免于逐行审查，但生成器输入与重新生成命令必须审查。

## 裁剪与度量

裁剪：

- R0：自审记录加必需校验；单人仓库以自审记录与 CI 输出代替人工批准，并作为已知缺口上报。
- R1：一名非作者审查者。
- R2：两名独立审查者（含领域或安全审查者），执行者不得自批，G4 与 G5 不得合并。
- 体量裁剪：可审查 diff 约 400 行以内；超出时拆分请求或以功能开关隐藏，并记录设计说明与第二名审查者。

度量：

- 首次响应时长与审查周转时长；阻塞评论解决率；批准过期次数；改派次数；R2 变更独立审查覆盖率。
- 指标恶化时先查根因，不得通过降低审查深度改善指标。
