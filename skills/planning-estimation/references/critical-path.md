# 关键路径与排期

## 1. 关键路径与排期

排期回答“先做什么”。关键路径是决定总时长的依赖链，资源应当优先保障它。

- 按依赖排序。任务顺序由依赖图决定，无依赖的任务方可并行；依赖方向画反会凭空造出等待。
- 识别关键路径。列出决定总时长的任务链；关键路径上的延误必须当天处理，非关键路径上的延误可以吸收。
- 里程碑可核验。每个里程碑对应可验证的状态（如“验收标准全通过”），不得以“完成 80%”充当里程碑。
- 缓冲显式。给不确定任务预留显式缓冲并写明理由；缓冲不得被悄悄挪用。
- 容量纳入排期。人员、环境、审查与运维容量不足时，排期必须反映排队；瓶颈在审查时，加开发人手不会提速。

| 正例 | 反例 | 原因 |
|---|---|---|
| 依赖图先行，再排并行窗口 | 所有任务串行排一遍 | 后者凭空拉长周期并掩盖真实依赖。 |
| 里程碑绑定可验证状态 | 里程碑写“开发基本完成” | 后者无法判定到达与否。 |
