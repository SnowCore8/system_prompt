# 缺陷诊断

调试有四类可预见的失效：未复现就改代码，把猜测当诊断；只修症状，同一缺陷换个触发条件又出现；修复不附
回归测试，既无法证明缺陷曾经存在，也无法确定回退时点；工具越界，日志淹没信号、调试器代替推理、profiler
被用来回答正确性问题。本 skill 给出从缺陷报告到修复验证的单一决策流程，并规定复现、二分定位、根因分析、
最小修复与工具纪律，把“先复现、再定位、后修复、必验证”作为不可跳过的顺序。

## 适用范围与优先级

效力层级自上而下，高层覆盖低层：

1. 平台、语言运行时、日志系统与合规要求等强制约束。
2. 本 skill 的规则：复现、二分定位、根因分析、最小修复与回归验证。
3. 项目运行手册、日志规范与缺陷跟踪系统格式属于事实输入，依本 skill 的规则处理。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 测试策略、门禁阈值与豁免程序归 `testing-quality`；本 skill 只要求修复必须附一条能证明缺陷的回归测试
  或可复现步骤。
- 性能剖析归 `performance`；本 skill 负责确认“确实慢”并交出复现与二分结果，再由该 skill 定位热点。
- 并发竞态归 `concurrency`；本 skill 提供复现与二分的通用方法。
- 修复提交的拆分归 `vcs-collaboration`；本 skill 只要求修复与无关改动分开提交。
- 阶段与门禁判定归 `project-lifecycle`；本 skill 在 S3–S7 提供可核验的缺陷证据。

## 生命周期定位

上游输入：可判定的缺陷报告、失败测试、事故单或监控告警，以及 G0 已记录的授权、风险级别与停止条件。缺陷
可能在 S3 构建或 S4 验证期间发现，也可能来自 S5 发布后的运营反馈。下游交接：修复增量与回归证据交给 G4；
未关闭缺陷、症状修补与临时缓解交给 G5 复核；根因与逃逸原因交给 S7 复盘。升级与停止：无法复现时停止改码
并向报告人索取信息；同一问题第二个补丁仍失败时停止打补丁，回到根因定位；根因修复超出授权、成本或兼容性
时按 HON 条款说明并报告，不得自行降级为症状修补。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S0 受理 | 判定报告是否可判定，确认对象与授权，区分正确性缺陷、性能问题与并发竞态 | 受理结论、缺失信息清单、分流结论 |
| S1 需求 | 对反复出现的缺陷评估结构性修复、绕过与不处理的代价 | 处置建议与影响评估 |
| S2 设计 | 固定复现环境、回归测试落点、修复范围与回滚点 | 复现方案、修复计划 |
| S3 构建 | 复现、二分定位、根因假设与验证、失败测试、最小修复 | 最小复现、排除记录、根因说明、修复提交 |
| S4 验证 | 取得修复前失败与修复后通过的对照，运行受影响范围回归 | 两次执行输出、回归结论、未覆盖项 |
| S5 发布 | 复核未关闭缺陷、症状修补与临时缓解的接受记录 | 缺陷状态清单、接受记录、发布阻塞项 |
| S6 运维 | 处置生产缺陷：止损、复现与临时缓解 | 止损记录、复现条件 |
| S7 收尾 | 把根因、逃逸原因与补充测试写入复盘 | 根因报告、行动项与负责人 |

## 门禁与证据

证据必须来自本次修复的同一提交范围；跨版本复用的旧输出、仅凭口头说明的验证均不构成证据。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G0 受理 | 报告四要素、分流结论、缺失信息、风险级别与停止条件 | Hold：报告缺期望与实际，无法判定 |
| G3 构建 | 最小复现步骤、修复前失败的回归测试、根因假设与已排除事项 | Hold：复现或失败测试缺失；范围不清时 Recycle 到 S3 |
| G4 验证 | 修复前后两次执行输出、受影响范围回归结论、未自动化时的双次步骤记录 | Recycle 到 S3：修复未针对根因或回归未捕获缺陷 |
| G5 发布 | 未关闭缺陷清单、症状修补的接受记录、临时缓解的负责人与到期日 | Hold：阻塞级缺陷未关闭且无接受记录 |
| G7 收尾 | 根因报告、逃逸原因、补充回归测试与行动项 | Hold：证据不全不得关闭复盘 |

## 维度索引

每个维度的完整规则、判定与正反例见对应文件；维度编号即该文件的节号。

| 编号 | 维度名 | 首条规则 | 详情 |
|---|---|---|---|
| 1 | 缺陷报告与复现 | 无法复现的报“无法复现”并附已尝试项，不得猜测；报告含最小复现、环境、期望与实际。 | `references/reproduction.md` 第 1 节 |
| 2 | 二分定位 | 每一步减半范围并记录已排除事项，定位至单个函数或语句。 | `references/bisection.md` 第 1 节 |
| 3 | 根因分析 | 区分根因与触发条件，仅修复根因；仅修症状的须记录根因不可修复的理由。 | `references/root-cause.md` 第 1 节 |
| 4 | 最小修复与回归验证 | 实施最小修复，回归测试在修复前失败、修复后通过方构成证明。 | `references/minimal-fix.md` 第 1 节 |
| 5 | 调试工具纪律 | 日志、调试器与 profiler 各有适用边界，超出边界将淹没信号或答非所问。 | `references/tools.md` 第 1 节 |
