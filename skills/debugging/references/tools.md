# 调试工具纪律

## 1. 调试工具纪律

日志、调试器与 profiler 各有适用范围；超出范围将淹没信号或答非所问。

- 日志：结构化、分级、可关闭；临时诊断日志用后移除，不得带入提交；日志内容与级别策略归 `code-style`。
- 调试器：用于验证假设与检查状态，不得替代推理；不得在代码中遗留断点。
- profiler：只回答“慢在何处、内存去向何处”，不回答正确性问题；性能剖析归 `performance`。
- 并发竞态的复现与推理由 `concurrency` 管辖；本 skill 只提供通用的复现与二分方法。

## 2. 判定与边界

- 工具选择：怀疑状态错误用调试器验证假设；怀疑路径范围用日志与插桩二分；怀疑慢用 profiler。
- 以重试或忽略掩盖缺陷不属于修复：记录失败并按本流程定位；重试仅用于已证实的基础设施错误。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 先提出假设再以调试器验证 | 以单步跟踪替代推理 | 仅观察现象，未形成根因假设 |
| 结构化、分级、可关闭的临时日志 | 噪声日志淹没关键线索 | 信号不可见，且拖慢系统 |
| 记录失败并按流程定位 | 以重试或忽略掩盖缺陷 | 根因未处理，缺陷在别处复现 |
