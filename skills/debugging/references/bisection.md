# 二分定位

## 1. 二分定位

二分把缺陷范围逐步减半，每一步都留下可复核的证据。

- 优先以 git bisect 定位引入缺陷的提交：确定一个已知正常的历史点与一个异常点，在两者之间自动二分。
- 无可运行历史的，以日志、断点或插桩二分：把疑点范围减半，插入断言或日志，确认缺陷位于左半还是右半。
- 每一步记录“已排除的事项”；二分至单个函数或语句后方可修改，记录写入修复说明供审查者复核。
- 使用调试器单步前先有假设：调试器用于验证“此处状态与假设不符”，不得替代推理。

## 2. 判定与边界

- git bisect 需要写明“好”与“坏”两个参照点的可判定条件。
- 每一步的排除记录使定位过程可复现；凭猜测二分不留证据的，审查者无法复核。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 每一步记录已排除事项 | 凭猜测二分不留证据 | 定位过程不可复现 |
| 收敛到单个函数或语句再修改 | 范围未收敛即改动多处 | 修复无法对应缺陷 |
