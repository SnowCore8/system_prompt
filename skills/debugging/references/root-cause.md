# 根因分析

## 1. 根因分析

根因指导致缺陷的代码缺陷；触发条件指使缺陷显现的输入。只修症状，缺陷将在另一条件下重现。

- 以“五个为什么”自现象追问至根因：每次回答后继续追问，直至落到代码缺陷或数据缺陷；停留于某一输入特例
  的属于触发条件。
- 区分根因与触发条件：除零的根因是缺少保护，触发条件是缺失汇率；修复应当补保护，不得仅对缺失汇率作
  特判。
- 针对同一问题的第二个补丁仍然失败的，停止打补丁，回到定位步骤；根因属结构性的，重构成本低于叠加补丁。
- 仅修症状的，须取得用户明确同意，说明根因不可修复或暂不具备修复条件的理由，并记录为遗留跟踪项。

## 2. 判定与边界

- 超出授权、成本、兼容性属于申请授权或排期的依据，不构成自动放行。
- 未记录的仅修症状视为未完成。
- 方案验证时三个版本应针对不同根因假设或不同实现路径，不得把三个版本做成三次叠补丁。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 修复除零保护并补回归测试 | 仅对缺失汇率作特判 | 同一缺陷在另一币种重现 |
| 第二个补丁失败即回到根因定位 | 持续叠加补丁 | 补丁掩盖根因，成本持续上升 |
| 仅修症状时记录理由并跟踪 | 吞掉异常并当作已修复 | 缺陷被隐藏，在别处复现 |
