# 最小修复与回归验证

## 1. 最小修复与回归验证

修复必须最小，并且能由一条回归测试或可复现步骤证明。

- 最小修复：仅修改根因所需的最小代码；顺带重构、格式化、重命名、升级依赖与缺陷修复分开提交。
- 回归测试先失败后通过：先写一条修复前失败、修复后通过的测试并取得失败结果，再实施最小修复，最后取得
  通过结果。
- 无法自动化时，以能稳定复现缺陷的步骤替代测试，在修复前后各执行一次并记录；跳过失败结果这一步等同于
  未证明。
- 回归测试层级由 `testing-quality` 管辖；本 skill 不另设默认层级或优先级。

## 2. 判定与边界

- 判据：修复前该测试失败、修复后通过，或同一复现步骤在修复前后得到不同结果。
- 仅有通过结果而无失败结果的，说明测试未捕获缺陷。
- 审查者发现修复 diff 混有无关改动的，应当驳回并要求拆分。

## 3. 正反例

| 正例 | 反例 | 原因 |
|---|---|---|
| 失败在前、通过在后 | 只有修复后通过的输出 | 无法证明缺陷曾经存在 |
| 修复只改根因所需代码 | 修复夹带重构与格式化 | 无法分辨哪项改动修复了缺陷 |
| 无法自动化时双次执行并记录 | 只口头说明验证 | 证据不可复核 |
