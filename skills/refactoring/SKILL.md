# 重构

重构存在四类可预见的失效：把行为变更伪装成重构提交，使审查者误以为只调整了结构；在没有测试保护的区域大改，缺陷无从察觉；在单次提交中并入数十处机械改动，任何一步出错都无法定位；在不该重构时重构，把发布压力或范围蔓延当作理由。本 skill 把“外部行为不变方构成重构、有测试保护方可改动危险区域、一次提交仅一步等价变换”作为不可跳过的顺序。

## 适用范围与优先级

效力按下列层级判定，高层覆盖低层，低层只在高层未规定时补充。

1. 平台与宿主的强制约束：编译器的语义行为与既有测试套件属于事实约束，优先于本 skill 的规则。
2. 本 skill 的规则：判定、手法、小步纪律与异味阈值以本文件与 `references/` 为准。
3. 项目约定与事实：现有代码、测试与提交历史是输入；项目约定只在本 skill 未规定处补充，不得覆盖本 skill。
4. 个人偏好，不得覆盖以上三层。

管辖与边界：

- 本 skill 判定一次改动是否属于重构，并规定安全手法、小步提交与异味触发条件。
- 行为变更属于 fix/feat；缺陷的复现、二分与根因诊断归 `debugging`。
- 名称本身归 `naming`；重命名属于安全手法之一，具体名称由 `naming` 裁定。
- 风格、格式化与日志策略归 `code-style`；重构不得顺带变更风格。
- 提交拆分与修复重构的分开提交归 `implementation-practices`；PR 流程与合并门禁归 `vcs-collaboration`；本 skill 只要求每个手法单独成提交并保持套件通过。
- 测试策略、覆盖阈值与豁免归 `testing-quality`；本 skill 只要求危险区域先有特征测试。

## 生命周期定位

上游输入：S1 需求中的异味依据与收益预期；S2 设计中的范围、行为保持验收与特征测试计划。下游交接：S3 构建中的分步实现、S4 验证中的独立审查与回归、S5 发布中的冻结窗口隔离。

升级与停止：重构范围扩大、需要改变外部行为或接口时退回 G2；发布冻结窗口内不启动重构；无测试且无法补充特征测试时停止，报告风险与替代方案。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S2 设计 | 依异味清单确定重构范围与顺序，写明行为保持验收与回滚点 | 重构任务清单、验收标准、特征测试计划 |
| S3 构建 | 一次实施一项安全手法，每步运行测试并单独提交，重命名后搜索旧名确认引用清零 | 手法提交、测试输出、旧名搜索记录 |
| S4 验证 | 核对 diff 无行为变更，审查测试未被弱化，确认新旧路径未并存 | 审查结论、全量测试结果、清理证据 |
| S5 发布 | 确认未完成的重构不进入发布，冻结窗口内无结构改动 | 发布范围清单、冻结窗口记录 |

## 门禁与证据

证据必须可复核：测试命令与退出码、逐条提交的 diff、旧名搜索命令；口头声明“只是重构”不构成证据。

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 设计 | 重构范围与异味依据、行为保持验收、特征测试与回滚方案 | 范围或验收未定时 Hold |
| G3 构建 | 每步测试通过记录、单手法 diff、旧名搜索结果 | Recycle 到 S3，拆分提交后重验 |
| G4 验证 | 行为保持结论、独立审查、全量测试输出、无被弱化的测试 | 修复或 Recycle 到 S3；夹带行为变更的拆分为 fix/feat 提交后重验 |
| G5 发布 | 冻结窗口记录、未完成重构的隔离清单 | Hold 发布，隔离未完成项后再过门 |

| 4 | 异味处理 | 由代码异味触发重构；无测试覆盖且无法补特征测试、发布冻结窗口与范围蔓延时不得重构。 | `references/smells.md` 第 1 节 |
