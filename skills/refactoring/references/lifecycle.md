# refactoring 生命周期契约

本文件是 `refactoring` 的阶段契约：阶段职责、门禁证据、交接与升级、裁剪与度量。阶段与门禁编号由 `project-lifecycle` 裁定；本文件只写本 skill 在各阶段的输入、活动、输出与证据形态。

## 阶段职责

| 阶段 | 输入 | 活动 | 产出与证据 |
|---|---|---|---|
| S0 受理 | 重构类请求：结构改造、清理、拆分提交 | 复述对象与范围，判断改动是否可逆、是否触及公开接口 | 受理记录、风险级别 R0/R1/R2 |
| S1 需求 | 异味依据与收益预期 | 盘点代码异味与测试覆盖现状，列出重构候选与优先级 | 异味清单、覆盖现状记录 |
| S2 设计 | 异味清单与验收要求 | 依清单确定重构范围与顺序，写明行为保持验收与回滚点 | 重构任务清单、验收标准、特征测试计划 |
| S3 构建 | G2 通过的任务清单 | 一次实施一项安全手法，每步运行测试并单独提交，重命名后搜索旧名确认引用清零 | 手法提交、测试输出、旧名搜索记录 |
| S4 验证 | 分步提交与测试记录 | 核对 diff 无行为变更，审查测试未被弱化，确认新旧路径未并存 | 审查结论、全量测试结果、清理证据 |
| S5 发布 | 验证证据 | 确认未完成的重构不进入发布，冻结窗口内无结构改动 | 发布范围清单、冻结窗口记录 |
| S6 运维 | 发布后的缺陷信号 | 依据回归缺陷判断某次重构是否夹带行为变更，归入修复待办 | 回归缺陷记录 |
| S7 收尾 | 全程记录 | 复盘手法选择与提交粒度，遗留的未完成重构移交 | 复盘记录、遗留项清单 |

## 门禁证据

G0：请求复述、授权依据、风险级别与停止条件；触及公开接口的重构按 R1 以上处理。
G1：异味清单与覆盖现状记录；未盘点的区域不得当作有测试保护。
G2：重构范围与异味依据、行为保持验收、特征测试与回滚方案；范围或验收未定时 Hold。
G3：每步测试通过记录、单手法 diff、旧名搜索结果；混有行为变更时 Recycle 到 S3 拆分。
G4：行为保持结论、独立审查、全量测试输出、无被弱化的测试；夹带行为变更的拆分为 fix/feat 提交并重验。
G5：冻结窗口记录、未完成重构的隔离清单；缺失时 Hold。
G6/G7：回归缺陷记录与复盘记录；只作记录，不作为发布前门禁的替代。

## 交接与升级

上游交接：`testing-quality` 提供特征测试的写法与覆盖判据；`code-style` 与 `naming` 提供风格与名称的规则；
`debugging` 提供缺陷的根因证据。下游交接：提交拆分与修复重构的分开提交交 `implementation-practices`；提交
消息格式交 `naming`；行为变更的测试交 `testing-quality`；发布冻结窗口的确认交 `release-operations`。

升级条件：重构范围扩大、需要改变外部行为或接口时退回 G2；发布冻结窗口内不启动重构。停止条件：无测试且无法补充特征测试时停止，报告风险与替代方案；不得以“只是重构”为由跳过验证。

## 裁剪与度量

裁剪：R0 只保留受理、一次验证与交付记录；R1 使用精简计划与 G4 非作者审查；R2 需独立审查与回滚演练。行为保持验收与特征测试要求不因裁剪而省略。

度量：重构提交中夹带行为变更的比例、回归缺陷数、平均提交粒度按基线比较趋势；指标恶化时先查根因，不调整阈值。度量不替代门禁判断。
