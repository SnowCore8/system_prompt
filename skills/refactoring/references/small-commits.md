# 小步提交

## 1. 小步提交

重构的价值在于每一步可验证、可回滚。

- 单条提交仅含一项手法，diff 中不出现行为变更；审查者逐条复核等价性，任何一步失败均可单独回滚。
- 每一步之后运行测试，套件保持通过；禁止一次大规模改动之后再行修复。
- 判定标准：单条提交的 diff 只包含一项手法的等价变换。
- 提交消息用 `refactor(scope):` 说明所做手法与理由，不夹带行为变更；提交拆分的完整规则由 `implementation-practices` 裁定，消息格式归 `naming`。
- 每一步都应当能够独立解释“结构如何变了、行为为何没变”；解释不了的步骤先拆小。
