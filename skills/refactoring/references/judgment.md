# 重构与修复的判定

## 1. 重构与修复的判定

动手改动之前先按本文件判定这次改动是什么。

- 判定重构的唯一标准是外部行为是否变更，而非改动规模。
- 可观察行为包括：API 与返回结构、错误语义、输出、副作用与性能特征；其中任一项变化的，按行为变更处理，不构成重构。
- 判定流程：先运行既有测试，再逐项核对 API、返回结构、错误语义、副作用与性能特征；全部不变的构成重构，任何一项变更的属于行为变更，用 fix/feat 并新增或修改测试。
- 测试通过只是必要条件：测试未覆盖当前行为的，先补特征测试锁定现状；补齐后仍无法判定的，按行为变更处理。
- 提交类型是判定结果，不是判定原因：先判定行为，再选择 refactor 或 fix/feat，不为使用 refactor 而变更行为。
- 重构与缺陷修复同时出现的，先修缺陷再重构，或先补测试再重构；分开提交的规则归 `implementation-practices`。
