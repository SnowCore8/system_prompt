# 命名规范生命周期契约

本文件把命名规则接入阶段与门禁：说明每个阶段需要哪些名称证据、如何交接、按风险如何裁剪。
命名规则本体的细则见 `dimensions-code.md`、`dimensions-interface.md`、`dimensions-system.md` 与 `languages.md`；
阶段编号、门禁决定与风险分级由 `project-lifecycle-governance` 裁定。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 接口契约、数据模型、目录与包边界、发布与分支方案、项目术语表 | 列出本迭代涉及的名称产物；确定跨层映射点；为公开名称与数据库标识符选定迁移策略；登记新术语与禁用同义词；配置命名 lint 规则 | 命名表条目、跨层名称清单、迁移与回滚说明、lint 规则 | G2 |
| S3 构建 | G2 通过的命名表与名称清单、语言与框架约定 | 按维度规则与大小写矩阵命名；重命名按引用清单逐处更新；每步运行 lint 与相关测试；同步 fixture 与快照 | 代码中的名称、命名表更新、重命名提交、lint 输出 | G3 |
| S4 验证 | 增量、命名表、lint 配置 | 核对同一概念在各层是否同名；检查公开名称的别名或弃用路径；核对测试、文档与示例中的旧名残留 | 跨层一致性结论、别名或弃用证据、旧名搜索记录 | G4 |
| S5 发布 | 版本号、变更记录、发布说明、标签方案 | 核对标签、发布标题与说明中的名称；确认命名表中的术语与说明一致 | 标签与说明一致性检查、发布记录中的名称 | G5 |

阶段之外的三条硬约束：

- 名称先于实现确定。S2 未定名的公开概念不得先写代码再补名，否则改名会以行为变更的形式进入 S3。
- 重命名不改变行为。S3 中的重命名提交不得携带逻辑修改，也不得与格式化或结构调整混在一起。
- 命名表与代码同仓提交；不得在代码、文档与看板各处维护互相冲突的名称清单。

## 门禁证据

G2 计划：

- 命名表新增或变更条目，含规范名称、避免的同义词与维护人。
- 禁用同义词逐条列出理由，避免后续以“同义”为由重新引入。
- 跨层名称清单：同一概念在代码、存储、HTTP、配置与日志中的写法，以及映射发生的位置。
- 需要映射的对象逐项列出：HTTP 字段与代码属性、存储列与领域字段、配置键与环境变量。
- 公开名称或数据库标识符的迁移方案：别名、弃用窗口、扩展—收缩步骤与回滚顺序。
- 命名 lint 规则已纳入配置，或说明项目暂不配置的理由与人工核对方式。

G3 构建：

- 命名 lint 的命令与真实输出，而非“已检查”。
- diff 中名称与大小写矩阵、语法形式的对照结果；新增术语已入表。
- 重命名提交的引用清单：调用点、测试、文档、fixture、快照与序列化字段。
- 别名、弃用标记或扩展—收缩的中间状态已写入代码，并附移除条件。
- 旧名搜索记录，证明没有残留的两套名称。

G4 验证：

- 跨层一致性核对结果，逐项列出代码名、线上名与存储名的对应关系。
- 示例、文档与测试夹具中的名称与代码一致，未残留旧名。
- 公开名称的兼容证据：别名保留期、弃用标记、调用方迁移状态。
- 未完成的命名债清单，含位置、风险与移除条件；未跟踪的命名债不得以 TODO 代替。

G5 发布：

- 发布标签与发布说明中的产品名、模块名、配置键与命名表一致。
- 制品名、包名、镜像标签与版本标签遵循同一命名规则，不得各用一套写法。
- 支持文档与运行手册中的产品名、命令名与配置键同步更新。
- 若本次发布包含公开改名，附迁移指南与移除窗口，并在变更记录中单列。

证据不满足时：G2 缺命名表或公开名称未定时 Hold，等待设计补齐或退回 S1；G3 出现两套名称或 lint 失败时
Recycle 到 S3；G4 发现不可兼容的公开改名且无迁移路径时按 No-Go 处理，不得以“后续补别名”通过；G5 名称不一致
时 Hold 发布，修正说明后再过门。决定语义与升级路径依 `project-lifecycle-governance` 的门禁规则。

## 交接与升级

上游交接：

- 从 `architecture-and-design-conventions` 接收模块与组件边界，名称不得越过边界自行发明层次词。
- 从 `api-and-data-conventions` 接收资源、字段与迁移约束；本 skill 只裁定这些对象的名称写法。
- 从 `code-style-conventions` 接收语言与 lint 配置；格式化细节不进入命名评审。
- 从 `documentation-conventions` 接收术语定义；命名表引用术语，不复制定义。
- 与 `vcs-collaboration-conventions` 就提交消息格式分歧时，名称语法归本 skill，正文与脚注构成归其裁定。

下游交接：

- 向 `vcs-collaboration-conventions` 交付提交消息、分支与标签的名称约定，流程与权限仍由该 skill 裁定。
- 向 `release-operations-conventions` 交付发布标题与说明中的名称，弃用时机与公告位置由其决定。
- 向 `testing-and-quality-conventions` 交付 lint 规则与失败处理方式，门禁阈值由其配置。
- 向 S6 复盘交付命名债清单与未关闭项，作为收尾核对的输入。
- 向 `security-compliance-conventions` 交付权限、角色与审计动作的名称，访问策略由其裁定。

升级与停止：

- 公开 API、事件名、数据库列或配置键的改名属于契约变更，升级到 G2 重新确认，并按授权要求取得同意。
- 跨仓库共享的标识符、权限动作名与事件类型名，需与消费方共同确认；单方改名视为未完成。
- 命名表与既有契约冲突且无法裁决时停止改动，列出冲突双方、影响面与可选方案，交由用户选择。
- 术语表与命名表对同一概念给出不同写法时，以术语表定义为准，命名表只调整名称写法。
- 发现注释、文档或示例仍在传播旧名时，先报告范围，再决定是否纳入本次变更。

## 裁剪与度量

按风险裁剪：

| 级别 | 典型命名工作 | 证据厚度 | 审查 |
|---|---|---|---|
| R0 轻量 | 单个局部变量、私有函数或测试名 | 命名表可省略，lint 与自检即可 | 执行者自检 |
| R1 标准 | 跨文件重命名、新增模块或接口名 | 命名表条目、引用清单、lint 输出 | 至少一名非作者审查 |
| R2 关键 | 公开 API、事件、数据库列、配置键或权限名改名 | 跨层清单、迁移与回滚方案、兼容证据 | 设计与契约独立评审，人工批准 |

裁剪只减少记录厚度，不减少证据：R0 也必须运行 lint 或人工核对，R1 不得省略引用清单，R2 不得省略回滚顺序与
弃用窗口。

度量用于发现命名债，不用于排名：

- 命名 lint 告警数与新增标识符数之比，按迭代统计。
- 跨层不一致项数量：同一概念在代码、存储与线上名称不同的处数。
- 重命名回滚次数与原因分类：证据不足、引用遗漏、兼容路径缺失。
- 命名表覆盖率：已登记概念占本迭代新增公开概念的比例。
- 跨层映射缺口数：尚缺对应关系的字段、列与配置键。
- 旧名残留数：发布前在代码、文档与示例中搜索到的旧名称条目。
- 别名保留期超期数：已过移除窗口仍在使用的兼容名称。

指标恶化时先查流程根因：缺少 S2 命名设计、lint 未接入，还是重命名未列引用清单；不得通过放宽规则或缩小统计
范围改善数字。命名债的清理进入待办，按 S2 的范围与 S3 的小步纪律执行，不在发布冻结窗口内批量改名。
