# 实现实践生命周期契约

本文件规定本 skill 在 S0–S7 中的职责、门禁证据、交接与升级、裁剪与度量。阶段与门禁编号由生命周期治理模型裁定；本 skill 主责 S3 构建，在 S2 核对 DoR、在 S4 提供验证证据。

## 阶段职责

### S2 设计

- 输入：任务清单、验收标准与设计。
- 活动：核对条目满足 DoR；明确每个增量的目标与提交边界。
- 产出与证据：DoR 结论、增量切分。

### S3 构建

- 输入：G2 结论与增量切分。
- 活动：按小步提交实现增量；保持在制品上限；发现缺陷时按调试四步处理；每个增量结束执行 DoD 检查。
- 产出与证据：提交记录、可运行增量、评审记录、DoD 结论、G3 证据。

### S4 验证

- 输入：增量与 DoD 结论。
- 活动：配合独立审查解释 diff；验证失败时修复并回归，修复与其余改动分开提交。
- 产出与证据：修复提交、回归证据、G4 证据。

### S0 受理

- 输入：用户请求。
- 活动：确认对象、授权与风险级别，避免在构建中才发现做错对象。
- 产出与证据：受理结论，作为 S3 开工的前置。

## 门禁证据

| 门禁 | 证据形态 | 判定 |
|---|---|---|
| G2 设计 | DoR 逐项结论、增量切分与提交边界 | 条目满足 DoR 为 Go；未满足的留在待办 |
| G3 构建 | 可运行增量、拆分提交、DoD 逐项结论、评审结论 | 增量可运行且 DoD 完成且无调试残留为 Go；否则 Recycle 到 S3 |
| G4 验证 | 修复提交与回归证据、失败项修复结论 | 证据可复核为 Go；缺失时 Hold 或 Recycle 到 S3 |

证据必须来自本次增量的实际执行：真实提交记录、真实构建输出与真实测试结果；计划中的检查与口头说明不构成证据。

## 交接与升级

- S2 → S3：把增量切分与 DoR 结论交给实现者；条目不满足 DoR 的不得开工。
- S3 → S4：把提交记录、增量与 DoD 结论交给验证方；增量不可运行的先修复再交接。
- 升级：同一缺陷第二个补丁仍失败时停止打补丁，回到根因定位；根因属于结构性缺陷时升级到架构决策。
- 停止：增量反复不可运行、DoD 长期未完成或调试无法复现时停止，报告受阻项与已确认项。

## 裁剪与度量

- R0：一次可验收增量即可，提交拆分与自检记录保留，DoD 不可跳过。
- R1：每个增量至少一次评审；G3 由非作者审查提交拆分与 DoD。
- R2：逐增量保留评审与集成记录；DoD 结论由独立审查者复核，不得自批。
- 度量：以逃逸缺陷数、提交回滚率与 DoD 一次通过率为准；指标恶化时先查提交拆分与调试纪律，不得放宽 DoD。
