# 在制品控制

## 1. 在制品控制

在制品是并行中的工作数量。在制品无上限，交付变慢、集成冲突、评审积压，忙碌不等于交付。

- 每人设上限。每个执行者同时进行的条目数设上限；多智能体团队按工作树或模块设上限。
- 到达上限先完成。先完成、评审或清理，再启动新条目；排队不是进度，启动新活不减少排队。
- 阻塞项显式标记。写明阻塞原因、责任人与解除条件；超过复审时间升级。
- 优先缩短前置时间。目标是把条目尽快送到完成，而不是让所有人都有活干。
- 插队记录影响。缺陷与安全问题可以插队，但必须记录对原承诺的影响。

| 正例 | 反例 | 原因 |
|---|---|---|
| 上限为三，满了先评审再开工 | 同时开七个任务，都“做了一半” | 前者持续产出完成项，后者全是半成品。 |
| 阻塞项带原因与解除条件 | 阻塞项只标“等一等” | 前者可追踪，后者无人负责解除。 |
