# 调试纪律

## 1. 调试纪律

缺陷诊断的完整流程——缺陷报告、复现、二分定位、根因分析、最小修复与回归验证——由 `debugging` 管辖，
其“先复现、再定位、后修复、必验证”四步顺序不可跳过；本维度不复制该流程的步骤与判据。

构建期间本 skill 只保留两条衔接要求：

- 构建中发现缺陷时，先记录缺陷并回到上一个可运行状态，再按 `debugging` 的流程修复；无法复现时按该 skill 停止改码的要求处理。
- 修复提交与其余改动分开提交（见本 skill 的提交拆分维度）；回归证据随修复提交一并交付。

| 正例 | 反例 | 原因 |
|---|---|---|
| 按 `debugging` 收敛到根因后修一处 | 加多个特判把异常吞掉 | 前者治根因，后者同一缺陷换个触发又现。 |
| 回归测试先失败后通过 | 修完说“应该好了” | 前者有证据，后者只是感觉。 |
