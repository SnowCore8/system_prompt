# 调试纪律

## 1. 调试纪律

调试的失效有四种：未复现就改代码、只修症状、修复不附回归、工具越界。四步顺序不可跳过。

- 先复现。把报告转成稳定触发缺陷的最小步骤并记录环境；无法复现时报告“无法复现”并附已尝试项，不改代码。
- 再定位。用二分法把范围减半，每一步记录已排除事项，收敛到单个函数或语句；区分根因与触发条件。
- 后修复。仅修改根因所需的最小代码；只修症状的，必须说明根因不可修复的理由、取得同意并建立跟踪项。
- 必验证。回归测试在修复前失败、修复后通过，无法自动化的用双次可复现步骤；受影响范围回归并标注未覆盖部分。
- 工具纪律。临时日志结构化、分级、可关闭，提交前移除；调试器用于验证假设，不得代替推理；第二个补丁仍失败时停止打补丁，回到定位。

| 正例 | 反例 | 原因 |
|---|---|---|
| 二分收敛到除零函数后修一处 | 加多个特判把异常吞掉 | 前者治根因，后者同一缺陷换个触发又现。 |
| 回归测试先失败后通过 | 修完说“应该好了” | 前者有证据，后者只是感觉。 |
