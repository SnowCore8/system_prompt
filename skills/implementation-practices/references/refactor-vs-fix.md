# 修复与重构的区分

## 1. 修复与重构的区分

修复与重构的判据是外部行为，不是改动规模。混在一起，验证与回滚都失去依据。

- 按行为区分。重构不改变外部行为，既有测试预期保持通过；修复改变外部行为，应当补充或修改测试证明该变化属于有意。
- 修复必须可证明。修复提交附“修复前失败、修复后通过”的测试或可复现步骤；证明不了的视为猜测性改动。
- 重构保持行为。重构前后运行同一测试集，输出不变；测试需要改动才能通过的，说明夹带了行为变化。
- 分开提交。修复与重构分别提交，先修后重构或先重构后修由依赖决定，但不得混在一处。
- 替换后清理。变更实现、接口或配置时，同一改动中删除被替换项；确需迁移窗口的，写明移除条件与期限。

| 正例 | 反例 | 原因 |
|---|---|---|
| “重命名变量”单独一个 refactor 提交 | 修复缺陷时顺带重命名与格式化 | 后者无法分辨哪项改动修复了缺陷。 |
| 修复附失败转通过的测试 | 修复只改代码不加测试 | 后者无法证明缺陷曾经存在。 |
