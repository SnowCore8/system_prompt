# 小步提交与提交拆分

## 1. 小步提交与提交拆分

提交是审查与回滚的单位。一次提交只承载一个逻辑单元，审查者才能从小步 diff 理解行为变化，回滚才能不误伤无关改动。

- 一个逻辑单元一次提交。逻辑单元指一个意图对应的最小改动集：一个缺陷、一次重构、一个功能点；判据：提交说明能否用一句话说清“为什么改”。
- 修复、重构与无关改动分开。修复改变行为，重构不改变行为，两者混在一个提交里无法单独回滚。
- 提交说明写“为什么”。说明改动原因与影响，不写“改了几个文件”之类的活动描述。
- 提交前自检。检查调试残留、生成产物、机密与无关格式化；本地配置与临时文件不得进入提交。
- 不重写已推送的历史。已推送的提交有问题时新增修复提交，不强制推送改写。

| 正例 | 反例 | 原因 |
|---|---|---|
| “修复：币种缺失时返回可判定错误”单独成提交 | 修复顺带重命名三个文件 | 后者无法分辨哪项改动修了缺陷。 |
| 提交说明写“为 X 修复 Y 的原因” | 提交说明写“更新代码” | 前者可复核意图，后者只是活动记录。 |
