# 小步提交与提交拆分

## 1. 小步提交与提交拆分

提交是审查与回滚的单位；一次提交只承载一个逻辑单元，审查者才能从小步 diff 理解行为变化（章程 5.4）。
本维度规定构建期间的提交拆分纪律；PR 拆分、审查与合并流程由 `vcs-collaboration` 裁定；提交信息格式由 `naming` 裁定。

- 一个逻辑单元一次提交。逻辑单元指一个意图对应的最小改动集：一个缺陷、一次重构、一个功能点；
  判据：提交说明能否用一句话说清“为什么改”。
- 每次提交附带相关测试。开发过程中只运行与改动相关的用例，完整测试留至提交前执行（EXE-7）。
- 修复、重构与无关改动分开提交。修复与重构的判定见 `refactoring`；低风险顺手修复单独提交并说明（CHG-1）。
- 提交说明写“为什么”。说明改动原因与影响，不写“改了几个文件”之类的活动描述；标题格式由 `naming` 裁定。
- 提交前自检。检查调试残留、生成产物、机密与无关格式化（IRR-9）；本地配置与临时文件不得进入提交（IRR-2）。
- 不重写已推送的历史（IRR-7）。已推送的提交有问题时新增修复提交，不强制推送改写。

| 正例 | 反例 | 原因 |
|---|---|---|
| “修复：币种缺失时返回可判定错误”单独成提交 | 修复顺带重命名三个文件 | 后者无法分辨哪项改动修了缺陷。 |
| 提交说明写“为 X 修复 Y 的原因” | 提交说明写“更新代码” | 前者可复核意图，后者只是活动记录。 |
