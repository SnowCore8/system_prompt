# 并发审查与排查工作表

本文件为并发 diff 审查与故障排查的速查表，包括同步原语决策表、死锁诊断工作表、竞态检测器命令与各语言原语对
照。查阅本文件时应当同时参照 `SKILL.md`；维度规则载于 `dimensions.md`；本文件仅列决策表与操作步骤，不重复维度规则。

## 同步原语决策表

判定顺序：先消除共享（不可变或单一所有者通道）；必须共享时，单个标量的读改写用原子操作；其余按等待、限量与
读写比例选择条件变量、信号量或读写锁；无法归入更具体行的，互斥锁为默认。

| 场景 | 选用 | 理由 | 注意 |
|---|---|---|---|
| 保护一组字段的临界区，写多读多 | 互斥锁 | 默认互斥，推理简单 | 持锁区间应当较小，不得回调、不得无序嵌套 |
| 读远多于写，且读取可以并发 | 读写锁 | 读并发，写互斥 | 写入频繁时开销反超，应当先测量读写比例 |
| 限制并发访问的资源数量，或用于有界缓冲 | 信号量 | 仅实施计数，不保护状态 | 状态保护应当另行加互斥锁 |
| 等待某状态变为真 | 条件变量 | 挂起等待，避免忙等 | 应当循环重查谓词，并设定超时 |
| 单个标量的读改写 | 原子操作 | 无锁读改写 | 不保护多字段不变量 |
| 数据仅有一个所有者 | 通道/队列 | 传递所有权，而非共享 | 传递后不得再共享引用 |
| 创建后不再改变的值 | 不可变值 | 零竞争 | 创建后不得再修改 |

## 死锁诊断工作表

1. 绘制资源等待图。每个执行流对应一个节点；执行流持有锁 X 并等待锁 Y 时，应当绘制一条自“持有 X 的执行流”
   指向“持锁 Y 的执行流”的边。
2. 查找环。存在环即为死锁；环上的每一条边均表示“某一执行流持锁等待另一把锁”。
3. 破环。可以选择下列一种：统一全局锁顺序（消除循环等待），并自第二把锁起采用 try-lock 加超时（打破持有并
   等待）、减少锁数量（合并不变量）、将回调与 I/O 移出临界区（消除锁嵌套）；锁数与超时上限记录于并发文档。
4. 验证。修复后应当运行压力测试与检测器；检测器不覆盖死锁的，应当以带超时的看门狗在停滞时打印每个执行流的
   锁状态。

## 竞态检测器命令

| 语言/运行时 | 命令或工具 | 覆盖 |
|---|---|---|
| Go | `go test -race` | 数据竞争 |
| C/C++ | ThreadSanitizer（`-fsanitize=thread`） | 数据竞争 |
| Rust | `loom` 或 `cargo miri test` | 数据竞争与交错枚举 |
| Java | 无运行期检测器；以并发压力测试、静态工具与审查替代 | 人工与压力；记录覆盖缺口 |
| Python | 无运行期检测器；以 `threading` 压力测试、静态工具与审查替代 | 人工与压力；记录覆盖缺口 |

## 各语言原语对照

以下为常见语言的对应原语示例，以各语言文档为准。

| 概念 | Go | Rust | Java | Python | C/C++ |
|---|---|---|---|---|---|
| 互斥锁 | `sync.Mutex` | `std::sync::Mutex` | `ReentrantLock` | `threading.Lock` | `std::mutex` |
| 读写锁 | `sync.RWMutex` | `std::sync::RwLock` | `ReentrantReadWriteLock` | 无内置读写锁 | `std::shared_mutex` |
| 原子操作 | `sync/atomic` | `std::sync::atomic` | `AtomicInteger` 等 | 需持锁模拟 | `std::atomic` |
| 条件变量 | `sync.Cond` | `std::sync::Condvar` | `Condition` | `threading.Condition` | `std::condition_variable` |
| 通道/队列 | `chan` | `std::sync::mpsc` | `BlockingQueue` | `queue.Queue` | 无内置 |
| 事件循环 | goroutine 加运行时 | `tokio`/`async-std` | 虚拟线程或执行器 | `asyncio` | 无内置 |

## 多锁申请核对

1. 多把锁按全局偏序申请；顺序未知的锁不得申请。
2. 自第二把锁起采用 try-lock 加超时；无法取得的，释放已持有锁并重试或上报。
3. 锁数、超时上限与重试上限记录于并发文档。

## 审查前先读

审查并发 diff 前，应当先阅读 `dimensions.md` 中与该 diff 相关的维度；本工作表仅供速查，不重复维度规则。
