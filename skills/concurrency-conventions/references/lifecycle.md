# 并发与并行规范生命周期契约

本文件说明并发工作在阶段与门禁中的位置：模型与共享状态何时定稿、竞态证据如何取得、事故后如何回到前序阶段。
维度规则见 `dimensions.md`，原语决策表与死锁工作表见 `checklist.md`；阶段与门禁的定义由
`project-lifecycle-governance` 裁定。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 需求中的并发点、现有线程与通道、性能目标、事故记录 | 判定是否真的需要并发；列出共享状态与所有者；选定执行模型与原语；确定锁全序、超时与取消方式；设计检测器与压力测试 | 并发设计说明、共享状态与锁顺序表、测试方案 | G2 |
| S3 构建 | G2 的模型与锁顺序、既有并发工具类 | 按决策表实现同步；缩小临界区；把回调与 I/O 移出锁；在代码与文档记录锁与不变式 | 实现与注释、锁顺序记录、局部检测结果 | G3 |
| S4 验证 | 增量、检测器配置、压测环境 | 运行检测器与压力测试；绘制资源等待图排查死锁；记录未覆盖的交错与替代验证 | 检测器与压测输出、死锁分析、覆盖缺口 | G4 |
| S6 收尾 | 事故时间线、复现条件、监控数据 | 复盘竞态与死锁事故；补复现用例与回归；更新并发文档、超时与告警；把行动项纳入待办 | 根因结论、回归用例、文档更新、行动项 | G6 |

并发工作的阶段边界：

- 并发模型属于设计决策，在 S2 定稿；S3 不得以“先写再调”的方式临场更换模型。
- 竞态证据在 S4 取得；没有证据的并发变更不得以“逻辑上正确”通过。
- 事故复盘在 S6 完成，但止损与最小修复按紧急路径先行。
- 并发变更的收益必须可度量；没有响应性、吞吐或资源利用目标的并发不属于本流程。

## 门禁证据

G2 计划：

- 是否需要并发的判定：响应性、吞吐或资源利用中至少一项有可测量目标。
- 共享状态清单：变量、字段与容器，各自的所有者、读写方与保护方式。
- 执行模型与边界：线程、协程、事件循环与线程池的职责，回调运行在哪个执行流。
- 执行流可见状态：回调、定时器与工作线程各自可以访问哪些数据，由谁负责同步。
- 锁全序、超时上限、重试上限与取消方式；无法取得锁时的行为。
- 原语备选方案与降级路径：主选原语在目标语言中不可用时的替代。
- 并发测试方案：检测器命令、压力测试参数、故障注入点与覆盖缺口。

G3 构建：

- 每项共享状态的同步覆盖读侧与写侧，附对应代码位置。
- 锁与通道的命名与注释符合相邻 skill 的规则，不变式对读者可读。
- 临界区清单：持锁期间没有回调、I/O 与无序锁嵌套。
- 检测器与局部测试的输出；未运行项标注原因。
- 锁与不变式已写入代码注释与并发文档，后续审查无需重新推导。

G4 验证：

- 检测器命令、测试路径与真实输出；压力测试的线程数、迭代次数与随机种子。
- 死锁排查记录：资源等待图、环的位置与破环方法。
- 未覆盖交错的说明与替代验证；以单次通过宣称无竞争的结论不予接受。
- 事故修复的回归用例，证明原交错已被覆盖或已被消除。

G6 收尾：

- 事故根因：哪项不变量被绕过、为何测试未覆盖、监控是否可见。
- 行动项：检测器接入、超时与告警、文档与培训，各有负责人与到期日。
- 回归用例进入常驻测试集，并在 CI 中启用检测器。
- 监控能否观察到该类竞态：日志、指标或追踪的缺口与补法。

不满足时：G2 缺共享状态清单或锁顺序时 Hold，退回设计；G3 出现无同步的共享写入时 Recycle 到 S3，不得以注释
说明替代同步；G4 没有检测器或替代验证时 Recycle，以单次测试通过冒充证明时按 No-Go 驳回；G6 缺根因或回归用例
时不得关闭事故，行动项未排期则保持待办。连续两次因同一竞态回退的，升级到 G2 重新评估模型。

## 交接与升级

上游交接：

- 从 `architecture-and-design-conventions` 接收模块边界与数据流；跨边界共享需在该层确认所有者。
- 从 `api-and-data-conventions` 接收幂等与重试语义；进程内同步不重复规定跨服务重试。
- 从 `performance-conventions` 接收性能目标；并发收益以该目标衡量，不以“可能更快”为由引入。
- 从 `naming-conventions` 与 `comment-conventions` 接收锁、通道与不变式的命名与注释写法。

下游交接：

- 向 `testing-and-quality-conventions` 交付检测器命令、压力测试与回归用例，作为门禁的一部分。
- 向 `release-operations-conventions` 交付并发相关的告警、超时与值班关注点。
- 向 `debugging-conventions` 交付竞态复现条件与种子，便于后续二分与修复。
- 向 `performance-conventions` 交付锁竞争观测数据，由其决定是否调优。
- 与 `testing-and-quality-conventions` 就门禁范围分歧时，检测器与压测由本 skill 要求，阈值与豁免由其配置。

升级与停止：

- 出现数据损坏、服务中断或漏洞正在被利用时按紧急路径先止损，再补门禁记录。
- 新增全局锁、改变锁全序、引入新的执行模型或跨进程共享时，升级到 G2 重新评审。
- 语言缺少运行期检测器且无法建立压力测试时，报告覆盖缺口与残余风险，不声称正确。
- 同一锁在多次审查中被指出顺序冲突时，停止增量改动，先统一全序并记录。

## 裁剪与度量

按风险裁剪：

| 级别 | 典型并发工作 | 证据厚度 | 审查 |
|---|---|---|---|
| R0 轻量 | 单函数内的原子计数、局部锁范围调整 | 检测器或单元测试即可 | 执行者自检 |
| R1 标准 | 新增共享缓存、线程池参数、通道所有权调整 | 共享状态清单、检测器输出、锁顺序记录 | 至少一名非作者审查 |
| R2 关键 | 全局锁顺序变更、新执行模型、跨进程共享、事故修复 | 完整设计、死锁分析、压测与回归、回滚方案 | 设计与并发独立评审，人工批准 |

裁剪只减少文档篇幅，不减少证据：R0 也运行检测器或替代验证，R1 不得省略锁顺序记录，R2 不得省略事故回归与
回滚方案。

度量用于发现并发债：

- 竞态逃逸数：发布后发现、可追溯到共享状态与同步缺陷的问题。
- 检测器覆盖率：启用检测器的并发测试占比，以及未覆盖路径清单长度。
- 死锁与锁等待超时次数，按服务与锁对象统计。
- 平均持锁时长与临界区内的 I/O、回调次数。
- 事故复现用例补充数与回归通过率。
- 锁竞争强度：平均等待时长与争用次数。
- 并发变更收益：响应性、吞吐或资源利用与 G2 目标的对照。

指标恶化时先查根因：模型选择不当、锁粒度过粗、检测器未接入，还是压力测试未覆盖真实交错；不得通过延长超时、
降低采样或关闭检测器改善数字。并发债进入待办，按 S2 的范围与 S3 的小步纪律清理，并在 S6 复盘时核对关闭情况。
