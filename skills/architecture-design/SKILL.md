# 架构与设计

架构是系统中最难撤销的决策。模块边界划错，每次改动都牵动整个区域；依赖成环或由内层指向外层，编译、测试与发布互相阻塞；接口放错位置，所有调用方都被它约束。本 skill 管辖 S2 设计阶段的主责工作：规定模块怎么划分、依赖方向如何保证、数据流与接缝如何设计、框架选择如何裁定，以及如何用 ADR 把决策固定下来，使后续变更不必重复争论同一问题。
它不决定“做什么”，只决定“怎么组织”；需求与验收由 `requirements-engineering` 管辖，任务拆分由 `planning-estimation` 管辖。

## 适用范围与优先级

效力依下列层级判断：高层覆盖低层，低层仅在高层未规定时补充。

1. 强制约束。宿主框架的模块系统、包管理器的依赖解析、构建图的拓扑约束与平台限制不是可选项；安全与授权约束不因架构便利而放松。
2. 本 skill 的规则。模块边界、分层与依赖方向、数据流、接缝与 ADR 的规则，以本文件与 `references/` 为准。
3. 项目约定与事实。既有模块清单、依赖图、分层约定与 ADR 是事实输入，先阅读再裁定；项目约定仅在本 skill 未规定时补充。

本 skill 管辖：模块与组件边界、分层与依赖方向、数据流与控制流、框架选择与变更、可测试性接缝、ADR。
本 skill 不管辖：接口的字段与错误形状、目录与包边界的物理落地、重构手法、测试策略（均由对应专业 skill 管辖）；需求与验收标准归 `requirements-engineering`，任务拆分与估算归 `planning-estimation`，实现与提交纪律归 `implementation-practices`。

## 生命周期定位

上游：G1 的问题、用户、验收标准与约束，安全与性能目标。下游：目标结构交目录与包边界落地，接口形状交接口契约定义，接缝的测试用法交测试策略。停止条件：依赖图成环或内层依赖外层且无法在本次变更内打破、框架变更缺少迁移步骤、ADR 与实现分叉时停止实施，报 Recycle 到 S2。

| 阶段 | 职责 | 产出与证据 |
|---|---|---|
| S1 需求 | 从需求与约束中识别架构风险，比较分层与框架选项（含不做事） | 架构选项比较、主要技术风险 |
| S2 设计 | 划定模块边界、分层与依赖方向，设计数据流、接缝与可测试性，裁定框架并编写 ADR | 依赖图、边界决策、ADR、接缝设计、G2 证据 |
| S3 构建 | 新代码置于正确边界，发现设计偏差时回写 ADR，不静默偏离 | 依赖图 diff、更新的 ADR、评审结论 |
| S4 验证 | 复核依赖图为 DAG、ADR 与实现一致、接缝可替换可测试 | 依赖校验输出、审查结论、G4 证据 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G1 需求 | 架构选项比较（含不做事）、主要技术风险与退出方式 | Hold：风险无法评估；Recycle 到 S1：约束缺失 |
| G2 设计 | 模块边界与变更理由、依赖图为 DAG 的校验输出、接缝与注入点、新决策或推翻决策的 ADR | Hold：边界或 ADR 缺失；Recycle 到 S1/S2：依赖方向无法自洽 |
| G3 构建 | 依赖校验输出随增量更新、设计偏差已回写 ADR、循环依赖在合并前被捕获 | Recycle 到 S2/S3：不得以 ADR 豁免新增反向依赖 |
| G4 验证 | 依赖与分层校验通过、抽象与实现方向一致、接缝可测试、ADR 与实现无分叉 | Hold：证据仅来自记忆；Recycle 到 S2：框架变更无迁移步骤 |

## 核心规则

- 依赖图必须为有向无环图。依赖不得由内层指向外层，同层允许但不得成环；违反在合并前由构建或静态分析捕获，存量越界以接缝逐步收紧。
- 每个模块一个变更理由。同一模块总是因两个不同理由而变化，即视为边界划定错误，应当拆分。
- 抽象在内层，实现在外层。稳定的抽象置于内层，易变的实现置于外层并依赖抽象。
- 接口的位置与形状分开裁定。本 skill 裁定接口位于何处、谁依赖谁；接口的字段与错误形状由接口契约 skill 定义。
- 新决策或推翻决策必须写 ADR。未记录的决策会在下一次变更时被重新争论；已接受的 ADR 决定正文不得改写。
