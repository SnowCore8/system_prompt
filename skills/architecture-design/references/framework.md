# 框架选择与变更

## 1. 框架选择与变更

框架是边界与依赖方向的载体。选错框架会锁死模块划分；替换框架没有迁移步骤，等于在运行中的系统上做器官移植。

- 选择必须比较选项。引入或替换框架前，比较至少两个选项（含维持现状），写明各选项的约束、成本与退出方式。
- 以 ADR 固定。框架选择、版本策略与替换决定写入 ADR；框架属于易变外层，抽象应当面向自身需求而非框架类型。
- 替换必须有迁移步骤。逐步迁移、并行窗口与验证方式写入计划；没有迁移步骤的替换不得进入 S3。
- 迁移窗口有期限。新旧并存的窗口写明移除条件与到期日，到期即清理；长期并存将分叉行为并扩大攻击面。
- 回退方式先行。替换前明确回退触发条件与回退路径，替换失败时按预案回退而不是现场决定。

| 正例 | 反例 | 原因 |
|---|---|---|
| 抽象按业务需要定义，框架实现于外层 | 全库类型以框架类型为骨架 | 前者换框架影响外层，后者换框架重写全部。 |
| 迁移分步、双写带验证与期限 | 一次性切库无回退预案 | 后者失败时无干净状态可回。 |
