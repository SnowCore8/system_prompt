# 分层与依赖方向

## 1. 分层与依赖方向

分层把变化的速率分开：内层稳定、变化慢，外层易变、变化快。依赖方向决定变更约束的归属。

- 依赖图必须为 DAG。外层可依赖内层，内层禁止依赖外层；同层依赖允许但不得成环。以构建或静态分析校验，使违反在合并前被捕获。
- 抽象在内层，实现在外层。内层定义抽象，外层提供实现并依赖该抽象，内层因此不依赖任何易变实现。
- 接口按调用方隔离。调用方不得依赖其不使用的方法；判据：去掉接口内任意方法，若没有调用方因此破坏，该方法属于过宽。
- 存量越界以接缝逐步收紧。新代码自始置于正确层；既有越界依赖先设接缝矫正方向，不得一次性重写整层。
- 分层是变化速率的排序。仅有一层且永不变化的系统强加四层，属于过度设计。

| 正例 | 反例 | 原因 |
|---|---|---|
| 领域层定义网关抽象，基础设施层实现 | 领域层直接导入具体 SDK | 前者内层独立演进，后者内层受外层约束。 |
| 依赖图经校验器判定为 DAG | 模块 A 依赖 B，B 又依赖 A | 环使编译、测试与发布互相阻塞。 |
