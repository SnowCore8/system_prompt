# 架构与设计生命周期契约

本文件规定本 skill 在 S0–S7 中的职责、门禁证据、交接与升级、裁剪与度量。阶段与门禁编号由生命周期治理模型裁定；本 skill 主责 S2 设计，在 S1 提供选项、在 S3 回写偏差、在 S4 复核证据。

## 阶段职责

### S1 需求

- 输入：问题、用户、验收标准与约束。
- 活动：判断架构是否承载主要风险；比较分层、边界与框架的选项及不做事方向。
- 产出与证据：架构选项比较、主要技术风险与退出方式。

### S2 设计

- 输入：G1 结论、需求与验收标准。
- 活动：划定模块边界与分层；确定依赖方向；设计数据流、接缝与注入点；裁定框架；编写或推翻 ADR。
- 产出与证据：依赖图、边界决策、接缝设计、ADR、G2 证据。

### S3 构建

- 输入：G2 结论与设计。
- 活动：把新代码置于正确边界；发现设计偏差时回写 ADR，不静默偏离。
- 产出与证据：依赖图 diff、更新的 ADR、评审结论。

### S4 验证

- 输入：增量与提交记录。
- 活动：复核依赖图为 DAG、抽象与实现方向一致、接缝可替换、ADR 与实现无分叉。
- 产出与证据：依赖校验输出、层检查结论、审查结论。

## 门禁证据

| 门禁 | 证据形态 | 判定 |
|---|---|---|
| G1 需求 | 架构选项比较（含不做事）、主要技术风险、退出方式 | 选项与风险可复核为 Go；风险无法评估时 Hold |
| G2 设计 | 边界与变更理由、DAG 校验输出、接缝与注入点、ADR | 依赖方向自洽且 ADR 齐备为 Go；否则 Recycle 到 S1/S2 |
| G3 构建 | 依赖校验输出随增量更新、偏差回写记录 | 新反向依赖或环在合并前被捕获为 Go；否则 Recycle 到 S2/S3 |
| G4 验证 | 依赖与分层校验通过、接缝可测试、ADR 与实现一致 | 证据可复核为 Go；仅凭记忆或截图时 Hold |

证据必须来自当前增量的实际校验输出；白板照片、讨论记录与计划中的校验不构成证据。

## 交接与升级

- S1 → S2：把架构选项与主要风险交给设计者；风险无法评估时退回 S1 补约束。
- S2 → S3：把依赖图、接缝与 ADR 交给交付方；新模块无归属边界的，先补边界再开工。
- S3 → S4：把依赖图 diff 与回写的 ADR 交给验证方；偏差未回写的不得进入验证。
- 升级：依赖图成环且本次无法打破、框架变更缺少迁移路径、ADR 与实现分叉时停止并报 Recycle 到 S2；强制规则冲突时报告用户裁决。
- 停止：继续实施会扩大反向依赖或破坏已接受 ADR 时停止，报告受阻项与已确认项。

## 裁剪与度量

- R0：单文件或单模块改动只做依赖方向自检，不要求新 ADR；仍不得新增环。
- R1：边界决策与依赖图随增量提交；G2 至少一名非作者审查。
- R2：完整 ADR、依赖校验输出与独立架构评审；框架或边界变更必须重新过 G2。
- 度量：以循环依赖数、跨层依赖数与 ADR 漂移数为准；数值上升时先查边界与接缝设计，不得放宽校验。
