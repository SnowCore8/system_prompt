# 威胁模型

本文件描述本仓库及发布制品的资产、信任边界、威胁与控制，是 S2 计划与 G4 验证的安全证据之一。维护者：
SnowCore8；阅读时机：评审 R2 变更、修改 hook 或注入路径、变更 MCP 工具、新增依赖或准备发布时。处置流程
与报告渠道见 [SECURITY.md](../SECURITY.md)。

## 在生命周期中的位置

| 环节 | 本文件的作用 | 边界 |
|---|---|---|
| S2 设计 | 变更前确认资产、边界与受影响控制 | 不替代逐条威胁建模与专业安全评审 |
| G4 验证 | 核对控制仍在、残余风险已记录 | 不替代扫描输出与测试证据 |
| G5 发布 | 发布前复核制品、凭据与下载路径 | 不替代发布检查单与校验和核对 |

## 资产

| 资产 | 位置 | 为什么重要 |
|---|---|---|
| 章程与 24 个 skill | `rules/`、`skills/` | 进入模型上下文，直接决定智能体行为 |
| MCP 服务器 | `mcp/` | 以用户身份执行，暴露审查与模板工具 |
| hook 与 DSH 提供者代码 | `shared/scripts/`、`plugins/` | 在用户机器上以用户权限执行 |
| 发布制品 | 三个 zip、四个 npm 包、SBOM 与 SHA256 | 用户安装的对象；被替换即等于代码被替换 |
| 发布凭据 | GitHub Actions secrets、npm token | 可发布或改写制品 |
| 用户本地状态 | 插件数据目录下的时钟状态文件 | 含会话标识哈希与时间，不含对话内容 |

## 信任边界

1. 贡献者与维护者 → 仓库：写入章程、skill、MCP、hook 与脚本。
2. 仓库 → CI：GitHub Actions 校验、组装与发布。
3. CI → 制品：`scripts/dist.sh` 生成 zip 与校验和，`release` 工作流发布 npm 包与 Release 附件。
4. 制品 → 用户机器：npm、GitHub Release 与插件安装。
5. 宿主 → hook / MCP：hook 经 stdin 接收 JSON payload；MCP 经 stdio 接收工具调用。
6. hook → 模型上下文：会话启动、提示提交与压缩后的注入文本。

## 威胁与控制

| 编号 | 威胁 | 路径 | 控制 | 残余风险 |
|---|---|---|---|---|
| T1 | 章程或 skill 被篡改，模型行为被劫持 | 提交、PR、安装包 | `CODEOWNERS` 全路径指派与审查约定；唯一真源与脚本组装；发布前 `scripts/check.sh`；zip 结构校验；npm provenance 与构建来源证明 | 单人维护；制品签名仍未启用 |
| T2 | 制品被替换或降级 | npm、Release、下载链路 | HTTPS；发布 SHA256；SBOM；包内清单版本校验；可复现构建；npm provenance 与构建来源证明 | 用户需自行核对校验和；registry 与 CDN 不受本仓库控制 |
| T3 | hook 收到恶意或畸形输入 | stdin payload | 仅 `JSON.parse`，无 `eval`、无子进程、无网络；非对象载荷直接返回；异常静默且退出码为 0；超时 10 秒 | 宿主自身漏洞不在范围内 |
| T4 | MCP 工具被滥用或输入注入 | stdio 工具调用 | 工具无网络、无文件写入、无子进程；输入按不可信数据处理；输出不含机密；schema 校验（Zod） | 调用者（模型或用户）自身的误用 |
| T5 | 路径穿越或软链 | 组装、zip、hook 读取 | 组装与包内零软链；zip 校验拒绝软链与缓存；读取限于固定文件名，状态写入限于插件数据目录 | 环境变量可指向任意目录，按用户输入处理 |
| T6 | 凭据泄露 | 提交、日志、CI | gitleaks 全历史扫描；敏感文件忽略与检查；仓库不保存密钥 | token 权限与轮换依赖人工操作 |
| T7 | 依赖供应链投毒 | pip、npm、GitHub Actions | 版本固定与哈希锁定；`pip-audit`；Dependabot；Action 按 SHA 固定；npm 锁文件 | 上游 0day 与投毒仍可能发生 |
| T8 | 注入内容膨胀或降级 | 会话启动与压缩后注入 | 64 KiB 硬上限；超限只提示读取原文；压缩后重新注入提醒与时间 | 超限时用户须手动读取章程 |
| T9 | 本地状态泄露 | 插件数据目录 | 状态文件仅含 turn 与时间，文件名是会话 ID 的 sha256 前缀；无网络调用 | 目录权限由宿主管理 |
| T10 | 发布管线滥用 | tag、workflow、secrets | tag 与六个清单版本一致性校验；发布工作流仅授予 contents、id-token 与 attestations；npm publish 带 provenance；发布前重跑全量校验 | 维护者账号被攻破时无可信第三方阻断 |

## 信任假设

- 宿主 CLI 与 Node 运行时可信；本仓库不防御宿主自身漏洞或已失陷的用户环境。
- 用户安装的是本仓库发布的包，并自行核对 SHA256；npm 与 GitHub 的传输层可信。
- `QODER_PLUGIN_ROOT`、`QODER_PLUGIN_DATA`、`DSH_HOME`、`DSH_AGENTS_HOME` 等环境变量视为用户可控输入，
  只影响读取与写入路径。
- 注入内容只来自包内文件与用户自己的规则文件；MCP 工具不处理第三方远程内容。

- 每次发布前复核 T1、T2、T6、T10 的控制是否仍然成立。
