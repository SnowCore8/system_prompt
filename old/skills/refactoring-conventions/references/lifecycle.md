# 重构规范生命周期契约

本文件把重构接入阶段与门禁：界定何时可以改动结构、每一步留下什么证据、失败时回退到哪一步。
手法与异味阈值见 `catalog.md`，维度规则见 `dimensions.md`，先读后改与替换清理见 `change-safety.md`；阶段与门禁
的定义由 `project-lifecycle-governance` 裁定。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 代码异味清单、测试覆盖现状、发布日历、待办 | 选定本次处理的异味与文件范围；判断哪些区域需要先补特征测试；确定手法顺序与提交拆分；写明回滚点与冻结窗口 | 重构范围、行为保持验收、特征测试计划、提交拆分方案 | G2 |
| S3 构建 | G2 的范围与验收、现有测试套件 | 按一项手法一步实施；每步运行测试并提交；删除被替换的实现；记录无法当场清理的残留 | 手法提交序列、测试输出、旧名搜索记录 | G3 |
| S4 验证 | 重构提交序列、验收标准 | 逐条核对 diff 是否等价；确认没有测试被删除或弱化；运行全量与回归测试；检查新旧并存路径 | 审查结论、测试结果、清理核对 | G4 |
| S5 发布 | 发布范围、未完成重构清单、冻结窗口 | 确认发布内容不含半成品重构；冻结窗口内停止结构改动；把未完成项移出本次发布 | 发布范围清单、冻结窗口记录 | G5 |

阶段边界：

- 重构在 S2 立项，不在 S3 顺手发起；S3 只执行已确定范围的手法。
- 行为变更不属于本流程，进入 fix/feat 与缺陷修复流程。
- 重构不跨越发布冻结窗口；窗口内只做与发布直接相关的最小改动。
- 重构提交不携带格式化、重命名或依赖升级，这些属于各自独立的变更。

## 门禁证据

G2 计划：

- 异味条目与文件清单，说明触发阈值与预期收益。
- 行为保持的判定方式：哪些测试、哪些可观察行为、由谁核对。
- 每项待处理异味的触发证据：重复位置、函数长度、参数数量或开关分支的分布。
- 危险区域的特征测试计划；无法补充的，记录例外、风险与用户同意。
- 特征测试的放置位置与命名已确定，避免与既有测试重复或冲突。
- 手法顺序、提交拆分与回滚点；涉及公共结构时附影响面与调用方清单。

G3 构建：

- 每步的测试命令与结果，含未运行项标注。
- 手法与提交的对应关系：一条提交只出现一项手法，反向手法已注明。
- 提交消息标明 refactor 与所用手法，便于按手法回溯与单独回滚。
- 旧实现、调用点、开关与兼容层的删除记录；迁移窗口的条件与期限。
- 残留清单：无法当场清理的旧路径、位置、风险与移除条件。

G4 验证：

- 等价性结论：API、返回结构、错误语义、副作用与性能特征均未变化。
- 手法目录的覆盖核对：所用手法均在目录内，未出现自定义的等价变换。
- 全量与回归测试输出；确认没有删除、跳过或弱化断言。
- 独立审查意见及处理结果；审查者不是增量作者。
- 旧名搜索与兼容层核对结果，证明没有新旧并存。

G5 发布：

- 本次发布不含未完成的重构，或已明确隔离并说明影响。
- 冻结窗口起止时间与期间的结构改动记录；例外须有批准。
- 发布说明中不宣称结构改进带来的行为变化。
- 若重构提高了发布风险，附回滚点与验证方式。

不满足时：G2 范围或验收未定时 Hold，缺特征测试又没有例外记录时拒绝开工；G3 出现多手法混提或测试失败时
Recycle 到 S3，要求拆分或回退到上一手法；G4 发现行为变更、测试被弱化或新旧并存时 Recycle，行为变更须改走
fix/feat；G5 发现半成品重构进入发布时 Hold，隔离后再过门。连续两次因同一原因回退的，升级到 G2 重新界定范围。

## 交接与升级

上游交接：

- 从 `architecture-and-design-conventions` 接收目标结构与边界；重构只向既定结构收敛，不自行改变分层。
- 从 `naming-conventions` 接收规范名称；重命名作为独立手法，按该 skill 的引用清单执行。
- 从 `testing-and-quality-conventions` 接收测试层级与覆盖率要求，特征测试的写法遵循其约定。
- 从 `debugging-conventions` 接收缺陷结论；修复与重构分开提交，先修复再重构或先补测试再重构。

下游交接：

- 向 `vcs-collaboration-conventions` 交付提交序列与消息类型，PR 描述写明手法与等价性证据。
- 向 `code-style-conventions` 交付风格例外；格式化不在重构提交中发生。
- 向 S6 复盘交付重构收益与遗留债务，未关闭项进入待办并保留触发条件。

升级与停止：

- 重构需要改变公共接口、配置键或数据形状时停止，退回 G2 并升级为契约变更。
- 拟改动区域没有测试且无法补充特征测试时停止，报告风险、替代方案与建议的测试投入。
- 发布冻结窗口、事故处理期间或范围蔓延时停止重构，记录暂停原因与恢复条件。
- 目标结构与既有架构决策冲突时，先按架构流程修订决策，再继续重构。
- 同一文件在两次迭代内反复重构时，升级到 S2 检查目标结构是否本身有问题。

## 裁剪与度量

按风险裁剪：

| 级别 | 典型重构 | 证据厚度 | 审查 |
|---|---|---|---|
| R0 轻量 | 单个私有方法提取或内联、局部替换魔法数 | 测试输出即可，记录一行说明 | 执行者自检 |
| R1 标准 | 跨文件提取类、移动方法、批量重命名 | 手法提交序列、等价性说明、清理记录 | 至少一名非作者审查 |
| R2 关键 | 公共接口附近的移动、跨模块结构调整、遗留系统分阶段改造 | 完整影响面、调用方清单、回滚点、分阶段方案 | 设计与契约独立评审，人工批准 |

裁剪只减少记录篇幅，不减少步骤：R0 也须每步测试，R1 不得合并多手法提交，R2 不得省略影响面与回滚点。

度量用于发现重构债与流程缺陷：

- 每千行改动的重构提交回滚次数与原因。
- 手法粒度：单条提交平均包含的手法数，超过一即需说明。
- 特征测试补充数与覆盖缺口变化。
- 兼容层与旧实现残留数，按发布统计。
- 冻结窗口内的结构改动次数与例外批准数。
- 重构后逃逸缺陷数：发布后发现、可追溯到结构改动的缺陷。
- 异味存量变化：按清单条目统计的关闭数与新增数。
- 单次重构的审查轮次与返工原因，用于判断范围是否界定清楚。
- 范围外溢次数：提交中出现未在 S2 列出的文件。

指标恶化时先查根因：范围没有在 S2 界定、测试保护不足，还是提交纪律被跳过；不得以减少重构或放宽等价性判定
改善数字。遗留系统的改造按分阶段方案推进，基线随清理缩小，一次性大重构不得作为收尾手段。
