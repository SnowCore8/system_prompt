# skill 编写生命周期契约

本文件说明 skill 包在阶段之间如何交付与验收：谁交入什么、正文与 references 各自承担什么证据、何时必须升级
或停止，以及按风险级别如何裁剪。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S1 探索 | 任务域、读者、现有 skill 清单 | 用任务句判断既有 skill 是否已覆盖；列出重叠与边界 | 新建或链接的结论、边界清单 | G1 |
| S2 计划 | 边界结论、宿主字段约束 | 设计目录、frontmatter、正文段落顺序、references 拆分与行数预算 | 骨架、description 草稿、拆分表 | G2 |
| S3 构建 | 骨架、领域规则来源 | 写正文与 references，标注事实管辖者，删除与他处重复的段落 | 正文、references、链接 | G3 |
| S4 验证 | 完整包、任务句样本、校验脚本 | 运行 Markdown 校验；核对名称、链接、节号与去重；判断触发 | 校验输出、触发判断结论、去重结果 | G4 |

阶段边界：S1 不写正文；S2 只定结构与预算；S3 才写入规则；S4 只做核对，不得在同一轮顺手改写规则，否则校验
结论与改动对象不一致。

## 门禁证据

- G1 立项。证据为三类应当加载的任务句、两类不应当加载的任务句，以及与相邻 skill 的边界结论。只有“这方面
  内容很多”不构成立项证据；已有 skill 能覆盖的，结论应当是链接而非新建。
- G2 计划。证据为目录与字段方案、正文段落清单、references 文件名与预计节号、正文行数预算。领域事实尚无
  管辖者时，只可 Conditional Go，条件为写明由谁裁定并在正文标注。
- G4 验证。证据为校验脚本的逐字输出与退出码、`name` 与目录名一致、相对链接可解析、维度索引行与节号一致、
  正文与 references 无逐字重复，以及五个任务句判断全对。任一项缺失即未通过。

证据与决定：

| 情形 | 决定 | 处理 |
|---|---|---|
| 校验 0 错误 0 警告，五个任务句判断全对，边界结论可核验 | Go | 可合入并供加载 |
| 触发面与边界不一致，但结构与校验已通过 | Conditional Go | 限定为仅由显式调用触发，写明修正负责人与期限 |
| 正文超 250 行仍保留逐条展开 | Recycle | 回到 S2 重划分工后再写 |
| 与相邻 skill 存在逐字重复 | Recycle | 保留管辖者一处，其余改为链接 |
| 一个 skill 承担两类读者且无法拆分 | No-Go | 拆成两个 skill，或降为项目文档的一节 |

## 交接与升级

上游交入：

- `prompt-authoring` 提供提示词正文的写法；skill 正文中涉及提示词技巧的部分引用该 skill，不复制。
- `system-prompt-authoring` 提供常驻指令文件的规则；同一文件兼作指令入口与 skill 说明时，以该 skill 为准。
- `documentation-conventions` 提供项目文档的结构与事实归属结论；skill 不重复项目文档的内容。
- 领域 skill 提供事实本身；本 skill 只决定承载结构与事实放在哪一层。

下游交出：

- 交给 `testing-and-quality-conventions` 的校验入口与期望退出码，使本地与 CI 使用同一条命令。
- 交给 `release-operations-conventions` 的打包后链接清单：正文链接、脚本路径与跨 skill 引用在打包后均可解析。
- 交给 `repository-governance-conventions` 的分发清单：目录名、入口文件名与 frontmatter 字段。

升级条件：

- 事实无管辖者：两项规则互相复制且都无法判定归属，升级到 `project-lifecycle-governance` 或由用户裁决。
- 宿主约束冲突：目录名、字段或加载方式与仓库规范冲突时按宿主执行，并在交付中记录偏离。
- 触发面重叠：两个 skill 都声明同一类任务时，由较强边界结论的一方保留，另一方改为排除项。
- 拆分超限：维度文件超过 20 节或 300 行时拆文件，不得靠压缩措辞规避。

停止条件：

- 一个 skill 无法在一类读者内闭合职责时，停止编写，先拆分。
- 需要复制他处事实才能自洽时，停止编写，先确定管辖者。
- 宿主不允许所需字段时，停止，改为项目文档或显式调用入口。

## 裁剪与度量

按风险裁剪：

| 级别 | 典型改动 | 必做 | 可省略 |
|---|---|---|---|
| R0 | 错字、断链、单行措辞 | 改一处并跑校验 | 触发判断抽样、独立审查 |
| R1 | 新增 references、调整段落顺序 | 校验、去重核对、五个任务句判断 | 宿主加载验证 |
| R2 | 新建 skill、改 `name`、改 frontmatter 字段 | 校验、独立审查、宿主加载与显式调用验证 | 无 |

度量：

| 指标 | 计算 | 用途 |
|---|---|---|
| 正文行数 | 不含 frontmatter 的行数 | 判断是否需要拆分 |
| 逐字重复段落数 | 正文与各 references 的交集 | 判断事实是否分叉 |
| 断链数 | 相对链接与脚本路径解析失败的数量 | 判断打包后是否可用 |
| 索引一致率 | 维度索引行与对应文件节号一致的比例 | 判断结构是否失修 |
| 触发判断准确率 | 抽样任务句中判断正确的比例 | 判断触发面是否可用 |

度量纪律：不以篇幅判断完整度，长不等于全；触发判断优先于文笔。指标恶化先查结构分工，不得先删规则或缩窄
适用面。
