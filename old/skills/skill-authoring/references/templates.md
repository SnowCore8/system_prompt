# skill 模板

本文件提供可复制的 `SKILL.md` 骨架与 `references/`、`scripts/` 布局。复制后应当删除不适用段落，不得保留空占
位。

## frontmatter 模板

```markdown
---
name: <目录名>
description: <一段话：适用于什么任务、何时加载；写清不适用于什么>
argument-hint: '[可选上下文]'
---

# <标题>

<第一段：这个 skill 解决什么问题，为什么加载它>

## 适用范围与优先级

按以下层级判断效力，高层覆盖低层，低层只在高层未规定时补充：

1. 强制的平台、法律、宿主与全局用户约束。
2. 本 skill 的规则。
3. 既有项目约定与事实；项目约定只在本 skill 未规定时补充，作为输入按本 skill 的规则处理，不能覆盖本 skill。
4. 个人偏好，永远不能覆盖上述三层。

<与相邻 skill 的分工边界>

## 工作流

<分步决策程序>

## 核心规则

<可判定的默认规则>

## 维度索引

每个维度的详细规则、示例与边界情况见 `references/dimensions.md`；维度列中的编号就是该文件中的节号。

| 维度 | 首条规则 | 详情 |
|---|---|---|
| 1. 维度 | 规则。 | `references/dimensions.md` 第 1 节 |

## 参考资料

- <模板或维度>：`references/<文件>.md`
```

含 `references/dimensions*.md` 的 skill 必须保留“维度索引”一节；不含维度文件的 skill，应当删除该节。

拆分为多个维度文件时，说明句改为“每个维度的详细规则、示例与边界情况见 `references/` 中对应的维度文件；维度列中的编号就是该文件中的节号。”，详情列仍写 `references/<文件>.md` 第 N 节。

## description 写法

`description` 应当写成“适用于……，不适用于……”，使智能体依任务判断是否加载。下列三类写法不合格：

- 太宽泛：`适用于一切编程任务。` 将导致无关任务亦触发，浪费加载上下文。
- 太窄：`只用于修复 Python 3.11 的 asyncio 超时。` 将导致应当触发的相邻任务从不加载。
- 复述名称：`文档规范 skill，帮助写文档。` 未提供触发信息，智能体无从判断。

合格写法应当同时给出适用范围与排除项，例如：

`定义、审查并重构项目的 README、指南与参考页。适用于启动文档集、审查过时与重复，或判断事实归属；不适用于代码注释与 API 文档。`

## 目录布局

```text
<skill-name>/
├── SKILL.md
├── references/
│   ├── dimensions.md   # 按维度展开的规则；或按主题拆成 dimensions-<主题>.md
│   └── templates.md    # 可复制骨架；或按主题拆成 templates-<主题>.md
└── scripts/            # 可选；运行时脚本，不含测试
```

## 拆分判断

- 正文超过 `../SKILL.md` 核心规则“入口应当简短”规定的行数（不含 frontmatter）的，应当将逐条展开移至
  `references/` 下的维度文件。
- 单个维度文件超过 300 行或 20 节的，应当按主题拆分为 `dimensions-<主题>.md`；其余 `references` 文件按
  内容命名，不受该拆分规则约束。正文索引说明句指向 `references/` 中的对应文件，详情列写明
  `references/<文件>.md` 第 N 节，节号与索引一致。
- 需要供读者复制粘贴的骨架，放置于 `references/` 下的模板文件。
- 需要机器执行的校验或生成，放置于 `scripts/`，正文说明调用方式。

## 可判定改写

应当将形容词替换为可观察条件、阈值与正反例：

- 不可判定：`正文要合理拆分。`
- 可判定：`正文超过 250 行（不含 frontmatter），就把逐条展开、示例与边缘情况移到 references/，正文只留规则与默认值。`

## 引用与链接

- 相对路径以 `SKILL.md` 所在目录为基准，使用 Markdown 相对链接。
- 跨 skill 引用应当写明“由哪个 skill 裁定”，不得复制内容。
- 打包后引用仍应可以解析；不得使用仓库外绝对路径。

## references 命名与去重

- 文件按内容维度命名，使用 kebab-case；文件类型、维度拆分与清单命名见 `../SKILL.md` 的「references 组织」与
  核心规则「`references` 按主题管理」。
- 文件名与正文链接一致；修改文件名的，应当同步修改链接；不得使用无意义名称（`ref1.md`、`extra.md`）。
- 一项事实仅在一处：正文与各 `references` 之间不得互相复制，其余以链接引用。
