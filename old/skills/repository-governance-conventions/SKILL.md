# 仓库治理规范

仓库治理的失效通常没有明显信号：缺少许可证的仓库外观完整，直到有人无法合法复用；无人负责的目录连续合并
未经审查的变更；某个包只在作者机器上构建成功；项目终止后页面仍公开、issue 仍开放。这些缺陷不出现在 diff
中，发现时已代价高昂。本 skill 规定必需文件与元数据、仓库卫生、决策流程、托管设置，以及发布时的打包与
分发，并把生命周期门禁、风险分级与证据要求落到仓库治理上。

## 适用范围与优先级

效力依下列层级判断：高层覆盖低层，低层仅在高层未规定时补充；同一范围内不得混用标准。

1. 强制的平台、法律、宿主与全局用户约束。托管平台设置、法律模板、包仓库规则与公司政策均非可选事项；与
   上述约束矛盾的仓库文件属于缺陷，不构成仓库内的例外。
2. 本 skill 的规则。必需文件、元数据、治理、打包与分发，以本文件与 `references/` 为准。
3. 既有仓库约定与事实。制定政策前先阅读文件清单、元数据、分支模型与 manifest；这些是事实输入，依本 skill
   的规则处理，项目约定仅在本 skill 未规定时补充。
4. 个人偏好不得覆盖上述三层，也不得为缺失的必需文件提供理由。

- 必需文件及其元数据由本 skill 管辖：哪些文件必须存在、置于何处、携带哪些字段。README、CONTRIBUTING 与
  决策记录的内容、模板与语气由 `documentation-conventions` 管辖；许可证政策与安全文件的内容由
  `security-compliance-conventions` 管辖；本 skill 管辖文件是否存在及其必需字段。
- 仓库必需文件的位置、元数据与卫生由本 skill 管辖；项目目录、包/工作区边界与物理依赖图由
  `project-structure-conventions` 管辖；模块内部布局由 `code-style-conventions` 管辖；命名由
  `naming-conventions` 管辖；分支、PR、审查者数量与 CODEOWNERS 机制由 `vcs-collaboration-conventions`
  管辖；版本号、发布时机与按发布类型的审批由 `release-operations-conventions` 管辖。
- 支撑 CI 门禁的仓库设置与模板由本 skill 管辖，门禁定义与通过标准由 `testing-and-quality-conventions`
  管辖。无法运行自身必需校验的仓库同时存在治理缺陷，应当报告缺口并与门禁所有者共同修复。
- 仓库属于产品界面：README、许可证、模板、包元数据与默认分支会被用户与工具阅读，治理变更按产品变更审查。
- 组织级政策与仓库文件冲突时，说明差异、遵循组织政策并修复仓库文件，使下一位读者只看到一条规则；生成的
  manifest 字段、模板与 lock 文件在真源修改并重新生成，不得手工编辑。
- 同一效力层级的强制规则冲突时报告用户裁决；非强制的项目约定冲突，记录所选约定与理由到 `GOVERNANCE.md`
  或决策记录。单人仓库在记录单点与补偿控制后可以仅设一名管理员；双许可仓库以 `LICENSE` 说明加各许可证
  全文文件满足要求；不提供行为准则的，在治理文件中记录理由、替代联系方式与补偿控制。

## 生命周期定位

上游输入是 G0 受理记录（仓库类型、授权、风险级别、停止条件）与 G1 立项结论；下游把目录与分支边界交给
`project-structure-conventions` 与 `vcs-collaboration-conventions`，把发布记录交给
`release-operations-conventions`。证据不足时停在 G0/G1 澄清；仓库类型、可见性或交付状态变化时回到 S0
重新分级；归档、转移、删除远端对象或权限变更超出授权时升级用户裁决。

| 阶段 | 本 skill 的职责 | 产出 / 证据 |
|---|---|---|
| S0 受理 | 分类仓库类型，读取必需文件、托管设置、manifest 与归档状态，记录缺口与停止条件 | 仓库类型、缺口清单、G0 记录 |
| S1 立项 | 判定必需文件的适用性，确认许可证、`SECURITY.md` 路径、角色与发布权归属，比较选项 | 治理章程草案、必需文件清单 |
| S2 计划 | 固定元数据、卫生范围、打包渠道、依赖更新与清理策略，路由审批至各所有者 | 治理计划、审批矩阵 |
| S5 发布 | 核对 manifest、许可证、第三方声明与 SBOM 随包，自包仓库做干净安装 | 安装验证记录、包元数据 |
| S6 收尾 | 归档或转移：只读、横幅、issue 重定向、保留发布与许可证、移除 CI 机密与 webhook | 归档记录、转移核对清单 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G0 受理 | 仓库类型、文件与设置读取记录、缺口清单、授权与风险级别 | Hold，补读或请有权限者核对 |
| G1 立项 | 必需文件适用性结论、许可证与安全文件归属、选项比较 | 缩小范围或 No-Go |
| G2 计划 | 治理计划、审批路由、依赖更新与清理策略、角色与权限映射 | Recycle 到 S1 |
| G5 发布 | manifest 与包仓库元数据、干净环境安装输出、SBOM 与声明随包、不可变发布设置 | Hold，不得发布 |
| G6 收尾 | 归档标志、README 横幅、issue 重定向、权限移除、转移后重定向验证 | 补充证据后复审 |

Hold 用于证据缺失或托管设置不可读；Recycle 用于角色、清单或卫生范围不成立；No-Go 用于仓库无合法复用
条件或类型判定为不应继续维护。决定语义与批准角色见 `project-lifecycle-governance`。

## 工作流

1. 分类仓库为公开库、应用、内部服务、仅文档项目或归档项目，记录类型与判断依据；获得外部用户或停止交付时
   重新分类。
2. 阅读当前状态：根文件、托管设置、受保护分支、环境机密、manifest、包仓库与归档状态，写清已有与缺失。
   无法读取设置的记录缺口，以仓库内配置为准并请求有权限者核对，不得猜测。
3. 与类型清单比对，列出缺失、位置错误、过时与无效项，每项指定负责人与到期动作；文件存在但必需字段为空的
   按缺失处理。
4. 先修复卫生：被跟踪与被忽略的文件、大型与生成产物、过时分支与标签、子模块、第三方引入代码与工作区布局；
   记录每次删除及原因。
5. 建立治理：角色与权限阶梯、决策模型、路由至各所有者 skill 的审批、提案路径、行为准则执行与发布权，
   写入 `GOVERNANCE.md`，核对角色与平台权限一致。
6. 修复打包与分发：manifest 元数据、包仓库渠道、随包 SBOM 与声明、安装验证、撤回与弃用路径；安装测试自
   包仓库实施。
7. 验证并记录：运行清单与元数据校验、干净环境安装、归档或转移核对，记录证据与下次审查日期；无法立即修复
   的标注不合规，并报告每个未关闭项。

## 核心规则

- **必需意味着有效，而非仅存在。** 必需文件置于平台与工具认可的路径并填写字段；位置错误的 `SECURITY.md`
  等同于缺失，未写负责人的文件只是占位。
- **首次公开推送前须有许可证。** 完整文本置于名称精确为 `LICENSE` 的文件，平台识别同一许可证，标识符镜像
  至 manifest；许可证变更属所有者的法律决定；多许可证以各全文文件加 `LICENSE` 说明适用关系。
- **每条可合并路径都须指向可问责角色。** 未分配路径属于治理失败；CODEOWNERS 的映射与校验由
  `vcs-collaboration-conventions` 管辖，本 skill 管辖角色是否存在。
- **决策模型书面化。** `GOVERNANCE.md` 写明维护者主导、惰性共识或投票，评论窗口与批准构成；只留在记忆
  中的模型会在第一次争议中失效。
- **路由审批，不重新定义审批。** 代码审查者数量取自 VCS skill，发布审批取自发布 skill；本 skill 仅补充
  治理与归属变更须两名批准者，且作者不得自批。
- **保护失效即治理失效。** 未受保护的默认分支、未经审查的合并与被重写的历史均为治理缺陷，修复机制由
  `vcs-collaboration-conventions` 定义。
- **托管设置按安全基线启用。** 默认分支受规则集保护；`GITHUB_TOKEN` 默认只读；第三方 action 仅白名单或
  全 SHA 固定；禁止 Actions 创建或批准 PR；启用依赖图、Dependabot 告警与安全更新、机密扫描与推送保护、
  代码扫描与私有漏洞报告；在可用处启用不可变发布。私有仓库受套餐限制的，记录原因与补偿控制。设置清单与
  证据表见 `references/lifecycle.md`。
- **社区健康文件置于认可路径。** 根目录、`.github/` 与 `docs/` 是平台读取位置；issue 表单位于
  `.github/ISSUE_TEMPLATE/`；PR 模板与 `CODEOWNERS` 位于上述三处之一。启用 issue 表单时关闭空白 issue，
  并在 `config.yml` 指向讨论区、安全报告与支持路径。
- **以 OpenSSF Scorecard 做周期审计。** 按周或按发布运行，覆盖分支保护、审查、CI、危险工作流、依赖更新、
  许可证、SAST、安全策略、签名发布与令牌权限；每项发现指定负责人与到期日；Scorecard 是证据来源，不替代
  本 skill 与各所有者的规则。
- **被跟踪文件与被忽略文件互不相交。** 全新克隆并构建后不得有已跟踪文件被修改，也不得有运行所需文件被
  忽略；本地配置、凭据、可由 CI 重建的输出与编辑器状态保持忽略。
- **可由 CI 重建的构建输出不提交；必须跟踪的生成代码、产物与 manifest 在记录来源、命令与版本后可跟踪。**
  工具要求的 lock 文件属于输入，仅依此规则提交。
- **资产有大小策略。** 设定阈值；超阈值文件与逐构建二进制放入 LFS 或制品库，并在 `.gitattributes` 按模式
  跟踪；不得靠重写历史修复缓慢克隆。
- **依赖更新有策略。** 以 Dependabot 或 Renovate 按固定频率生成小批量更新，按主版本、次版本与补丁分级：
  补丁轻量审查，次版本标准审查，主版本高风险路径，审查人数取自 VCS skill；安全修复优先，并满足安全与
  测试门禁；按生态或来源分组并记录升级依据、兼容性结论与具名负责人；自动合并仅在必需批准与校验齐备时
  启用。分级细则见 `references/lifecycle.md`。
- **按计划清理分支与标签。** 已合并分支在声明窗口内删除；删除远端分支或标签前取得 AU-1 明确同意；被放弃
  的分支指定负责人与退出日期；从未成为发布的标签删除；已发布标签的不可变与保护由 VCS skill 定义。
- **打标签与发布由发布流程驱动。** 标签、门禁顺序、制品签名与晋级由 `release-operations-conventions` 定义；
  本 skill 管辖制品一侧：manifest 元数据、随包许可证与必需文件、SBOM 与声明、自包仓库安装验证、撤回与
  弃用经已发布路径实施；不得自工作区直接发布。
- **不当发布以撤回或弃用处理，不删除。** 撤回用于安全缺陷、不可安装产物或法律问题；说明原因并使固定版本
  仍可解析；弃用写明替代方案与移除日期；版本号不得重用、重打或覆盖。
- **继任安排应在需要前记录。** 目标为至少两名维护者持有管理权限；单人仓库记录单点与补偿控制；
  `MAINTAINERS.md` 指定继任者；维护者离开时移除权限，长期不活跃者经通知转为荣休，权限按计划与每次离开
  后审查。
- **归档而非抛弃。** 停止时设置归档标志、README 横幅、关闭或重定向 issue 与支持路径、保持发布与许可证
  可用、指定管理员并移除不再需要的 CI 机密与 webhook；转移时用平台重定向并更新元数据与链接。

## 文件清单矩阵

`references/playbooks.md` 中按类型划分的清单为权威来源；“负责人”指对存在性与元数据负责的角色。

| 文件或设置 | 用途 | 适用于 | 负责人 |
|---|---|---|---|
| `README.md` | 用户与工具认可的入口 | 所有活跃类型；归档保留横幅 | 仓库所有者 |
| `LICENSE` | 授予复用条款 | 库、应用、仅文档；对外交付的内部项目；归档保留 | 仓库所有者，经法务审查 |
| `CONTRIBUTING.md` | 贡献者路径 | 库、应用、仅文档；内部服务推荐 | 维护者 |
| `CODE_OF_CONDUCT.md` | 行为预期与执行途径 | 库与应用；仅文档推荐 | 社区管理者 |
| `SECURITY.md` | 安全报告路径 | 所有活跃类型；归档保留 | 安全负责人 |
| `SUPPORT.md` | 支持路径 | 库与应用；内部服务与仅文档可选 | 维护者 |
| `THIRD-PARTY-NOTICES.md` | 第三方许可证与署名 | 含第三方代码的库与应用 | 维护者，经法务审查 |
| `CHANGELOG.md` | 用户须知的发布内容 | 库与应用；内部服务推荐 | 发布管理者 |
| 文档索引 | 读者任务到页面 | 有文档树的仓库；仅文档必需 | 文档所有者 |
| `CODEOWNERS` | 可合并路径的可问责角色 | 库、应用、内部服务；仅文档推荐 | 维护者 |
| `.github/ISSUE_TEMPLATE/` | 规范报告收集 | 库与应用 | 维护者 |
| `.github/PULL_REQUEST_TEMPLATE.md` | 要求审查证据 | 库、应用、仅文档；内部服务推荐 | 维护者 |
| `.editorconfig` | 编辑器默认值 | 所有活跃类型；归档冻结 | 维护者 |
| `.gitignore` 与 `.gitattributes` | 忽略本地产物并设定行尾与 LFS | 所有活跃类型；后者代码仓库必需 | 维护者 |
| `GOVERNANCE.md`、`MAINTAINERS.md`、`FUNDING.yml`、`CITATION.cff` | 角色、继任、赞助与引用 | 代码仓库推荐；CITATION 用于研究产出 | 维护者 |
| 仓库元数据 | 描述、主题、主页、默认分支、可见性、发布与讨论 | 所有活跃类型；归档保留描述与主页 | 仓库所有者 |

每个维度的详细规则、示例与边界情况见 `references/dimensions.md`；维度列中的编号就是该文件中的节号。

| 维度 | 首条规则 | 详情 |
|---|---|---|
| 1. 必需的社区文件与元数据 | 每个必需文件均位于被认可的路径，并携带其用途所需的字段。 | `references/dimensions.md` 第 1 节 |
| 2. 仓库卫生 | 被跟踪内容均非生成的、超大的或本地配置；过时分支均有负责人。 | `references/dimensions.md` 第 2 节 |
| 3. 治理与决策流程 | 决策模型、路由的审批规则与继任者均以书面形式写明。 | `references/dimensions.md` 第 3 节 |
| 4. 打包与分发 | manifest 精确；许可证、SBOM 与署名声明随包；并证明产物能够在空环境中安装。 | `references/dimensions.md` 第 4 节 |

## 反模式

| 反模式 | 失败原因 | 修复 |
|---|---|---|
| `LICENSE.md` 只有名称而无文本 | 平台识别与法务审查均失败 | 完整文本放入 `LICENSE` 并确认识别 |
| `CODEOWNERS` 指向已不存在的角色 | 路径无审查者即合并 | 按活跃角色重新校验，节奏由 VCS skill 裁定 |
| 公开仓库 README 为空 | 用户提交 issue 等一个不存在的产品 | 首个可用发布前保持私有或归档 |
| 提交构建输出或“仅一次”的大二进制 | 历史膨胀，克隆与镜像永久携带 | 忽略输出、CI 构建、资产移入 LFS 或制品库 |
| 已合并分支无限保留 | 分支列表掩盖活跃工作 | 合并后删除；长期分支有负责人与退出日期 |
| 缺少默认分支保护 | 重写与未审查合并摧毁已审查工作 | 执行 VCS 保护规则并按未审查处理 |
| 一名维护者持有全部权限 | 该人员离开即停摆 | 单人记录单点与补偿控制，指定继任者并审查权限 |
| `SECURITY.md` 缺失或路径错误 | 报告转入公开 issue | 置于认可路径并记录负责人 |
| 未打标签未过门禁即发布 | 输入未知且不可重建 | 只发布经批准标签构建、过门禁的 CI 产物 |
| 不当发布后重发同一版本 | 缓存与 lock 继续提供不同内容 | 说明原因后撤回，再发补丁 |
| 归档仓库仍可写 | 用户误认为仍在维护 | 归档、加横幅、重定向支持 |
| 转移未更新重定向与元数据 | 旧链接与包页面失效 | 平台重定向并更新 manifest、文档与包元数据 |
| 平台与 manifest 描述不一致 | 两个页面描述不同项目 | 单一来源并在 CI 校验镜像 |

## 审查清单

- [ ] 已记录项目类型，并与必需文件清单中的某一行匹配。
- [ ] `README.md`、`LICENSE` 与 `SECURITY.md` 位于认可路径；`LICENSE` 为完整文本且平台识别一致，
  `SECURITY.md` 记录负责人。
- [ ] `CONTRIBUTING.md` 覆盖全新克隆的环境搭建、测试与提交路径；`CODE_OF_CONDUCT.md` 写明联系人与升级途径。
- [ ] 含第三方代码时 `THIRD-PARTY-NOTICES.md` 可到达并随包发布。
- [ ] 每条可合并路径指向活跃角色；issue 与 PR 模板要求分诊者与审查者所需的字段。
- [ ] `.gitignore` 覆盖本地配置、凭据与构建输出；`.gitattributes` 设定行尾、LFS 与生成标记。
- [ ] 依赖更新工具按固定频率运行，升级分级、具名负责人与安全优先均已落实。
- [ ] 无被跟踪文件超过大小策略；生成与第三方引入文件带来源或版本标记。
- [ ] 过时分支与未发布标签已删除，或带负责人与日期；默认分支、发布分支与标签受保护。
- [ ] GitHub 设置已核对：令牌只读、action 准入与固定、fork 构建、环境审批、安全功能与不可变发布均有记录。
- [ ] 社区健康文件位于认可路径；issue 表单关闭空白 issue 并链接安全与支持入口。
- [ ] 最近一次 OpenSSF Scorecard 已运行，发现项有负责人与到期日。
- [ ] `GOVERNANCE.md` 或 `MAINTAINERS.md` 写明角色、决策模型、路由审批与继任。
- [ ] 有文档树的仓库提供文档索引，且自仓库入口可达。
- [ ] manifest 与仓库元数据、当前版本一致；包使用已发布制品并在干净环境安装运行。
- [ ] 发布制品含许可证、声明、SBOM 与必需文件，并已自包仓库安装验证。
- [ ] 归档仓库只读并带横幅；权限按计划审查，已离开的维护者不持有权限。
- [ ] 命令与设置无法读取时已记录缺口、负责人与到期日，未猜测设置值；清单审查与元数据审查均有负责人与计划日期。
