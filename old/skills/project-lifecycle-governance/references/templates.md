# 生命周期模板

模板只规定最小字段，不规定篇幅。R0 可以只保留一段记录；R1 使用完整字段但可精简；R2 应保留证据链接与
批准记录。所有模板中的字段均为必填，除非标注“可选”。

## 受理记录

| 字段 | 填写要求 |
|---|---|
| 请求 | 一句话复述对象、动作与预期结果 |
| 分类 | 提问、动作请求、陈述、歧义、混合、对象不明等 |
| 授权 | 任务级、计划级或逐次明确同意；写明依据 |
| 风险级别 | R0/R1/R2 与判断依据 |
| 影响面 | 文件、系统、数据、用户、生产与共享资源 |
| 停止条件 | 出现何种错误、成本、风险或证据时停止 |
| 负责人 | 决策人、执行人与沟通路径 |
| 下一门禁 | G0–G6 中的下一个门禁与时间 |

## 章程 / 探索简报

| 字段 | 填写要求 |
|---|---|
| 问题 | 当前状态、受影响用户与不做的后果 |
| 结果 | 可测量的结果指标与收益基线 |
| 范围 | 包含与不包含的事项 |
| 约束 | 法规、平台、预算、时间、技术、安全与隐私 |
| 选项 | 至少两个方案，含“不做事”，比较成本、风险与收益 |
| 建议 | 继续、缩小、延期或停止，并说明理由 |
| 风险 | 主要风险、触发信号与缓解措施 |
| 决策 | 批准人、日期与条件 |

## 计划 / 待办

| 字段 | 填写要求 |
|---|---|
| 目标 | 本阶段或本迭代要交付的结果 |
| 验收 | 可判定的验收标准与验收人 |
| 设计 | 模块、接口、数据、目录、依赖与关键决策 |
| 任务 | 拆分到可估算、可验收的条目 |
| 依赖 | 内部与外部依赖、提供者与可用时间 |
| 风险 | 概率、影响、缓解、负责人与复审时间 |
| 测试 | 层级、环境、数据、覆盖目标与失败处理 |
| 发布 | 版本、变更记录、部署、回滚与可观测性 |
| DoR | 每条是否满足 Definition of Ready |

## 门禁记录

| 字段 | 填写要求 |
|---|---|
| 门禁 | G0–G6 与阶段名 |
| 时间与地点 | 日期、时区、会议或异步记录链接 |
| 参与人 | 批准人、执行人、审查者与记录人 |
| 风险级别 | R0/R1/R2 与依据 |
| 证据 | 每项证据的链接、命令输出或指标 |
| 决定 | Go、Conditional Go、Hold、Recycle、No-Go 或 Defer |
| 条件 | 条件、负责人、到期日与关闭证据 |
| 未解决项 | 风险、缺陷、依赖与升级路径 |
| 下一门禁 | 阶段、时间与前置条件 |

示例：

| 字段 | 内容 |
|---|---|
| 门禁 | G4 验证门 |
| 证据 | 单元与集成测试通过；依赖审计无高危；独立审查通过 |
| 决定 | Conditional Go |
| 条件 | 性能回归基线在发布前补齐；负责人为性能负责人；到期日为下一工作日 |
| 下一门禁 | G5 发布门，条件关闭后召开 |

## 收尾报告

| 字段 | 填写要求 |
|---|---|
| 结果 | 对照 G1 基线的收益、采用率与用户结果 |
| 偏差 | 范围、时间、成本、质量与风险的偏差及原因 |
| 质量 | 缺陷、事故、变更失败率与遗留问题 |
| 教训 | 什么有效、什么无效、意外与下一次改变 |
| 行动 | 行动项、负责人、到期日与验证方式 |
| 资产 | 代码、文档、数据、环境与访问权限的归档或移交 |
| 关闭 | 未完成事项的转移、接受或取消决定 |

## 使用纪律

- 模板是证据载体，不是官僚检查表；没有决策价值的字段可以合并，但不得删除授权、风险、验收、回滚与
  收益字段。
- 记录应当在门禁发生时完成；事后补记必须标注补记时间与当时已知事实。
- 记录中的敏感信息按 `security-compliance-conventions` 处理，不得把凭据、个人信息或内部地址写入
  可广泛分发的模板。
- 模板版本由项目维护；修改模板后，下一次门禁使用新版本，已完成的记录保持原样。

## 变更请求

| 字段 | 填写要求 |
|---|---|
| 基线 | 当前范围、验收、日期、成本、风险与依赖 |
| 变更 | 拟改变的内容与原因 |
| 影响 | 对范围、质量、进度、成本、风险与依赖的影响 |
| 选项 | 至少两个方案，含“不变更” |
| 回滚 | 撤销变更或恢复基线的方式 |
| 决定 | 批准人、条件、到期日与重新评审的门禁 |

变更请求在 LC-12 下重新过门；不得在构建或发布中静默改变目标。

## 风险登记

| 字段 | 填写要求 |
|---|---|
| 风险 | 事件、原因与可能后果 |
| 级别 | 概率 × 影响；R0/R1/R2 关联 |
| 触发信号 | 什么迹象表明风险正在发生 |
| 缓解 | 预防、检测、响应与补偿控制 |
| 负责人 | 谁监控、谁决定、谁执行 |
| 复审 | 日期、门禁与关闭证据 |

风险登记随阶段更新；超过复审日期未处理的，升级并进入门禁记录。

## 依赖登记

| 字段 | 填写要求 |
|---|---|
| 依赖 | 接口、数据、团队、供应商或合规条件 |
| 提供者 / 消费者 | 双方负责人 |
| 窗口 | 需要与可用的时间范围 |
| 验证 | 如何确认依赖可用 |
| 失败回退 | 延迟、失效或变更时的替代方案 |
| 升级 | 触发条件、路径与最晚决定时间 |

依赖未经提供者确认时，不得把门禁判为 Go；应按 Hold 或 Recycle 处理。

## 例外记录

| 字段 | 填写要求 |
|---|---|
| 规则 | 被偏离的条款或门禁 |
| 范围与期限 | 适用对象、到期日、自动失效条件 |
| 理由与影响 | 为什么需要、影响与替代方案 |
| 补偿控制 | 监控、限制、回滚与复核 |
| 批准 | 具名批准人、记录人与复核人 |

例外到期未复核的自动失效；智能体不得自批例外，也不得把例外写成项目约定。
