# 安全与合规规范生命周期契约

本文件把安全与合规规范接入 S0–S6 与 G0–G6：界定各阶段的输入、活动、输出与门禁，规定证据包与复核方式，给出
交接对象与升级路径，并说明按风险与组织条件裁剪的方式与度量口径。控制措施细节见 `dimensions.md`，工作表与
运行手册见 `checklists.md`。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S0 受理 | 请求、涉及的数据与系统 | 列出资产、入口点与数据类别，初步判定风险级别与受保护对象，确认授权 | 分级结论与停止条件 | G0 |
| S1 探索 | 分级结论与方案选项 | 判断是否涉及个人数据、凭据、第三方代码或生产变更，形成初步威胁与合规约束 | 初步威胁说明与约束清单 | G1 |
| S2 计划 | 初步威胁与数据清单 | 完成威胁模型、许可证分类、依赖策略、PII 清单与审查分派 | 威胁模型、许可证分类、清单条目 | G2 |
| S3 构建 | 威胁模型与控制要求 | 落实默认拒绝、校验与编码、授权、凭据注入，运行机密与代码扫描 | 控制措施说明、扫描结果、安全债务 | G3 |
| S4 验证 | 可运行增量与扫描结果 | 评定发现项、确定修复期限、处理例外、生成 SBOM 与许可证报告 | 安全与合规结论、VEX 或例外记录 | G4 |
| S5 发布 | 验证结论与发布候选 | 复核 SBOM、声明、签名、来源证明、披露状态与残余风险 | 发布证据包与公告状态 | G5 |
| S6 收尾 | 事故、泄露与发布后反馈 | 复盘根因、更新威胁模型与运行手册、关闭或续期例外 | 事后审查与控制改进项 | G6 |

S3 与 S4 之间的边界是扫描与评定的分界：扫描可以随提交持续运行，结论必须在 G4 之前出具，并在依赖树变化后重新
生成。

## 门禁证据

| 门禁 | 证据包 | 复核人 | 失效条件 |
|---|---|---|---|
| G0 | 数据分类、资产与信任边界清单、风险级别、受保护对象、授权依据 | 项目负责人与发起人 | 分类缺失，或处理生产数据无授权 |
| G2 | 威胁模型或“未跨越边界”说明、许可证分类、依赖审查记录、PII 清单、审查分派 | 项目负责人与安全审查者 | 信任边界无模型，或审查未分派 |
| G4 | 扫描结果与严重程度、修复期限、VEX 或例外记录、SBOM 与许可证报告 | 安全与合规独立结论 | 扫描未运行、结果过期，或高危无接受记录 |
| G5 | 重新生成的 SBOM 与声明、签名或来源证明、公告与披露状态、残余风险 | 发布负责人与运营 | 制品缺 SBOM、签名不可验证，或公告与版本不符 |

证据组织：

- 扫描结果、SBOM 与许可证报告附在发布记录或变更上，并关联到具体制品与提交；只有结论没有原始输出的记录无法
  复核。
- 例外条目写明控制缺口、补偿措施、负责人、到期日与审查日期；到期未复审的例外自动成为未处理发现项。
- 威胁模型与数据清单随设计变更更新；入口点、数据类别或信任边界变化后，旧模型不再作为当前设计的证据。
- 公开前的漏洞材料仅经私有渠道流转，公告与修复说明在发布时同步，不得提前进入公开议题。

## 交接与升级

上游交接：

- 从 `project-lifecycle-governance` 接收 G0 风险级别与受保护对象清单；涉及生产、凭据、个人数据与合规的，
  自动升至 R2 流程。
- 从 `architecture-and-design-conventions` 接收模块边界、数据流与框架变更，用于更新威胁模型与信任边界。
- 从 `api-and-data-conventions` 接收数据模型与保留机制，用于核对 PII 清单与删除路径是否一致。

下游交接：

- 扫描门禁的位置、命令与阻塞阈值交给 `testing-and-quality-conventions`；严重程度、修复期限与例外批准留在本
  skill。
- 制品签名、来源证明与发布流程交给 `release-operations-conventions`；本 skill 只规定发布必须携带的安全证据。
- `SECURITY.md` 的存在性与元数据交给 `repository-governance-conventions`，页面结构与行文交给
  `documentation-conventions`；本 skill 管辖其必需内容与响应承诺。
- 事故与泄露的复盘进入 S6，并回写测试、运行手册与威胁模型；威胁模型的改进项需有负责人与到期日。

升级条件：

- 确认凭据泄露或漏洞正在被利用：按 AU-5 先实施最小止损（吊销、隔离、关闭入口），再按 SP-6 保留证据并报告，
  调查结束前不清理痕迹。
- 发现未知许可证、禁止类许可证或缺失许可证：停止引入该依赖，取得书面例外或替换方案后再继续。
- 隐私变更涉及新处理者、跨境传输或同意机制：转隐私审查，必要时移交法务；审查未完成不得上线。
- 无法取得 CNA 编号：在发布说明与平台公告中记录申请状态与联系对象，不虚构编号，也不以此延迟修复发布。
- 第三方代码存在缺陷：报告上游或在独立 fork 维护有记录的补丁；不得在上游副本中就地修改。

## 裁剪与度量

| 级别 | 安全与合规工作的裁剪 | 不可裁剪项 |
|---|---|---|
| R0 | 未跨越信任边界的功能写一行说明，扫描沿用既有配置 | 机密扫描与依赖许可检查 |
| R1 | 一页威胁模型、许可证分类与依赖审查记录 | 必需审查、例外记录与修复期限 |
| R2 | 完整威胁模型、独立安全与合规结论、SBOM 与签名、披露计划 | 独立结论不得由交付团队自出，G4 与 G5 不得合并 |

组织条件：

- 单人维护时，披露与修复时限标注为尽力而为，不作为对外承诺的 SLA；豁免与风险接受由维护者具名记录，并在治理
  文件中说明补偿控制，不由智能体自批。
- 没有 CNA 或未被授权时，公告可以不含编号，但必须记录申请状态与所联系的 CNA，并在编号分配后更新；编号不得
  杜撰。
- 私有仓库受套餐限制、无法启用某项平台安全功能时，记录补偿控制（等效扫描、人工审查、定期盘点）与负责人，
  不得据此跳过其他控制。
- 无生产环境或不分发制品的仓库，可省略签名与来源证明，但仍需 SBOM 与许可证清单；内部工具按网络已被攻陷的
  假设建模，不因“内部”而豁免。

度量口径：

| 指标 | 定义 | 用途 |
|---|---|---|
| 期限内修复率 | 在分级期限内关闭的发现项占比 | 评估响应能力 |
| 机密命中轮换时长 | 从确认命中到完成轮换的时间 | 评估止损速度 |
| 依赖告警老化 | 未处置告警的平均存续天数 | 评估供应链维护 |
| SBOM 覆盖率 | 发布制品中带 SBOM 的比例 | 评估发布证据完整度 |
| 例外到期关闭率 | 到期前关闭或重新评估的例外占比 | 评估例外治理 |
| 披露响应达成率 | 在承诺时点完成确认与分诊的报告占比 | 评估披露承诺 |

指标按季度或按发布复核；异常先查分级是否一致、扫描覆盖是否完整，再判断控制是否失效。指标用于改进控制与
流程，不用于个人排名；不得通过缩小扫描范围或重定义严重程度改善数字。
