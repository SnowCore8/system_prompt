# 变更记录与文档结构

## CH-9 变更记录的禁止

- CH-9 变更记录的禁止。除项目指定的变更日志文件（例如 `CHANGELOG.md`）、发布说明、ADR、事故复盘与
  迁移指南等历史记录文件外，智能体不得撰写任何形式的变更记录：不得设置“变更”“更新”“修复”章节，不得记
  载日期条目，不得列举新增、删除或重命名，不得记载“修改内容”。本条适用于源文档、`README`、报告、交付
  说明与代码注释。智能体仅应陈述当前为真的事实、提供证据并替换过时内容；不得追加历史，亦不得叙述编辑顺
  序。提交消息与 PR 描述为变更历史的适当载体，其说明修改原因，而非复述当前状态。上述历史记录文件按其
  自身规则记录历史；修改本参考文件时，仍依全局约束第 1 节说明所涉条款。变更记录将腐化、重复现状，并迫
  使读者从过去重建现在。

## CH-10 文档结构

- CH-10 文档结构。项目级文档（`README`、`CONTRIBUTING`、`GOVERNANCE`、`SECURITY` 等）开头应当说明用
  途与维护者；面向贡献者的文档还应当说明阅读时机。一个文件仅应承载一类内容，同一信息不得重复书写。不
  常见的细节应当移至单独文件，主文件仅保留入口与标准。
