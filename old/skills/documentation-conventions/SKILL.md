# 文档规范

文档缺陷多源于缺失与脱节，而非文笔不佳：页面从未编写，代码变更后事实随之过时，同一答案散落于三个文件，
读者找不到页面，也无人负责。上述缺陷在写作时预防成本较低；读者已经信任错误页面之后再修复，成本高昂。本
skill 规定一套决策程序与规则集，并将文档视为产品的组成部分，而非附属产物。

## 适用范围与优先级

效力依下列层级判断：高层覆盖低层，低层仅在高层未规定时补充：

1. 强制性的平台、法律、宿主与全局用户约束。文档站生成器约束、API 参考工具、法律披露模板与公司强制政策，
   均非可选事项。
2. 本 skill 的规则与默认值。
3. 既有项目约定与事实。现有文档结构、模板、工具链与配置作为输入，依本 skill 的规则处理；项目约定仅在本
   skill 未规定时补充。
4. 个人偏好，不得覆盖上述三层。

管辖与边界：

- 手写文档的结构、模板与文笔由本 skill 管辖。变更日志、发布说明、运行手册与事故复盘的编写节奏与触发条件，
  以及其中必须记录的发布事实（版本、批准、上线与回滚、观察结果），由 `release-operations-conventions` 管辖；
  弃用时机与公告位置亦由该 skill 管辖；代码内标记格式由 `comment-conventions` 管辖。
- API 契约内容（字段、请求与响应形态、版本管理）与数据迁移，由 `api-and-data-conventions` 管辖；本 skill 规定
  API 参考页的结构与文笔。契约以 IDL/schema 为唯一真源，参考页是其生成投影并链接契约，不得另行定义字段。
- 术语表的散文定义由本 skill 管辖；名称、大小写、被禁用的同义词、文件名、目录名、锚点与 ADR 编号由
  `naming-conventions` 管辖。术语表仅写定义，并链接项目命名表。
- 哪些文件必须存在、需要哪些元数据，由 `repository-governance-conventions` 管辖；本 skill 规定上述页面的内容与
  结构。CI 中的文档校验与门禁由 `testing-and-quality-conventions` 管辖，流水线配置由
  `release-operations-conventions` 管辖；本 skill 规定应当校验的链接、示例与页面。
- 源代码注释、docstring 与文档注释由 `comment-conventions` 管辖；由文档注释生成的参考页，结构依本 skill，文笔
  依该 skill。常驻指令文件（AGENTS.md、CLAUDE.md、QWEN.md）的结构与条款由 `system-prompt-authoring` 管辖；
  同一文件兼作指令入口与项目维护说明时，边界以该 skill 为准。
- 生成的文档，结构规则与生成规则适用本 skill；不得手工编辑生成产物，应当修改生成器或源注释后重新生成，保留
  生成标记，并在页面或索引中记录上游来源。第三方引入文档保留原文结构与来源标记，不得改写为自有文档；确需调整的，应当在边界处隔离并记录上游来源。

交付要求：

- 每项事实仅保留一个权威归属。其他页面应当链接至该归属；第二份副本即使仍然准确，亦构成缺陷，因为第一次
  编辑即会使两个页面不一致。
- 文档应当与其描述的行为在同一次变更中更新。文档与代码分属不同提交的，仍应当于同一次交付中落地；默认分支
  不得描述旧行为。
- 文档树视为产品界面的组成部分。改变用户可见行为的变更，应当包含对应页面；忽略文档的审查，视为不完整的
  审查。
- 同一效力层级的强制规则冲突时，智能体应当报告用户裁决；非强制的项目约定冲突，可以说明冲突与所选约定，并
  记录于项目的文档指南或 ADR，使下一次变更遵循该决定；跨层冲突依全局用户约束的效力顺序处理。

## 生命周期定位

上游输入：S1 的问题、用户与结果指标决定文档服务谁；S2 的范围与设计决策决定需要哪些页面与章节。下游交接：S3
的增量与文档 diff 同批落地；S4 的一致性结论进入验证证据；S5 的变更日志与迁移指南供发布使用；S6 的归档与交接
记录进入收尾报告。升级与停止：归属或发布节奏出现争议时交 `project-lifecycle-governance` 裁定；发布事实与文档
冲突时以 `release-operations-conventions` 为准；缺少权威来源时停止编写；批量删除或归档依 IR-1 与 AU-1 取得同意。

| 阶段 | 本 skill 的职责 | 产出 / 证据 |
|---|---|---|
| S1 探索 | 把问题、用户与约束写成可读的章程或简报，划定文档集范围 | 读者定义、文档缺口清单、负责人 |
| S2 计划 | 为设计与决策记录提供类型模板与必需章节，规划文档任务 | 设计文档与 ADR 骨架、文档任务与触发条件 |
| S3 构建 | 随增量更新页面，维持单一权威归属与当前事实 | 与代码同批的文档 diff |
| S4 验证 | 核对文档与实现一致，运行构建、链接与示例校验 | 构建输出、链接校验结果、一致性结论 |
| S5 发布 | 交付变更日志、发布说明、迁移与弃用指南的结构与动作 | 分组条目、升级动作、字段映射表 |
| S6 收尾 | 写收尾报告，归档过时页面并留下墓碑与重定向 | 收尾报告、归档状态、交接记录 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G1 立项 | 章程或简报按类型模板写明问题、用户与结果；文档缺口与负责人已列出 | Hold：读者与问题未定时不写页面 |
| G4 验证 | 文档构建、链接与拼写校验输出；代码 diff 中每项可见行为变化均有对应文档 diff | Recycle：缺文档 diff 的视为验证未完成 |
| G5 发布 | 变更日志按 Keep a Changelog 分组；发布说明含升级动作与迁移链接；弃用写明替代与移除版本 | Hold：缺升级动作的说明不得发布 |
| G6 收尾 | 收尾报告与偏差分析；过时页面的归档状态与重定向记录 | No-Go：未归档即关闭视为遗留缺陷 |

文档证据缺失按缺陷处理；是否阻塞合并由 `testing-and-quality-conventions` 裁定，是否阻断发布由
`release-operations-conventions` 裁定。构建失败、死链与示例不可运行不得以“稍后修复”结案。

## 工作流

1. 确定读者与问题。写明一位主要读者，以及该读者读完后必须能够完成的事项；面向所有读者的页面无法服务任何
   读者。
2. 以文档类型矩阵分类。教程、操作指南、参考与解释回答不同的问题；不得将这四种类型合并为一个页面。
3. 确定权威归属。于仓库与文档站中检索该项事实；已存在的，更新该页面并建立链接，不得另行编写副本。
4. 阅读项目既有结构与模板，匹配相邻页面的目录、文件名、标题风格、语气与 front matter 约定。
5. 依文档类型取对应的必需章节。范围、前提与结果置于首屏；非必需段落与示例可以删除，必需章节不得删除。
6. 将页面接入导航与归属，删除或重定向其所替代的内容，并更新文档索引。
7. 校验链接、示例与构建：运行每条命令与示例，打开每个链接与锚点，重新生成过时截图；审查渲染后的页面。

## 核心规则

- **为一位读者、一个问题而编写。** 写明页面服务哪位读者、回答什么问题；不指定读者的页面，会演变为无法服务
  任何读者的功能清单。
- **先写结果。** 结果、决定或下一步放在开头数行，背景放在其后；读者会先判断页面是否适用于自身，再读细节。
- **一项事实仅设一个归属。** 每项事实只属于一个页面，其他所有位置都应当链接至该页面；重复的事实会在第一次
  变更时分叉，使读者得到两个答案。
- **文档与变更同步更新。** 同一个 PR、同一次审查、同一次发布；过时文档比缺失文档更为不利，因为读者会信任它。
- **使示例可以运行，并粘贴真实输出与版本。** 给出完整命令，包括工作目录、变量与预期结果；输出从实际运行复制
  并说明其版本；编造的输出会掩盖不兼容。
- **校验每个链接与锚点。** 在构建中解析链接，并在同一次变更中修复；死链是作者始终未察觉的死胡同。
- **说明适用范围。** 写明页面所属的产品版本、平台、部署模式或受众；未作版本说明的指令，会在下一次发布改变
  行为时无声失效。
- **指定负责人与审查触发条件。** 为每个页面指定负责团队与强制审查事件；触发条件依对应流程 skill 确定：发布与
  事故依 `release-operations-conventions`，schema 变更依 `api-and-data-conventions`。无人负责的页面无人修复。
- **优先归档过时页面。** 归档或重定向，并留下墓碑页说明替代位置；仅当无法归档且完成入站引用核查时，方可删除；
  批量删除依 IR-1 与 AU-1 取得明确同意。过时页面会继续在搜索中排名，持续误导读者。
- **保持公开边界可见。** 面向客户的页面与内部笔记分开，并标注受众；将内部权衡写入公开文档会泄露信息，并使
  读者困惑。
- **先采用类型模板，再创建页面。** 从该文档类型的必需章节开始；必需章节不得删除，仅可替换示例内容；从零设计
  的页面通常缺少前提、范围或下一步。
- **先写受支持的路径，再写替代方案。** 将每个选项均列为菜单，会迫使读者作出文档本应代其作出的决定。
- **陈述当前事实，而非历史。** 指南与参考保留当前行为；日期、迁移与原因放在变更日志或 ADR 中。
- **GitHub 社区文件按平台路径与模板交付。** README、CONTRIBUTING、SECURITY、SUPPORT 与行为准则置于根目录、
  `.github/` 或 `docs/`；issue 表单置于 `.github/ISSUE_TEMPLATE/` 并关闭空白 issue，PR 模板置于认可路径。变更
  日志按 Keep a Changelog 分组，发布说明由 `.github/release.yml` 分类生成并补迁移步骤；链接、锚点与示例在 CI
  校验。

## 事实的归属

两个页面都可能承载同一项事实；确定归属看读者所提的问题，不看事实从何处获知；项目约定作为输入，本规则优先。

| 事实 | 权威归属 | 同时链接自 |
|---|---|---|
| 项目内容、安装与首次运行 | `README.md` | 文档首页、包仓库页面 |
| 开发环境搭建与测试命令 | `CONTRIBUTING.md` 文档入口（命令值以项目配置为准；规则由 `testing-and-quality-conventions` 的 CH-8 裁定） | README、issue 与 PR 模板 |
| 当前标志、默认值与限制 | 参考页 | 指南、README 示例 |
| 选择某种设计或技术的原因 | ADR | 架构页、代码注释 |
| 端点接收与返回数据的方式 | API 契约（IDL/schema） | API 参考页、指南、客户端库 |
| 故障服务的恢复方法 | 运行手册 | 告警规则、事故模板 |
| 各发布之间的变化 | 变更日志或发布说明 | 迁移指南、支持回复 |
| 任务的分步完成方法 | 操作指南 | README、参考页 |
| 领域术语的含义 | 术语表 | 使用该术语的每个页面 |
| 事故的成因 | 事故复盘 | 变更日志、故障排查页 |

## 文档类型矩阵

| 文档 | 读者与关切 | 必需章节 | 典型位置 |
|---|---|---|---|
| README | 新用户：项目内容与入门路径 | 名称与范围、安装、快速开始、配置、文档链接、许可证 | `README.md` |
| CONTRIBUTING | 贡献者：环境搭建与提交路径 | 工具链、环境搭建、运行与测试、约定、审查预期 | `CONTRIBUTING.md` |
| 架构概览 | 维护者：系统构成方式 | 背景、组件、边界、数据流、决策、已知限制 | `docs/architecture/` |
| ADR | 维护者：决策依据 | 状态、日期、背景、决定、后果、备选方案 | `docs/adr/` |
| 设计文档或 RFC | 审查者：提案的运作方式 | 问题、目标与非目标、提案、备选方案、风险、上线、未决问题 | `docs/rfcs/` |
| 教程 | 学习者：示例构建方法 | 预期结果、前提、编号步骤、最终结果、下一步 | `docs/tutorials/` |
| 操作指南 | 实践者：任务完成方法 | 目标、前提、步骤、验证、常见失败 | `docs/guides/` |
| 参考页 | 实践者：可用选项 | 概要、选项与默认值、约束、版本说明、示例 | `docs/reference/` |
| API 参考 | 集成者：端点能力 | 方法与路径、认证、参数、响应、错误、示例 | `docs/api/` |
| 概念或解释 | 学习者：运作原理 | 概念、模型、词汇、权衡、示例、链接 | `docs/concepts/` |
| 运行手册 | 值班人员：即时处置步骤 | 触发条件、影响、首个动作、步骤、验证、回滚、升级 | `docs/runbooks/` |
| 变更日志 | 用户：各发布之间的变化 | 版本与日期、分组条目、升级动作、issue 链接、亮点、分类 | `CHANGELOG.md` |
| 发布说明 | 用户：单次发布的内容与动作 | 版本与日期、分组条目、升级动作、issue 链接、亮点、分类 | 托管平台的 Release 页 |
| 迁移指南 | 升级者：迁移方法 | 受影响受众、时间线、字段映射、步骤、验证、回滚 | `docs/migrations/` |
| 故障排查与常见问题 | 受阻用户：问题含义 | 症状、原因、修复、预防、相关链接 | `docs/troubleshooting/` |
| 安全、法律与支持 | 报告者：报告路径 | 页面结构：策略章节及各章节链接去向；披露内容由 `security-compliance-conventions` 规定 | `SECURITY.md` |
| 事故复盘 | 维护者：事故成因 | 摘要、影响、时间线、根因、发现、行动项、负责人 | `docs/postmortems/` |

矩阵列出主要页面类型；弃用通知、术语表与文档索引无独立矩阵行，仅设模板，分别由维度 12、16 与 15 负责。

## 反模式

| 反模式 | 为什么失败 | 修复 |
|---|---|---|
| README 罗列功能 | 读者无法判断应当先安装何种内容。 | 先写范围、安装与快速开始。 |
| 将计划描述为已发布行为 | 读者将基于不存在的行为实施开发。 | 将计划移至设计文档。 |
| README、wiki 与站点重复同一答案 | 副本将分叉；无任何一份为最新。 | 仅保留一个权威页面；其余页面链接至该页面。 |
| 命令缺少工作目录或仅有截图 | 命令将失败，且无法复制与检索。 | 写明目录、变量与输出；以文本粘贴输出。 |
| 变更日志重复 git log | 读者无法找到需要采取行动的变化。 | 依影响分组；说明所需动作。 |
| 运行手册未设回滚 | 操作者可以开始，却无法撤销。 | 补充验证与回滚。 |
| 生成器未覆盖结构、认证与示例 | 参考页缺章节、认证与示例。 | 扩展生成器或源注释后重新生成；不得手工编辑产物。 |
| 代码变更数周后方更新文档 | 分支所描述的行为已经消失。 | 于同一次变更中更新页面。 |
| 未设负责人与审查触发条件 | 在有人提出抱怨之前，页面无人编辑。 | 指定负责人与审查触发条件。 |
| 每个选项均同等对待 | 读者必须选择文档本应代其选择的路径。 | 先写受支持的路径。 |
| 弃用未设日期或路径 | 用户无法规划，因而拖延。 | 说明时间线、替代方案与步骤。 |

## 审查清单

- [ ] 页面设有一位指定读者与一个问题，并采用了匹配的模板与必需章节。
- [ ] 事实仅有一个权威页面，其余位置链接而非复制。
- [ ] 范围、前提与结果出现于首屏；受支持路径先于替代方案。
- [ ] 指南与参考陈述当前行为；日期、迁移与原因位于变更日志或 ADR。
- [ ] 代码行为变化在同一次变更中具有对应文档 diff。
- [ ] 命令包含工作目录与必需变量；示例可运行，输出真实并载明版本或环境。
- [ ] 每个链接与锚点均可在文档构建中解析。
- [ ] 已写明适用的版本、平台与受众；公开页面不含内部地址、机密或员工数据。
- [ ] 页面可从文档索引或侧边栏到达；被替代的页面已作重定向。
- [ ] 已记录负责团队与审查触发条件。
- [ ] 术语表只写定义并链接命名表；标题遵循项目的层级与锚点约定。
- [ ] 截图与图表同当前 UI 一致，且清晰可读。
- [ ] 变更日志已说明用户可见的变更与必需动作。
- [ ] 文档构建、链接校验与拼写校验通过。
