# 调试规范生命周期契约

本文件把调试规范接入 S0–S6 与 G0–G6：界定每个阶段的输入、活动、输出与门禁，规定证据包与复核方式，给出交接
对象、升级条件、裁剪方式与度量口径。技术规则见 `dimensions.md`，报告写法见 `report-template.md`，根因治理见
`root-cause-discipline.md`。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S0 受理 | 缺陷报告、失败测试、监控告警或事故单 | 判断报告是否可判定，确认对象与授权，区分正确性缺陷、性能与并发问题 | 受理结论与缺失信息清单 | G0 |
| S1 探索 | 反复出现的缺陷与用户反馈 | 判断是否需要结构性修复，列出修复、绕过与不处理的代价 | 处置建议与影响评估 | G1 |
| S2 计划 | 已受理缺陷与验收标准 | 固定复现环境、回归测试落点、修复范围、回滚点与负责人 | 复现方案与修复计划 | G2 |
| S3 构建 | 复现方案 | 复现、二分、根因验证、失败测试、最小修复 | 复现步骤、排除记录、根因说明、修复提交 | G3 |
| S4 验证 | 修复增量与失败测试 | 前后对照执行，运行受影响范围回归，标注未覆盖部分 | 验证证据包与残留风险 | G4 |
| S5 发布 | 缺陷清单与接受记录 | 复核未关闭项、症状修补与临时缓解，判断是否存在发布阻塞项 | 阻塞清单与接受记录 | G5 |
| S6 收尾 | 事故与逃逸缺陷 | 把根因回填为回归测试，撰写复盘行动项 | 根因报告与行动项 | G6 |

S1 的处置建议只在 G1 需要立项判断时产出；单个可判定缺陷直接从 S0 进入 S2，不为此补建探索记录。

## 门禁证据

| 门禁 | 证据包 | 复核人 | 失效条件 |
|---|---|---|---|
| G0 | 报告四要素、分流结论、缺失信息、风险级别与停止条件 | 任务负责人 | 报告缺“期望与实际”，无法判定 |
| G2 | 复现环境、回归测试位置与负责人、修复范围、回滚点 | 项目负责人 | 复现环境不可重跑，或范围未固定 |
| G3 | 二分记录与已排除事项、根因与触发条件的区分、修复前失败的测试输出 | 增量审查者 | 只有修复后通过的输出，缺失败基线 |
| G4 | 修复前后两次输出、回归结论、无法自动化时的双次步骤记录、未覆盖项 | 独立审查者 | 证据来自其他提交，或回归未捕获缺陷 |
| G5 | 未关闭缺陷清单、症状修补的接受记录、临时缓解的负责人与到期日 | 发布负责人 | 阻塞级缺陷无接受人，或到期日缺失 |
| G6 | 根因报告、新增回归测试、逃逸原因与行动项 | 项目负责人 | 根因未落成测试，或行动项无负责人 |

证据按提交范围组织，每份证据写明命令、版本与执行时间。以下情形一律视为证据不足：只描述计划中的验证；用
“本地试过”代替输出；把其他缺陷的通过结果移植到本次修复；用重试覆盖首次失败。

证据留存：

- 最小复现、二分记录与两次执行输出附在缺陷工单或修复提交中，供未参与排查的人复核。
- 临时日志与插桩脚本属于过程材料，提交前移除；其中包含的输入与环境信息写入工单摘要后再删除。
- R2 缺陷增加独立事后审查记录；止损动作与后续验证分开记录，不改写时间线。
- 同一缺陷的后续补丁复用同一证据编号，新增证据追加而不替换旧件。

## 交接与升级

上游交接：

- 从 `testing-and-quality-conventions` 接收失败用例与不稳定测试的根因调查请求；测试策略与门禁阈值仍由该
  skill 管辖。
- 从 `release-operations-conventions` 接收事故与发布后缺陷；先按本流程复现，再由发布负责人决定回滚或止损。
- 从 `concurrency-conventions`、`performance-conventions` 接收已被判定为正确性缺陷的线索，反向移交时附上复现
  与二分结果。

下游交接：

- 修复增量交给 G4 验证；验证证据包由独立审查者核对，不由修复作者自批。
- 未关闭缺陷与临时缓解交给 G5 发布复核；接受记录须含负责人、到期日与补偿控制。
- 根因与逃逸原因交给 S6 复盘，并回写测试策略、威胁模型或运行手册。

升级条件：

- 同一问题第二个补丁仍失败：停止叠加补丁，重新定位根因；根因属结构性时升级到
  `architecture-and-design-conventions`，由用户决定是否安排重构。
- 根因修复超出当前授权、成本或兼容性约束：按 HO-7 报告原目标、障碍与选项，取得明确同意后再仅修症状。
- 疑似凭据或个人信息泄露：按 SP-6 立即停止、保留证据并报告，不得继续排查或清理。
- 缺陷影响生产数据或正在被利用：按 AU-5 先实施最小止损，再补门禁记录并区分当时已知与事后信息。

停止条件：

- 报告缺关键要素且报告人无法补齐时，保持 Hold，不进入定位。
- 复现需要读取受保护文件或生产数据时，先取得对应授权，不得以调试为由扩大权限。
- 修复需要跨模块改动或引入新依赖时，按范围规则重新确认，不在修复提交中顺带完成。

## 裁剪与度量

| 级别 | 缺陷诊断的裁剪 | 不可裁剪项 |
|---|---|---|
| R0 | 报告与回归测试合并为一条记录，可自检自查 | 修复前失败与修复后通过的对照 |
| R1 | 使用完整报告与二分记录，G4 由非作者复核 | 根因与触发条件的区分，症状修补的接受记录 |
| R2 | 生产或数据损坏类缺陷增加独立事后审查与回滚证据 | 止损记录、根因报告、复盘行动项与到期日 |

度量口径：

| 指标 | 定义 | 用途 |
|---|---|---|
| 首次修复成功率 | 一次修复后回归通过且未复发的缺陷占比 | 判断根因定位质量 |
| 同根因复发率 | 因同一根因再次被报告的缺陷占比 | 识别症状修补与缺失测试 |
| 无法复现率 | 受理后未能取得可判定复现的缺陷占比 | 评估报告质量与环境可观测性 |
| 定位深度 | 二分记录中的步数与收敛位置 | 评估定位方法与工具配置 |
| 无关改动比例 | 修复 diff 中与根因无关的行数占比 | 约束最小修复纪律 |

指标按迭代或按月复核，异常先查报告质量、环境差异与工具配置，不得直接调整目标或隐藏失败。R0 任务只在出现
返工时记录指标。指标不得用于个人排名；同一根因反复出现时，优先补测试与改进可观测性，而不是要求更快的修复
速度。
