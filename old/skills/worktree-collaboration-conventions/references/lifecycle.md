# 智能体团队的工作树协作生命周期契约

本文件把工作树协作接入 Stage-Gate 生命周期：计划阶段确定任务边界与依赖，构建阶段隔离写入并集成，收尾
阶段保全、移除与审计。维度规则见 `dimensions.md`，操作表见 `playbooks.md`；本文件只写阶段职责、门禁
证据、交接升级与裁剪度量。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 任务清单、分支模型、测试命令、资源清单 | 画依赖 DAG，划分写入范围与可并行边界，识别共享文件、迁移、生成物与外部资源，登记工作树 | 任务板、并行方案、集成工作树安排 | G2 |
| S3 构建 | 已登记的任务与基线 | 从提交创建工作树，初始化环境，写者小步提交，领导者按 DAG 集成并在集成结果上验证 | 基线 SHA、提交、集成记录、验证输出 | G3 |
| S6 收尾 | 已合并、已放弃或失联的工作树 | 盘点脏状态，归档或移交，普通移除，prune，回收分支、端口与锁，审计记录一致性 | 清理记录、归档位置、任务板关闭状态 | G6 |

阶段细则：

- **S2 拆分。** 两个任务改不同模块且无共享契约才并行；共享文件、同一 schema、同一生成物或顺序依赖放在
  同一工作树串行。一个写者同一时间只持有一个活跃写入工作树，顺序任务可复用同一工作树并切换基线。
- **S2 登记字段。** 任务板记录任务 ID、写者、领导者、基线 SHA、分支、工作树路径、写入范围、依赖任务与
  状态；缺少领导者授权记录的工作树不得写入。只读调查不登记可写工作树，使用临时副本或只读检出。
- **S2 集成安排。** 存在多个交付物时，领导者指定一个专用集成工作树；写者不接触集成基线。集成顺序按依赖
  DAG 排列，同层任务可并行验证，但合入集成基线时串行。
- **S3 创建核对。** 领导者先确认源基线 `HEAD` 与工作区状态，再用 `git worktree list --porcelain` 排除路径
  与分支冲突，随后以 `git worktree add -b <branch> <path> <base>` 创建；子模块、LFS、稀疏检出与 hooks
  在工作树内显式初始化并验证，不假设主工作树配置自动可用。
- **S3 创建后验证。** 检查 `.git` 文件指向、忽略规则、子模块与 LFS 状态，运行最小构建或测试，确认路径可
  写且工具链可用；把实际路径与 `HEAD` 写回任务板，不只记录创建命令。
- **S3 环境隔离。** 依赖、构建输出、缓存与临时目录按树独立；数据库使用独立文件、schema 或实例；服务、
  端口、socket、命名管道与锁文件按树分配，并行测试使用端口池或动态端口；共享只读缓存须不可写并锁定版本。
- **S3 共享资源。** 设备、模拟器、浏览器与消息队列无法隔离时，显式加锁串行，锁持有者、超时与释放条件
  写入任务板；测试失败先区分环境隔离缺陷与代码缺陷，不用清理全局缓存掩盖问题。
- **S3 写者行为。** 写者只改写入范围，小步提交，不重置或清理不属于自己的文件；需要跨范围修改时先向领导者
  申请；不得推受保护或共享分支，不得在领导者不知情时改变基线。
- **S3 交付记录。** 写者交付提交 SHA、基线、diff 范围、测试命令、已知失败与风险，不以“当前目录能跑”
  代替证据；领导者核对写者、基线、范围与依赖后才进入集成。
- **S3 集成队列。** 领导者按 DAG 排序，在集成工作树更新到当前基线，合入或变基一个变更，运行受影响测试与
  冒烟；失败退回写者或调整顺序；成功后记录集成 SHA 与验证证据，再处理下一个。
- **S3 冲突处理。** 冲突由领导者或指定处理者解决，解决后重跑受影响门禁；不得沿用写者工作树的旧结果，也
  不得由最后提交者在不理解双方语义时随意合并。
- **S6 盘点。** 清理前检查 `git status`、未跟踪文件、stash、进行中进程、未推送提交与分支合并状态；有未提交
  内容时先提交到临时分支、生成 patch 或归档到任务记录，不直接 `reset --hard`、`clean -fd` 或强制移除。
- **S6 失联处置。** 写者失联时先隔离工作树并通知领导者，保留路径、分支与证据；新写者不得直接接管目录，
  由领导者审查后决定移交或回收。
- **S6 移除与回收。** 工作树干净且提交已合入或已归档后使用普通 `git worktree remove`；随后 `git worktree
  prune`，删除已合入分支，释放端口、锁与临时目录，更新任务板；清理失败记录原因、路径与下次处理人。
- **S6 平台核对。** Windows 验证路径长度、保留字符、大小写与文件锁，移除前关闭编辑器、终端与测试进程；
  Linux 与 macOS 验证权限位、umask、软链接与大小写敏感，确认容器内 Git 看到的路径与宿主一致。

## 门禁证据

- **G2**：任务板条目完整、依赖 DAG 无环、并行任务无共享可变文件、共享资源有锁与超时、集成工作树已指定。
  缺登记或存在两个写者时 Hold，不得创建可写工作树。
- **G3**：基线 SHA、创建后验证输出、写者交付记录、按 DAG 的集成顺序、集成结果上的测试、lint、类型检查与
  冒烟输出、冲突解决说明。只在写者工作树通过时 Recycle，不得宣称集成完成。
- **G6**：脏状态清点结果、归档或移交位置、普通移除输出、prune 与资源回收记录、任务板关闭状态、失败或
  回退工作树的保留证据。存在未提交内容、进程占用或所有权争议时 Hold。
- 强制移除、删除未合并分支或清理未跟踪内容须取得用户明确同意；记录操作者、对象、原因与保全方式。
- 证据须可复核：命令输出、提交 SHA、任务板链接与归档路径；口头交接与“已经清理”不构成证据。

## 交接与升级

- 上游：`project-lifecycle-governance` 给出阶段与风险级别；`vcs-collaboration-conventions` 给出分支模型、
  合并方式与审查要求；`testing-and-quality-conventions` 给出测试层级与门禁；`project-structure-conventions`
  给出目录与包边界；`naming-conventions` 给出分支与工作树命名。
- 下游：集成结果交回领导者管理的合并路径，由 `vcs-collaboration-conventions` 的审查与合并规则接管；
  发布由 `release-operations-conventions` 执行，不得从工作树直接发布；清理证据进入 S6 收尾记录。
- 升级触发：需要跨写入范围修改、共享文件出现第二个写者、基线漂移无法快进、写者失联、脏状态含唯一成果、
  路径冲突或平台锁无法释放。上述情形停下并请求领导者或用户裁决。
- 停止条件：工作树未登记、基线不是已提交对象、写入范围与依赖不清、集成结果未验证、强制移除未获同意时
  保持 Hold，不开始写入也不进入清理。

## 裁剪与度量

- R0 单写者小任务使用一个工作树，不设独立集成工作树，提交后直接验证并清理；R1 使用任务板与一个集成
  工作树，保留集成验证输出；R2 每个交付物独立工作树、专用集成工作树、完整分配与清理记录，并核对平台差异。
- 只读调查、代码搜索与方案比较不建工作树；一个写者的顺序任务复用同一工作树，不按任务数量扩张路径。
- 不可裁剪：单写者、登记与基线、环境隔离、集成结果验证、脏状态保全、移除前确认与资源回收。
- 度量：并行任务数、集成前置时间、冲突与返工次数、脏状态回收次数、清理逾期工作树数、WIP 超限次数、
  端口或锁冲突次数。
- 度量口径：集成前置时间从写者交付计至集成验证通过；冲突率按需人工解决冲突的集成次数除以总集成次数；
  清理逾期按任务关闭日至工作树移除日计算。
- 度量审查按任务结束或每周进行；异常先查拆分粒度、依赖顺序与环境隔离，不通过增加工作树数量或跳过验证
  来改善数字。
