# 项目结构与模块化生命周期契约

本文件说明目录与包的工作如何嵌入阶段与门禁：结构何时随计划定稿、何时随增量落地、以什么证据证明边界仍然有效。
阶段与门禁的定义由 `project-lifecycle-governance` 裁定；本文件不重复其判定，只把结论落到目录、导入、构建图与所有者映射上。
未列出的阶段不产出本 skill 的证据；发布阶段如需核对包入口，按 G2 的映射逐项查对，不新增门禁。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | architecture 的模块清单与依赖方向、项目现状 | 选择项目形态；把模块映射到目录、包与工作区；设计公开面与门禁 | 目录映射表、包清单、导入与构建图规则 | G2 |
| S3 构建 | 已通过 G2 的映射 | 落地新增或移动目录；同步导入、测试、文档与所有者；保持构建通过 | 结构调整 diff、导入检查输出、CODEOWNERS 更新 | G3 |
| S4 验证 | 增量与 CI 配置 | 复跑导入检查与构建图；核对别名、生成物与包导出未绕过门禁 | 门禁输出、例外清单与到期条件 | G4 |

S3 只落地 S2 选定的形态；需要更换形态或重划工作区时，按 Recycle 重新过 G2。

## 门禁证据

| 门禁 | 证据形态 | 复核者 | 不可接受的证据 |
|---|---|---|---|
| G2 | 形态选择理由、目录到模块与所有者的映射、公开面设计、门禁方案 | 结构负责人与 architecture 负责人 | 只有目录截图，没有导入与构建图规则 |
| G3 | 结构调整 diff、构建与导入检查输出、manifest 与导出、所有者映射更新 | 提交者自检；R1 起加独立审查 | 以行为变更夹带目录移动 |
| G4 | 导入检查、构建图、包导出校验均通过；例外有所有者与到期条件 | 独立审查者 | 门禁只在本地运行，CI 未启用 |

- R0：单个模块内新增文件，只需说明所属目录与公开面，不调整包边界。
- R1：新增包、移动目录或修改导入规则时，构建图与所有者映射随同一次交付更新。
- R2：跨工作区拆分、合并包或改变发布边界时，G2 需要 architecture 结论，G4 需要独立核对包导出与发布入口。
- 导入检查与构建图的配置与代码同仓、同版本，禁止在 CI 之外维护第二套规则。
- 例外（跨包深层导入、暂不拆分的共享层）必须有所有者、范围与到期条件，并写入结构决策。
- 结构门禁在合并前运行一次、在发布前复跑一次；两次结果不一致时先查基线分支再改规则。
- G2 与 G4 使用同一份目录映射表，避免计划与实际结构各留一份。
- 记录与模板以 `project-lifecycle-governance` 为准；门禁输出应当可由未参与者复跑。

## 交接与升级

交接：

- 自 `architecture-and-design-conventions` 接收模块清单、依赖方向与公开面裁定；未收到时不得自行划定边界。
- 交 `code-style-conventions`：模块内部布局与资源放置的边界，以及生成目录的格式化与 lint 排除项。
- 交 `testing-and-quality-conventions`：导入检查、构建图与包导出校验作为 CI 必需任务。
- 交 `repository-governance-conventions`：CODEOWNERS 路径表与仓库必需文件的位置。
- 交 `vcs-collaboration-conventions`：所有者映射与审查路径，用于确定边界变更的审查者。
- 交 `worktree-collaboration-conventions`：多智能体并行时的目录分配，避免两人写入同一包。

升级：

- architecture 未裁定边界，或现行目录与其裁定冲突：停止落点工作，先回到该 skill 取得结论。
- 结构调整无法在一次交付内保持构建通过：拆分为多次移动，每次保持可构建，按 Recycle 处理。
- 门禁缺失且无法在本次变更内补齐：把边界标为未强制，列入风险与到期条件，不得宣称边界已建立。
- 强制规则冲突：报告用户裁决；非强制约定冲突可记录于结构决策或 ADR。

停止条件：

- 移动目录会改变包版本或发布入口而未取得对应授权时，停止并说明所需批准。
- 目录中包含未跟踪的用户文件或未知来源内容时，先核查再移动，不得批量删除。
- 所有者无法确定的新顶层目录不得合并，先指定所有者。
- 多个智能体并行改动同一包时，按工作树协作规则指定唯一写入者，避免边界调整相互覆盖。
- 目录移动涉及多个工作树时，先确认各自基线，再由领导者统一集成。

## 裁剪与度量

裁剪：

- R0：一段说明，记录目录归属与是否需要门禁。
- R1：目录映射表加导入检查结果；包边界变更附所有者更新。
- R2：不得裁剪；形态决策、公开面、门禁与发布入口核对同时存在。
- 结构调整暂不新增门禁时，在结构决策中写明下一轮评估时点与责任人。

度量：

| 指标 | 定义 | 用途 |
|---|---|---|
| 无主顶层目录数 | 没有 CODEOWNERS 条目的代码顶层目录数量 | 发现无人审查的结构漂移 |
| 深层导入数 | 绕过包入口直接引用内部子路径的导入语句数 | 衡量公开面是否被绕过 |
| 未声明依赖数 | 导入存在但 manifest 未声明的包依赖数量 | 发现幽灵依赖 |
| 跨包相对路径数 | 以 `../` 跨越包边界的导入数量 | 判断工作区边界是否失效 |
| 门禁覆盖率 | 启用导入检查或构建图的包数与总包数之比 | 判断边界是否可执行 |
| 结构变更回滚次数 | 因构建失败或边界冲突而撤回的目录调整次数 | 校准拆分粒度 |

审查节奏：每次调整包边界时核对上表；每月检查无主目录与未声明依赖，异常先查目录映射再改规则。
度量由结构负责人汇总；结构变更回滚次数上升时，先查拆分粒度与门禁失败信息是否可读。
