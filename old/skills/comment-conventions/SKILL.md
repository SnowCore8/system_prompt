# 注释规范

注释以三种方式失效：重述代码已经说明的内容；随代码演进变得过时；用机械的概括掩盖意图。只有当注释记录读者
无法从代码恢复的信息（契约、理由、隐患或计划）时，才值得维护成本。本 skill 规定注释的决策流程与每种注释的
规则集，既服务于写注释的作者，也服务于评判注释的审查者；生命周期中的阶段职责见 `## 生命周期定位`。

## 适用范围与优先级

效力依下列层级判断：高层覆盖低层，低层仅在高层未规定时补充。

1. 强制性的平台、法律、宿主与全局用户约束。Javadoc doclint、rustdoc、TSDoc 与 godoc 的注释位置要求不是可选项。
2. 本 skill 的规则：注释内容、位置、标记、弃用与工具指令。
3. 既有项目约定与事实：先读代码、文档工具配置、注释 linter 与仓库声明的自然语言；项目约定仅在本 skill
   未规定时补充，不得覆盖本 skill。
4. 个人偏好，不得覆盖上述三层。

管辖与边界：

- 本 skill 管辖嵌入源码的注释、由文档注释生成的 API 文档、标记、指令与法律声明头；独立文档（README、文档站、
  ADR、变更日志、发布说明）归 documentation-conventions。注释长成文档时移动它并链接，不得复制。
- 弃用时机、移除窗口与公告位置归 release-operations-conventions；本 skill 只规定弃用标记的语法与替代项。
- 格式化工具、行宽与注释 linter 配置归 code-style-conventions；门禁阈值与跳过、隔离、豁免归
  testing-and-quality-conventions；机密扫描与泄露响应归 security-compliance-conventions；审查深度与合并门禁
  归 vcs-collaboration-conventions。
- 生成代码与第三方引入代码不受风格修改约束：保留生成标记与上游注释，重新生成或重新引入，不得手工编辑。
- 每个仓库仅声明一种自然语言，并应用于每种注释类型；标识符、API 术语与引用的上游文本保持原样。
- 注释变更属于代码变更：在同一次提交中更新它，像审查代码一样审查，并重新运行文档构建与 doctest。
- 注释不得替代测试、类型或清晰的名称；强制规则冲突时报告用户裁决，不得自行选定。

## 生命周期定位

上游输入来自 S2 的接口契约与文档工具链：公开符号的契约、文档生成器、注释 linter 与仓库声明的语言在此时确定；
下游交接给 S3 的增量实现、S4 的文档构建与 doctest、S5 的弃用声明与发布说明。

- 升级与停止：弃用时机与移除窗口升级给 release-operations-conventions；注释中出现凭据或个人数据时立即停止，
  保留证据并报告；公开符号的契约变更退回 G2 重新确认。

| 阶段 | 本 skill 的职责 | 产出 / 证据 |
|---|---|---|
| S2 计划 | 确定公开契约的文档注释要求、自然语言、标记与工具指令策略 | 注释策略、文档工具配置、语言声明 |
| S3 构建 | 按类型矩阵写注释，契约随签名同步；标记带负责人与触发条件 | diff 中的注释、标记清单、弃用声明 |
| S4 验证 | 核对注释与代码一致，运行文档构建、doctest 与注释 linter | 构建输出、doctest 结果、过时注释清单 |
| S5 发布 | 核对弃用声明、生成标记与发布说明的衔接 | 弃用与移除窗口记录、发布说明 |

## 门禁与证据

| 门禁 | 必须提供的证据 | 不满足时 |
|---|---|---|
| G2 计划 | 注释策略、文档工具配置、仓库语言声明、公开契约清单 | 策略缺失时 Hold，补齐后再过门 |
| G3 构建 | 注释 diff、标记负责人与触发条件、弃用声明与替代项 | Recycle 到 S3；裸 TODO 与注释掉代码阻断合并 |
| G4 验证 | 文档构建与 doctest 输出、注释 linter 结果、过时注释清单 | 修复后重验；行为变更未同步注释时 Recycle；契约破坏且无迁移路径时按 No-Go 处理 |
| G5 发布 | 弃用与移除窗口记录、生成标记完整、发布说明衔接 | Hold 发布，补齐迁移说明后再过门 |

证据必须可复核：构建命令与输出、diff 行号、issue 链接；口头说明与计划不构成证据。

## 工作流

1. 判断是否确实需要注释：代码已经说明事实的，删除注释或改进代码；代码清晰时，缺少注释不构成缺陷。
2. 为注释分类：文档注释、模块或文件头、行内理由、块说明、标记、弃用、法律声明头、工具指令或被注释掉的代码。
3. 阅读周边代码、项目约定与文档工具配置，找出将评判结果的 lint 规则；文档构建与 linter 属于验收测试。
4. 写出读者无法自代码获得的内容：契约、理由、隐患、外部约束或计划；宁可一句精确的话，不用三句含糊的话。
5. 套用形式：正确的语法与位置、必需的标签或小节、一种自然语言、项目的行宽与标点。
6. 在同一次变更中更新调用方注释、生成文档、示例、弃用声明与被解决的标记；最终编辑后重读注释，运行文档构建、
   doctest 与注释 linter，删除不再成立的内容。

## 核心规则

- **解释原因，不得复述行为。** 重述代码的注释使维护成本翻倍，并且最先过时；代码本身能够表达的，应当重写代码。
- **文档注释是契约。** 在每个公开边界记录参数、返回值、错误、副作用与不变量；改变契约即改变 API。
- **代码是事实来源。** 与当前代码矛盾的注释属于缺陷，应在同一次变更中修复或删除；无注释胜于错误注释。
- **删除代码，不得将其注释掉。** 版本控制保留历史；被注释掉的代码会腐化、掩盖废弃 API 并干扰搜索。临时禁用
  必须标明负责人、工单与到期时间。
- **标记带上类型要求的内容。** `TODO`、`FIXME` 与 `HACK` 包含负责人与移除触发条件；`NOTE` 与 `WARNING` 说明
  条件、后果与必需动作；所有标记遵循项目的拼写。
- **工单引用与生成标记使用平台可解析的语法。** issue 写作 `#123`，跨仓库写作 `owner/repo#123`，外部跟踪器用
  完整链接；生成文件除工具原生标记外包含 `@generated`。裸的“以后修复”不属于工单引用。
- **弃用标记写明替代项与移除版本。** 使用语言的弃用机制，并在标记里写明替代项与移除版本；仅有 `@deprecated`
  将使调用方缺乏迁移路径。
- **工具指令最少且有理由。** 从最窄范围开始，先一行再一个函数；每条指令需要理由，文件级抑制还需要清理工单；
  任何情况下都不得为一个位置在仓库范围禁用规则。
- **法律声明头与生成标记保持字节级一致。** 不得重排格式、翻译或手工编辑，亦不得删除第三方声明。
- **记录不显而易见的内容。** 记录外部约束、变通做法、unsafe 不变量、令人意外的边界情况与实测性能界限；跳过
  语言教程；熟悉的内容不记录。解释超出一段的属于设计说明，注释只负责链接。
- **写明单位、范围、可空性与所有权。** 类型无法承载时，文档注释必须说明：毫秒还是秒、包含还是不包含、缺失
  还是为空、借用还是拥有。
- **将注释附着于其对象上。** 文档注释放在声明上，行内注释放在所解释的行或块上，文件头置于文件开头；脱离对象
  的注释会被对照错误的代码阅读，重复的注释会与孪生条目漂移。
- **依照格式的语气写作。** 句首大写、完整句子、正确标点、项目的行宽；描述用现在时陈述行为，指令用祈使式。
- **密度取决于意外程度，而非行数。** 每行都有注释的文件与完全无注释的文件一样难读，每条注释都是维护负担。

## 注释类型矩阵

注释类型决定语法、位置与必填字段；动笔之前先选定类型，文档注释与行内注释遵循不同规则。

| 类型 | 用途 | 必需形式 | 示例 |
|---|---|---|---|
| 文档注释（docstring） | 声明的公开契约 | 紧跟声明上方的工具语法；摘要、契约、标签 | `"""Return the invoice total in cents."""` |
| 文件或模块头 | 文件的用途、范围与不变量 | 法律声明头之后的第一个注释；不记载变更历史 | `// Package billing reconciles invoices.` |
| 行内理由 | 解释下一行中不显而易见的选择 | 行上方的 `//` 或 `#`，同缩进，一个想法 | `# Retry once: the gateway resets idle connections.` |
| 块说明 | 多行理由、算法、外部约束 | 项目的块注释语法，折行，无装饰边框 | `/* The vendor caps a batch at 500 items. */` |
| API 文档标签 | 供生成的参考文档使用的机器可读字段 | 工具要求的语言标签语法与顺序 | `@throws InvoiceNotFoundError when the id is unknown` |
| TODO | 有负责人的计划内工作 | 标记加负责人、动作、issue 或移除触发条件 | `// TODO(maria): drop the shim after v2 ships (#512).` |
| FIXME/HACK/NOTE/WARNING | 缺陷、捷径、上下文或隐患 | FIXME/HACK：错误行为、负责人、移除触发条件；NOTE/WARNING：条件、后果、动作 | `// WARNING: without the caller's lock, the balance read races writers (#318).` |
| 弃用标记 | 迁移路径与移除版本 | 语言机制加替代项与版本 | `@deprecated Use create_invoice; removed in v3.0.` |
| 法律声明头 | 许可证与版权义务 | 位于要求位置的精确 SPDX 与版权行 | `// SPDX-License-Identifier: Apache-2.0` |
| 工具指令 | 给 linter、格式化工具或生成器的指令 | 最窄范围内的精确工具语法，并给出理由 | `// eslint-disable-next-line no-console -- CLI output.` |
| 生成标记 | 阻止手工编辑并指向生成器 | 位于顶部的工具原生标记，字节级一致 | `// Code generated by sqlc. DO NOT EDIT.` |
| 被注释掉的代码 | 无：旧代码由版本控制负责 | 删除它；使用构建系统，或带到期时间的标记指令 | `n/a` |

遗留项目强制要求的变更头按 `references/dimensions-inline.md` 第 10 节处理；该例外仅限既有文件，新文件不得引入。

## 反模式

| 阶段 | 反模式 | 为什么失败 | 修复 |
|---|---|---|---|
| S2 | 无替代项的弃用 | 使调用方无迁移路径 | 补上替代项、版本与移除工单。 |
| S3 | 逐行重述的注释（`// increment i`） | 重复代码，而且最先失效 | 删除它；意图不明时重命名标识符。 |
| S3 | 与代码矛盾的过时注释 | 使读者形成错误理解 | 同一次变更中修复或删除；每次行为变更后审查。 |
| S3 | 裸的 `// TODO: fix later` | 无负责人、无触发条件、无审查路径 | `TODO(owner): action and reason` 加一个 issue。 |
| S3 | 被注释掉的代码块 | 掩盖废弃 API，干扰搜索与覆盖率 | 删除它；依赖版本控制。 |
| S3 | `@param user the user` | 重复签名，未增加任何契约 | 写明格式、范围、可空性或所有权。 |
| S3 | 文件头里的变更历史 | 重复版本控制，而且立刻过时 | 删除它；提交消息承载历史。 |
| S3 | 无理由的整文件 lint 抑制 | 掩盖未来所有违规，且存续时间超过其理由 | 仅在线级或函数级不可行时用文件级；补理由与清理工单。 |
| S3 | 被注释掉的调试输出 | 造成污染，且会于提交中再次出现 | 使用可配置级别的 logger。 |
| S3 | 未指明动作的警告 | 读者无法针对隐患采取行动 | 写明条件、后果与必需动作。 |
| S3 | 示例中的机密或个人数据 | 注释随源码一起发布并泄露 | 使用 `example.test.invalid` 与占位标识符。 |
| S3 | 外语注释 | 破坏单一语言规则，拖慢审查 | 使用仓库声明的语言。 |
| S3 | 以注释代替具名常量 | 将含义置于代码之外 | 提取 `DEFAULT_TIMEOUT_MS` 并删除该说明。 |
| S3 | 于多个函数间复制的文档注释 | 副本之间互相漂移 | 链接到唯一的归属处，或只写一次契约。 |
| S3 | 作者或日期横幅、注释里的变更记录 | 重复提交元数据，并于下次变更时腐化 | 删除它；提交元数据承载该信息。 |

## 审查清单

计划与契约（G2）：

- [ ] 公开符号的文档注释已列入契约评审，语言与标签风格已声明。
- [ ] 文档工具、doctest 与注释 linter 已配置，失败处理方式明确。

构建（G3）：

- [ ] 注释补充了代码未说明的信息；每条文档注释与当前签名、行为与错误一致。
- [ ] 公开的参数、返回值、错误、副作用与不变量都有记录；单位、范围、可空性与所有权显式。
- [ ] 摘要一句，描述用现在时、指令用祈使式；行内注释位于所解释行上方或旁边，缩进相同。
- [ ] 每个 TODO、FIXME 与 HACK 都有负责人，以及被跟踪的 issue 或移除触发条件；issue 引用格式可解析。
- [ ] 每个 NOTE 与 WARNING 说明条件、后果与必需动作；弃用声明写明替代项与移除版本。
- [ ] 变更中未留下被注释掉的代码或调试输出；迁移期临时禁用注明了负责人、工单与到期时间。
- [ ] 注释语言是仓库声明的语言，标识符不变；行宽、标点、大小写与间距符合项目约定。

验证与发布（G4/G5）：

- [ ] 法律声明头与生成标记完整且未被修改；生成与引入文件是重新生成的。
- [ ] 被重构移动或删除的注释未留下孤立或过时的引用；与独立文档重复的注释改为链接。
- [ ] 支持 doctest 的示例已执行并产生所述输出；其余示例标为非执行围栏。
- [ ] 已配置的文档构建、doctest 与注释 linter 通过；diff 中每个行为变更都包含注释更新。
- [ ] 弃用与移除窗口与发布说明一致；任何注释中均无机密、令牌、个人数据或内部地址。

## 示例

<example>
为公开函数写文档注释：
`"""Charge the invoice and return the payment id; raise PaymentDeclinedError when the gateway declines."""`
项目使用 Google 风格时补上 `Args:` 与 `Raises:` 小节，不得在正文重复类型提示；函数体不再重复。
</example>

<example>
对无锁读取写并发警告：
`// WARNING: the snapshot may be stale if a writer commits; take the write lock before comparing versions (#412).`
按条件、后果、必需动作的顺序说明，并把完整历史链接到 issue；不得把隐患埋于一段描述之中。
</example>

<example>
修复过时的文档注释：注释写着 `Return the cached user or None`，但函数现在抛出 `UserNotFoundError`。
在同一次变更中重写契约，更新仍承诺 null 的调用方注释，修正断言 `is None` 的 doctest，并搜索旧的承诺。
</example>
