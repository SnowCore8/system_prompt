# 系统提示生命周期契约

本文件说明常驻指令文件在阶段之间如何交付与验收：输入从何而来、逐节编写时保留什么证据、校验结果如何支撑
门禁决定，以及何时必须升级或停止。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S1 探索 | 请求、目标文件候选、项目现状 | 判断项目文档与 skill 是否已覆盖；列出只有常驻才需要的信息 | 新建或沿用的结论、分工边界 | G1 |
| S2 计划 | 范围、完成定义、五项输入 | 定节顺序、长度预算与 S1-S13 归属；标注假设与待提问项 | 骨架、假设清单、长度预算 | G2 |
| S3 构建 | 骨架、仓库事实（构建命令、目录约定） | 逐节写入；`Context` 只留模型无法推导的信息；红线附理由 | 草稿、每行对应的可阻止错误 | G3 |
| S4 验证 | 草稿、校验脚本、S1-S13 | 逐行适用删除标准；运行校验；逐条结论；整理报告 | 校验输出、逐项结论、未解决项 | G4 |

阶段边界：S1 不写内容；S2 不写规则；S3 一次只写一节，便于逐行判断去留；S4 不得顺手改规则，发现必须修改时
退回 S3，使校验对象与改动一致。

## 门禁证据

- G1 立项。证据为目标文件、任务类型、范围与完成定义，以及“项目文档与 skill 已覆盖”的判断。仅表示这份文件
  重要，不构成立项证据。
- G2 计划。证据为五项输入的处理表（已提问、已假设、已省略）、节列表与长度预算、目标模型或 S13 默认值、红线
  清单。安全边界未确认且未提问的，不得进入构建。
- G4 验证。证据为四项：
  - 校验命令的逐字输出与退出码，`--strict` 下 0 错误 0 警告；
  - S1-S13 逐项结论，每项附证据（行号、引用或校验项）；
  - 红线每条附替代行为或理由，未确认的工具与配置键已删除；
  - `[建议]` 项逐条按 S9 判断，写明保留或删除的理由。
- 非 `--strict` 模式下的警告可以写结论，但结论不改变退出码；需要过门禁时必须在源头消除。

证据与决定：

| 情形 | 决定 | 处理 |
|---|---|---|
| 0 错误 0 警告，S1-S13 均有结论 | Go | 可合入并加载 |
| 仅剩与 S9 相关的建议项 | Conditional Go | 条件为写明保留理由与负责人，下次改动时复核 |
| 警告未在源头消除 | Recycle | 回到 S3 改造写法或修校验脚本 |
| 内容规则无结论，或红线缺理由 | Hold | 补齐结论前不交付 |
| 目标文件不属于常驻指令 | No-Go | 说明超出范围并指向对应 skill |

## 交接与升级

上游交入：

- 用户与 `project-lifecycle-governance` 给出范围、完成定义与门禁要求；本 skill 不自行放宽。
- `documentation-conventions` 给出项目文档中的事实与结构；指令文件只引用，不复制其内容。
- `naming-conventions` 给出文件名、目录名与标识符；`security-compliance-conventions` 给出凭据与红线的边界。

下游交出：

- 需要产品化、非每会话加载的提示词内容，交 `prompt-authoring` 处理写法与评测。
- 只在部分任务使用的规则，交 `skill-authoring` 作为 skill 维护，正文只留加载指引。
- 项目说明、教程与决策理由，交 `documentation-conventions` 承载。

升级条件：

- 超过项目长度上限：按主题把规则提取到对应 skill 的参考文件，正文保留摘要与加载指引，不得压缩措辞规避。
- 安全边界与篇幅冲突：保留红线，删除其他可推断内容；不得为压缩篇幅删去红线。
- 目标模型未知：采用 S13 默认值并在报告标注；更换目标模型视为行为变更，须重新检查 S3、S7 与 S13。
- 校验告警无法消除：改造写法，或修改校验脚本并为其补测试；不得记录解释后放行。

停止条件：

- 范围或完成定义未确认时停止提问，不先写草稿。
- 目标文件不属于指令文件时停止，改为对应 skill 或项目文档。
- 需要写入未确认的工具、命令或配置键时停止，按 S10 提问或省略。

## 裁剪与度量

按风险裁剪：

| 级别 | 典型改动 | 必做 | 可省略 |
|---|---|---|---|
| R0 | 单行措辞、断链、拼写 | 格式校验与 S9 判断 | S1-S13 全量结论 |
| R1 | 增删小节、调整顺序 | `--strict` 校验、S1-S13 结论、假设清单 | 独立审查 |
| R2 | 新建文件、改红线或安全边界 | 五项输入齐全、独立审查、加载验证、报告逐项证据 | 无 |

度量：

| 指标 | 计算 | 用途 |
|---|---|---|
| 有效行占比 | 抽样十行中能阻止具体错误的行数 | 判断是否仍有可删内容 |
| 结论覆盖率 | S1-S13 中有证据结论的条数比例 | 判断验证是否完整 |
| 严格校验通过率 | `--strict` 下 0 警告的提交比例 | 判断格式是否稳定 |
| 变更频率 | 单位时间内该文件的改动次数 | 判断是否破坏 prompt caching |
| 假设数量 | 交付报告中标注假设的条数 | 判断信息收集是否充分 |

度量纪律：不以行数少为目标，也不以规则全为目标；指标恶化先查是否有可移入 skill 的细节，不得先删红线或
放宽 S 项要求。
