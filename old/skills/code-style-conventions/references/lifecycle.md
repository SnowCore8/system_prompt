# 代码风格规范生命周期契约

本文件说明风格、依赖、配置与日志工作如何进入阶段与门禁：规则在计划阶段定稿，在构建阶段随增量落地，在验证阶段以工具输出证明。
阶段与门禁的判定由 `project-lifecycle-governance` 负责；本文件只描述本 skill 提供什么证据、交给谁、在哪些条件下停下。
未列出的阶段不产出本 skill 的证据；发布阶段如需核对锁定版本，沿用 G4 的校验输出，不另立门禁。

## 阶段职责

| 阶段 | 输入 | 活动 | 输出 | 门禁 |
|---|---|---|---|---|
| S2 计划 | 项目现有工具链、模块边界、依赖准入标准 | 选定 formatter 与 linter，确定行宽、导入分组与依赖策略；设计配置优先级与启动校验 | 工具配置、依赖准入结论、配置 schema | G2 |
| S3 构建 | 已定稿的规则与配置 | 以最小配置或代码变更落地；机械变更与行为变更分开；同步参考页与说明 | 配置 diff、仅重格式化的独立提交、锁文件变更 | G3 |
| S4 验证 | 干净检出、CI 命令 | 运行格式校验、lint、构建与相关测试；核对 diff 无生成物、无机密、无隐藏行为变更 | 命令输出与退出码、diff 核对结论 | G4 |

S3 只按 S2 定稿的规则改代码；需要新增或放宽规则时，先以独立配置变更过 G2，再继续实现。

## 门禁证据

| 门禁 | 证据形态 | 复核者 | 不可接受的证据 |
|---|---|---|---|
| G2 | 工具选型与唯一取值、依赖锁定方案、配置优先级与 schema、生成目录排除项 | 提交者与模块负责人 | 只有口头约定或风格指南，没有配置 |
| G3 | 配置 diff、机械提交与行为提交分离、manifest 与锁文件同步、重生成的生成物 | 提交者自检；R1 起加独立审查 | 风格修复夹带工具升级或无关重排 |
| G4 | 干净检出上的格式校验与 lint 输出、构建与测试结果、退出码、diff 核对 | 独立审查者 | 仅在本地通过；粘贴未经运行的输出 |

- R0：单文件内的小改动，只需运行对应 formatter 与 linter，并说明命令。
- R1：新增或删除依赖、调整配置优先级、改变日志字段时需要独立审查与锁文件 diff。
- R2：跨仓库工具链切换、涉及凭据或日志脱敏策略的变更，G4 需要安全结论与制品核对记录。
- 规则文件、工具版本与 CI 命令同仓维护，本地与 CI 使用同一锁定版本。
- 例外（生成目录、第三方引入树、平台文件）必须带注释说明来源与排除理由。
- 机械变更的提交信息只写 formatter 命令与受影响路径，便于与其他提交区分。
- G2 记录的规则与 G4 复跑的校验项一一对应，未落地的规则不计入证据。
- 门禁记录字段以 `project-lifecycle-governance` 的模板为准；命令输出需可复跑。
- 既有工具已覆盖某条规则时，以工具配置为准，并在风格指南中注明规则来源。
- 配置与日志字段的变更须同时更新参考页，否则 G4 的证据不完整。

## 交接与升级

交接：

- 交 `testing-and-quality-conventions`：格式校验、lint 与构建命令，以及它们在 CI 中的必需性。
- 交 `release-operations-conventions`：日志级别与字段内容策略，由该 skill 决定存储、索引与告警。
- 交 `documentation-conventions`：配置键参考页、风格指南条目与依赖说明的更新点。
- 交 `project-structure-conventions`：生成目录与第三方引入目录的排除项，以及模块内部布局的边界。
- 交 `security-compliance-conventions`：依赖准入中的漏洞、许可证与供应链证据。
- 交 `naming-conventions`：重命名与重新格式化的拆分顺序，两者不得混在同一 diff。

升级：

- 工具版本未锁定，或本地与 CI 的 formatter 版本不一致：先对齐版本，不得改规则绕过失败。
- 风格变更与行为变更混在同一 diff：拆分为两次提交，各自验证。
- 新增依赖缺少健康度或许可证证据：停在 G2，补齐证据再进入构建。
- 配置键在多个模块各自读取，或优先级阶梯出现第二套：Recycle 到 S2，收敛为单一读取点。
- 强制规则冲突：说明冲突并报告用户裁决；非强制约定冲突可记录于风格指南。

停止条件：

- 发现机密或个人数据已进入代码、配置、日志、fixture 或提交历史时，停止操作并按凭据与隐私处置流程处理。
- 代码生成器的输入来源不明，或重新生成会产生无法解释的差异时，停止提交生成物，先查清来源。
- 依赖安装脚本未经审查即被要求执行时，停止安装，先审查脚本。
- 删除锁文件、跳过校验或以 `--no-verify` 提交的请求，一律视为需先解决根因。
- 紧急止损按 AU-5 优先：先撤销可疑配置或回退锁定版本，再补门禁记录与复盘。

## 裁剪与度量

裁剪：

- R0：一条命令记录加一次 diff 自查，不新增规则。
- R1：完整配置与锁文件证据；规范条目写入风格指南一行。
- R2：不得裁剪；工具链变更需要独立审查与制品核对。

度量：

| 指标 | 定义 | 用途 |
|---|---|---|
| 格式校验失败率 | CI 中格式校验失败次数与提交次数之比 | 判断本地与 CI 是否一致 |
| lint 违规密度 | 每千行代码的 lint 告警数 | 发现规则与代码脱节 |
| 风格提交混入率 | 含格式重排但仍夹带行为变更的提交比例 | 检验变更拆分纪律 |
| 未声明依赖数 | 导入存在但 manifest 未声明的包数量 | 发现幽灵依赖 |
| 配置键重复数 | 同一行为被多个键控制的实例数 | 发现配置腐化 |
| 生成物漂移次数 | CI 重新生成后 diff 不为空的次数 | 检验生成流程确定性 |

审查节奏：每个发布周期核对格式与 lint 趋势；每季度清理未使用依赖、遗留开关与到期豁免，异常先查配置与流程根因。
